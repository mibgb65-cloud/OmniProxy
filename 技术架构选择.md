# OmniProxy 技术栈选型

> 本文档定义 OmniProxy 全面重构后的核心技术栈、架构边界与技术选型约束。
> 后续开发、重构以及 AI Agent 自动生成代码时，应优先遵循本文档。

## 1. 项目定位

OmniProxy 是一个面向本地桌面环境的 AI API 网关与多账号管理工具。

核心能力包括：

- 多 AI Provider 接入
- 多账号统一管理
- API 请求代理
- 模型路由
- 账号自动调度
- 配额监控
- 请求失败自动切换
- 请求历史
- 使用量统计
- Provider 健康检测
- Codex / Claude Code / Gemini CLI 等客户端配置管理
- 本地 Control API
- Windows 桌面管理界面
- 系统托盘
- 开机自启动
- 自动更新

项目采用：

```
Go Core
+
Wails 3 Desktop
+
React Frontend
```

作为整体技术架构。

# 2. 核心技术栈

## 2.1 桌面框架

选择：

```
Wails 3
```

用途：

- Windows 桌面应用
- 原生窗口
- Go 与 TypeScript 通信
- System Tray
- Single Instance
- Autostart
- Native Menu
- Events
- 自动更新
- 应用打包

原则：

```
Wails 只负责 Desktop Shell
```

Wails 不应该侵入 OmniProxy Core。

核心业务逻辑禁止直接依赖 Wails。

# 19. Core Architecture

OmniProxy Core 必须独立于：

```
Wails
React
Desktop
```

原则：

> 即使完全删除 Wails 和 React，OmniProxy Core 仍然应该能够独立运行。

依赖方向：

```
Desktop
   ↓
Application
   ↓
Core
   ↑
Infrastructure
```

禁止：

```
Core
 ↓
Wails
```

# 20. Provider Architecture

所有 AI Provider 使用统一 Adapter 架构。

例如：

```
Provider
├── OpenAI
├── Anthropic
├── Google
├── DeepSeek
├── Kimi
├── MiMo
└── OpenAI Compatible
```

Provider 应实现统一能力接口，例如：

```
Authenticate
Models
Quota
TransformRequest
TransformResponse
ClassifyError
HealthCheck
```

禁止大量出现：

```
if provider == "openai"

if provider == "anthropic"

if provider == "google"
```

新增 Provider 应尽可能通过：

```
New Provider Adapter
```

完成。


# 33. Architecture Rules

必须遵守：

### Rule 1

```
Core 不依赖 Wails
```

### Rule 2

```
Core 不依赖 React
```

### Rule 3

```
UI 不直接操作 SQLite
```

### Rule 4

```
UI 不直接访问 Credential Store
```

### Rule 5

```
Provider 不负责 UI
```

### Rule 6

```
HTTP API 与 Wails Binding 共用 Application Service
```

### Rule 7

```
业务逻辑禁止写在 React Component 中
```

### Rule 8

```
敏感凭据禁止写入日志
```

### Rule 9

```
实时状态优先 Events，而不是 Polling
```

### Rule 10

```
新增 Provider 优先 Adapter，而不是修改 Gateway Core
```

# 36. 技术选型原则

整个 OmniProxy 重构遵循：

```
Core First
Typed First
Local First
Secure by Default
Explicit over Magic
Small Modules
Loose Coupling
High Cohesion
Replaceable Infrastructure
Testable Business Logic
```

最终目标不是简单地：

```
把 OmniProxy 升级到 Wails 3
```

而是建立：

```
                 OmniProxy Core
                       │
       ┌───────────────┼───────────────┐
       │               │               │
   Wails App       Control API      Future CLI
       │               │               │
     React          Agent/MCP        Terminal
```

让 OmniProxy Core 成为整个项目真正稳定、可测试、可扩展的基础。
