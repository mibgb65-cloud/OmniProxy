# v1 → v2 数据导入与更新

应用版本为 `2.0.0-beta.1`，Git 发布标签采用 `v2.0.0-beta.1`。Windows 安装器使用数字版本 `2.0.0`，PE 文件数字版本为 `2.0.0.0`；应用和产品版本字符串保留 Beta 后缀。Beta 序号和正式版提升由应用的 SemVer 比较负责，不依赖 Windows 数字资源判断。

## 数据导入

在「设置与关于 → 数据存储 → 导入 OmniProxy v1 数据」中选择旧目录，或留空后点击「预览旧版数据」。预览不会保存账号，也不会自动读取真实数据；只有用户点击才访问源文件。确认可导入数量和跳过原因后，再点击确认导入。

- 生产环境默认识别 `%USERPROFILE%/.omniproxy`，开发环境为 `.omniproxy-dev`。优先读取旧版对应 `OmniProxy/bootstrap.json` 或 `OmniProxyDev/bootstrap.json` 指向的自定义目录；仍可手动选择目录。测试环境必须显式指定测试源目录。
- 读取固定文件 `tokens.json` 与可选 `config.json`，不移动、不删除、不回写。v1 Windows 凭据按原 entropy 在同一 Windows 用户下解密，再经新版凭据库重新加密；SQLite 只保存新引用。
- 支持可明确映射官方入口的 OpenAI、Anthropic、DeepSeek、Google API Key、智谱普通 Key、Atria、Kimi 普通／Coding Key 和 MiMo 普通／三个套餐集群。保留可用名称、停用状态和明确的账号计费／地区选项；旧统计、配额快照、置顶／优先级不迁移。
- Codex／Claude OAuth 账号需要在新版重新登录，不能直接复制到新版官方隔离登录命名空间。MiniMax 旧记录缺少明确计费身份，提示手动添加并确认；智谱 Coding Plan、未接通的服务商、自定义地址也逐项提示手动处理。
- 历史统计、模型路由、全局设置、客户端备份和外观设置仍保留在旧版，导入不改写真实客户端文件，也不承诺整库兼容。
- 同一旧身份使用确定性迁移 ID；同服务商相同 Key 也会跳过。已有新版账号不会被覆盖；若需替换密钥或修改计费类型，应使用新版编辑入口。
- 预览后旧文件变化会拒绝导入，要求重新预览。导入采用单账号事务：失败项单独报告，已成功项保留，重新预览可重试剩余项。数据库写入失败时清理本账号新建凭据，旧凭据和旧文件不受影响。
- 文件大小、条目数量、字段和目录受限，拒绝文件符号链接／非普通文件。预览与结果仅返回公开元数据和结果码，不返回 Key、密文或凭据引用。

## 更新渠道

在「设置与关于 → 检查更新」选择正式版，或正式版与 Beta 测试版。选择持久保存；没有明确选择时，Beta 应用默认 Beta 渠道，正式应用默认正式渠道。切换成功清除旧检查结果，不自动联网。

默认仓库为 `mibgb65-cloud/OmniProxy`。正式渠道使用正式发布端点，Beta 渠道读取有界分页列表，排除草稿和无效版本，按版本优先级选择最高版本，包含后续正式版。仓库输入、响应大小、重定向和返回链接都有边界；发布页链接由已校验仓库及版本构造。

比较满足 `beta.1 < beta.2 < beta.10 < rc.1 < 正式版`，忽略构建元数据；不会将 `v1.x` 当作新版 `2.0.0-beta.1` 的升级或提出降级。

已补齐启动后自动检查、侧栏升级标记、浮窗下载／进度／取消、SHA256 校验和重启静默更新，下载与安装始终由用户点击触发。完整行为和缓存信任边界见 [UPDATE](UPDATE.md)，发布与实际安装验收见 `docs/development/RELEASE.md`。没有实际发布远端 Release；用户级及机器级安装验收分别记录，不能相互替代。
