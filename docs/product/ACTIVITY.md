# Token 用量、请求与日志

仪表盘按本地今日／7 天／30 天展示请求结果、完整耗时和 Token 趋势。迁移 010 独立 15 分钟聚合保留明细淘汰后的统计，历史仅回填现存记录并标示缺口；详见 `DASHBOARD.md` 和 ADR-007。

## 统计规则

- 用量页展示累计输入、输出和合计 Token，累计请求数、完整用量覆盖、近 30 天与账号成员／模型汇总。
- 「按提供商与模型」按具体提供商配置 ID 和实际模型分别展示输入、输出、合计 Token 与请求数。同名模型在不同提供商中独立累计，同一提供商多个账号的模型用量合并。
- 统计从本功能启用后开始采集，不从旧日志或文本长度推测历史 Token。
- 输入／输出只取原上游返回的 usage；已包含缓存和推理的总数不重复相加。Messages 原生输入若拆出缓存计数，则合并实际输入。DeepSeek 流式主动请求 include_usage。
- 流式累计快照取最大已报告值，并在事务中按差值更新；重复终止事件只记一次。已报告部分即使请求失败／取消也累计；没有报告的部分标记未知，区别于真实的 0。
- 上游读取完成时立即落库，客户端断开不会取消已报告用量的写入。JSON、SSE、Responses WebSocket 和跨协议统一使用请求 ID；HTTP 返回 X-Request-ID。
- 迁移 032 追加可空首字毫秒和独立桶总和／样本数。首字按网关首次写出有效流式内容记录；旧记录、非流式及未发出内容保持未知。明细可保留失败／取消后的已测值，平均仅取成功样本，真实 0 与未知区分；详见 [网关统计](GATEWAY.md#请求统计与首字耗时)。

## 保存与身份

迁移 033 增加请求尝试明细。一次客户端请求仍只算一次，先前明确拒绝不绑定主记录；唯一接受的响应／已报告 usage 才绑定目标，全部拒绝则归最后实际目标。原 subject 不变保护保持，未知尝试用量不伪造为零。请求列表可选返回尝试数、详情返回有序尝试；历史数据不构造尝试。子明细随父明细清理，幂等完成与崩溃恢复不改变已记累计。行为见 [账号故障切换](FAILOVER.md) 与 ADR-015。

迁移 008 保存累计表、按日／成员／模型汇总、请求快照和保留设置。账号及提供商删除不会级联删除这些记录；请求明细淘汰也不减少汇总。

迁移 009 独立保存提供商／模型累计，跟随同一个用量差值事务更新，没有删除外键。已有每日桶优先按保存请求的唯一提供商 ID 归属，再按唯一名称映射；歧义或资源已无法确认时保留历史分组，页面标记「历史归属待确认」，不凭模型名称猜测厂商。

Team 工作区可包含多个邮箱。订阅统计身份为提供商类型 + 规范化邮箱 + account_id，而非单独 account_id；同一身份删除后重新添加可继续合并历史。请求详情保留当时邮箱、工作区和名称，已删除账号明确标记。推理、额度、目录和重置操作核对实际授权邮箱；同工作区其他邮箱不能沿用旧成员身份。

请求明细默认 10000 条，可在设置修改为 100–1000000。按时间淘汰最早已结束明细，正在执行的请求保留在容量内。代理本身有并发限制。超出代理最长期限的旧进行中记录在启动时恢复为中断，不改写已累计用量。

## 页面关联

请求页支持结果筛选、关键字搜索和分页；详情提供请求 ID、账号／工作区、协议／传输、Token 报告状态、耗时和错误代码，可跳到关联日志。日志展开行可回到请求详情。

请求列表每页 50 条；底部显示“第 N 页 / 共 M 页”，总页数按筛选后的记录总数向上取整，空列表显示 1 / 1。记录数量和保留上限在左侧独立展示，不混作页数。

日志缓存默认及最大 5000 条；较早关联日志过期时请求明细／累计仍可存在。日志文件沿用现有轮转策略。请求／统计记录不保存提示词、输出正文、凭据或原始头部，日志只携带请求 ID、模型、用量及有限诊断字段。

## 容错与边界

开始记录失败会阻断代理；用量持久化失败会中断当前响应并报告。记录结束写入失败明确记录 accounting_unavailable，既有用量事务保留。崩溃或上游未返回终止用量时无法恢复未报告 Token，页面显示报告覆盖状态。总数以十进制字符串返回，前端 BigInt 格式化，避免超过 JavaScript 安全整数后的精度损失。

不统计模型目录、余额、额度等后台查询；这些操作不通过推理代理。

上游格式依据：[OpenAI Responses usage](https://platform.openai.com/docs/api-reference/responses/object)、[DeepSeek Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion)、[Messages 累计流式 usage](https://platform.claude.com/docs/en/build-with-claude/streaming)。
