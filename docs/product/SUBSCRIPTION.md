# ChatGPT 订阅账号

Google AI / Antigravity 使用独立订阅通道与浏览器授权，详见
[Google 订阅说明](GOOGLE_SUBSCRIPTION.md)；不共用本文的 Codex 额度、重置卡或系统登录。

OpenAI 账号支持 API Key 与 ChatGPT / Codex 两种认证方式。订阅授权已用于模型目录同步与 Responses 转发，跨协议支持文本和工具；具体权限仍由官方每次请求决定，见 `LOCAL_AGENTS.md`。

## 使用

登录弹窗使用整块可选的浏览器／设备码授权卡片，并提供各自说明与键盘焦点反馈。顶部显示品牌和用途，底部固定主要操作，内容过高时独立滚动；新增账号可选填名称，重新登录不显示名称输入。等待状态集中显示官方页面入口和设备码，完成／错误使用独立状态面板；关闭保留后台授权，取消才停止。深浅主题及最小窗口沿用同一布局，界面不再显示已过时的“订阅转发待接入”提示。

1. 确认本机官方 `codex --version` 可用。目前已验证版本为 codex-cli 0.155.1。
2. 在“账号 → OpenAI”点击“登录 ChatGPT”。名称选填，留空使用官方账号身份，身份为空时使用 ChatGPT Codex。
3. 选择浏览器授权或设备码授权，点击“开始授权”。应用打开官方页面；设备码模式在窗口显示一次性代码。设备码可用性由官方服务和账号策略决定，无法使用时可改用浏览器。
4. 在官方页面完成登录。应用通过状态事件读取结果，以登录邮箱为账号标题，并显示套餐标签；邮箱尚未返回时使用账号名称。正常状态不额外显示“已授权”，异常授权状态仍可见，不接收用户密码。
5. 账号详情通过图标按钮刷新状态、重新登录或退出，鼠标悬停和键盘聚焦显示统一风格提示。普通刷新只读取托管身份，不强制续期；临时失败保留原状态，用可关闭、5 秒后自动消失的非阻断提示反馈，不在卡片上长期保留“授权已取消”。真实身份变化、缺失授权或本地保存失败仍明确显示；后续重新登录／账号更新后不继承旧操作红字。退出保留账号记录；删除仅清理该账号的本地记录与授权，不调用官方退出登录，也不影响网页或其他客户端。
6. 套餐后显示官方 account_id 的首 8 位和末 6 位，完整值可通过鼠标悬停或键盘聚焦查看；旧账号点击“刷新状态”补全。账号启停使用电源图标按钮，绿色表示已启用，灰色表示已停用，悬浮提示说明下一步操作。
7. 账号详情自动读取真实订阅额度：Plus／Team 普通套餐显示 5h 与一周窗口，其他套餐显示一周窗口。蓝／绿进度条显示剩余百分比，不推算固定请求次数。状态刷新后自动重新读取；查询失败可点击额度区域的刷新图标重试。
8. 额度窗口显示重置倒计时，悬浮或键盘聚焦可查看本地时区的完整重置时间。已过期快照提示“待刷新”，不擅自把进度条恢复为 100%；缺失窗口或时间明确提示。全额且无官方重置目标时显示本地“未开始计时”，悬浮提示说明时间尚未返回。
9. 订阅卡片底部并排显示创建／更新时间，统一为本地时区 YYYY-MM-DD HH:mm；列表沿用相同格式。OpenAI 账号详情顶部的设置图标在入口旁展开局部设置面板，自动避让窗口边缘、内部滚动，不遮暗或模糊整页；关闭按钮、再次点击入口、Escape 或点击外部可收起。提供「Codex WebSocket」开关，默认开启、所有 OpenAI 账号共用。只控制当前 OmniProxy 网关的 WebSocket 接入，开关自动保存并即时生效，普通 HTTP/SSE 仍可用；不修改 Codex 认证或会话。面板只保留主要功能说明，不堆叠共用范围、自动保存周期等补充文案。提供「账号轮换方式」队列／平衡二选一，默认队列；真实请求策略见 `FAILOVER.md`。读取失败提供重试，保存失败保留原值，任一设置保存期间禁用其他设置，关闭或重开面板不会取消已经提交的保存。自动激活检测结果采用 5 秒全局悬浮提示，关闭面板后仍可见，同一结果不重复弹出；初始无检测结果不提示。详见 `LOCAL_AGENTS.md`。
10. 每个订阅账号提供“重置卡”图标，有可用数量时显示角标。点击在按钮下方展开局部面板，靠近窗口边缘时自动避让，不遮暗或模糊整页；卡片列表在面板内滚动。可查看官方可用总数、卡片名称／说明、状态、获得时间和有效期。信息未返回不当作零数量，详情不完整时可让官方选择下一张可用卡。关闭按钮、再次点击入口、Escape 或点击面板外可收起面板；使用过程中禁止关闭。
11. 点击“使用这张卡”或“使用下一张可用卡”后，必须点击“确认使用”才会兑换。结果不确定时显示“核对本次使用”，关闭／重开面板或重启后可恢复同一请求；使用结果和额度刷新结果独立显示。

重置卡明细和账号设置面板统一使用细圆角滚动条，轨道始终保留占位，默认及滚动时隐藏，仅悬停轨道或拖动时淡入、移开后淡出，内容宽度不随显隐变化。保留滚轮、键盘、轨道点击和滑块拖动，减少动态效果模式下取消透明度过渡。

## 自动激活额度窗口

OpenAI 账号设置提供「自动激活 Codex 额度窗口」，默认关闭。切换开关直接持久保存并生效，无需二次确认或保存按钮；保存期间显示进度，失败保留原状态并允许重试。开启成功后立即检测，应用运行期间每 5 分钟串行检查，已有额度读取也会唤醒限频检测。只处理启用的 OpenAI 提供商及已授权、身份完整的启用订阅账号，不要求网关运行。

有效的 5h／周窗口剩余 100% 且没有重置目标时，可直接进入发送前复查。官方也可能对未开始窗口返回接近完整周期的滑动目标，页面看起来可能是“5 小时 1 分钟后重置”；这时先做同身份的两次独立观测，目标随查询同步后移才允许激活，不按显示文案或单个未来日期猜测。初次观测显示待确认，通常在下一轮检测中继续判断；已有额度读取也能限频唤醒观测。缺失窗口、异常时间、已知耗尽和已开始的窗口不触发。使用原账号官方目录中的默认模型发送固定短消息，禁用工具、使用已公布的低推理档位，会消耗少量订阅额度；发送前再检查额度和身份，完成后复查官方重置目标。收到模型响应并不等于确认激活；窗口还在滑动或信息不足时只复查，看到有效使用量与未来目标或确认目标固定后才报告已开始计时。一次消息可以激活两种窗口。

迁移 017 保存默认关闭设置和每账号／窗口的身份及周期登记；迁移 034 增加观测时间与已确认固定目标，原有发送登记保留。发送前登记，同周期在并发、重启、超时或结果不确定时均不重发，只复查；观察到新周期后才可再次激活。尚未确认时明确显示待复查，不宣称已激活。关闭保存停止后续自动请求，已经发送的请求无法撤回；退出取消并有界等待。设置不会修改原客户端配置或会话，不自动使用重置卡。见 [ADR-009](../decisions/ADR-009-codex-quota-auto-activation.md)。

检测失败的**原因**按账号记录：状态里的错误码是具体分类（`quota_unavailable`、`models_unavailable`、`prepare_failed`、`request_failed`、`record_failed`、`identity_changed`、`awaiting_quota`、`accounts_unavailable`），日志另有
`Codex quota activation account failed`（稳定码 + 账号 ID，不含凭据与提示词）。面板与悬浮提示按码显示原因，例如账号官方模型目录为空时提示先同步该账号模型，而不是笼统的「检测未完成」。拿不到具体分类时才使用通用文案。

## 行为边界

- 授权等待最多 10 分钟，初始化及单次操作有 30 秒超时。关闭登录窗口或切换页面会保留后台授权，重新打开同一操作可恢复；显式取消、应用退出或超时才停止回调。后台授权完成后账号列表通过事件刷新。
- 应用重启后原授权链接失效，需要重新开始。重试使用新的浏览器页面，旧页面的重新加载无法恢复已经结束的回调服务。
- 一次只允许一个授权会话。正在重新授权的账号不能同时刷新、退出或删除。
- 重新登录需保持原身份。改用其他身份请新增账号；取消不会破坏原授权。
- 隔离登录授权由官方组件托管，没有独立定时续期任务。网关先读取受保护授权，在同一份材料中核对成员邮箱、工作区与有效期，健康热路径不再每次启动官方组件强刷；仅临近过期时调用 account/read(refreshToken=true)，由官方组件保存旋转后的授权，再重新读取核验，不保留脱离官方存储的影子 refresh token 缓存。准备前后检查账号启用、身份版本与 profile；缺少成员证据时明确失败，不按同工作区放行。普通“刷新状态”与额度查询先以 refreshToken=false 读取当前托管身份；状态刷新只在旧账号缺少 account_id 时补全。刷新成功后更新元数据并触发额度重查，额度区域仅重查额度；临时失败不擅自注销，套餐不代表模型权限或剩余额度。
- 已保存账号的凭据准备、额度读取、状态刷新、模型读取、兑换、注销及删除按账号互斥，不因另一账号联网而全局排队；登录提交仍全局排他。真实 KDF 继续受全局内存上限保护，等候 KDF 可以取消。网关自管 auth.json 的续期按账号串行，回写同时校验成员、原授权内容／引用及版本，防止旧结果覆盖重新导入或已更新授权。
- RPC 截止时间和主动取消分别返回稳定的 operation_timeout／operation_cancelled，并保留可检查的 context 原因。普通状态刷新总预算包含排队，分别提示队列繁忙、读取超时和临时不可用；调用前已取消的 RPC 不写入官方组件。原始组件错误与凭据不进入界面。
- 官方授权完成后使用强制刷新读取身份。新增账号的身份读取暂时失败时，保存已成功的系统授权与账号引用，标记状态待确认并显示警告，用户可刷新恢复，不因元数据读取失败注销有效授权。重新登录已有账号仍须确认原身份后才能替换。
- 订阅账号没有密钥预览、密钥复制或 API Key 替换入口；修改名称不改变授权。
- 套餐标签按官方返回的套餐标识配色，支持 Free、Go、Plus、Team、Business、Pro、Pro Lite 等不同背景。未识别的标识保留原文并使用中性配色；不根据套餐大类推断未返回的价格或额度档位。
- 官方账号 ID 通过本机 account/rateLimits/read 返回的 accountId 获取，不读取令牌或使用本地记录 ID 代替。附加读取最多等待 5 秒；暂未返回时保留授权和已有 ID，并明确提示刷新，不将身份信息写入日志。
- 额度通过独立 SubscriptionQuota 查询读取官方公开用量：优先使用同一官方额度接口（`/backend-api/wham/usage`，15 秒上限，`Bearer` + `ChatGPT-Account-Id`，不启动官方组件），把窗口秒数换算成分钟后再按同一规则识别 300／10080；接口返回 401／403、传输失败或响应形状不可用时回退现有 `account/rateLimits/read` 子进程链路，续期仍只由官方组件完成。优先使用 codex 用量桶。缺失持续时间不根据 primary／secondary 位置猜测；官方未返回窗口时不展示假数值。
- 查询读取与接口总操作上下文均最多 30 秒，从排队前开始计时，覆盖官方子进程初始化、授权续期和额度读取。凭据准备与账号操作串行以限制官方子进程数量，排队支持取消和超时；网关及自动激活在完成身份／版本核验并读取短期凭据副本后释放准备锁，再执行网络请求，回调结束即清零副本，不缓存令牌。长响应不再占用额度查询所需的准备锁；已经开始的请求依旧由原请求上下文结束，退出或重新授权后新请求使用最新状态。前端按本地账号、邮箱、工作区及授权状态隔离内存缓存，60 秒后待刷新、暂离界面保留 10 分钟，不后台轮询或自动重试。迁移 036 同时将最近成功的公开额度显示快照保存在当前运行环境的数据库，内存 GC、页面切换和应用重启不会删除；页面先恢复再查询，失败保留原值，官方暂缺的窗口／重置时间也保留上次显示并标记留存。元数据更新时间变化触发同一身份内的后台查询，保留数值／时间／布局；退出登录隐藏但保留，切换成员或工作区不复用其他身份，删除账号级联清理。
- 留存显示不等于实时观测：过期目标仍显示待刷新，绝不推算满额或新重置时间。调度和自动激活只读取经过新查询验证的原始额度，不能使用历史显示快照作为新鲜依据。显示快照写入失败只记录稳定码告警并返回本次已读到的额度，不清空旧快照、不把一次成功读取变成失败。详见 ADR-019。
- 配额页与账号详情共用查询选项、缓存和前端串行队列；排队时离开页面会取消未开始的请求，已开始的查询等待后端结束后释放名额。全局页面能力见 `QUOTA.md`。
- 首次没有快照时使用安静的固定布局占位，不显示查询中的可见文案或推算额度。结果返回后数值／时间淡入、进度条宽度过渡，遵循减少动画偏好；多个组件共享刷新时不取消并重启同一查询。
- 额度读取前核验授权成员邮箱，官方身份字段存在时还验证快照与保存账号一致；HTTP 快路径只使用本地受保护材料，先核对账号 ID 与邮箱再访问网络。额度读取失败不改变账号授权状态；排队超时（quota_busy）、实际查询超时（quota_timeout）与额度不可用分别提示，不把账号操作繁忙误报为网络故障。瞬时失败（网络、超时、5xx、429）在最近一次成功后 10 分钟内继续显示上次结果并标注“已保留上次获取的信息”，确定性失败（未授权、身份变化、凭据不可用）立即显示错误且不保留旧值。保留旧版本的授权刷新失败错误码兼容提示。失败日志仅记录固定阶段、稳定错误码和原因码，不含身份、凭据或原始响应。网络错误不直接认定为 Token 失效；旧失败缺少阶段证据时不能还原唯一原因。额度百分比与计时不代表实际模型调用权限。
- 重置卡数量使用 availableCount，不用详情数组长度推算；credits:null 表示仅数量，空数组表示详情已查询但未返回可用条目，列表可能被官方截断。未知类型／状态、已使用和已过期的指定卡片不可使用。
- 重置只由用户手动确认触发，无自动重试或自动使用。官方返回 reset／alreadyRedeemed／nothingToReset／noCredit 后更新记录并重新读取；超时保留同一幂等键，不能换键当作一次新使用。待核对操作不允许被新请求覆盖。
- 迁移 006 保存重置操作的公开身份归属、卡片 ID、UUID 和有限状态，支持跨重启核对及完成回执恢复，不存凭据或原始响应。详见 [ADR-004](../decisions/ADR-004-reset-credit-idempotency.md)。
- 清理失败会返回错误或警告。临时授权保留清理标记，下次登录前重试；已替换的旧授权保留定位信息，退出、删除或下次成功重新授权时重试。

## 美元额度参考估算

账号详情在额度进度条下用紧凑表格展示 5 小时／一周的预计总额与预计剩余；每个窗口一行，金额两列，无额外标题或状态说明。只有官方显示对应窗口时才展示。
沿用旧版 `tokenDisplay.js` 的公式：**当前窗口保留的本机 Token 基础等值成本 ÷ 官方已用比例**。
已用不足 5%、缺少重置时间、窗口到期、超过两成记录缺用量或任何样本模型价格未知时，不显示虚构金额。
零星「成功但没有 usage」的记录不否决整窗：金额按已确认样本估算（本来就带 `≈`），只会偏低，不会凭空偏高；
未知模型不经回退定价，因此仍按整窗未知处理。

按每笔请求的实际模型分别应用美元基础参考价，不再将所有模型当成固定 GPT 计费；
未知型号、未知价格和人民币报价不擅自回退／换汇。参考价不是实时价格或实际账单，
不含长上下文、加速和工具附加费。缓存读取从普通输入扣除，避免重复计费；
金额仅显示一个带 `≈` 的具体值。升级前缺少缓存明细的历史用量不计缓存折扣，不猜命中率，
也不将未知缓存标记为已知零；旧 RPC 区间字段保留兼容。未知、过期或读取失败时金额显示 `—`，不展示额外提示。

### 账号 Token 用量

估算下方独立展示输入、输出、缓存三列，使用 K／M 等紧凑单位，悬浮可查看完整整数。
输入已包含缓存读取，三列不可相加。统计按当前账号、成员、工作区隔离，仅取本机留存的代理请求，
不代表其他客户端的直接消费或账号全生命周期总量；清理请求历史会减少统计。
没有额度快照也可以读取本机统计，代理请求变化后自动刷新，无需额外调用官方接口。

缓存明细全部缺失时显示 `—`；部分缺失时以 `≥` 展示已知缓存量；
上游明确返回零或没有本机请求时显示 `0`。输入／输出明细未知时不伪造零，
读取错误不显示旧数值或原始错误。不显示“本机留存”、缓存包含关系、缓存明细缺失或不完整用量的说明文字。

## 存储与安全

- 登录弹窗支持复制当前会话的官方链接，在本机其他浏览器资料中完成授权；链接视同一次性授权信息，不展示到错误或日志，不应分享。
- 进度只依据后台真实状态。Codex 官方组件在 Token 交换完成后才发通知，因此等待提示明确包含官方交换；通知后依次显示获取账号信息、保存授权。Google 回调可直接观察到 Token 交换与保存。弹窗进行中每秒读取状态兜底，完成后停止；关闭弹窗不取消授权，重开恢复处理阶段。
- ChatGPT 账号删除不依赖官方 CLI 可用性，直接清理经过校验的隔离路径所对应的旧版 Windows keyring token 与新版加密存储口令，随后移除本地记录和目录，不调用 `account/logout` 或远端撤销接口。本地 keyring 清理失败保留记录与定位信息供重试。只有显式“退出登录”使用已保存账号的官方 Logout 流程；取消及失败的新授权仍按既有规则清理临时会话。

- 本机官方 app-server 使用固定参数、独立 CODEX_HOME 与强制 keyring，不将令牌写入 SQLite 或明文 auth.json。
- CODEX_HOME：操作系统缓存目录中的 `OmniProxy-CodexAuth/<运行环境>/<随机 ID>`。开发与生产隔离，应用数据目录迁移不改变其 keyring 定位。
- SQLite 通过迁移 004 新增 `auth_method`、`auth_email`、`auth_plan`、`auth_state`。旧账号默认为 API Key。
- 迁移 005 新增 `auth_account_id`，仅保存公开身份标识，长度与格式经过校验；与本地 `id`、隔离配置 ID 和凭据引用分离。
- `credential_ref` 指向原有 DPAPI 存储，密文只含隔离配置定位；授权令牌由官方组件管理。删除与失败清理仅操作经过格式和根目录校验的隔离目录。
- 授权 URL 限定到官方 HTTPS 域名，浏览器打开接口只接受进行中的随机会话 ID，不接受任意 URL。
- 不读取或修改用户原有 Codex 配置和登录。日志不记录授权 URL、用户码、账号身份或令牌；前端只显示稳定错误码对应的文案。
- 授权阶段诊断仅记录状态与稳定错误码，通过中央脱敏 logger 输出；用于区分等待、超时、协议、账号读取和保存失败，不记录授权内容。
- 授权子进程过滤启动器继承的来源、登录客户端和签发方覆盖变量，使用 OmniProxy 初始化的客户端身份；用户配置的 HTTPS 代理和自定义 CA 保留。避免从 Codex 桌面启动开发环境时混用桌面应用的授权来源。
- 旧版 `auth.openai.com/oauth/authorize` 浏览器入口采用参考项目已可登录的流程来源 `codex_vscode`，映射仅作用于此端点的 originator。client_id、scope、state、PKCE 与 redirect_uri 保留官方组件原值；app-server 初始化和请求归属仍标识 OmniProxy，设备码及其他授权端点不改变。

协议来源：[官方认证说明](https://learn.chatgpt.com/docs/auth)、[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。具体实现决策见 [ADR-003](../decisions/ADR-003-official-codex-subscription-auth.md)。

## 混合提供商账号与登录诊断

ChatGPT 登录前的待清理授权扫描，只读取 OpenAI／Codex 提供商的订阅引用；Google／Antigravity 等其他提供商即使同为 subscription_login，也使用各自独立的凭据格式和生命周期。扫描不读取、退出或清理其他提供商凭据；无法确认自身提供商或自身引用的情况仍保守报错，避免误清理已有授权。

登录开始前的失败也记录固定的 begin 操作与稳定错误码；前端区分账号信息不可读、组件／目录初始化、官方组件协议及请求失败，不把这些情况一律归因于网络。所有提示和日志都不携带原始错误正文、授权链接、令牌或用户码。详见 TASK-20261019-007。
