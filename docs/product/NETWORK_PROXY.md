# 提供商出站代理（Network Proxy）

## 目的

部分海外提供商的接口在本机网络下不可达。用户已经在运行 v2rayN / Clash / mihomo
这类代理客户端，希望 OmniProxy 只把「选定提供商」的出站请求转发到它的本地监听端口。

OmniProxy 只作为客户端连接**已经启动**的代理端口：不启动、不重启、不更新代理软件，
不读取订阅与节点，不解析 vmess/vless/trojan 链接，也不修改系统代理。

## 用户可见行为

- 提供商页右上角「网络代理」按钮打开设置窗口。窗口是左右两栏（窄窗口自动堆叠），标题与
  「保存／取消」固定，只有中间内容滚动：
  - 左栏「代理服务器」：启用开关、协议（自动识别 / HTTP / SOCKS5）、地址、端口、可选用户名与密码、
    不走代理的地址列表。地址可以是本机端口，也可以是带认证的远端代理；远端代理的出口就是它自己的 IP。
  - 「探测本机代理」：并行检查常见本地端口（10808、10809、7890、7891、7897、1080、2080、1087），
    命中后显示 `auto://127.0.0.1:10808 · SOCKS5` 形式的一键填充；点击只把主机名与端口填进表单，
    协议前缀不会进入「地址」字段。地址只接受主机名或 IP，含协议、端口或路径时就地提示并禁用测试／保存。
  - 「测试」：探测该端点支持哪些协议并给出延迟；失败时区分「代理端口无响应」与
    「端口不是 HTTP/SOCKS 代理」。
  - 右栏「使用代理的提供商」：每个提供商三态——跟随全局 / 直连 / 走代理，另有「全部走代理」与
    「全部直连」；列表自身滚动，可按名称筛选，列表下方显示各态计数。
- 提供商卡片在走代理时显示「代理」徽标；把鼠标停在上面可看到实际协议。

## mixed 端口与协议识别

v2rayN 默认监听形如 `本地:[mixed:10808]`，同一个端口同时接受 HTTP CONNECT 与 SOCKS5。
Go 的 `http.Transport` 必须二选一，所以：

- `scheme=auto` 表示「由探测决定」。探测只做握手，不产生真实出网流量：
  SOCKS5 greeting（`05 01 00`，必要时补用户名密码子协商）与 HTTP `CONNECT` 状态行。
  单次握手预算 4 秒：本机端口毫秒级完成，远端带认证的 SOCKS5 代理握手可能接近 3 秒。
- 两种协议都通（mixed）时使用 SOCKS5：纯 TCP 隧道对 `ws://` 与 `wss://` 都不依赖代理侧
  的 HTTP 解析。
- 显式选了 `http` 或 `socks5` 也要先确认：首次使用（每个配置版本一次）用同样的握手验证该协议，
  成立就照旧使用；不成立而另一种协议成立时自动切换并回写识别结果。这样把远端纯 SOCKS5 端口
  （对 HTTP `CONNECT` 既不回应也不断开）填成 HTTP 时不会让每个请求都挂到调用方超时。
  两种协议都不应答时保留用户配置，由真实请求暴露问题。
- 识别结果写入 `proxy_settings.detected_scheme`；端点（主机、端口、用户名）或协议变化后清除，
  避免历史识别压过新的显式选择。
- 运行期纠偏：连接建立但协议不成立时自动切换另一种协议重试一次（同一端点 60 秒内最多一次），
  成功后回写识别结果。因此用户把 mixed 改成纯 SOCKS 也不需要重新配置。

## 解析顺序

单个请求是否走代理，按以下顺序判定：

1. `no_proxy` 命中或目标是 loopback／`localhost`，且该提供商不是显式「走代理」→ 直连。
2. 提供商 `proxy_mode = direct` → 直连。
3. `proxy_mode = proxy` → 走代理；全局未配置端点时报 `proxy_not_configured`，不静默直连。
4. `proxy_mode = inherit` → 跟随全局「启用代理」。
5. 都不适用 → 进程环境变量 `HTTP(S)_PROXY`（既有行为）→ 直连。

提供商身份优先取请求上下文。知道账号或提供商身份的调用一律显式写入上下文，
不依赖主机名：网关推理、Codex 透明转发（HTTP 与 WebSocket）、连通性探针，以及账号额度／余额／
积分查询、模型目录同步、登录轮询与令牌续期。只有既没有账号也没有提供商身份的调用
（例如应用自身更新、Antigravity 客户端版本清单）才回退到目标主机名匹配，再跟随全局开关。

## 覆盖范围

走同一套策略的出站路径：网关转发（全部提供商适配器）、连通性测试、Codex 透明转发
（HTTP 与 WebSocket）、Codex 额度读取与令牌续期，以及经由适配器实现的余额／额度查询。

账号资源类调用与推理使用同一个提供商作用域，因此「只给这个提供商配置代理」同样覆盖：

- Google 订阅：额度摘要、可选模型、目录、令牌续期与身份／项目核对（含 `oauth2.googleapis.com`、
  `www.googleapis.com`、`cloudcode-pa.googleapis.com`、`daily-cloudcode-pa.googleapis.com`），
  以及登录完成前的授权码交换；
- Codex 订阅：`chatgpt.com` 额度与重置卡、`auth.openai.com` 续期，以及透明转发借令牌时的续期；
- WorkBuddy AI（国际版／国内版）：Credits、目录、令牌续期与登录轮询；
- MiniMax、Kimi、StepFun、HowToFix、DeepSeek 的余额／额度与目录同步；
- DuMate：控制台积分、签到与导入时的身份核对；
- 激活流程发送的最小请求。

这些调用在账号凭据版本复核之后仍使用同一 `ProviderID`，重新登录不会改变代理策略。

应用自身更新与 Agent 安装下载**不走**提供商代理：代理挂掉或限速不应连带更新失败。
Antigravity 客户端版本清单是跨账号共享的后台尽力抓取，失败时回退内置版本，不属于账号资源调用。

## 失败语义

| 情况 | 错误码 | 是否影响账号 |
| --- | --- | --- |
| 代理端口无响应（预连失败，30 秒缓存） | `proxy_unavailable` | 不影响：不换号、不写冷却 |
| 端口通了但两种协议都不成立 | `proxy_protocol_mismatch` | 不影响 |
| 提供商显式走代理但未配置端点 | `proxy_not_configured` | 不影响 |

## 数据与安全

- `proxy_settings` 只保存 scheme／主机／端口／用户名／`no_proxy`／识别结果；
  密码只写 `credential_ref` 指向的 DPAPI 凭据文件，界面只显示是否已保存。
- 日志、错误与 UI 一律使用脱敏端点（`http://127.0.0.1:10809`），不出现用户名密码。

## 不在范围

- 不做 `tun2socks`／系统级代理接管。
- 不支持多个代理出口分组（需要分流时由代理客户端自身配置规则）。
- 不探测非 loopback 网段，也不自动启动代理软件。
