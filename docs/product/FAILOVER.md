# 账号故障切换

## 使用方式

网关「运行概览」提供「账号故障切换」开关，默认开启并持久保存，修改对后续请求生效。最多尝试三个账号，包含首次；不会延长原有的 120 秒请求总时限。

例如同一 DeepSeek 配置中 A 账号限流，网关记录该次拒绝并短期跳过 A，再使用 B。客户端只收到一个最终响应；请求总数仍为一条，详情可以查看两次账号尝试、结果与用量报告情况。

## 切换范围

- 同一个提供商配置 ID、同一认证方式、同一计费方式和地区／集群，且账号启用、模型能力和配置版本仍有效。
- 用户显式固定的账号不切换；系统生成的旧通道兼容别名保留该通道的同池范围。
- 不将订阅额度不足改为按量消费，不按服务商优先级跨服务商重试，不静默换模型。
- 同一 API Key 的重复账号不会在同一次请求中重复发送；相同的已知订阅身份也不会作为独立备用额度。

## 可恢复的拒绝

上游明确返回 401 时可尝试其他账号，适用的 429 按实际请求模型冷却；DeepSeek 402 作为余额不足处理。Google 普通 API／Antigravity 的 429 暂不切换，避免对项目或共享额度轮换账号。其他尚未识别的余额、登录或权限错误仍明确返回，不推断可重试。

冷却优先使用合法 Retry-After 的秒数或 HTTP-date，最大一天；缺失／非法时，429 默认 30 秒，401／DeepSeek 402 默认五分钟。到期后由一次正常业务请求确认恢复，无后台模型探测；其他并发请求可选择同池健康账号。

网关显示暂不可用的账号资源、原因和可恢复时间，账号的用户启用开关保持原值。凭据／配置更新后，下次请求使用新版本；应用重启后重新观察运行健康状态。

## 停止重试的边界

**上游返回 200 后不再自动切换**，即使还没显示首字、协议转换失败、流中断或客户端未收到正文。首字和响应提交不是同一概念，不能据此保证上游没有执行。

参数／模型／上下文错误、403、普通 5xx、执行结果不确定的网络错误、本地并发满、统计失败、取消和总超时均不触发账号切换。所有候选失败／冷却时快速返回；不会在同一请求里等待长冷却。客户端自身重试属于新的客户端请求，内部 request_id 不作为上游幂等保证。

## 统计与数据

- 一次客户端请求只有一条结果和一个 request_id；中间拒绝以尝试明细记录，不扩大请求数或最终失败率。
- 前面的拒绝没有报告 Tokens 时显示「未报告」。只有上游真正报告的用量进入累计，失败／取消后的已知部分仍保留。
- 首版最多一个成功响应，父记录和账号累计归该次响应账号；全部拒绝时保留最后实际拒绝的目标，Token 仍未知。
- 明细保留账号／提供商公开快照、模型、状态、时间、稳定错误码与报告用量，不保存正文、密钥、凭据引用或原始错误。尝试随父明细淘汰，累计不减少；历史请求不补造尝试。

实现取舍见 [ADR-015](../decisions/ADR-015-account-failover.md)。
