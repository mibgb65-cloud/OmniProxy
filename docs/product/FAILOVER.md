# 账号故障切换

## 使用方式

网关「运行概览」提供「账号故障切换」开关，默认开启并持久保存，修改对后续请求生效。最多尝试三个账号，包含首次；不会延长原有的 120 秒请求总时限。

例如同一 DeepSeek 配置中 A 账号限流，网关记录该次拒绝并短期跳过 A，再使用 B。客户端只收到一个最终响应；请求总数仍为一条，详情可以查看两次账号尝试、结果与用量报告情况。

## 切换范围

- 同一个提供商配置 ID、同一认证方式、同一计费方式和地区／集群，且账号启用、模型能力和配置版本仍有效。
- 用户显式固定的账号不切换；系统生成的旧通道兼容别名保留该通道的同池范围。
- 不将订阅额度不足改为按量消费，不按服务商优先级跨服务商重试，不静默换模型。
- 同一 API Key 的重复账号不会在同一次请求中重复发送；相同的已知订阅身份也不会作为独立备用额度。

## 订阅窗口耗尽

### 客户端工作区额度与网关额度的区别

网关只能对已发送到本地代理的请求做账号切换。Codex Desktop 登录工作区显示额度耗尽，
并不等同于网关的全部上游账号耗尽。现有接入对内置 `openai` 保留客户端提供商身份和
官方认证文件；若客户端在发请求前自行拦截，网关无法触发故障切换。

已经明确是 Desktop 发送前拦截时，不需要继续寻找不存在的网关请求；增加重试、
更换网关选号策略或代理额度响应也不能解决该层问题。应核对客户端当前提供商与认证
模式，并在隔离环境验证独立接入及旧聊天兼容性，不篡改客户端的额度判断或伪造剩余额度。

排查时先对照请求记录：是否有该次请求、是否固定账号、故障切换是否开启、备用账号是否
启用且属于同一提供商／认证／计费／地区池，以及备用账号是否支持该模型。一般请求不会
跨服务商自动换模型。请求已开始生成后的错误也不会重放。

独立 Codex 提供商接入分支使用 `requires_openai_auth=false`，可用于与官方登录分离的
客户端配置，但不能将 CLI 的验证结果等同于 Desktop 的额度拦截已解决；迁移提供商身份
需要单独确认对已有会话和客户端体验的影响，不能擅自改写真实配置或认证文件。

保留 `model_provider=openai` 不代表客户端登录策略相同。旧版 OmniProxy 在一键配置时
从账号池选择状态可用的 ChatGPT 账号，刷新授权后写入客户端 `auth.json`，设置
`forced_login_method=chatgpt` 和 `cli_auth_credentials_store=file`；没有合格账号时另有
API 登录回退。当前版遵循 ADR-005，不改官方登录文件或凭据存储，故不会同步替换已耗尽的
客户端登录账号。旧版没有关闭额度检查的显式实现，也没有证实耗尽后自动重载 Desktop；
此差异是接入改进的核对方向，不能直接当作当前版本已修复。任何登录同步都需用户明确
确认和安全备份／恢复，不能因仅对照源码而覆盖真实授权。

用户明确授权试验时，可使用独立的 Windows
[`codex-login-trial`](../../cmd/codex-login-trial/README.md) 工具。它不改变普通一键接入，
先查询官方额度并核验身份，显式应用时保留 openai，将可用池账号写为 ChatGPT/file
登录，原文件通过 DPAPI 加密备份并提供版本保护恢复；不含旧版的 API 登录回退，
不自动改写系统加密登录或重启 Desktop。试验效果必须在实际 Desktop 重启后确认，
不能将 app-server 识别文件登录等同于发送门禁已解除。

### OpenAI 账号轮换方式

“账号 → OpenAI → 账号设置”可选“队列轮换”（默认）或“平衡切换”，选择后自动保存并对下一个请求生效。
队列沿用稳定顺序，额度耗尽或明确拒绝后使用下一个同池账号；平衡在可用账号间平滑分配请求。
候选都有一分钟内、同版本且完整的额度快照时，按 5h／周等适用窗口中较低的剩余百分比加权；任一候选无可信新鲜额度时改为等权轮换，不额外查询或发送探测。

平衡只适用于 OpenAI 订阅同池账号，固定账号及其他提供商不受影响，相同已知订阅身份不会作为多个独立额度来源。已知耗尽或冷却账号不参与选号，全部不可用时返回 429。
关闭“账号故障切换”仅停止单次请求内的备用尝试，不取消跨请求平衡；已经开始生成或结果不确定的请求仍不重放。
轮换分配的是请求，模型及 Token 用量不同，不保证各账号实际额度百分比完全相等。细节见 [ADR-018](../decisions/ADR-018-codex-account-rotation.md)。

已通过官方身份校验读取的订阅额度会作为有界内存快照供网关使用。5h 或一周窗口任一个明确为 0%，且重置时间尚未到达时，自动请求跳过该账号，尝试同池的其他账号；两个窗口都耗尽时等待较晚的重置时间。共享窗口对该账号的不同模型生效。窗口重置、读取到新的可用快照或账号凭据版本变化后重新评估，不改用户启用开关。

缺失窗口不等于额度已恢复；没有可信重置时间的耗尽快照只短期使用。重启后重新观察额度，不持久保存授权或新增后台模型探测。若尚无额度快照，由上游的明确拒绝触发切换。

新登录的同池 OpenAI 订阅账号若尚无当前版本模型目录，可以作为已经发现模型的备用尝试；它不会扩大主路由或对外公布的模型列表。存在当前目录但未包含请求模型时仍排除；实际权限以该账号的官方响应为准。

## 可恢复的拒绝

上游明确返回 401 时可尝试其他账号，适用的 429 按实际请求模型冷却；DeepSeek 402 作为余额不足处理。Google 普通 API／Antigravity 的 429 暂不切换，避免对项目或共享额度轮换账号。其他尚未识别的余额、登录或权限错误仍明确返回，不推断可重试。

冷却优先使用合法 Retry-After 的秒数或 HTTP-date，最大一天；缺失／非法时，429 默认 30 秒，401／DeepSeek 402 默认五分钟。到期后由一次正常业务请求确认恢复，无后台模型探测；其他并发请求可选择同池健康账号。

网关运行卡展示短期拒绝的账号资源、原因和可恢复时间；订阅窗口耗尽和重置时间以额度卡为准。已知额度跳过不伪造上游尝试，账号的用户启用开关保持原值。凭据／配置更新后，下次请求使用新版本；应用重启后重新观察运行健康状态。

## 停止重试的边界

**开始生成后不再自动切换**，即使还没显示首字、协议转换失败、流中断或客户端未收到正文。首字和响应提交不是同一概念，不能据此保证上游没有执行。

固定 Codex 订阅端点的一个严格例外：HTTP 200 可能包装执行前的额度拒绝。只有首个完整 JSON／SSE 错误明确携带 `usage_limit_reached`，且没有响应 ID、生成响应或输出时，才按执行前拒绝处理并切换；尝试明细保留实际 HTTP 200 和 `upstream_quota_exhausted`。已出现 `response.created` 后再报额度错误、残缺事件、普通 200 错误或仅在自然语言中提到额度，都不触发该例外。全部账号耗尽或账号被固定时返回受控 429，不泄露上游错误正文。

参数／模型／上下文错误、403、普通 5xx、执行结果不确定的网络错误、本地并发满、统计失败、取消和总超时均不触发账号切换。所有候选失败／冷却时快速返回；不会在同一请求里等待长冷却。客户端自身重试属于新的客户端请求，内部 request_id 不作为上游幂等保证。

## 统计与数据

- 一次客户端请求只有一条结果和一个 request_id；中间拒绝以尝试明细记录，不扩大请求数或最终失败率。
- 前面的拒绝没有报告 Tokens 时显示「未报告」。只有上游真正报告的用量进入累计，失败／取消后的已知部分仍保留。
- 首版最多一个成功响应，父记录和账号累计归该次响应账号；全部拒绝时保留最后实际拒绝的目标，Token 仍未知。
- 明细保留账号／提供商公开快照、模型、状态、时间、稳定错误码与报告用量，不保存正文、密钥、凭据引用或原始错误。尝试随父明细淘汰，累计不减少；历史请求不补造尝试。

实现取舍见 [ADR-015](../decisions/ADR-015-account-failover.md)。
