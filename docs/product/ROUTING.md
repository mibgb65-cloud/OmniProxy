# 模型路由

路由页自动展示已有模型的默认映射，并管理客户端 `model` 到提供商配置／实际模型的自定义精确规则。当前支持 DeepSeek／Atria／Gemini／MiMo API Key 和 ChatGPT / Codex 订阅适配器。

MiMo 普通 API Key 账号提供五个已核对对话模型的官方预设，也可同步账号实际目录；同步成功后不以预设补回已消失模型，失败保留当前凭据版本的目录。默认映射、显式别名、固定账号与客户端菜单均复用同一选择逻辑，三种原生协议保留思考与工具上下文。详见 [MIMO.md](MIMO.md)。

Atria API Key 账号添加后自动提供 `Atria-Dawn-Preview` 官方预设及默认同名映射，也支持显式别名／固定账号。目录注明来源，不代表账号认证或额度已验证；停用账号或提供商后不在可调用网关／客户端目录中公布。预设模型大小写保持不变，元数据为 256000 上下文与仅文本输入。

「默认模型映射」读取已同步的官方目录及内置 DeepSeek／已配置账号的 Atria 模型，按模型 ID 去重，提供同名初步映射，无需逐条新增规则。读取过程不写入自定义规则；新增／同步模型后自动出现。目录未返回的模型不会被猜测生成。「官方模型目录」支持 ChatGPT／DeepSeek／Gemini，Atria 使用明确标注的官方预设；缓存按凭据引用和工作区身份隔离，更新名称／额度不会使目录失效。路由与实际网关同时检查模型所属账号，其他提供商仍不可选。详见 `LOCAL_AGENTS.md`。

Gemini 取官方兼容 `/v1beta/openai/models` 与分页原生 `/v1beta/models` 的生成模型交集，兼容目录的 `models/` 前缀被规范为裸模型 ID。名称、描述、输入／输出限制均校验后保存，不使用展示名称调用、不猜总上下文、不把输入和输出限制相加。同步失败保留当前 Key 上次成功快照；更换 Key 后旧快照失效。目录可见不保证当前 Key 的推理权限或额度可用。Gemini 路由及别名仅公布 Chat 协议，不写入尚未支持的 Codex／Claude 模型菜单。

每个默认模型可以选择优先服务商，选择后立即保存；空值为自动选择。下拉仅允许当前支持同一模型 ID 且具有可用账号的具体提供商配置。页面显示当前实际目标、可用服务商名称与数量，失效偏好保留并显示回落／不可用状态，可以恢复自动选择。相同模型只有一个可用服务商时，仍可直接使用默认映射。

同名模型有多个服务商时，点击「配置优先级」，使用上移／下移按 1、2、3… 调整顺序并保存。已保存顺序在模型和服务商两个视图中均可查看，预览显示实际使用的优先级。首选下拉将该服务商移到第一位并保留其余顺序；恢复自动选择清除整个顺序。不可用的已保存项保留并标注，可以在配置中移除。每个模型最多配置 100 个服务商，拒绝重复、非法 ID 或不支持同名模型的新目标；同名配置以 ID 区分。

默认映射和模型目录均提供「按模型／按服务商」视图。按模型列出对应服务商，按服务商配置 ID 分组列出支持的模型；同名服务商配置保持独立。默认映射在两个视图下均可保存优先服务商，搜索服务商视图时只保留对应分组及匹配模型，无可用候选的模型单独展示。目录按模型和服务商合并同一模型的账号条目，保留账号来源与能力元数据；已删除服务商以原 ID 标识。目录不再显示账号同步用途说明，列表直接可见。

## 页面结构

顶栏只显示页面标题、刷新和新增规则入口，与选项卡导航一起在内容滚动时保持可见。沿用网关页的图标、选中下划线和键盘操作，分为四个选项卡：

- **默认映射**：默认页面，查看自动映射、搜索模型和选择优先服务商。
- **自定义规则**：搜索、筛选、新增、编辑、启停和删除精确规则。
- **模型目录**：选择账号、同步官方目录并查看已同步模型。
- **匹配预览**：输入客户端模型名，查看当前目标与账号元数据。

通过 `/routing?tab=defaults|rules|catalog|preview` 定位，缺省或非法参数回到默认映射，支持刷新和前进／后退。方向键移动页签焦点，Enter／Space 激活；切换后内容回到顶部。业务面板首次访问才挂载，访问后保留到离开路由页，往返切换保留搜索、筛选、同步账号、进行中的操作及预览输入／结果；隐藏面板不接收键盘焦点。点击顶栏新增规则会切到自定义规则页并打开编辑弹窗。

## 当前能力

- 保存规则到本机 SQLite，支持新增、编辑、启停、删除确认、搜索和状态筛选。
- 模型名区分大小写，1–128 个 ASCII 字符，允许字母、数字及 `- _ . : /`；所有规则（含停用）共享唯一模型名。最多 1000 条规则。
- 目标选择具体提供商配置 ID 和实际 API 模型 ID，不能选择另一个别名作为目标，避免递归和循环映射。
- 账号范围默认使用目标提供商启用账号，按创建时间／ID 选择最早者；也可以固定一个属于该提供商的账号。
- 匹配预览与实际请求使用同一套配置解析和账号选择逻辑。预览仅读取元数据，不读取密钥、不调用模型，不保证认证、额度或实际调用成功。
- 规则保存后无需重启网关，每次请求重新读取。配置读取失败会明确报错，不当作没有规则。
- 模型服务商偏好单独保存在本机 SQLite（迁移 012／015），最多 1000 个模型；迁移 015 将旧首选转为有序列表，保留兼容字段。单模型最多 100 个服务商，序列化最多 14000 字节；精确规则和偏好数量分别限制，保存／读取校验模型名、提供商标识和配置边界，损坏配置明确报错。
- 默认映射、匹配预览、网关请求和客户端目录使用共同的服务商／账号选择逻辑；修改偏好后目录能力随实际选中账号更新，受管客户端目录按既有安全规则刷新。

## 匹配顺序

1. 先查找启用的同名规则，精确匹配且区分大小写。
2. 命中规则时按目标配置和账号范围转发；异常目标明确报错，不静默切换账号或提供商。
3. 未命中时，按已读取的原始模型 ID 直通，按该模型保存的服务商顺序寻找可用账号。高优先级服务商被停用／删除、没有可用账号或账号目录失效时跳过，依次选择下一优先级。
4. 未保存顺序或全部已排序服务商不可用时，在未排序且支持相同模型 ID 的可用服务商中选择最早创建的账号，时间相同按账号 ID 稳定排序；同一优先级服务商内部也沿用此账号顺序。
5. 没有可用候选时返回明确错误。不同模型名不会自动视为等价，不进行跨模型替换或请求失败后的隐式重试。

与原始模型名同名的启用规则会覆盖该模型的直通行为，编辑器明确提示。
停用此规则后，原始模型恢复直通；普通别名停用后不再可调用。

## 网关行为

代理先解析路由再检查实际模型，改写 JSON 顶层 `model`，保留消息、流式模式和其他参数的 JSON 语义。
请求正文不能指定内部提供商或账号目标。转发前重新检查目标启用状态，密钥仍只在原 UseAPIKey 回调内使用。
`GET /v1/models` 返回当前可解析的原始模型和启用别名，并去重；同名启用规则覆盖原模型时，其失效目标也不会被宣传为可用。Codex 目录及客户端配置继续沿用统一目录格式和已确认元数据。

## 目标变化与删除

规则保留目标标识，目标被删除／停用后显示具体异常，可编辑修复或停用规则。
迁移不对目标设置级联删除或限制外键，保持已有账号／提供商删除流程兼容。
删除规则只删除映射，不删除账号、提供商或凭证。
服务商偏好与固定目标不同：偏好失效时允许配置层回落，手工规则／固定账号失效时明确报错。失效偏好不因删除资源而级联清除，便于查看、修复或恢复自动选择。

## 使用示例

创建 `coding-fast → DeepSeek → deepseek-flash`，然后向本地 `/v1/chat/completions` 发送 `model: "coding-fast"`。
模型列表中可以发现 `coding-fast`。消息和 `stream` 参数按原请求转发。
响应保留上游真实模型标识，不伪装模型来源。
