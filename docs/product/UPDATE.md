# 应用安装与更新

## 入口和检查策略

发现新版本后，「设置与关于」按钮右侧显示升级标记；侧栏折叠时保留小图标。点击打开独立浮窗，标题栏与操作区固定，中间滚动展示版本摘要与发布说明：摘要按「当前版本 → 可升级版本」分区，附发布时间、包大小与发布页入口；说明正文按 Markdown 排版（标题、段落、粗体、行内代码、链接、有序／无序及嵌套列表、引用、代码块、分隔线），HTML 标签与 `javascript:` 等非 http(s) 链接只作为纯文本显示，远端图片不加载、只保留替代文字。浮窗和设置里的检查更新共用一份后端状态，关闭窗口不会中断下载。

正式运行环境默认启动 30 秒后检查一次，此后每 6 小时检查，可在设置中关闭。自动下载是独立的显式选择，默认关闭，旧配置缺少字段时也保持关闭；开启后，正式安装运行环境在后台或手动检查发现可安装的新候选时自动下载并做 SHA256 校验，安装与重启仍需用户确认。开发、测试和未安装的便携运行不自动下载，开发和测试环境也不自动联网检查。前端只轮询本地快照：闲置 15 秒，传输／安装期间 500 毫秒；查询快照不访问 GitHub。

正式版／Beta 渠道及 SemVer 规则沿用 UPGRADE。切换渠道会清除旧候选，下载、复验、安装或检查进行中拒绝切换；正式渠道不激活已缓存的 Beta 安装器。

检查更新页按当前版本摘要、更新设置、当前版本更新日志分组。“已是最新版本”仅在手动检查成功后以悬浮提示显示 5 秒，可关闭并在悬停或键盘焦点进入时暂停计时；提示位于窗口非滚动层，不占内容空间，不因本地快照轮询重播。发现新版本和失败仍保留在内容区。版本摘要展示运行版本及其发行渠道；候选渠道选择不改变运行版本徽标。设置依次提供更新渠道、自动检查与自动下载开关，保存失败保留原值并提示错误。切换自动下载设置本身不联网，也不立即下载；关闭不取消已开始的下载，可使用现有取消入口。同一候选已下载、失败或被用户取消后，后续自动检查不重新启动下载，仍可手动重试；新版本候选可重新自动下载。

当前版本日志由构建时收录的 `docs/releases/v*.md` 按运行版本精确匹配，离线可读，不使用待升级候选的说明。没有匹配文档时明确提示，绝不展示其他版本的日志；正文与升级浮窗共用同一套 Markdown 排版（标题、段落、粗体／斜体、行内代码、链接、有序／无序及嵌套列表、引用、代码块、分隔线），卡片页眉已显示运行版本，正文不再重复顶级版本标题；`http(s)` 与以 `/` 开头的站内路径可点击，HTML 标签与 `javascript:` 等其余协议只作纯文本，远端图片不加载、只保留替代文字。界面中英文控件跟随语言设置，发行说明保留原文。

## 下载和安装

客户端只从已校验仓库与标签的资产列表选择唯一配对：

```text
OmniProxy-Setup-<vTag>-windows-amd64.exe
OmniProxy-Setup-<vTag>-windows-amd64.exe.sha256
```

当前只承诺 Windows amd64 全量安装器。缺少配对、大小异常或平台不匹配时只提供发布页入口。开发／便携运行没有匹配的安装登记，不提供静默覆盖入口。

- 前端仅提交预期版本，不接受 URL、文件路径或命令。初始地址必须是对应仓库／版本／文件的 GitHub 发布路径，重定向仅允许 GitHub 的资产域名和 HTTPS，最多五次。
- 校验文件最多 4096 字节，接受单个 SHA256 或带匹配文件名的常规格式；安装器精确核对资产大小，最多 1 GiB，网络任务最多 30 分钟。
- 下载支持共享进度、取消和重试，失败文件清理，缓存按 profile 隔离。状态只在开始及终态落盘；进度在内存更新。
- SHA256 在下载时校验；点击安装后再检查本地文件、重新取得可信发布地址的摘要，防止把本地状态文件当作信任根。独立辅助进程在安装完成前持有禁止写入／删除的文件句柄并再次核对摘要。
- 点击「重启并静默升级」后，先启动原用户的独立辅助进程；系统权限请求取消或启动失败，当前应用保持运行。辅助进程确认安装器已启动后，应用正常退出；安装结束后辅助进程以原启动用户的令牌重新打开目标程序。
- 校验失败不会执行安装器，安装失败会留下可诊断的本地结果。更新状态和结果在当前数据目录的 `updates/`，完整密钥、账号令牌和签名下载 URL 不进入这些记录。

SHA256 验证下载完整性；当前流程未接入代码签名，不把 SHA256 描述为数字签名。

## 更新完成提示

安装结束并以新版本重新打开后，应用自动弹一次「更新完成」浮窗，说明「升级前版本 → 当前版本」，正文列出本版新增内容；不再出现「装完了没有任何反馈」的空档。浮窗沿用升级浮窗的三段式结构：标题栏与操作区固定，中间滚动展示版本过渡与本版说明。正文由构建时收录的 `docs/releases/v<运行版本>.md` 提供，与升级浮窗、设置页日志共用同一套 Markdown 排版与链接白名单，因此不为了这条提示联网；没有匹配文档时只说明可在「设置 → 关于」查看版本信息，绝不借用其他版本的说明。

确认方式有三种，都视为已读：点「知道了」、关闭按钮或 Esc／遮罩关闭。「查看完整更新日志」先回执再打开设置页的关于分区，不在浮窗之上再叠一层弹窗。回执写入 `updates/status.json` 的 `noticeSeen`，同一运行版本只提示一次；写入失败时不假装已读，下次启动会再提示一次。提示只在应用自己下载并安装过的更新上出现：从没有更新记录的启动、下载了但未安装、安装回执为失败的情况都不提示。记录里同时保存安装前版本（`previous`），所以跨多个版本手动覆盖安装时不会凭空编造来源版本。

## 更新目录与残留清理

更新状态、安装结果和安装包缓存都落在当前数据目录的 `updates/`：`status.json`、`install-result.json`、`package-<32 位十六进制>.exe`，以及每次安装尝试由应用复制出的辅助程序副本 `runner-<32 位十六进制>.exe`。

「设置与关于 → 数据存储」把占用拆成数据库、运行日志、本地缓存、更新缓存、登录凭据和其他六类，只显示实际占用非零的分类，并按字节从大到小排列。更新缓存单独成类并附一行说明，用户不必再从「其他」里猜体积来源。

数据存储提供「清理更新残留」，删除辅助程序副本与临时文件，返回释放的空间并刷新占用。已下载的安装包、状态和结果文件保留，避免强制重新下载；清理只由用户显式触发，没有后台自动删除。正在运行的辅助程序对应的副本可能因文件占用而删除失败，此时提示失败，其余文件释放的空间仍然生效。

## 安装路径、进程和卸载

NSIS 支持用户级及机器级构建，优先读取对应卸载登记的 `InstallLocation`；兼容旧版只有 `DisplayIcon` 的情况。覆盖升级沿用旧目录，保留用户已经删除的桌面快捷方式。

交互安装的数据位置优先读取实际使用者的 `app.json`，兼容原安装目录中的旧 `data-dir.txt`；
已有数据库时拒绝切换到新的空目录。保持历史位置可将标记固化为用户配置，不移动数据。
数据位置读写在实际使用者的 Windows 令牌权限下完成，不能使用另一提权管理员的配置或权限；
无法确认身份／位置时明确失败，不静默回落到默认目录。静默更新不改数据位置。

首次安装完成页的「立即启动」和旧版更新器的自动启动入口也使用交互桌面的普通用户令牌，避免把管理员身份带入 WebView2 界面。没有可用的普通用户桌面时提示从开始菜单打开，不回退为管理员界面。

安装器提取受限辅助程序，按规范化的完整程序路径匹配进程，优先请求正常退出，兼容旧版窗口关闭；等待 20 秒后仅对仍匹配该路径的进程执行终止。其他目录中的同名开发版、生产版不受影响。机器级安装依赖 Windows 管理员权限，不能以用户级测试代替权限分支验收。

卸载只移除目标程序、卸载器、安装登记、对应快捷方式和匹配目标路径的自启动项；账号、数据库、日志、旧版数据及安装目录中的未知文件均保留。没有默认递归删除用户数据的行为。
