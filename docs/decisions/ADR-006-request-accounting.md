# ADR 006: 请求明细与累计 Token 分离

Status: Accepted

Date: 2026-10-09

## 背景

用户要求每次代理记录输入／输出用量，与日志和请求关联；删除账号与淘汰 10000 条之外的明细均不能删除累计。Team 的多个成员共享 account_id，必须结合邮箱识别。

## 决策

- Core 只依赖 RequestObserver 和公开快照，应用层 activity 实现 SQLite 持久化。
- Begin 先保存随机请求 ID；在原上游读流采集 usage，更新请求快照和累计／每日桶使用同一事务。服务锁与事务保护并发，累计快照按差值增加，避免重复事件。
- 明细与汇总没有账号／提供商删除外键；汇总永久保留，不依赖有上限的明细回算。
- 订阅成员维度是规范化邮箱和工作区 ID 的组合哈希；只保存身份快照，不存令牌／凭据引用或请求正文。
- 只有上游报告的整数进入统计；未知、部分、完整用量独立于请求结果。拒绝超界／负数／小数，并保护 int64 累计溢出。
- Token 数经绑定使用字符串，前端 BigInt 精确展示；没有新增依赖。
- 请求和日志双向通过 request_id 关联；日志内存上限 5000，请求默认 10000 可配置。正在处理的请求不能被淘汰。

## 后果

磁盘故障阻断或中断推理并报告，不能伪装成正常计数。上游未报告的 Token 或历史已缺失的数据无法补算。每日汇总按应用所在本地日期保存；明细时间统一 UTC，界面显示本地时间。
