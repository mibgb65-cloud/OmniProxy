# ADR 028: 可选记录请求正文并导出 XLSX

## Status

Accepted

## Date

2026-11-19

## Context

用户需要回看每次请求的内容与本次实际使用的模型，并把请求记录导出为 XLSX。模型、输入模型、档位、账号、Token 等元数据已保存在 `request_records`，但 `ADR-006` 与 `docs/product/ACTIVITY.md`、`PRIVACY.md` 明确承诺请求明细不保存提示词与正文。

请求正文可能包含系统提示词、代码、密钥与内联图片，体积可达数十 MiB。默认采集会改变既有隐私边界，也会让请求列表与统计查询承担大字段成本。

## Decision

- 数据库迁移 053 在 `request_retention` 增加 `record_content`，默认 `0`；只有用户显式开启后才采集。
- 只采集**客户端请求正文**，不采集上游响应正文。采集点是协议入口规整后、路由改写前的字节；Codex 透明 HTTP 与透明 WebSocket 按实际发送的正文／帧保存；Responses WebSocket 按每一轮 `response.create` 保存。
- 正文独立保存在 `request_contents`（与请求 ID 一对一）。请求列表、用量与仪表盘查询不读取正文；请求详情按需读取。
- 单条最多保存 256 KiB，超出按 UTF-8 边界截断并标记，同时保留原始字节数；长度不少于 1000 个字符的 Base64 内联数据折叠为占位文本；压缩或非 UTF-8 的透明转发正文不保存，避免引入解压风险或写入二进制乱码。
- 正文随父请求明细被保留上限淘汰；关闭开关只停止新增记录，已有正文保留到淘汰或用户手动清除。
- 采集失败不阻断请求：设置读取失败按不记录处理；写入失败只写稳定错误码日志与结束日志字段（`request_content_failed`）。
- 不保存原始头部、User-Agent、接入 Key 或凭据；正文不进入运行日志。
- 请求页导出 XLSX 使用原生保存对话框，按当前搜索与结果筛选导出最多 100000 行；正文单元格按 Excel 的 32767 字符上限截断，并在「正文截断」列标记。
- XLSX 由标准库写最小 OOXML（单工作表），不引入第三方表格依赖。

## Alternatives Considered

- **始终记录正文**：实现最简单，但所有用户对话都会落盘，隐私影响最大，否决。
- **只记录请求摘要（条数／字符数／角色）**：无法回看具体内容，也无法满足导出需求，否决。
- **引入 excelize**：格式能力更完整，但为单表导出引入较大依赖与二进制体积，否决；自实现写入器并用 openpyxl 实际打开验证。
- **正文与请求记录同表**：实现更简单，但会让所有列表查询与明细扫描携带大字段，否决。

## Reasoning

正文是用户本机数据且需求明确，开关默认关闭把是否保存的决定权交给用户。分表与按需读取避免大字段拖慢现有统计路径；有界、折叠、随明细淘汰让存储增长可控。采集失败不影响推理，与「记账失败阻断请求」的既有取舍区分：正文是可选诊断数据，不是计费依据。

## Consequences

- 隐私承诺调整为：默认不保存正文；开启后仅在本机数据库保存客户端请求正文，用户需自行评估其中的敏感信息。
- 开启后数据库会增长；导出会把正文写入用户通过系统对话框选择的 XLSX 文件。
- 响应正文、全文搜索、正文加密或云同步不在本次范围；若后续需要，应另立 ADR。
