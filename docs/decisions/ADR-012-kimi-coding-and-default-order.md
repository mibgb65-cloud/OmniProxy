# ADR-012: Kimi Code 订阅 Key、默认顺序与统一模型目录

## Status

Accepted — 2026-10-16

## Context

用户要求 Kimi 同样去重、设置默认顺序，并明确确认包含 Kimi Code 订阅 Key。普通 API 与订阅服务的域名、Messages 路径、模型 ID 和权限并不完全相同，不能只改标签或全局地址。

## Decision

- 迁移 028 为既有账号增加默认 payg 的计费字段，保存独立的首选计费／地区；缺失／损坏设置明确失败，不从 Key 或会员模型名猜权限。计费变更与地区变更共用配置版本、目录失效及在途身份检查。
- 原生三协议通过固定地区／计费端点调用；K3、同款高速版使用统一逻辑 ID，并精确映射订阅原生 ID。订阅独有 K2.8 Preview 和 K3-256k 保留独立名称。公开目录不发布自动通道副本，旧地区／显式通道／Claude ID 及原生订阅 ID 保持兼容。
- 选择顺序为固定规则／账号、模型服务商顺序、计费方式、地区、创建时间／ID。默认订阅优先／国内优先，无合格候选才使用下一通道，不因失败重试或改用按量消费。
- Kimi Code K3 的会员档位未验证时只公布 256K，不把标称 1M 当作账号权益。原生文本／工具／SSE 保留；不宣称未实现的多模态或 OAuth 登录，不允许关闭思考引起静默换模型。
- 客户端真实 User-Agent 有界保留，不伪装工具、不透传认证头；只在订阅上游使用，缺失时诚实使用 OmniProxy。订阅模型发现和额度 API 未确认时不探测，展示预设／未知额度及固定控制台入口，不借普通余额替代订阅。

## Alternatives Considered

只按地区去重无法覆盖用户确认的订阅需求；把所有 Code ID 直接改成普通 ID 会混淆不同模型；完整 OAuth 与官方 CLI 管理属于另一认证生命周期，没有当前需求。选择官方专用 Key 接入和有限、已确认的型号映射。

## Consequences

用户可保存计费及地区顺序，同款模型只选一次，已有普通账号保持身份。真实套餐权限及真实付费请求仍待账号验证；外部客户端可能需要重载目录。
