# ADR 030: 用量统计按模型家族合并推理档位变体

## Status

Accepted

## Date

2026-11-20

## Context

上游用独立模型 ID 表达推理档位。Google 订阅（Antigravity）发布的 `gemini-4-neon-high`、
`gemini-4-neon-low`、`gemini-4-neon-medium`、`gemini-4-neon-xhigh` 是同一个模型的四种思考程度；
`gemini-4-hydrogen-…`、`gemini-4-argon-…`、`gemini-3.8-flash-…` 同理。目录层已按 ADR-022
把这些 ID 识别为同一家族的档位变体，网关也会在请求时解析到具体变体。

统计层却以「实际模型 ID」为分组键：`usage_provider_models(provider_id, model)`、
`usage_buckets.model`、仪表盘的 `usage_buckets` 汇总都按变体 ID 分组，于是同一个模型在
用量页被拆成多行（实测 `gemini-4-neon-high` 612 请求／`-xhigh` 672 请求各一行），
模型占比、模型每日趋势、仪表盘模型占比也把变体当成不同模型，前六名因此被同一家族的多个变体挤占。

## Decision

- 模型维度统计按**模型家族**归并：档位变体与基础模型合并为一行，请求数与输入／输出 Token 相加。
  适用位置：用量页「按提供商与模型」、用量页模型占比、用量页模型每日用量、仪表盘模型 Token 占比。
- 归并只接受证据，不按名字猜测：
  - 同一基础名出现两个及以上已确认档位后缀（上游确实按档位发布型号）；或
  - 基础名本身也是一个已知模型（档位变体有明确的基础模型）。
  - 只有一个档位后缀且没有基础模型的型号保持原样。
- 档位后缀词汇沿用目录既有口径（`minimal`／`low`／`medium`／`high`／`xhigh`／`ultra`，
  见 `internal/core/modelcatalog/effort_variants.go`）；`-thinking`、`-tiered`、`-lite`、`-free`
  等非档位后缀不合并，`…-tiered-high` 与 `…-tiered-xhigh` 归并为各自的 `…-tiered` 家族。
- 证据来源是「已记录的模型」与「已同步目录的模型」的并集：历史型号即使已从目录消失仍参与判断，
  目录里已发布但尚未使用的档位变体也能让家族成立。
- 归并在读取时完成，**不新增迁移、不修改历史数据、不改写入路径**。
- 「按提供商与模型」的合并行返回被合并的变体 ID，前端在悬浮提示里列出；
  合并行本身显示基础模型名。
- 请求明细、记录页、日志与导出保留每次请求实际使用的变体 ID——那是单次请求的事实，不参与归并。

## Alternatives Considered

- **写入时保存 `model_family` 列**：查询最简单，但需要迁移与回填，且回填规则与读取时完全一致；
  历史数据仍要按同一证据规则推断。收益不足以抵消迁移与双写风险，否决。
- **按名字后缀无条件合并**：会把名字恰好以 `-high` 结尾的独立型号（以及 `qwen3-max` 这类
  档位词根不同的型号）错并，否决。
- **只在「按提供商与模型」表里合并**：模型占比、每日趋势与仪表盘仍按变体拆分，同一页面两套口径，
  且前六名会被同一家族的变体占满，等于没解决根本问题，否决。
- **前端合并**：前六名与「其他」由服务端挑选，前端归并会把同一家族的变体仍挤占其它模型的名额，
  事实上的分组发生在服务端，否决。
- **保留每档位明细并提供展开**：统计页的诉求是「这个模型用了多少」，档位明细属于诊断信息，
  需要时仍可在请求明细里看到实际型号，本版不引入展开树。

## Reasoning

档位是同一个模型的推理强度，不是不同的模型；把用量按档位拆分会让用户无法回答「这个模型一共用了多少」。
归并点在读取时，既保持历史数据不动，也让所有模型维度共用同一口径；证据规则沿用目录层已经验证过的
档位判定，避免按名字猜测导致误合并。

## Consequences

- 用量页与仪表盘的模型行数变少、数值变大；同一模型的请求数与 Token 是各档位之和。
- 合并行显示基础模型名，该名字可能是目录里存在但从未单独计费的家族名（例如 `gemini-4-neon`）；
  具体型号仍可通过悬浮提示与请求明细查看。
- 前六名与「其他」按归并后的家族计算，不同版本的截图对比时行数可能变化。
- 家族判定依赖证据集合；若某个变体家族只有一个档位被使用且基础模型从未出现，该行保持原样，
  待目录同步或第二个档位出现后自动归并（读取时计算，无需数据修复）。
