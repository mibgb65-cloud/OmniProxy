# ADR-017: 安装器与应用自身更新

## Status

Accepted

## Context

v2 已有版本发现，用户要求补齐安装、下载校验、静默重启、发布流程及侧栏标记。旧版按进程名关闭会误伤另一安装，直接从提权安装器重启也会改变应用的启动令牌。

## Decision

`infrastructure/update` 管理发布资产及受限网络传输；`application/updater` 管理共享状态、取消、缓存、预期版本及安装复验；Wails 仅适配调用、自动检查和正常退出。前端共享 TanStack Query 快照，设置与浮窗不各自创建下载任务。

继续使用全量 NSIS 安装包及独立 SHA256，不增加差分工具或更新框架依赖。已发现的版本和资产在后端冻结，前端不传执行地址。安装前重新向可信发布位置取摘要，不信任可修改的缓存状态；启动安装辅助进程时再次锁定并校验文件。

同一 Go 程序提供受限辅助模式，必须在 profile、数据库及桌面初始化前处理。安装器按完整可执行路径处理目标实例；正常退出事件依赖当前用户默认权限。独立更新辅助进程保留原用户令牌，等待安装结果并重启，不让提权 NSIS 进程直接承担新版应用的正常启动。旧版安装器调用保留静默更新后的启动兼容。

首次安装完成页和旧版兼容启动函数获取交互 shell 的普通用户令牌，通过 [CreateProcessWithTokenW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createprocesswithtokenw) 创建界面进程，并构建对应用户的环境块；不依赖外部脚本或附加 NSIS 插件。没有普通用户桌面时提示手动打开，不继承安装器管理员身份作为后备。

卸载不递归删除数据和未知文件。Release 作业先完成质量门和打包，在 draft 状态上传并核对资产，最后发布；不替换公开的同标签发布。

## 补充：显式自动下载选择（2026-10-19）

用户要求在更新设置中增加自动下载开关。沿用既有更新服务与安全传输链，profile 配置新增默认关闭的布尔字段；检查后重新读取当前选择，只有正式安装运行环境且已有合法新候选时才启动自动下载。开始动作与候选／下载状态检查共用服务锁，避免并发重复启动；同版本已经缓存、下载失败或被取消后不自动重试。设置动作不联网，关闭不取消已开始任务，下载、校验、取消与进度均复用既有实现；安装和重启仍由用户确认。没有数据库迁移、新依赖或公开 API 行为替换，偏好 DTO 只追加字段和设置方法。

## Alternatives Considered

- 照搬旧版按名称批量停止：会影响其他目录的同名开发版或生产版。
- 在当前应用进程等待安装：自身占用二进制，无法安全替换并退出。
- 从管理员安装器直接重启：不能保持原用户令牌。
- 依赖缓存中的 SHA256：缓存状态不应成为执行程序的信任根。
- 差分更新或新增大型更新框架：当前没有对应需求。

## Consequences

无需新增业务依赖或数据库迁移；安装器嵌入辅助模式使卸载器及安装包增大。机器级验收依赖管理员确认，必须单独记录。ADR-016 的只读迁移决策继续有效，其中手动更新限制由本 ADR 和 UPDATE 替代。
