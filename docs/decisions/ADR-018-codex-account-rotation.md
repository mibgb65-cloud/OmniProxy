# ADR 018: OpenAI 同池账号的队列和平衡轮换

Status: Accepted

Date: 2026-10-20

## 背景

用户要求除额度耗尽后切换外，也能均衡消耗多个 OpenAI 订阅账号的额度。
已有 ADR-015 定义同池候选、固定账号、执行前拒绝及不可重放边界，不能为平衡选号重新实现请求重试。

## 决策

- 迁移 035 向 `codex_settings` 增加受 CHECK 约束的 `account_rotation_mode`，只允许 queue、balanced。默认 queue 保留升级前行为，其他两个设置保持不变；Wails 薄接口保存后，下一个请求读取新值。
- gateway 在固定提供商、认证、计费和地区的既有候选计划内重排首次选号，只适用于 OpenAI 订阅。固定账号、其他提供商、实际发送前的状态／版本核验和最多三个账号尝试保持不变。
- balanced 使用平滑加权轮询。所有健康候选均有同版本、完整且一分钟内的可信额度观察时，权重是可用窗口的最小剩余百分比；任何一个缺失或过期时，整个可用候选集采用等权轮询。不在请求热路径启动官方组件、读取 Token 或额外发送模型探测。
- 已知耗尽和短期冷却账号不参与平衡；全部不可用时返回现有 429 冷却错误。账号故障切换关闭仍限制一个请求只尝试一个账号，但不关闭跨请求的平衡选号。
- 已知的相同工作区／成员身份只计为一个额度来源；状态只保存有界的账号公开 ID／配置版本和分数，最多 4096 条，重启后重新均衡。分配在互斥锁内完成，不持锁执行网络请求。
- 平衡分配的是请求，不推算每次请求对应的额度点数；模型、上下文和 Token 消耗不同，不能承诺最终百分比完全相等。不为追求平衡重放已开始生成或结果不确定的请求。
- 只读路由预览展示基础候选，不消耗轮询位置；HTTP／SSE 和每次 WebSocket response.create 在真实转发时采用同一策略。

## 方案取舍

- 仅轮询：简单但忽略已经观察到的剩余额度差异，作为未知额度时的降级。
- 只选最高剩余：可能集中并发请求，快照更新前持续使用同一账号。
- 每次实时查询：增加官方子进程、网络延迟与认证失败，不采用。
- Token 预算调度：没有可靠的跨套餐／模型额度换算，当前不引入猜测模型或持久预算账本。

## 后果

新增一个非敏感持久字段，无新依赖、凭据格式或 Core API 变更。既有 queue 行为不变；
balanced 的结果由当前可用候选及观测决定，不构成每个账号实际模型权限或精确消耗的保证。

## River 扩展（2026-10-20）

TASK-20261020-015 复用现有首次选号和同池故障边界，将队列／均衡选择扩展到 River API Key，
使用独立 `river_settings` 持久记录，默认 queue；没有可靠的官方额度权重，因此 balanced 采用等权轮询。
冷却和配置版本复核共用既有机制；连续网络／5xx 失败只冷却后续请求，不改变不确定结果不得重放的决策。
