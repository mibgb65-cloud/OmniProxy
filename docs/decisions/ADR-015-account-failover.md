# ADR 015: 同通道账号故障切换与尝试明细

Status: Accepted

Date: 2026-10-18

## 背景

服务商优先级只在发送前选一次账号。用户要求实施请求失败后的自动切换，并确认首版仅限同一服务商和计费通道。已有统计在首次绑定后禁止改变 subject，不能用覆盖目标或重复创建请求的方式重试。

## 决策

- 应用层 gateway 使用 routing 的共用 evaluate 生成同池候选，保留用户固定账号与系统兼容别名的区别；冻结提供商配置 ID、认证、计费方式及地区／集群。每次尝试重新检查状态和版本，受控凭据回调完全结束后才选下一账号。
- 默认开启、最多三次账号尝试，共用原 120 秒期限。只处理明确的上游 401、适用的 429 以及 DeepSeek 402；普通 Google／Antigravity 的 429 不轮换，避免将项目或共享额度解释为独立 Key。403、5xx、传输执行不确定及本地错误不重放。
- 上游 200 后绝不切换，包含转换提前读取、未出首字、JSON 验证失败及流中断；HTTP／SSE／每次 WebSocket response.create 共用应用策略。
- 429 默认按实际模型冷却 30 秒，401／已识别余额拒绝默认五分钟；有效 Retry-After 秒数或 HTTP-date 优先，最大一天。运行状态有界且只存在内存，不修改用户启用状态；到期只允许一次恢复尝试，旧并发成功不能清除新失败。
- API Key 的单请求内存摘要用于排除重复凭据，不保存或输出摘要；订阅计划排除重复的已知身份。不会主动调用模型探测健康状态。
- 迁移 033 追加尝试表和开关；父请求仅在最终消费／上游报告 usage 时绑定账号，保留原 subject 不变约束。前面的明确拒绝没有已报告用量，以 Unknown 保存；不会构造为真实零。首版最多一个 200 尝试，已知用量仍由该账号的原累计算法记录。
- 一个客户端请求只增加一次请求数和最终结果；尝试数另计，账号请求数归最终目标。请求详情返回可选尝试字段，历史无尝试记录。子明细随父明细淘汰，累计独立保留；启动恢复覆盖未完成尝试。
- UI 在网关运行概览提供开关／资源状态，请求详情展示完整尝试过程；持久化失败显示固定错误，不暴露上游正文、凭据或诊断原文。

本决策局部扩展 ADR-010／011／012／013 原先“不做失败重试”的范围，仅允许同池明确拒绝后切换；其跨服务商／计费／地区限制保持。ADR-006／014 的累计与实际下游首字定义保持。

## 后果

多个账号可以在明确拒绝时恢复一次请求；所有候选失败或冷却时快速返回，不长时间等待。成功后断流、未识别的登录／网络失败仍交给客户端处理。不会假定多个 Key 具有独立额度，也不承诺上游跨账号 exactly-once 或所有提供商的错误都能自动恢复。
