# ADR-020: 受系统保护的 Codex 授权解密缓存

## Status

Accepted

## Context

官方 Windows Codex 新版将授权保存在隔离 CODEX_HOME 下的 `secrets/codex_auth.age`，passphrase 由官方系统凭据库管理。work factor 20 的 scrypt 单次必需约 1 GiB 工作区。原流程每次中转准备令牌时重复解密，Go 堆可能先后保留两个 GiB 区域；完全虚构密文已复现约 1,044／2,070 MiB 工作集，分配栈指向 `scrypt.Key`。

本决策补充 ADR-003 的进程内授权读取路径，不改变官方登录、刷新、密文格式或持久化来源。

## Decision

- 在基础设施层增加进程内缓存，最多 16 条、固定 5 分钟有效期，不因命中续期。
- 每次仍先读取官方系统凭据和有界的完整密文。缓存按隔离文件路径区分，同时比较密文和当前 passphrase 的 SHA256 摘要；不只依赖文件大小／mtime。
- 缓存仅保留既有 Windows 用户范围 DPAPI 保护的授权快照，不把明文或新增授权副本写入磁盘、SQLite、日志或 UI。缓存读取返回独立、由调用方负责清零的明文副本。
- 密文／passphrase 变化、文件删除、注销、固定期限或容量淘汰使旧缓存失效，淘汰时清零密文。期限在后续读取时惰性清理，过期内容不能命中。
- 缓存损坏或 Windows 保护失败返回稳定错误，不降级为明文缓存。没有系统保护提供者的非 Windows 读取测试沿用原来的无缓存行为。
- 不同入口的真实 KDF 串行，避免多个 GiB 工作区叠加。仅在实际尝试大工作因子（18–20）解密后执行 `debug.FreeOSMemory`，及时归还临时工作区；不添加周期性强制 GC，不调低安全参数。
- 每次请求仍走官方刷新、账号启用／授权版本／身份核对；缓存不作为授权来源，不绕过这些检查，也不让网络流持有缓存锁。

## Alternatives Considered

- 降低 work factor：无法解开现有官方密文，且改变官方安全边界，拒绝。
- 只定时 GC／清工作集：仍逐请求执行昂贵 KDF，无法消除重复计算，拒绝。
- 缓存明文 token 或直接写入普通文件：扩大明文凭据暴露面，拒绝。
- 改官方组件或另建解密子进程：维护／通信成本更高，且不消除 KDF 本身的瞬时内存需求，当前不采用。

## Consequences

- 文件／凭据未变化且缓存有效时，中转读取不再重复 scrypt，只有文件核对、DPAPI 解封和小对象复制。
- 冷读取、官方授权更新、到期或淘汰仍可能短暂需要约 1 GiB；本改动不承诺消除此算法必需峰值，也不约束官方外部进程的内部实现。
- 首次冷读取完成后不应长期保留 KDF 工作区。真实工作因子专项使用假数据单独运行，默认单测使用低成本夹具，避免给常规 CI 增加 GiB 预算。
- 无新增依赖、数据库迁移、公开接口或常开诊断入口。DPAPI 的持久化定位信息与原凭据存储策略不变。
