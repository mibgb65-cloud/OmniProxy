# ADR 019: 额度显示快照持久化与实时观察隔离

Status: Accepted

Date: 2026-10-20

## 背景

前端额度缓存最多留在内存十分钟，进程结束即丢失。用户要求获取过一次的额度和重置时间在页面切换、重启后持续保留，后续成功查询正常更新。
单纯扩大 Query GC 时间不能跨进程；浏览器 localStorage 则会引入与本地账号数据库不同的生命周期及运行环境隔离。

## 决策

- 迁移 036 在每个 profile 自有 SQLite 中保存每账号一条公开额度快照，随账号删除级联清理，无历史无限增长。
- 只保存套餐、百分比、绝对重置时间、获取时间和显示留存标记；不保存 Token、密钥、明文身份、重置卡或原始上游响应。
- 使用提供商／邮箱／工作区摘要隔离身份；工作区字段暂缺或随后补全时，仅允许相同成员和相同隔离授权配置恢复。相同已确认身份重新授权仍可留存，换成员或工作区不得复用。
- 成功查询经现有官方身份校验后事务保存；保存失败返回稳定错误，不清空旧快照。较早响应不能覆盖较新结果，账号配置变化后旧查询不能写回。
- 显示合并保留暂缺窗口和暂缺重置时间；已过目标保留原值并显示待刷新，不填 100%，不推算新目标。完整的新数据正常替换旧值。
- `ReadQuota` 继续返回实时结果，内存额度观察只接收该实时数据。`ReadDisplayQuota` 才合并显示历史，`CachedQuota` 只读本地存储、不启动官方组件。留存数据不触发自动激活或成为平衡调度的新鲜权重。
- 账号与配额页先恢复本地快照，再进入已有官方查询队列；首次完全没有历史才显示占位。刷新失败保留已有显示，成功后原位更新。首页保留既有被动订阅共享缓存、不在挂载时主动批量调用官方接口的行为。
- 内存仍按 60 秒 stale／10 分钟 GC 管理，但 GC 和进程退出均不删除数据库快照。退出登录隐藏但保留，账号删除级联清理。

## 后果

无新依赖、凭据格式或 Core API 变化，新增只读本地快照绑定和可选 `fromCache` 标记。
原有“缺失窗口即未知”的实时业务语义不变；配额概况将留存显示标为待刷新，不把历史值计作当前已确认额度。

## Google 扩展（2026-10-20）

TASK-20261020-015 通过迁移 038 将同样的显示恢复模式扩展到 Google／Antigravity：
独立白名单分组 DTO、最大 128 KiB、每账号一条；公开身份摘要和当前授权版本联合校验。
普通令牌刷新与快照版本重绑定在账号事务内完成，重新授权不复用旧版本。
本地读取不争用可能联网的刷新锁，查询时联查当前账号身份／授权版本；保存失败明确返回错误。
百分比和绝对重置时间仅用于恢复显示，保留值标为待刷新，不进入实时调度／权限判定。
