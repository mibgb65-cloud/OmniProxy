# ADR-009: Codex 额度自动激活的授权与持久去重

Status: Accepted — 2026-10-13

## 背景

用户要求在 OpenAI 账号设置中开启自动激活：额度未开始计时时，以原账号发送最小消息并复查。网络失败、额度发布延迟和重启均可能发生在上游已经处理请求之后，不能依靠页面 loading 或内存标记避免重复消耗。

## 决策

- 默认关闭，用户切换开关直接持久保存，成功开启才授权后台检测，无需二次确认；保存后立即检查，运行时每 5 分钟串行检查，额度读取信号合并并限频。保存失败保留旧授权。
- 只检查启用的 OpenAI 提供商与已授权、身份完整的启用订阅账号。沿用页面判定：完整窗口、剩余 100% 且无重置目标。缺失、异常时间和已知耗尽不触发。
- 使用原账号的官方目录和隔离令牌回调，固定短提示词、不启用工具、采用已公布的低推理档位；不经过路由，不使用其他账号，不改写客户端或原会话。
- 一条消息可以启动两种窗口。发送前在事务中登记所有未开始窗口的当前周期；账号公开身份经哈希隔离，记录不含凭据或消息。
- 初次没有官方重置目标时使用 initial 周期；之后以曾观察到的官方重置时间区分新周期。已有未来目标又暂时缺失时不重发。
- 同周期超时、失败、退出或复查不确定均不自动重新发送，只继续读取额度。只有实际返回未来重置时间才报告已确认；这不是官方独立的额度激活 API，不能承诺一次调用必然开始计时。
- 已确定失败发生在发送前（例如模型目录／凭据准备失败或尚未发送即取消）时，只释放本次身份／周期的登记，允许后续正常检查；已经进入 HTTP 发送的失败仍保留登记，不能重复发送。
- 关闭取消当前批次与后续请求；退出先取消后台，再停止网关释放订阅操作锁，最后有界等待。已经到达上游的请求无法撤回。
- 独立更新信号使额度页面读共享缓存的新快照；忽略 FetchedAt 的变化，避免后台检查与前端刷新相互触发循环。

## 取舍

采用保守的至多一次发送：登记后、实际发送前退出可能使该周期不再自动发送；结果不确定时也不重试。这比自动重复消耗更符合用户“不会重复发送”的要求。用户仍可正常手动使用该账号；后续官方窗口变化会被观察到。

这是额度激活专用后台行为，默认关闭时原配额页只读查询策略保持不变。不自动兑换重置卡，不加入常规模型请求重试或调度。

Related Task: TASK-20261013-009

2026-10-13，TASK-20261013-011 根据用户后续要求移除独立保存按钮，改为切换开关直接保存生效；后台请求、周期登记及未知结果去重决策继续沿用。

## 2026-10-19：滑动占位目标的补充判定（TASK-20261019-001）

真实只读采样确认：未开始的五小时窗口也会返回 `now + window duration` 的未来目标，
两次查询的目标随查询时间同步后移。因此未来日期不是已开始的充分证据，不能仅按“5h1m”
文案、100% 或单次未来时间决定发送／确认。

在同一账号身份下，保留原本“明确无目标”的触发条件；另对剩余 100% 且接近完整周期的目标，
要求两次相隔至少 30 秒、不超过 15 分钟的观测，目标增量与观测时间增量一致才认定滑动。
允许 90 秒的周期边界取整／时钟容差及 2 秒的增量误差；固定目标、无效／过期观测、耗尽、
时钟回拨或过长观测间隔都不能被当成新的发送许可。

迁移 034 只新增 `observed_at`、`confirmed_reset`，不删除或改写既有发送登记。
原始目标与已证实的固定目标分别保存；滑动占位不能覆盖已确认周期。旧记录缺少已确认周期时，
只要有不确定发送记录就继续阻止重发，直至真实活动给出新周期证据。已确认目标不会因延迟快照倒退。

发送器接收后台观测计划并再次核对原账号额度；为避免秒级快照导致永不前进，必要时有界等待约
2 秒再读取，取消立即停止。只有仍满足条件且属于本次已持久登记的窗口，才发送同一条最小消息；其他未登记窗口不能成为临时发送许可。HTTP 完成不等于窗口完成激活：
后续快照仍滑动或未知时保持待确认，看到有效使用量及未来目标，或经独立观测确认目标固定后，
才报告已确认。确认发送后的未知结果绝不自动重发；明确未发出的准备失败才允许释放登记。

后台额外记录统一脱敏的检查／发送／确认／待复查计数，不记录账号邮箱、令牌、提示词或正文。
本次仅用指定账号进行只读对照，真实最小消息激活仍需部署后的授权后台或另行明确验收。


## 2026-10-25：后台常驻与结果自动刷新（TASK-20261025-012）

用户反馈「必须打开软件、点进设置才会自动激活」。复核确认三处实现与预期的差距：默认关闭窗口即退出
应用，后台循环随进程结束；滑动候选的第二次观测要等下一个完整周期；状态查询与提示只在设置面板挂载时
存在。本次保持发送判定与至多一次语义不变，只调整运行方式：

- 开启自动激活时把窗口关闭行为落到托盘（`profile.CloseBehavior`），启动时对已开启的用户同样校正。
  托盘菜单的「退出」仍然真正退出，退出即停止后续检测。用户之后显式改回退出不会被后台悄悄改写。
- 出现「接近满周期、需要第二次独立观测」的候选后，后台循环用短间隔（35 秒，长于 30 秒最小间隔）
  补一次复检；连续补检最多 3 次，之后回到 5 分钟周期。启动、唤醒或额度读取唤醒后不必再等满一个周期。
- 每轮检测结束推送一次 `subscription:activation-updated`（只有计数与稳定错误码），前端在应用级监听，
  任意页面都能自动刷新结果；提示条不再依赖设置面板是否打开，同一结果仍不重复弹出。

不改变窗口判定条件、持久去重、发送前复核与未知结果不重发；不增加自动开机启动。
