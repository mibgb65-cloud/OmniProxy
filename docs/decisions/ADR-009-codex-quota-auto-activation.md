# ADR-009: Codex 额度自动激活的授权与持久去重

Status: Accepted — 2026-10-13

## 背景

用户要求在 OpenAI 账号设置中显式开启并保存自动激活：额度未开始计时时，以原账号发送最小消息并复查。网络失败、额度发布延迟和重启均可能发生在上游已经处理请求之后，不能依靠页面 loading 或内存标记避免重复消耗。

## 决策

- 默认关闭，只有保存开启才授权后台检测；保存后立即检查，运行时每 5 分钟串行检查，额度读取信号合并并限频。
- 只检查启用的 OpenAI 提供商与已授权、身份完整的启用订阅账号。沿用页面判定：完整窗口、剩余 100% 且无重置目标。缺失、异常时间和已知耗尽不触发。
- 使用原账号的官方目录和隔离令牌回调，固定短提示词、不启用工具、采用已公布的低推理档位；不经过路由，不使用其他账号，不改写客户端或原会话。
- 一条消息可以启动两种窗口。发送前在事务中登记所有未开始窗口的当前周期；账号公开身份经哈希隔离，记录不含凭据或消息。
- 初次没有官方重置目标时使用 initial 周期；之后以曾观察到的官方重置时间区分新周期。已有未来目标又暂时缺失时不重发。
- 同周期超时、失败、退出或复查不确定均不自动重新发送，只继续读取额度。只有实际返回未来重置时间才报告已确认；这不是官方独立的额度激活 API，不能承诺一次调用必然开始计时。
- 已确定失败发生在发送前（例如模型目录／凭据准备失败或尚未发送即取消）时，只释放本次身份／周期的登记，允许后续正常检查；已经进入 HTTP 发送的失败仍保留登记，不能重复发送。
- 关闭取消当前批次与后续请求；退出先取消后台，再停止网关释放订阅操作锁，最后有界等待。已经到达上游的请求无法撤回。
- 独立更新信号使额度页面读共享缓存的新快照；忽略 FetchedAt 的变化，避免后台检查与前端刷新相互触发循环。

## 取舍

采用保守的至多一次发送：登记后、实际发送前退出可能使该周期不再自动发送；结果不确定时也不重试。这比自动重复消耗更符合用户“不会重复发送”的要求。用户仍可正常手动使用该账号；后续官方窗口变化会被观察到。

这是额度激活专用后台行为，默认关闭时原配额页只读查询策略保持不变。不自动兑换重置卡，不加入常规模型请求重试或调度。
