# ADR-003: 使用官方 Codex 组件管理 ChatGPT 订阅授权

## Status

Accepted

## Context

OpenAI 账号需要支持 ChatGPT 订阅的 Codex 登录。订阅授权与 API Key 是不同的认证方式；订阅套餐不能直接作为 OpenAI API 平台密钥使用。

本机官方 Codex CLI 0.155.1 的 app-server 提供登录、取消、读取、刷新和退出协议，支持强制 keyring 存储。参见[官方认证说明](https://learn.chatgpt.com/docs/auth)与[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。

## Decision

- 使用 PATH 中的官方 `codex` 可执行程序，以固定参数启动 stdio app-server；不新增 SDK 或自行实现 OAuth。
- 每个账号使用随机隔离 CODEX_HOME，强制 `cli_auth_credentials_store="keyring"` 和 ChatGPT 登录；不读取、导入或修改用户默认 Codex 配置和登录。
- SQLite 保存认证类型、身份、套餐和状态及 `credential_ref`。DPAPI 密文仅保存隔离配置 ID 与待清理旧配置 ID；实际授权令牌由官方组件的系统凭证库管理。这是 ADR-002 的补充，原 API Key 存储保持不变。
- CODEX_HOME 位于操作系统缓存目录下的 `OmniProxy-CodexAuth/<运行环境>/<随机 ID>`，不随可迁移数据目录改变，避免 keyring 定位失效。
- 重新授权先使用新隔离配置；确认同一身份并成功切换数据库引用后，再退出并清理旧配置。失败清理保留定位信息并报告警告。
- 尚未保存账号的授权目录带有空的清理标记；取消、失败或异常退出后的清理失败可在下次登录前重试。恢复清理先排除所有已保存账号引用。
- 官方子进程输出不进入应用日志；绑定仅返回白名单身份元数据、进行中的授权位置和设备码，事件只发送变更信号。
- 针对旧版浏览器授权端点的兼容映射仅对齐参考项目的公共 originator 参数。SDK 仍生成并验证 PKCE / state、管理回调及系统凭证；初始化的真实客户端身份保留 OmniProxy。此映射不作用于设备码或其他端点。

## Alternatives Considered

- 自行实现 OAuth：需要维护客户端登记、回调、安全验证与刷新协议，当前没有必要。
- 读取用户默认 auth.json：会混用用户现有授权，且无法实现账号隔离。
- 应用持有原始令牌：增加敏感凭证暴露与协议维护成本，官方本地接口已经覆盖本阶段需求。

## Reasoning

复用官方本机组件可以先完成最小的账号管理闭环。授权协议、刷新和 keyring 由官方实现维护，应用只负责隔离、元数据和生命周期。Go 服务与 Wails 分离，测试可以注入最小协议接口。

## Consequences

- 此功能需要本机安装兼容的官方 Codex CLI；缺失时给出明确提示，系统凭证库不可用时不降级到明文文件。
- 首个实际验证版本是 0.155.1；其他版本的兼容性需要验证，协议错误不会作为成功登录处理。
- 真实身份和套餐来自官方 account/read，不推断模型权限或剩余额度。
- 本阶段只实现授权管理，订阅推理与 Responses 网关仍待接入；设备码是否可用由官方服务和账号策略决定。
- 正常退出应用取消未完成登录，保留已保存账号的系统凭证。删除账号先退出其系统凭证，再移除元数据和受控目录。
- 关闭前端授权弹窗仅隐藏界面；会话由应用服务持有并支持恢复，避免浏览器返回时回调已经关闭。显式取消、应用退出或超时仍清理未完成授权。
