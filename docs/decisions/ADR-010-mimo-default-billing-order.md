# ADR-010: MiMo 默认计费顺序与模型目录去重

## Status

Accepted — 2026-10-16

失败重试条款局部由 [ADR-015](ADR-015-account-failover.md) 取代（Partially superseded）；原跨计费／地区及共享额度限制保持。

## Context

MiMo 普通按量与三个 Token Plan 集群支持重叠模型。此前同时存在多个通道时，裸模型名报歧义，自动发布通道别名使客户端列表出现大量同名选项。用户要求在 MiMo 设置中选择默认使用顺序并简化模型列表。

## Decision

- 迁移 026 保存唯一非敏感设置 `mimo_settings.preferred_billing_mode`，只允许 `token_plan`／`payg`，初始 Token Plan 优先。缺失／损坏报错，不静默改变计费选择。
- 显式规则／固定账号保持优先；默认路由在每个提供商内选择有启用且支持该模型账号的优先计费方式，然后沿用服务商顺序及账号创建时间／ID 顺序。没有首选通道候选时才选另一通道，多套餐集群也沿用稳定账号顺序。请求发出后不因失败重试或切换计费。
- 公共 Catalog、网关模型发现与受管客户端目录仅发布原模型及用户显式规则，不再自动发布 MiMo 通道别名；旧通道名仍能解析。旧 Claude 上下文后缀和桌面编码 ID 通过仅用于解析的兼容目录验证能力，避免重新发布重复项。
- MiMo 设置选择后直接持久保存，下一次路由解析生效，刷新既有受管客户端目录和前端相关查询；不改账号凭据、集群和目录版本，不新增依赖。

## Alternatives Considered

继续要求通道模型名会保留列表重复；只隐藏别名而不解决裸模型歧义会使模型不可用；收到失败后跨通道重试会扩大计费与请求副作用，因此均未采用。

## Consequences

同名模型只需选择一次。用户仍可用固定账号或显式通道精确控制计费及集群；官方额度未知不会被推断为可用或耗尽。客户端可能需要重新加载目录，新设置不改变已选定目标的在途请求。
