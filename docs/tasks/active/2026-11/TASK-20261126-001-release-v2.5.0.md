## 托管预检发现的发布阻塞

- 首次预检的 `TestPassthroughSocketRecordsTurnUsage` 失败：客户端收到终结帧就发送下一轮，下一轮的 `response.create` 可能先于上游方向完成记账取得锁，将已成功交付上一轮误记为 `request_cancelled`。
- 只在终结帧发送与成功收尾之间共用现有轮次锁；仍先交付后结算，写失败时不记成功。普通数据帧不把写操作放入锁内。补充覆盖终结帧交付边界与失败交付的回归测试，重跑质量门和托管预检。
