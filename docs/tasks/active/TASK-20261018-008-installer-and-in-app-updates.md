## Request

用户要求适配：更新包下载／进度／SHA256／静默安装和重启，覆盖安装沿用旧目录并处理运行进程，完整安装／升级／卸载实机验证，GitHub Release 自动打包／校验／发布，以及「设置与关于」右侧升级标记和版本浮窗。

## Goal

Windows v2 具备可验证的全量安装包更新闭环；UI 能展示新版本、下载进度和重启更新；Release 工作流生成可被客户端识别和校验的资产。

## Scope

- 复用旧版业务行为，按新版模块边界实现可信资产发现、后台下载／取消、校验、持久状态、安装前复验及重启。
- 适配 NSIS 旧安装路径识别、目标进程处理、更新后启动与数据保留；隔离注册项／快捷方式／目录做真实安装、升级和卸载验证。
- 升级标记和浮窗与更新页共用状态，支持正式／Beta 渠道。
- 增加 Windows Release 工作流、版本／资产校验脚本、发布说明与验证文档；不实际发布远端。
- 最小充分定向测试、完整 task verify、原生交互与安装生命周期验收，提交 main 并归档。

## Out of Scope

不修改旧仓库、不更新用户真实安装或账号、不自动发布 GitHub Release、不引入差分更新或新平台承诺。

## Analysis

五份既有未跟踪任务记录不纳入提交。现有更新仅查版本，NSIS 仍为基础模板；旧版已有下载、校验及安装流程可参考，但不能照搬按进程名称批量终止等行为。

采用全量安装器资产，资产及 SHA 文件严格按当前平台／版本配对；前端只传预期版本，不接受任意下载 URL、路径或命令。下载与安装前均校验，后台下载有界且可取消；状态保存在当前 profile 的独立更新目录。正式安装版启动后及定时自动检查，不自动下载；开发／测试版不自动联网。

安装器复用 HKCU／HKLM 的旧 InstallLocation／DisplayIcon 路径。以同一程序的受限辅助模式按完整可执行路径处理进程，优先正常退出，超时仅终止匹配路径的进程；不按名称批量关闭。新版更新通过独立辅助进程等待安装、以原用户重启，避免直接把用户界面留在提权进程中。卸载仅删除受管程序文件、匹配的快捷方式和自启动，保留数据及不属于程序的文件。

Release 先校验版本、执行质量门、打包和核验资产，再由具备 contents:write 权限的独立步骤发布；预发布与 stable latest 分离，不删除历史 Release。参考官方文档：GitHub REST Releases／Assets、NSIS Chapter 4、Microsoft ShellExecuteExW。BrowserOS MCP 当前未提供连接，外部接口核对使用只读官方文档检索，原生验收使用 Windows UI Automation。

## Implementation Plan

1. 核对边界、旧实现和当前官方接口／工具行为，完善方案及 ADR。
2. 实现更新服务、系统安装适配、NSIS 与 Release 流程。

4. 在隔离安装身份和数据下执行真实安装／运行中升级／重启／卸载矩阵，运行质量门。
5. 更新结果与风险、审查差异、提交和归档；不操作正式安装或远端发布。

最终审查补充：机器级实机发现 WebView2 无法从管理员令牌启动。除新版更新辅助进程外，安装完成页及旧版自动更新兼容分支也须通过交互桌面的普通用户进程启动，不能保留直接继承 NSIS 管理员令牌的入口；补充对应真实启动／令牌验收。

## Implementation Result

已完成以下闭环，未增加业务依赖或修改旧仓库：

- `infrastructure/update` 严格配对 Windows amd64 安装器与 SHA256，限制初始地址／重定向、文件大小、时间和校验格式，提供真实流式进度与取消。
- `application/updater` 统一版本候选、下载／安装互斥、渠道、缓存恢复及失败重试。安装前重新取得可信摘要，辅助进程锁定文件并复验，前端不能指定 URL、路径或命令。
- 独立 Windows 辅助进程请求安装权限、等待安装并以原用户重启；取消权限或启动失败不退出应用。NSIS 沿用旧登记目录，按完整路径关闭目标实例，卸载保留数据及未知文件。
- 首次安装完成页及旧更新器兼容启动入口获取交互桌面的普通用户令牌，复制主令牌并加载用户配置后启动界面；没有可用普通桌面时提示手动打开，不回退到管理员界面。
- 设置按钮右侧升级标记、折叠态图标、独立版本浮窗、下载进度／取消／重试及「重启并静默升级」。设置页共享状态，中英文、深浅主题与窄窗口适配；生产环境默认后台检查，可关闭，下载／安装仍需主动操作。
- GitHub Release 工作流、版本映射／原生资源／资产验证脚本、Beta 发布说明、UPDATE、RELEASE 和 ADR-017。先验证和打包、再向 draft 上传完整资产，最后发布；Beta 与 stable latest 分离，不覆盖公开 Release。
