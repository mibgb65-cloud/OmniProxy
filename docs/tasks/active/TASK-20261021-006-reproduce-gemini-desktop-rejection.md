## Status

## Created

## Request

用户反馈 Beta.17 仍无法使用 Gemini，要求继续定位实际原因，不能只以短请求成功说明恢复。

## Goal

通过隔离内核的完整默认工具请求形态，取得真实上游拒绝分类；修复有证据支持的适配缺陷，
保留用户原会话、账号和配置，不盲目重试或遍历账号。

## Scope

- 只读核对最新请求与客户端错误元数据。
- 在无用户配置／MCP／会话的隔离目录捕获新合成请求，只保留结构和合成内容。
- 默认仅一次受控上游复现；不让 Claude SDK 对真实上游自动重试。
  若根因明确，后续仅进行必要的单次修复对照，记录实际次数。
- 对确认的缺陷补回归、最小实现和适用质量门，明确生产安装仍未替换。
- 用户后续明确回复“可以”，授权使用一个当前禁用的备用账号，对同一完整请求做一次
  对照；不改变启用状态或生产路由，不自动重试。仅选择当前令牌仍有效、且登录身份与
  项目均不同的备用账号；若没有符合条件的账号则停止，不擅自续期。

## Out of Scope

- 不重放真实用户消息，不打印账号身份、凭据或原始上游正文。
- 不自动改真实账号、路由和客户端配置，不安装或重启生产程序。
- 不绕过额度、不启用付费积分、不将所有 Google 429 无条件当作账号额度错误。
- 不改 Atria 等无关草稿或模块。

- 当前上游错误正文被安全丢弃，现有历史无法确定 429 细分原因；不以旧官方余额代替本次证据。
- 非 bare 隔离内核产生 21 个默认工具、约 79 KB 请求、`max_tokens=32000`；
  新合成请求单次真实复现 HTTP 429／RESOURCE_EXHAUSTED。上游无 details，白名单只匹配到
  quota 通用提示，没有账号级／项目级／模型容量或 RetryInfo 细分证据。
- 为避免将通用 429 当作唯一根因，追加至多一次单变量对照：完整保留工具／系统／消息，
  仅将最大输出降为 512。此为诊断参数，不改生产默认值；对照后停止额外推理。
- 输出降到 512 的对照仍为 HTTP 429／RESOURCE_EXHAUSTED、无 details；不能简单归因于
  `max_tokens=32000`。两次上游生成均拒绝，没有让 SDK 自动重试。
- 额外只读查询当前账号的官方选择器：该型号仍在列表，`maxOutputTokens=65536`，
  模型资源 `remainingFraction=0.99977905`。这不等同于本次所触发资源维度的余额，
  不能以高比例否定真实拒绝，也不能用它反推原始请求的全部限制。
- 诊断期间只读检查发现当前账号状态已变为 1 个启用、2 个禁用；最新失败账号仍启用。
  没有使用被禁用的备用账号，也未改变用户状态。当前并无其他启用的换号候选。
- 用户同意备用账号对照后，只读预检发现：两个禁用账号的凭据均可正常读取、登录身份均
  不同，但两个访问令牌均已过期／不足一分钟有效期，且两者的授权项目均与原账号相同。
  没有找到“有效令牌且独立项目”的候选，因此实际备用账号生成请求为 0，未自动续期。
  同项目不能直接证明所有额度都共享，但此对照不能被当成独立项目资源测试。
- 合成请求文件未变：21 工具、79,026 bytes、最大输出 32000，SHA256 为
