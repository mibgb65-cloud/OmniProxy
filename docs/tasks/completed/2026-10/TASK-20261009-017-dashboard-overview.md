## Request

用户认可新仪表盘规划并要求实施，原应用信息与绑定测试内容全部移除。首页展示所选时段的请求／Token／成功率／耗时、趋势、待处理问题、最近请求、资源概况及客户端接入。

## Goal

交付以真实数据为依据的运行总览，今日／7 天／30 天口径一致，未知及不完整历史明确呈现；资源默认使用缓存，主动检查才调用官方接口，并确认原生 Wails 窗口实际更新。

## Analysis

现有请求记录会按保留上限淘汰，已有用量汇总缺少结果分类与耗时。需要追加独立聚合，避免近期列表代替完整统计；历史仅回填保留记录并标示缺口。复用既有配额缓存、路由诊断与客户端元数据。工作区有大量前序未提交实现，保留且不混合提交。

采用 UTC 15 分钟桶，允许本地整点、半小时及 45 分钟时区按实际边界聚合；前端提交有限、递增的时段边界，后端校验范围并回传同口径统计。Begin／用量差值／Finish／崩溃恢复同事务更新独立聚合，清理明细不删除聚合。新迁移只回填保留记录，历史缺口明确标记；新活动通过有界合并事件刷新首页，不后台查询官方额度。

## Implementation Plan

1. 明确统计口径，追加可跨清理保留的时间桶与统计读取接口，验证时区边界、幂等更新、历史缺口和事件同步。
2. 重建首页模块，复用账号资源、路由和客户端数据，完善加载／空／失败状态、筛选与跳转。
3. 关键测试、task verify、主题／字号／窄窗口检查及原生窗口验收，同步文档和任务记录。
