## Status

Completed

## Created

## Request

- 周额度必须覆盖一周窗口内所有用量，不随 5 小时额度重置而丢弃此前用量。
- 美元估算只显示预计总额度和剩余额度，缩小占用空间，移除“仅统计提前重置后的用量”等额外提示。
- 不显示“缓存已包含在输入中”“部分请求无缓存明细。”“部分请求用量不完整。”及“本机留存”。

## Goal

保持 5 小时与一周统计窗口独立，提供紧凑且不伪造未知数值的额度和 Token 展示。

## Scope

额度窗口估算、账号卡片、必要回归测试及受影响产品文档。保留已有未提交用户改动，不涉及真实凭证、生产数据库、安装包或发布。

# Analysis

- 现有窗口查询按窗口类型区分，但周估算还读取“提前重置基线”，其写入条件包括周重置时间变化或已用比例下降，会截断仍处于当前一周窗口的请求。既有测试只覆盖 5h 单独重置不写周基线，未覆盖历史周基线导致的错误裁剪。
- 周估算改为只按自己的 `resetsAt - 7 天` 至独立观察时刻聚合；不读取或继续生成周提前重置基线。5h 提前重置保护保留，旧 RPC 字段保持兼容，无需迁移或操作真实用户数据。
- UI 使用三列表格：窗口、预计总额、预计剩余，避免额外标题、逐列重复标签和状态说明挤占空间。未知／过期／错误值显示 `—`，不伪造金额；保留 Token 精确整数提示、未知缓存和部分缓存下界的区分。

# Implementation Plan

1. 检查估算时间窗口、重置基线及相关测试，定位周统计被截断的条件。
2. 最小化修复统计并精简额度／Token 卡片。
3. 增加独立窗口与展示回归，执行针对性验证及 `task verify`，同步任务与产品文档。
