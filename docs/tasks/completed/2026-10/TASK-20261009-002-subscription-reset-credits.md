# TASK-20261009-002: Codex 订阅重置卡查询与手动使用

## Status

Completed

## Created

2026-10-09

## Request

账号卡片增加重置卡按钮，点击查看当前账号的可用数量与卡片信息，支持手动使用；先规划最小完整流程再实施。

## Goal

在账号上下文中查询官方重置权益，通过明确的使用确认和幂等调用手动兑换，并刷新真实额度与卡片数量。

## Scope

- 官方额度查询解析重置卡汇总和详情；数量以 availableCount 为准。
- 订阅账号卡片增加图标入口和全局详情弹窗。
- 查询失败、未返回、无卡、仅数量、可用／兑换中／已使用／未知状态和有效期处理。
- 支持指定卡片与官方选择下一张卡；明确确认后调用官方 consume。
- 处理 reset、alreadyRedeemed、nothingToReset、noCredit，以及不确定结果的同一请求重试。

## Out of Scope

- 自动使用、购买重置卡、修改套餐或推理转发。
- 开发验证时兑换真实账号的重置卡，真实兑换由用户在页面确认触发。

# Analysis

本机官方 schema 与文档确认 account/rateLimits/read 含 rateLimitResetCredits；null 表示未返回，credits:null 表示仅数量已知，空数组表示没有返回可用详情，详情可能少于 availableCount。consume 接受必填 idempotencyKey 与可选 creditId，并返回四种稳定结果。

## Approach

扩展现有额度快照，账号入口复用查询缓存；详情弹窗打开后重新核对数据。每次用户确认的兑换分配稳定 UUID，并在重复点击、超时与同一操作重试时复用。使用前核对账号／隔离配置、身份与可用权益；兑换后重新读取官方额度，不自行恢复百分比或减数量。后端串行保护与已有账号操作一致，返回结果明确区分兑换成功和刷新失败。

采用 SQLite 的轻量操作记录保存幂等键、账号归属、卡片 ID 与结果，避免关闭弹窗或重启应用后忘记不确定的使用请求。只保存公开标识和稳定状态，不保存凭据；每账号最多一个待确认操作，新的使用确认不能覆盖它。

## Risks

重置卡属于有限权益，必须通过界面确认手动触发；网络超时不能当作明确未使用，也不能自动换新的请求标识。官方未定义的类型／状态保持未知且不允许按指定卡使用。所有身份和凭据继续禁止日志输出。

# Implementation Plan

1. 校验协议与结果字段，建立查询／兑换 DTO 和最小输入约束。
2. 扩展额度查询，实现幂等兑换和兑换后刷新，模拟各种结果与失败。
3. 实现账号图标、全局详情弹窗、使用确认、状态与同一操作重试。
4. 验证交互与主题布局，查询真实账号但使用模拟兑换，运行 task verify，更新文档与任务记录。
