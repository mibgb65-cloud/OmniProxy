# TASK-20261013-007: 同名模型服务商优先级

## Status

Completed

## Created

2026-10-13（Asia/Singapore）

## Request

按模型配置服务商时，如果有不同服务商提供了相同的模型，则需要支持配置使用优先级。

## Goal

同一模型可保存多个服务商的使用顺序，页面、预览、实际网关和客户端目录使用一致的优先级。

## Scope

模型偏好持久化与迁移、核心账号选择、应用与 Wails 接口、路由页配置、相关测试与文档。

## Analysis

现有实现只保存一个优先服务商，其余候选按账号创建时间回落。需要扩展为有序列表，并保留已有单服务商偏好、精确规则与固定账号的兼容性。

选择在既有偏好表新增有界 JSON 顺序列，保留首选 provider_id 与旧接口；相比分拆独立排序表，避免双表配置同步和不必要的模型重构。迁移将旧首选转为顺序列表。核心先按服务商顺序，再按账号创建时间／ID；未排序的候选保留原默认顺序。最多 100 个服务商／模型，禁止重复和无效 ID，保存采用参数化 SQL 和事务。

页面沿用现有首选入口，增加优先级配置弹窗及顺序摘要，使用上移／下移按钮和明确保存／恢复自动选择；不依赖拖拽。配置不可用时保留诊断，保存失败不覆盖已有顺序。只调整配置选择，不新增请求失败重试或服务商适配器。

## Implementation Plan

1. 检查现有偏好存储、共同解析路径、迁移与测试模式。
2. 实现兼容的多服务商顺序保存和按可用性选择。
3. 添加可通过键盘操作的优先级配置，显示当前顺序和不可用项。
4. 验证持久化、边界、预览／网关／目录一致性，运行 `task verify`。
5. 同步相关文档，审查并提交任务变更，完成归档。

## Implementation Result

- 迁移 015 为既有模型偏好增加有界 JSON 顺序，自动将旧首选迁移为第一优先，保留兼容字段与旧接口；空列表恢复自动选择。
- 新增核心有序选择函数，先按服务商优先级，再按同一服务商内的账号创建时间／ID；不可用项跳过，未排序候选沿用原顺序，精确规则和固定账号保持强制范围。
- 顺序保存限制 100 个服务商／模型、14000 序列化字节、1000 个模型；校验模型、ID、重复和同名模型可用候选，允许保留已有失效项，事务保存；损坏数据明确报错。
- Wails 增加 SetModelProviderOrder，默认映射返回完整顺序与可用性，预览返回实际使用优先级；已有首选入口移到第一位时保留后续顺序，受管客户端目录沿用既有安全刷新。
- 模型和服务商视图增加优先级入口与已保存顺序；弹窗提供上移／下移、不可用项移除、保存和恢复自动选择，保存失败保留草稿与原配置，保存中禁止重复操作／关闭，取消和保存后恢复焦点。
- 同步中英文文案、自动生成绑定与产品／架构文档，无新增依赖或适配器。
