# TASK-20261016-003: MiMo 默认计费通道顺序与模型去重

Completed

## Request

在 MiMo 设置页面增加默认使用顺序，可设置优先 Token Plan 还是 API Key，让模型列表不再包含大量同名模型。用户要求实现。

## Goal

持久保存 MiMo 默认通道优先级，同名模型默认按顺序选择可用账号；统一模型展示和客户端目录去重，保留明确指定通道／账号的兼容行为。

## Analysis

现有 MiMo 多通道同时存在时，裸模型名返回 ambiguous_mimo_pool；Catalog 自动添加带通道前缀的别名导致客户端重复。新增迁移 026 与路由服务的 MiMo 设置读取／保存，默认 Token Plan 优先；每个提供商内先过滤优先计费方式的启用且支持模型账号，再沿用现有创建时间／ID 顺序，保持服务商优先级。没有合格首选账号时选择另一通道，请求失败不重试；多套餐集群沿用稳定账号顺序。Catalog 停止自动发布 MiMo 通道别名，解析继续兼容旧通道名，显式规则／固定账号优先。沿用现有受管客户端目录刷新。保留五份既有未跟踪记录和已有用户数据。Related ADR: ADR-010-mimo-default-billing-order。

## Implementation Plan

1. 检查现有路由和设置存储，确定优先级的作用范围与兼容策略。
2. 实现持久设置、默认账号选择及展示目录去重，明确固定通道／账号行为。
3. 接入 MiMo 浮层，补充中英文文案、边界／回归测试和相关文档。
4. 定向验证、完整 `task verify`，从正常桌面启动并验证设置与目录，审查提交并归档。

## Implementation Result

- MiMo 设置增加「默认使用顺序」下拉选项，支持 Token Plan 优先和普通 API Key 优先，选择后立即保存；读取失败可重试、保存失败保留原值，保存中及关闭重开均阻止重复提交并隔离旧读取响应。
- 迁移 026 新增受枚举约束的非敏感设置，默认 Token Plan 优先；设置缺失／损坏明确报错。Wails 生成两项类型化绑定，保存后复用受管客户端目录刷新及前端查询失效。
- 路由按每个服务商内合格账号的计费顺序过滤，再沿用核心服务商优先级及账号创建时间／ID；首选无合格账号时使用另一通道，高速版等仅按量支持的模型正确落到按量。固定账号和显式通道优先，失败请求没有新增重试。
- 公共 Catalog、网关模型列表和受管客户端目录不再自动发布 MiMo 通道副本，保留用户显式规则。兼容目录仅用于旧 Claude `[1m]`／桌面编码 ID 解析，不重新发布重复项。
- 正常桌面开发环境由原有 Wails 监听器重建并保持运行；原生界面已核对双向选择、SQLite 持久值、重开、深浅主题和 960×600，恢复初始 Token Plan 优先及原窗口／主题。
