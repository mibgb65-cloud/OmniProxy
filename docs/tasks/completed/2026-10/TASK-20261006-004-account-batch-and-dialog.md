## Status

Completed

## Request

1. 账号名称非必填，留空时使用 API Key 的前 8 个字符作为名称。
2. 支持一次添加多个 API Key；批量添加时不能填写账号名称。
3. 重做原生删除确认弹窗，匹配当前 UI 风格。

## Goal

单个账号可自动命名，批量账号按每行一个 Key 录入并自动命名；删除使用统一主题和可访问的应用内确认弹窗。

## Analysis

- 现有前端和 Go 服务都要求非空名称，必须同步调整；默认名称按 Unicode 字符取前 8 个，短于 8 个时使用实际长度。
- 批量逐个调用现有接口简单，但失败后会产生部分成功及重试重复；选择新增 Go 批量服务，先完整校验，再用数据库事务保存，失败清理已写入凭证。
- 批量输入每行一个 Key，忽略空行，最多 100 个；名称字段在批量模式隐藏，后端批量输入只接受提供商和 Keys。
- 删除当前使用 `window.confirm`；使用已有 Radix AlertDialog 和主题样式，取消不调用后端，保存删除中的状态与错误反馈。
- 用户明确要求名称展示 Key 前缀；仅前缀会成为名称，完整 Key 仍保存在受保护凭证存储中，不增加 Key 日志或错误回显。

## Implementation Plan

1. 更新单账号自动命名，新增有界且可回滚的批量账号服务与 Wails 绑定。
2. 添加单个／批量录入方式，校验名称、每个 Key 和数量，接入现有查询刷新机制。
3. 统一总览及详情的删除确认弹窗，覆盖确认、取消、提交中禁用、失败反馈和焦点恢复。
4. 完成后端边界／事务回滚与前端交互测试，运行完整质量门禁；检查实际窗口并恢复开发环境。
5. 同步相关产品／架构文档、状态看板和任务记录，审查并提交本任务文件。

## Risks

批量凭证写入与数据库不共享事务，必须校验后写入，并在失败时清理每个已写入凭证；不得把完整 Key 或批量文本放入日志、异常与任务记录。默认名称有意显示前缀。Go 变更会触发开发重编译，质量门禁使用独立产物目录避免覆盖运行中的开发程序。

## Implementation Result

- 单账号创建允许空名称，在 Go 服务中按经过校验的 Key 前最多 8 个 Unicode 字符生成名称；原有自定义名称行为保持不变。
- 新增批量账号服务与 `CreateAccounts` Wails 绑定，只接受提供商 ID 和 1–100 个 Keys；完整校验后写入受保护凭证和 SQLite 事务，任何写入失败回滚本批元数据并清理已写入凭证，清理错误一并返回。
- 新增单个／批量方式，批量每行一个 Key、忽略空行，显示数量且隐藏名称输入；批量输入在当前 WebView2 中遮掩显示，保存中锁定输入、模式、取消和重复提交。
- 总览与详情共用应用内 Radix AlertDialog 删除确认，支持取消、确认、删除中、失败提示和重试；取消恢复原按钮焦点，成功删除后可回到添加按钮。
- 表单拆分为呈现、字段、输入校验和状态 hook，手写新文件均保持 200 行以内；复用现有 UI、查询和凭证存储依赖，未新增依赖或数据库迁移。
- 已重新生成并保留前端 Wails 绑定，同步中英文文案、PRD、架构说明和状态看板。

## Compatibility

现有单账号 API 继续支持自定义名称；空名称由非法输入改为自动命名，属于用户明确要求的行为变化。批量 API 为新增能力，不改变已有方法签名；删除服务本身保持不变。

## Remaining Risks

自动名称有意包含 Key 前缀，短于 8 个字符的 Key 会完整出现在名称中；按用户要求保留此规则，并在产品文档和代码注释中明确名称不得写入日志。凭证文件与 SQLite 不能共享事务，极端清理失败或进程异常退出可能留下未被账号引用的加密文件，正常失败路径已验证回滚并报告清理错误。

## Deviations
