## Request

按已讨论的路由页面思路实现第一版，延续不影响其他任务的要求。

## Goal

保存并管理模型别名到提供商／实际模型的精确映射，支持启停、编辑、删除、筛选和不发请求的匹配预览；网关动态读取规则、改写 model 并同步模型列表。

## Analysis

- 当前网关仅支持 DeepSeek，模型白名单和账号选择固定；路由页为占位。
- 使用唯一、区分大小写的模型名精确匹配。启用规则优先；未命中时保留已支持原模型直通行为，其他模型明确报错。
- 目标按提供商配置 ID 定位，模型使用适配器实际 API ID；账号可使用提供商启用账号范围，或固定一个所属账号。
- Core 保持纯 Go，规则和选择算法不依赖数据库／Wails／React。Application 保存规则、验证引用和生成预览，凭证只在原网关受控回调中使用。
- 目标被删除或停用后保留规则并显示异常，匹配到异常规则时禁止静默回退；不改变现有账号／提供商删除流程。
- 使用独立 worktree，基于已完成的 DeepSeek 分支开发；真实提供商调用继续按用户要求延后。

## Implementation Plan

1. 建立独立分支和任务记录，补充规则迁移与核心模型名／精确解析／账号选择逻辑。
2. 实现 SQLite 规则 CRUD、引用验证、配置异常状态和预览；提供 Wails 绑定与独立前端服务。
3. 网关解析规则后改写模型并绑定提供商／账号，动态返回模型列表；覆盖原行为兼容性和禁用／异常边界。
4. 实现紧凑列表、搜索／筛选、编辑弹窗、删除确认和匹配预览，支持中英及亮暗主题。
5. 完成契约、集成和界面验证，运行 task verify，同步文档，独立提交和最小回填。

## Risks

别名重复、覆盖原始模型名、删除目标、错误账号归属和配置读取失败必须明确处理。预览不能读取密钥或发起模型请求；请求不能通过正文绕过目标选择。保存后应动态生效，历史模型直通行为需要回归验证。共享绑定、文案和文档须核对并行改动。
