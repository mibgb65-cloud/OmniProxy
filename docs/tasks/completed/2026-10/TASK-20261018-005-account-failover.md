# TASK-20261018-005: 实施同通道账号自动故障切换

## Status

Completed

## Request

用户授权实施 TASK-20261018-004 的方案；首版仅在同服务商、同计费通道的账号之间切换。

## Goal

明确的上游账号拒绝后，可在严格相同的账号池中有限切换，保留固定账号、流式响应、凭据及统计边界，并提供开关和尝试记录。

## Scope

- 共用候选计划与规则来源，冻结服务商配置、认证、计费、地区与模型能力。
- 应用层顺序尝试、错误分类、冷却、恢复资格及取消／超时保护。
- 尝试级明细与一次逻辑请求统计，兼容历史数据。
- 网关故障切换开关、运行状态及请求尝试详情，中英文同步。
- 最小充分契约／集成测试、原生验收、完整质量门及文档。

## Out of Scope

跨服务商／计费切换、成功响应后的重放、完整负载均衡、后台模型探测和自动额度预测。

## Analysis

依据已完成的设计记录。默认启用同池切换，最多三次（包括首次），共用既有总期限；冷却仅为运行状态，不修改用户启用开关。具体实现需保持先登记尝试、资源释放后切换与未知用量不伪造为零。

具体实施采用延迟绑定父记录：明确拒绝的尝试只保存未知用量的尝试明细，唯一被接受的 200 响应（包括转换提前读取的 usage）才绑定父记录；所有失败时绑定最后实际被拒绝的账号。保留原 subject 不可改写约束和已有累计算法，不需要重写工作正常的统计模块。新增迁移 033，历史记录不虚构尝试；冷却默认 429 为 30 秒、401／已识别余额拒绝为 5 分钟，优先使用有效 Retry-After。Google 项目级 429 不轮换 Key，泛化 5xx／不确定传输失败不重放。

## Implementation Result

- 新增同池候选计划，复用当前模型资格与稳定排序，区分手工固定和旧通道别名。每次尝试冻结服务商／认证／计费／地区并检查账号版本；API Key、Codex 与 Google 订阅凭据在读取／等待锁后复核版本。
- 默认开启，最多三次，沿用原总期限；只在明确 401、适用 429、DeepSeek 402 时切换，Google 429／403／5xx／不确定传输错误／本地失败／取消均不重放，200 后绝不再生成。重复 API Key 通过单请求内存摘要跳过，已知重复订阅身份不纳入备用池。
- 有界内存冷却按账号版本和模型隔离，合法 Retry-After 秒数／HTTP-date 优先；单恢复资格、失败代次、取消／异常释放与旧成功不覆盖新失败。冷却候选先做内存筛选，避免逐个重复读取资源。
- 迁移 033 保存设置和最多三条子尝试；延迟父目标绑定、原 subject 保护、一次请求计数及已报告用量累计算法保持。明细支持幂等、原始上游状态、未知用量、历史兼容、级联清理和中断恢复。
- 网关运行概览增加持久开关与冷却状态，保存失败保留原值并支持重新读取；请求列表／详情增加切换次数和有序尝试、原因与报告用量。中英文同步，使用生成绑定与既有组件，无新增依赖。
- 修改仅限此功能及其测试／文档；开发版暂时正常退出以避免编辑期间反复重编译，完成后恢复普通桌面环境。
