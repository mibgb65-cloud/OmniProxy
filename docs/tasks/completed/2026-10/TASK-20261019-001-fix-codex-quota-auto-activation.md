## Status

Completed

## Created

## Request

用户反馈「自动激活 Codex 额度窗口」似乎没有实际激活，要求排查。

## Goal

确认当前配置、后台触发、资格判定、发送和复查链路的真实状态；根因明确时最小修复并验证，不能把请求发出等同于窗口已激活。

## Scope

- 只读检查生产日志、开关、账号公开状态和周期登记。
- 对照 quotaactivation、订阅额度与原生发送器、设置和生命周期集成。
- 必要的隔离回归、最终质量门、诊断和状态反馈改进。

## Out of Scope

- 不修改真实开关、账号、登录或当前 Agent 配置，不重启生产应用。
- 不删除或重置生产激活登记，不强行重发已发送／结果不确定的激活消息，不使用额度重置卡。
- 不自动发布新版本；不将官方窗口行为或套餐配额当成本地可控制的保证。

# Analysis

生产 Beta.4 的 auto_quota_activation=1，两个 Team 订阅账号均启用且 authenticated，后台已写入各自 five_hour／weekly 窗口；当前 attempted_cycle／attempted_at 都为空。代码只把 remaining=100 且 ResetsAt 为空判为未开始，持久窗口目前都有未来重置目标。需只读对照官方原始窗口的剩余／重置时间是否随查询移动，不能在证据不足时把 100% 窗口全部当作未启动。沿用 ADR-009 的默认关闭、发送前登记、未知结果不重复发送和确认后才称已激活的边界。

# Implementation Plan

1. 核对真实开关、服务启动、最近安全日志和周期登记。
2. 检查触发与资格、单账号最小发送、后续复查和 UI 状态；建立根因回归。
3. 修复并验证去重、取消和不确定结果边界，记录实际验收与限制。

# Progress

- 只读原始额度两次采样确认：账号 1 的五小时窗口 used=0、reset_after=18000，查询相隔约 38 秒，reset_at 同步增加约 39 秒；其周窗口已有用量、目标固定。另一个账号五小时已有用量，重置目标固定；详细用量仅保存在忽略的本地诊断中，不写入任务历史或提交。仅 GET 查询，没有模型调用。
- 原实现把任何未来目标直接视为已启动，且会把滑动占位目标存为周期，导致账号 1 从不进入发送分支。
- 方案比较：不采用“100% 或倒计时接近 5h 就发消息”的单快照规则，避免向刚启动且百分比四舍五入为 100% 的窗口重复发送。采用同身份、30 秒至 15 分钟间隔、目标随查询同步移动的双观测，再发送前复查。
- 新增两个非敏感持久字段：观测时间与已确认固定目标；原周期／发送记录保留，未知旧结果仍不重发。补充状态计数／安全日志；发送成功但尚未观察到固定目标不能报告已激活。
- 用户补充未激活时界面可能显示 5h1m；判定使用官方时间戳和周期而非 UI 文案，并容许秒级取整与时钟偏差。


# Implementation Result

## Changes

- 将原始未来目标与已确认固定周期分开保存：迁移 034 增加 observed_at、confirmed_reset，不删除或重置已有 attempted_cycle／attempted_at。
- 同身份的两次独立观测在 30 秒至 15 分钟内证明目标随查询同步滑动后，才将满额窗口作为未开始候选；固定的 100% 计时窗口、耗尽、坏数据、时钟回拨与长间隔不会触发。兼容 5h1m 的边界取整但不解析界面字符串。
- 发送计划显式携带后台确认的时序证据，发送器复查原账号并在必要时有界等待约 2 秒，避免同秒快照永远无法前进。只有明确未发出的准备失败可以释放登记；请求已发或结果未知继续保留，重启和占位目标过期都不重发。
- 不把模型 completed 当作窗口确认：仍滑动／未知保持待复查；有效使用量加未来目标或目标经独立观测固定后才确认。过期周期必须来自已确认目标，延迟快照不能倒退该目标。
- 补充安全计数日志和更准确的界面状态文案；额度读取对滑动候选也可限频唤醒，默认关闭时仍不调用。
- 保留既有测试并补充周期迁移、并发、重启、未知结果、时序／边界、发送前复核和日志不泄露回归。原有 check_test.go 为 225 行的关联场景测试；本次只保留其位置并更新发送器签名／确定性周期时钟，新生产文件和新测试文件均分拆为不超过 200 行，避免无关重排。

## Actual Evidence and Limits

- 对用户指定账号做了过滤后的两次只读官方额度查询：五小时已用为零、reset_after 等于完整周期，重置目标随查询时间同步后移；有用量的周窗口目标固定。最后一次只读复核仍符合这个未启动特征。
- 真实凭据仅通过现有受控 UseToken 回调读取；所有诊断仅 GET 固定官方额度端点，不发送模型消息、不刷新／切换登录、不使用重置卡，不在代码或任务记录保存真实邮箱、令牌、身份和使用明细。
- 将真实观测的时序关系匿名化重放，时间整体平移、百分比改为典型值；运行真实 Service／MessageSender／chatgpt 适配器的模拟传输闭环，验证发送前持久登记、一次请求、固定计时后才确认。
- 本轮没有对该账号或其他真实账号发送激活消息，没有运行生产库迁移或修改真实开关／周期登记。因此不能宣称该账号已被实际激活；当前 Beta.4 仍是旧判定，修复需后续发布／升级或另行明确单次真实验收。
