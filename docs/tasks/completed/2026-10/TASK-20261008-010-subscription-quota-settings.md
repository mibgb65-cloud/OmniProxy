## Goal

按官方真实额度数据展示可用资源与重置时间，提供清晰紧凑的卡片信息和后续设置入口。

## Scope

- 扩展官方 account/rateLimits/read 读取面，安全查询每个隔离订阅账号的额度窗口。
- 按套餐展示 5h／一周，缺失及查询失败明确提示，不伪造次数、额度或重置时间。
- 订阅卡片和列表展示额度，刷新身份时同步刷新额度。
- 时间使用 YYYY-MM-DD HH:mm 紧凑格式，订阅卡片底部并排创建／更新时间。
- OpenAI 账号详情设置按钮打开空内容悬浮弹窗。

## Out of Scope

- 订阅推理转发、账号调度、额度历史落库及尚未定义的设置功能。
- 从百分比推算官方未返回的固定请求总数。

# Analysis

现有官方接口已用于读取账号 ID，可扩展同一协议返回额度窗口，避免访问令牌。账号列表本身保留轻量元数据查询，额度通过单独的查询接口获取；先核对 SDK 返回的窗口持续时间与重置字段。

本机 schema 与官方文档确认窗口只提供 usedPercent、windowDurationMins 和可空 resetsAt，无固定请求总数。采用剩余百分比展示；优先选择 codex 桶，按窗口分钟数识别 300／10080，避免把其他模型或未知窗口误当成周额度。额度按需读取，查询缓存 60 秒，无后台轮询和自动失败重试；后端复用现有操作互斥，限制为一个官方子进程。

## Risks

区分本地账号 ID 与官方 ID；额度查询失败不可破坏授权。比例与时间须验证边界，不把已过期或缺失快照当作全额恢复。禁止记录身份与授权值。查询需有超时、避免自动重试及并发启动大量官方进程。

# Implementation Plan

1. 核对官方 schema／文档和当前账号返回的数据结构，明确窗口选择与展示语义。
2. 实现最小安全额度查询接口及绑定，覆盖验证、身份关联、错误与并发边界。
3. 实现进度条、计时、紧凑时间与空设置弹窗，保留 API Key 展示行为。
4. 做关键路径测试、真实账号和浏览器布局验证，运行 task verify，更新文档并恢复开发环境。
