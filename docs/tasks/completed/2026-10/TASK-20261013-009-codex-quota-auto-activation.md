# TASK-20261013-009: 自动激活 Codex 额度窗口

## Status

Completed

## Created

## Request

在 OpenAI 账号设置新增「自动激活 Codex 额度窗口」：开启并保存后，检测到 5 小时或周额度尚未开始计时时，使用该账号自动发送一条最小消息并复查；已激活账号不会重复发送。

## Goal

提供默认关闭、明确保存的自动激活设置，安全识别未开始的窗口，按原账号触发最小请求并复查，防止重复发送。

## Scope

OpenAI 账号设置、订阅额度检测与账号请求、持久化去重及生命周期、必要测试和文档。

## Analysis

沿用现有页面的未开始判定：已返回有效窗口、剩余 100% 且没有 resetsAt；缺失／异常／已过期的快照不当作未开始。只处理已启用、已授权且身份可验证的 OpenAI 订阅账号；默认关闭，用户显式保存后立即检测，应用运行时每 5 分钟串行检测，额度读取可唤醒检测。

复用官方账号模型目录、隔离令牌回调和已有 ChatGPT Responses 请求，不经过路由或其他账号，发送固定短消息且不启用工具。先按账号身份和额度周期持久登记尝试，再发送一条消息并复查；不确定或失败结果同周期不重发，已启动窗口直接跳过。记录上一官方重置时间，区分后续新周期。关闭停止后续请求，退出取消并等待任务结束。

设置保存与 WebSocket 即时开关共用既有设置记录，自动激活采用独立保存入口和后台状态。日志／状态仅暴露计数和稳定错误码，凭据和原始响应不进入前端。不自动兑换重置卡，不改变客户端配置或原会话。

## Implementation Plan

1. 检查未开始计时的判定、账号身份校验和现有额度／请求流程。
2. 实现设置持久化、自动检测、原账号最小请求与复查，保证去重和生命周期安全。
3. 增加开关、保存及结果反馈，同步中英文文案。
4. 验证已激活／未知／未启动状态、并发、失败与重启，运行 `task verify`。
5. 更新文档，审查提交并归档任务。

- 迁移 017 保存自动激活开关和每账号／窗口的身份哈希、观察到的官方重置时间、已尝试周期与时间。发送前事务登记，初次采用 initial 周期；之后只根据曾观察到的官方目标进入新周期，未知结果不重发。
- 后台单循环每 5 分钟串行检查，额度读取信号合并并限频；只处理启用且身份完整的 OpenAI 订阅账号，缺失／异常时间、已知耗尽和已启动窗口不触发。
- 使用原账号的官方目录与隔离令牌，固定 Hi／Reply only OK.，禁用工具，选择已公布的低推理档位，HTTP 只访问既有固定官方端点；响应限 64 KiB，成功完成后复查官方窗口，不经过路由或其他账号。

- 生命周期接入 Wails：保存开启唤醒，保存关闭取消当前批次，退出先取消后台、停止网关释放订阅操作锁，再有界等待。默认关闭时不新增额度或模型调用。
- 同步中英文、生成绑定、独立额度更新信号、产品文档和 ADR-009，无新增依赖，不改写客户端身份／配置／会话，不自动兑换重置卡。
