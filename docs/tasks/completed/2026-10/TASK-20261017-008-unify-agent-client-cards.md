## Request

用户认为客户端接入页的大卡片与 Claude 分组卡片割裂，要求全部统一为参考图二的
“产品标题＋内部 CLI／Desktop 入口”样式；共用配置的入口进入相同页面即可。

## Goal

七个产品使用同一分组卡片结构，各软件入口保留安装和接入状态；共用配置的入口
指向现有同一详情页，Claude／Harness 保留其独立配置范围，返回时恢复原入口焦点。

## Analysis

当前 AgentClientTile 同时支持整张大卡片与紧凑入口，只有 Claude／Harness 使用分组容器。
统一复用分组结构，以产品定义和软件目标区分入口，接入状态继续来自实际 client ID。
Codex／OpenCode／Kilo／Qwen／MiMo 的各入口共用现有详情地址；不新增后端配置范围或 Key。
现有返回焦点只按 client 查找，共用详情后会选到第一个入口，需记录实际点击的软件目标。
原生检查发现父 GatewayView 的布局效果在子组件恢复焦点后将滚动归零，下面几组会出现
“已聚焦但在屏幕外”；焦点恢复改在父布局完成后执行，并补充带真实父视口的顺序回归。

## Implementation Plan

1. 复用现有 Claude 分组结构，统一产品与软件入口定义。
2. 将安装状态限定到对应软件，接入状态继续使用其实际配置客户端。
3. 保持已有详情 URL 和配置行为，修复共享详情下的原入口焦点恢复。
4. 回归导航／状态，运行质量门和原生深浅主题／最小窗口检查，更新文档并提交归档。

## Implementation Result

- 七个产品统一复用同一分组组件，15 个软件入口统一标题／状态／安装信息／进入配置
  结构；去掉原大卡片分支和仅包裹 Claude／Harness 的重复组件。
- 产品／软件入口分别定义，单项安装状态只读取对应软件目标；接入状态按真实 client
  展示。共用配置的软件保留各自入口，详情 URL、Key、模型配置和安装操作沿用原实现。
- 记录点击的软件目标恢复原入口焦点，父页签完成布局／滚动归零后再聚焦，避免下面
  几组入口在返回时被移出视口；保留独立配置与深链接行为。
- 增加中英文产品分组标题，更新本地 Agent 使用说明；无后端、数据或依赖变更。
