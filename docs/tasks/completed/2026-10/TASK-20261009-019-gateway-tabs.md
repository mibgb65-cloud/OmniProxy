## Goal

将网关长页面按使用目的拆分为选项卡，降低信息密度，保持启停控制可见，并保留已有接入与测试能力。用户已于规划后要求「做吧」，本轮实施已授权方案。

## Scope

- 实现网关公共顶栏、四个选项卡与内容面板。
- 路由参数校验、切换状态保留、延迟加载、交互与文案核对。
- 页面回归测试、质量验证与相关文档更新。

## Out of Scope

- 不改变后端接口或手工修改生成绑定。
- 后续页面重构不扩展代理协议、账号调度或客户端支持范围。
- 不将模型路由、请求记录和运行日志的完整页面迁入网关。

## Existing Behavior

`GatewayView` 依次渲染运行状态、本地 Agent、Codex／Claude 手动接入、地址／运行参数、接入检查、测试请求及相关页面入口。

`useGatewayPreparation` 与 `useGatewayRuntime` 提供共享查询和启停控制，侧栏通过相同查询键及 mutation 键同步状态。手动接入模式、测试模型与流式选项保存在各自组件内。客户端配置使用弹窗，支持预览、应用、备份恢复及独立 Key 管理。

部分手动接入文案仍为早期「待接入」提示；当前本地客户端配置及相关代理协议已实现。运行参数目前只读；接入统计／检查及测试仍有 DeepSeek 范围限制，不能解释成全部提供商的可用性验证。

## Expected Behavior

在公共顶栏展示标题、运行状态、实际端口／地址摘要、启停与刷新入口。下方选项卡切换网关内部页面内容：

| 选项卡 | 内容 | 对应现有组件 |
| --- | --- | --- |
| 运行概览（默认） | 资源概况、只读运行参数、模型路由入口 | `GatewayStatusCard` 的概况部分、`GatewayConfigCard`、路由快捷入口 |
| 客户端接入 | Codex CLI／Desktop、Claude Code CLI、Claude Desktop Code 的配置、独立 Key、启停与恢复 | `LocalAgents`、`AgentConfigDialog` |
| 手动接入 | 地址复制、协议／端点说明、Codex／Claude 手动配置摘要与说明 | `GatewayConnectionCard`、`GatewayClientCard`、`GatewayClientConfigPanel` |
| 测试诊断 | 元数据接入检查、模型／流式测试、结果与错误、请求／日志入口 | `GatewayReadinessCard`、`GatewayTestCard`、请求／日志快捷入口 |

## Analysis

### 方案取舍

- 按使用目的分组：运行、自动配置、手动接入、验证，功能边界清楚，所有既有卡片都有归属。推荐。
- 按 Codex／Claude 分组：会重复运行控制、诊断和接入信息；增加客户端时还会扩大一级导航。不推荐作为一级选项卡。
- 网关内部采用同一路由的内容选项卡，沿用现有侧栏入口；无需新增四个侧栏页面或大规模路由重构。

### Related Modules

- `frontend/src/app/routes/gateway.tsx`
- `frontend/src/features/gateway/gateway-view.tsx` 及所属卡片、hooks、测试
- `frontend/src/components/ui/`：新增项目样式的 Tabs 封装
- `frontend/src/i18n/locales/gateway-zh.ts`、`gateway-en.ts` 及必要的 Agent 文案
- `docs/product/GATEWAY.md`、`docs/plans/CURRENT.md`、本记录

### Dependencies

沿用 React、TanStack Router／Query、Tailwind、现有 `radix-ui` 和 Lucide，不计划新增依赖。参考 `ui-ux-pro-max` 的桌面网页导航、键盘操作、状态保留及 shadcn Tabs 指引。

### Risks

- 直接条件渲染会卸载面板，丢失手动接入模式、测试选择、操作反馈；异步配置或测试的结果也可能无法再看见。
- 在各面板重复调用运行 hooks，可能增加事件订阅并拆散启停互斥控制。
- 未访问面板提前加载可能触发不必要的客户端检测；隐藏面板仍必须从键盘导航和辅助技术中正确隐藏。
- 公共顶栏在窄窗口、放大字号与英文下可能拥挤，需要响应式验证。
- 工作区已有大量未提交内容，实施时须只修改本任务涉及的范围，保留其他变更。
