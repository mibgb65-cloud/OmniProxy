## Analysis

- 运行中 Wails 日志 `21:52:24` 明确返回 `agentinstall: update_check_failed`；同期无 WinGet 更新日志，失败发生于更新前第二次 HTTP 查询，尚未执行安装。随后只读探测官方入口成功返回 307，本机仍为 `2.37337.1.0`，不能将本次失败归因于安装器。
- `StartUpdate` 无条件再次 `CheckUpdate`，刚检查成功的结果未在服务端复用，导致短暂网络故障阻断点击更新。
- 前端错误白名单遗漏 `update_check_failed`／`update_unsupported`，又被测试替身统一替换成 failed，原组件测试未发现错误映射缺口。
- 修复方案：服务端保存五分钟内成功验证的官方检查结果，点击更新仍重新核对本机安装；过期／版本变化才重新查询，显式检查始终查新。补齐纯错误映射与实际组件回归，保持固定软件目标和真实版本核对。
- 修复预检后实际重试已进入 WinGet，日志返回 `0x8A15002B`（[官方返回码：无适用更新](https://github.com/microsoft/winget-cli/blob/master/doc/windows/package-manager/winget/returnCodes.md)），本机版本未变化。原 ConPTY 丢失退出码，进而误映射为建议关闭客户端的普通失败；现保留安全退出码，识别渠道不可用，并提供固定 Claude 官方下载页入口。
