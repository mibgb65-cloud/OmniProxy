## Analysis

当前有两个同名 OmniProxy 进程：旧正式版位于 `E:/codexproxy/OmniProxy/OmniProxy.exe`，项目开发版位于工作区 `bin/omniproxy.exe`。开发 Vite 9245 和开发后端 3891／3001 正常，配额路由源码已经指向新组件。需要检查各窗口实际内容及页面刷新。

原生 UIAutomation 确认项目开发窗口（PID 64244）仍存在旧描述“按账号与提供商的配额监控。”，缺少新概况／筛选；同一 Vite 返回的路由已引用 QuotaView。问题是实际窗口仍保留旧页面状态，并非源码或新组件没有接入。

普通刷新未改变页面。运行中二进制包含旧占位描述但不包含新页面文案；它是开发构建，但普通 `wails3 task run` 启动不能保证连接前端开发服务。Wails 本地源码确认开发代理通过 `FRONTEND_DEVSERVER_URL` 启用。已构建最新开发二进制，准备在保留原运行环境及界面状态的情况下显式连接 Vite 重启并核对。

## Implementation Plan

1. 按进程路径确认实际窗口与已加载配额内容。
2. 刷新正确的开发窗口；必要时修复运行或页面加载问题。
3. 在原生窗口核对新页面，记录结果。
