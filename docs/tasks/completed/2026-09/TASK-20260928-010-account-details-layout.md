# TASK-20260928-010: 账号卡片滚动、厂商详情页与全局内容宽度

## Status

Completed

## Created

## Request

账号较多时卡片不要无限增高：在最大高度前自然增高，达到上限后独立滚动。账号页可进入具体厂商的二级页面，展示更多账号信息（如余额）。超大屏时缩小左右留白，并让宽度规则作用于每个页面。

## Goal

账号总览保持紧凑；每个提供商有可直接访问的账号详情页；全局页面容器在常规窗口保留最小边距，在大屏提高可用宽度。

## Existing Behavior

账号列表无限增高，同一网格行的空卡片被拉高；所有页面分别限制最大宽度，超大屏留白很大；没有厂商账号详情路由。

## Expected Behavior

账号列表最多 240px 后在卡片内滚动；点击厂商标题进入详情页，查看该厂商所有账号的状态、创建时间等真实元数据，余额显示待接入；所有页面共用左右边距介于 16px 和 96px 的响应式容器。

---

# Analysis

## Related Modules

- `frontend/src/app/routes/__root.tsx` 与 `frontend/src/app/routes/accounts_.$providerId.tsx`
- `frontend/src/features/accounts/`
- `frontend/src/components/common/scroll-region.tsx`
- 各页面局部 `max-w-*` 限制

## Risks

嵌套滚动不能引入横向滚动或破坏已有隐藏滚动条交互；详情页必须处理无效、已删除的提供商 ID；余额没有后端查询能力，不得展示模拟数据。

---

# Implementation Plan

1. 给账号列表设置高度上限和独立滚动，并停止网格拉伸空卡片。
2. 加入以提供商 ID 为参数的详情路由，展示账号真实元数据、管理操作和明确的余额待接入状态。
3. 将宽度和边距规则收敛到根布局，移除页面级宽度冲突，覆盖现有页面。
4. 运行相关测试与 `task verify`，检查普通窗口和大屏窗口的实际布局。

# Progress

- 账号总览的列表限高为 240px，并使用已有 ScrollRegion 保持隐藏滚动条交互；网格卡片不再被同行高卡片拉伸。
- 已新增按提供商 ID 打开的详情路由，展示真实元数据和余额待接入状态。
- 全部页面改用根布局的 16–96px 响应式左右边距，移除冲突的页面级最大宽度。
