# v1.2.7-beta.1 - Codex auth validity safeguards / Codex auth 有效性保护

This beta prevents expired Codex auth files from being imported or written back by one-click configuration when they cannot be refreshed, and falls through to another usable account when available.

本次 beta 阻止一键配置导入或回写已过期且无法刷新的 Codex auth 文件，并在账号池中存在其他可用账号时自动切换。

## Features / 新特性

- None / 无

## Bug Fixes / 问题修复

- **Validated local auth import**: One-click Codex configuration refreshes an expired local `auth.json` before importing it. Credentials that are expired and cannot be refreshed are skipped instead of being added to the account pool as active accounts.
  - **校验本地 auth 导入**：Codex 一键配置会在导入前刷新已过期的本地 `auth.json`；已过期且无法刷新的凭据会被跳过，不再作为正常账号加入账号池。
- **Fresh local account selection**: Before writing account-pool credentials to the local Codex configuration, OmniProxy checks whether the candidate needs a refresh. Failed candidates are marked invalid and the next usable account is selected automatically.
  - **优先选择有效本地账号**：将账号池凭据写入本地 Codex 配置前，OmniProxy 会检查候选账号是否需要刷新；刷新失败的账号会标记为失效，并自动选择下一个可用账号。
- **Safe API fallback**: When neither the local auth file nor the account pool contains a usable Codex account, one-click configuration keeps the existing API login fallback.
  - **安全 API 兜底**：本地 auth 文件和账号池都没有可用 Codex 账号时，一键配置继续使用原有 API 登录兜底。
