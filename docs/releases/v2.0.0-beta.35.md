# OmniProxy v2.0.0-beta.35

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版修三件事：**请求列表里「成功了却显示失败」**、**Codex WebSocket 的失败原因被吞掉**、**自动激活看不出为什么失败**。另外请求归属现在能区分 Codex 的 CLI、桌面应用和 IDE 扩展。

## 1. 请求记录不再把已交付的回答记成失败

之前 Codex（`gpt-6.1-sol` 等）的每一行都是「失败 / 未报告」，但回答其实收到了。原因是透明转发把任何流结束错误都写成 `client_write_failed`，不区分是上游读流断了、客户端收完就断开，还是用量入库失败。现在按可证实的信号判定：

- 已经收到协议终结事件（`response.completed`／`response.incomplete`／`message_delta`／`[DONE]`）之后再断开 → 记为成功。
- 客户端自己结束连接 → 记为「取消」，不再算失败。
- 其余上游读流错误 → `upstream_stream_failed`，并在网关日志里带 `stream_error_side`（`client`／`upstream`）。
- 用量入库失败只标记 `accounting_failed`，不再打断已经交付的回答。

## 2. Token 与用量不再恒为「未报告」

官方 Codex 的流式响应可能不带 `Content-Type`，而旧实现只在上游声明 `text/event-stream`／`application/json` 时才解析用量，于是一整段 SSE 从未被统计。现在上游没声明类型时只读一小段前缀判断是不是 SSE／JSON，再把前缀和剩余正文接回去继续按原字节转发——**客户端收到的内容一个字节都不变**，但输入／输出／缓存 Token 和成本估算能正常统计了。

## 3. Codex WebSocket：失败不再一律 502，账号也会换号

- 握手阶段账号侧失败（凭据不可用、账号冷却、路由不可用）以前被折叠成 `502 upstream_unavailable`，客户端只能无限重连。现在按真实原因返回（例如 `credential_unavailable` 503），网关日志写 `gateway websocket failed` 加稳定代码（不含 URL、账号或令牌）。
- WebSocket 握手没有正文、读不到模型时，取号改为遍历**全部**已授权订阅账号；以前只认第一个账号，那一个借不出凭据整条 WS 就废掉，而带模型的 HTTP 路径却能成功。
- 「Codex WebSocket」开关现在对**已建立**的连接也生效：每个客户端帧转发前复核，关掉开关即断开该连接；普通 HTTP/SSE 不受影响。

## 4. 请求归属区分 Codex CLI / Desktop / VS Code

Agent 列不再只有一个「Codex CLI / Desktop」。网关按客户端自己声明的来源标识细分，请求明细写入 `codex-cli`、`codex-desktop`、`codex-vscode`；识别不出来时仍是 `codex`。原始 `User-Agent`／请求头依旧不落库，只保存映射后的固定标识。

## 5. 自动激活：失败原因看得见了

开启「自动激活 Codex 额度窗口」后，面板和悬浮提示以前只会说「部分账号检测或激活未完成」，日志也只有一句 `code=activation_failed`。现在：

- 状态里保存具体错误码：`quota_unavailable`、`models_unavailable`、`prepare_failed`、`request_failed`、`record_failed`、`identity_changed`、`awaiting_quota`、`accounts_unavailable`。
- 日志增加 `Codex quota activation account failed`（稳定码 + 账号 ID，不含凭据与提示词）。
- 面板与提示条按码显示原因。例如某个账号的官方模型目录为空时会明确提示「请先同步该账号模型」，而不是笼统的失败。

本机实测这一版之前一直在失败的账号（`x4107034@gmail.com`）在数据库里 `account_models` 为 0 行 —— 同一 workspace 的另一个登录有 7 个模型。**这不是本版能自动修的**：请在账号页对该账号执行同步模型，若同步后仍为空，需要重新授权该账号。

## 兼容与已知边界

- 无数据库迁移，`app.json` 结构与 Beta.34 一致；可直接覆盖安装。
- 历史请求记录不会回填：旧行仍是「失败／未报告」，只有新请求按新规则记账。
- WebSocket 透明转发仍不建立逐条请求记录（连接成不成功只体现在客户端提示与网关日志），逐轮记账留作后续任务。
- Codex 约 500k 提前压缩、Google `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项。
- 安装器未签名、未自动安装、未打标签、未推送。

## 安装与数据保留

从托盘完全退出旧版（托盘菜单「退出」，不是关窗口），备份数据目录后覆盖安装。安装后在「设置与关于」核对版本为 2.0.0-beta.35。
