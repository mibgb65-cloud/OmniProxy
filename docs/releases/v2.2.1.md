# OmniProxy v2.2.1 - 账号用量口径修正与仪表盘／账号页布局打磨 / Correct account usage totals and tighter dashboard/accounts layout

Windows amd64 正式版，汇总自 v2.2.0 以来的用量口径修正与界面布局打磨，取代本地未公开的 2.2.1-beta.1 至 beta.5 构建。

This Windows amd64 stable release brings together the account-usage correction and the interface layout polish since v2.2.0. It supersedes the local, unpublished 2.2.1-beta.1 through beta.5 builds.

## Features / 新特性

- **Denser dashboard**: on wide windows the issue and resource cards now stretch to the row height instead of leaving a large empty area underneath, with footers pinned to the card bottom; the trend chart grows with the window and its column ratio narrows from 2:1 to 1.75:1 on very wide screens.
  - **仪表盘右侧卡片自适应填充**：宽窗口下「待处理问题」与「资源概况」不再只按内容撑高、在下方留出大块空白，而是与左侧高卡片等高、脚注统一贴住卡底；调用趋势的绘图高度随窗口分档增高（13／14.5／16.5rem），超宽窗口下左右比例由 2:1 收成 1.75:1，柱状图不再被拉扁。
- **Empty state as a checklist**: with no confirmed issue, the issue card lists subscription sign-in, quota and balance, and routing configuration row by row (`正常 N` or an amber `N 项待处理`); real issues are grouped by account, resource and route, followed by one "rest normal" line.
  - **「待处理问题」空态变成体检清单**：没有已确认问题时不再只剩一行「暂无」，而是逐项给出订阅登录／额度与余额／路由配置的实际结果（`正常 N` 或琥珀色 `N 项待处理`）；有问题时按账号／资源／路由分组，并在列表后带出一行「其余正常」。
- **Resource overview detail**: a health distribution bar (normal／exhausted／failed／unconfirmed, with legend and accessible labels), a per-provider status breakdown sorted by issue count, and cache time／last check／"view quota" collected in the card footer.
  - **「资源概况」补齐分布信息**：新增健康度分段条（正常／耗尽／失败／待确认，含图例与无障碍标签），供应商列表按问题数排序并给出状态点阵与计数，缓存时间、最近检查与「查看配额」收口到卡底。

## Bug Fixes / 问题修复

- **Account token usage is now the lifetime total**: the account card and quota page used to sum only the retained request details (default cap 10,000), so the figure fell as soon as history was evicted and disagreed with the Usage page by 1.5–2.4× (`rv_1jfif`: 749,404,763 vs 1,798,841,626 here). Both now read a per-identity lifetime total that survives detail eviction, account or provider deletion and restarts, and only grows with new traffic.
  - **账号 Token 用量改为终身累计**：账号卡片与配额页此前把「最近留存的 1 万条请求」当成累计值，明细一被淘汰数字就往下掉，同一账号还会比「用量」页少一大截（本机实测 `rv_1jfif` 卡片 749,404,763 对用量页 1,798,841,626）。现在改读按记账身份索引的终身累计表，请求明细淘汰、账号或提供商删除、应用重启都不会让它变小，只有新的代理请求会增加。
- **One identity everywhere**: the identity index also backs the Usage page, dashboard and provider／model totals in the same transaction; subscription identities are provider type + email + workspace, API-key identities are provider type + account ID, and re-adding the same account continues its history instead of restarting at 0.
  - **同一身份两处口径一致**：身份索引与「用量」页、仪表盘、提供商／模型汇总同源同事务；订阅身份为「提供商类型 + 邮箱 + 工作区」，API Key 身份为「提供商类型 + 账号 ID」，删除后重新添加同一账号继续合并历史。
- **Usable reset credits are clickable**: the "can be used" badge looked at the official status while the button also required an exact `reset_type` literal, so a different official spelling (case, underscores) produced "says usable but the button is grey". Both now share one predicate that only normalizes the spelling, and the backend pre-consume check matches; expired, redeemed and clearly foreign credits are still rejected. The refresh button also stays available while a quota read is in flight (only redemption disables it) and spins instead, with a short explanatory line while the latest redemption is checked.
  - **重置卡「使用这张卡」不再无故变灰**：徽标此前只看官方状态，按钮却还要求 `reset_type` 等于字面量 `codexRateLimits`，官方写法（大小写、下划线）不一致时就出现「写着可使用、按钮是灰的」。现在徽标与按钮共用同一判定，类型只做写法归一，后端兑换前的可用性检查同步放宽；过期、已使用、明显属于其他权益的卡仍然拒绝。刷新按钮不再在额度读取期间变灰（仅兑换进行中禁用），改为读取中旋转图标，并提示正在核对最近一次使用记录。
- **Provider dock stays put**: expanding an account no longer pushes the provider switcher around or covers account content. The page scroller is locked (`overflow-y: clip`, offset reset) while only the detail region scrolls, the overlay itself is clipped, and the dock row is declared by the component (`data-has-dock`) instead of being inferred with `:has()`.
  - **账号页提供商切换栏不再上下移动**：展开账号详情后，页面本身被锁定为不可滚动（`overflow-y: clip` 并把偏移归零），只有中间的详情区域可以滚动；覆盖层自身 `overflow: clip`，Dock 所在两行网格改用显式 `data-has-dock` 声明，不再依赖 `:has()` 推断结构。展开第一屏总是回到顶部，底部切换栏固定在底部且不再遮挡账号内容。
- **Capped card width, more columns**: the expanded account panel used to force two equal columns, stretching each card to roughly 1075px at 2560-wide and flattening its quota bars and metrics. It now reuses the detail-page rule (`auto-fill` + `clamp(20rem, …, 28rem)`): 4 × 448px where it used to be 2 × 1075px, and a single column grows to the 28rem cap instead of stopping at 20rem.
  - **展开面板卡片宽度封顶、宽屏只增列**：此前固定两列等分，2560×1392 全屏时单卡约 1075px，卡片里的额度进度条、5h／一周数值与 Token 三列全被摊平。现在沿用详情页既定规则（单卡不超过 28rem、按可用宽度自动增列），同一宽度下从 2 列 × ≈1075px 变为 4 列 × 448px；窄面板只剩一列时用满 28rem 上限。

## Breaking Changes / 不兼容更新

None. Installation identity, account data, routing, client configuration and data locations are preserved; the only schema change is migration 045 (new table plus backfill).

无。沿用安装身份、账号数据、路由、客户端配置与数据位置；唯一的库结构变更是迁移 045（新建表并回填）。

## Refactor & Performance / 重构与优化

- **Cheaper account usage read**: the card no longer aggregates the retained request details; it reads one row by identity key, while pending requests still come from the retained details. Cache snapshots only grow — a later snapshot without cache fields no longer wipes a known value, and the same cache figure reported twice is counted once.
  - **账号用量读取更省**：卡片不再聚合仍保留的请求明细，改为按身份主键读一行；待处理请求数仍取留存明细。缓存明细只增不减——后续快照缺少缓存字段时不再把已知值改写为未知，同一份缓存重复上报也只计一次。
- **Regression guards**: the dashboard checklist and the issue list share one filter with a unit test asserting equal issue counts; CSS assertion tests pin the auto-fill column rule and reject fixed column counts again.
  - **回归保护**：体检清单与问题列表共用同一过滤口径，并有单元测试断言两者的问题总数相等；新增 CSS 断言测试锁住「自动增列 + 单卡封顶」，禁止再写固定列数。
- **Consistent accessibility**: status colour dots never carry information alone (screen-reader text attached) and the health bar uses `role="img"` with a full text label.
  - **无障碍一致**：状态色点不单独承载信息（附屏幕阅读器文本），健康条带 `role="img"` 与完整文案标签。

## Upgrade notes / 升级说明

- Exit the app normally and make a consistent data-directory backup, including SQLite WAL, before upgrading. Upgrading from v2.2.0 does not require account re-import or moving the data directory.
  - 升级前正常退出应用，并做包含 SQLite WAL 的一致性数据目录备份；从 v2.2.0 升级无需重新导入账号或搬迁数据目录。
- **Expect account token numbers to grow**: migration 045 seeds the lifetime table from the existing daily buckets on first start, so the card and quota page immediately show the historical total instead of the retained-detail subset (749,404,763 → 1,798,841,626 on the account measured here). Cached input detail is only recovered where request details are still retained; older parts stay a lower bound (`≥`) instead of being fabricated.
  - **账号 Token 数字会明显变大**：首次启动时迁移 045 会从既有每日桶回填终身累计，卡片与配额页立刻显示历史累计，而不是受保留上限约束的明细子集（本机实测该账号 749,404,763 → 1,798,841,626）。缓存明细只能回填仍在保留期内的部分，更早的部分显示下界（`≥`），不伪造完整值。
- The "request detail limit" setting no longer affects the card figures; it only decides how far back the Requests page can page.
  - 「请求明细上限」不再影响卡片数字，只决定请求页能翻到多少条历史。
- Application and installer version: `2.2.1`; Windows numeric resource version: `2.2.1.0`. This stable version is newer than all local `2.2.1-beta.*` builds.
  - 应用与安装器版本为 `2.2.1`，Windows 数字资源为 `2.2.1.0`；本正式版高于所有本地 `2.2.1-beta.*`。
- No new dependencies; migration 045 only reads existing tables and does not rewrite request details.
  - 无新增依赖；迁移 045 只读既有表，不改写请求明细。

## Release verification and limits / 发布校验与边界

- Public assets are built by GitHub Actions. Before publication the installer is self-signed with the pinned project certificate and checked for signature validity, certificate pin, tamper rejection and final SHA256. Local unsigned validation packages are not public release assets.
  - 公开资产由 GitHub Actions 构建；发布前使用固定项目证书自签安装器，校验签名、证书 pin、篡改拒绝和最终 SHA256。本地未签名验证包不作为公开发布资产。
- Self-signing is not publicly trusted CA signing and may still trigger SmartScreen or unknown-publisher warnings. The application executable is not separately signed, and the installer does not import the certificate into the user's trust stores.
  - 自签不等同于公开受信任 CA 签名，仍可能触发 SmartScreen／未知发布者提示；应用本体暂不单独签名，安装器不向用户信任库导入证书。
- The 2.2.1-beta.1–beta.5 builds were local and unsigned. Automated tests, isolated browser checks and this build do not replace a real in-place upgrade from v2.2.0, the first real run of migration 045, native WebView2 layout at 140% font size, or real client traffic.
  - 2.2.1-beta.1 至 beta.5 仅为本地未签名构建；自动测试、隔离浏览器检查与本次构建都不能替代从 v2.2.0 的真实覆盖安装、迁移 045 的首次实机执行、140% 字号下的原生 WebView2 观感与真实客户端请求。
