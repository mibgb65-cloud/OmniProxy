# OmniProxy v2.2.3-beta.15

## Bug Fixes / 问题修复

- Antigravity sessions no longer die at 30 seconds. The subscription client waited only 30 s for upstream response headers, but the thinking models the desktop app uses (Gemini 4 Argon and friends) can think for a minute or more before the first token — and a streaming response has no headers until that first chunk. Every request was therefore aborted at ~30.1 s and surfaced as `502 operation_failed`. The header wait is now 5 minutes; connect and TLS handshakes still fail fast at 10 s. / Antigravity 会话不再在 30 秒被掐断。订阅客户端只等上游 30 秒响应头，而桌面端使用的思考型模型（Gemini 4 Argon 等）在第一个 token 之前可能先想一分钟以上，流式响应也要等第一个分片才有响应头，于是每个请求都在约 30.1 秒被中止并映射为 `502 operation_failed`。现在响应头等待放宽到 5 分钟；连接与 TLS 握手仍在 10 秒内快速失败。
- Desktop agent sessions get their own overall budget. The regular 120 s request limit would cut a long streaming answer mid-flight; Antigravity now gets at least 10 minutes, while every other client keeps its existing limits. / 桌面代理会话有独立的总体时限。普通请求的 120 秒会在长流式回答中途切断；Antigravity 现在至少 10 分钟，其它客户端时限不变。

## Breaking Changes / 不兼容变更

None / 无。No database migration or public API change; other clients, protocols and timeouts are untouched / 无新增数据库迁移或公共 API 变更；其它客户端、协议与时限不变。

## Verification and limits / 校验与边界

- `task --force verify` passed: format check, lint, typecheck, Go test packages, frontend suite (147 files / 898 tests) and the Windows production build. / `task --force verify` 通过：格式检查、lint、类型检查、Go 测试包、前端测试（147 文件／898 项）与 Windows 生产构建。
- Reproduced and fixed end-to-end on an isolated instance built from this source (copy of the production data directory, separate port, running app untouched): a streaming request with an ~8 KB system prompt and a deliberately slow thinking model completed in **60.3 s** with status 200 (`gemini-4-argon-high`); the same shape failed at 30.1 s before the change. A normal streamed request still returns in 9.1 s. / 由本源码构建的隔离实例上完成复现与验证（生产数据目录副本、独立端口，未触碰运行中的应用）：带约 8 KB system、故意选慢速思考模型的流式请求 **60.3 秒**返回 200（`gemini-4-argon-high`）；改动前同样的请求在 30.1 秒失败。普通流式请求仍 9.1 秒返回。
- New unit tests pin the header-timeout floor, require the whole-request client timeout to stay unlimited, and check that only Antigravity gets the wider budget. / 新增单元测试固定响应头时限下限、要求整请求超时保持无限，并确认只有 Antigravity 得到更宽的时限。
- The desktop app itself has not been re-tested here; after installing, send a message in Antigravity and check the request detail shows status 200. / 桌面端本身未在此环境复测；安装后在 Antigravity 发一条消息，请求明细应显示 200。
- The local installer is unsigned and may trigger an unknown-publisher or SmartScreen warning. Building does not install or launch the application. / 本地安装器未签名，可能触发未知发布者或 SmartScreen 提示；构建不安装、不启动应用。
