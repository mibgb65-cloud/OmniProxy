# OmniProxy v2.2.3-beta.11

## Features / 新功能

- Antigravity desktop app (2.15+) now connects to the local gateway through its official Enterprise Gateway. The gateway page writes the two settings files the app reads (`~/.gemini/config/config.json` for 2.30+, `~/.antigravity/settings.json` for 2.29 and earlier), points `models.listSource` at the local catalog, and keeps the user's other settings. No TLS interception, local CA, system proxy or Google sign-in is needed. / Antigravity 桌面端（2.15+）现在可以通过官方 Enterprise Gateway 接入本地网关。网关页会写入桌面端读取的两个设置文件（2.30+ 为 `~/.gemini/config/config.json`，2.29 及以前为 `~/.antigravity/settings.json`），把 `models.listSource` 指向本机目录，并保留用户其他设置。不需要 TLS 拦截、本地 CA、系统代理或 Google 登录。
- The Antigravity model menu now publishes every text model the Google subscription actually provides: Gemini, Claude and GPT-OSS. The default model prefers the official default, then Gemini; Claude and GPT-OSS can be picked from the card or the app's own picker. / Antigravity 的模型菜单现在发布 Google 订阅实际提供的全部文本模型：Gemini、Claude 与 GPT-OSS。默认模型优先官方默认，其次 Gemini；Claude 与 GPT-OSS 可在卡片或桌面端自己的模型选择器中选择。
- Requests from the desktop app reuse the existing Google subscription account pool, quota cooldown, failover and request history. Only fields the subscription Chat adapter does not accept (`reasoning_effort`, `service_tier`, `metadata`, `store`) are removed, and only for this client. / 桌面端请求复用现有 Google 订阅账号池、额度冷却、故障切换与请求记录。仅对该客户端移除订阅 Chat 适配器不接受的字段（`reasoning_effort`、`service_tier`、`metadata`、`store`）。
- Disconnecting now removes only the managed `gateway` / `models` fields and restores their original values, so theme, permissions and other settings the app writes while connected are preserved. Gateway port changes rewrite both settings files. / 断开时只撤销受管的 `gateway`／`models` 字段并恢复原值，连接期间桌面端写入的主题、权限等设置保留；网关端口变化会同步改写两个设置文件。

## Bug Fixes / 问题修复

- The desktop app's catalog request is accepted when it carries the gateway key as `x-goog-api-key`, not only as a bearer token. The header is treated as a local access key and never forwarded upstream. / 桌面端目录请求以 `x-goog-api-key` 携带网关 Key 时也能通过鉴权，不再只接受 Bearer；该头只作为本地接入 Key，不转发上游。
- The desktop app rewrites its own settings while connected; disconnecting no longer fails with `config_changed` because the whole file changed. / 桌面端连接期间会改写自己的设置；断开不再因为整文件变化而报 `config_changed`。

## Breaking Changes / 不兼容变更

None / 无。No database migration or public API change / 无新增数据库迁移或公共 API 变更。Antigravity integration is off until the user connects the card; existing clients and settings are unchanged / Antigravity 接入在用户点击连接前不生效，现有客户端与设置不变。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release. Fully exit OmniProxy from the system tray (the running instance is an older build), back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布。请先从托盘完全退出 OmniProxy（当前运行的是更早的构建），备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.2.3-beta.11`; Windows numeric resources: `2.2.3.0`; NSIS installer base version: `2.2.3`. / 应用／前端版本为 `2.2.3-beta.11`，Windows 数字资源版本为 `2.2.3.0`，NSIS 安装器基础版本为 `2.2.3`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。
- To use Antigravity: start the desktop app once, open OmniProxy → Gateway → Local agents → Antigravity, connect and pick a default model, then quit and restart Antigravity. While connected the app uses no Google sign-in, so Google account experiments and commands such as `/boost`, `/teamwork` and `/plugin` are unavailable until you disconnect. / 使用 Antigravity：先启动一次桌面端，打开 OmniProxy → 网关 → 本地 Agent 接入 → Antigravity，连接并选择默认模型，然后完全退出并重启 Antigravity。连接期间不使用 Google 登录，`/boost`、`/teamwork`、`/plugin` 等 Google 账号功能在断开前不可用。
- Organisation-level `admin_settings.json` or `AGY_LLM_GATEWAY_*` variables take precedence over the user settings and are not rewritten by OmniProxy. / 组织级 `admin_settings.json` 或 `AGY_LLM_GATEWAY_*` 变量优先于用户设置，OmniProxy 不会改写它们。
