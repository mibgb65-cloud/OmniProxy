# v1.3.1-beta.4 - Fix token usage lost on compressed streams / 修复压缩流下 token 用量丢失

Claude Code and Codex send `Accept-Encoding: gzip, deflate, br`. Providers such as Atria answer with a brotli compressed event stream, so the proxy's usage capture kept the compressed bytes and could not find any `data:` line. Requests succeeded (status 200) but per-request token usage, token stats, and the history page all recorded zero. The bytes forwarded to the client were never affected.

Claude Code 与 Codex 会发送 `Accept-Encoding: gzip, deflate, br`，Atria 等服务商会以 brotli 压缩事件流返回。代理留作统计的响应体副本仍是压缩字节，找不到任何 `data:` 行，于是请求成功（状态 200）但每次请求的 token 用量、令牌统计与历史请求页全部记为 0。转发给客户端的字节不受影响。

## Features And Fixes / 新增与修复

- Decode the captured response body according to the upstream `Content-Encoding` (gzip / deflate / br) before parsing usage, model, and error summaries. Only the internal copy is decoded; the client still receives exactly the bytes the upstream sent.
  - 解析用量、模型与错误摘要之前，先按上游 `Content-Encoding`（gzip / deflate / br）解码留存的响应体副本；只有内部副本被解码，客户端收到的仍是上游的原始字节。
- Added `github.com/andybalholm/brotli` to support the encoding Atria actually picks when the client offers `br`.
  - 新增 `github.com/andybalholm/brotli` 依赖，覆盖客户端提供 `br` 时 Atria 实际选用的编码。
- Regression test `service_usage_compressed_test.go` replays a gzip / deflate / brotli event stream through the gateway and asserts usage is recorded; disabling the fix reproduces the zero-token history entries seen in v1.3.1-beta.3.
  - 回归测试 `service_usage_compressed_test.go` 通过网关回放 gzip / deflate / brotli 事件流并断言用量已记录；关掉该修复会复现 v1.3.1-beta.3 中历史记录 0 token 的现象。
- Tightened the Atria streaming usage assertions and added coverage for the one-click gateway paths, the documented anonymous `data:` stream format, and routing alongside an official Anthropic token.
  - 收紧 Atria 流式用量的断言，并补充一键配置网关路径、文档中的匿名 `data:` 流格式，以及与官方 Anthropic 令牌并存路由的覆盖。

## Upgrade Guidance / 升级说明

- This is a bug fix with no configuration change. Restart OmniProxy after upgrading so the fix applies to new requests.
  - 纯缺陷修复，无需改动配置；升级后重启 OmniProxy 即可对新请求生效。
- Token usage that was already recorded as zero in earlier betas is not backfilled; totals accumulate from new requests onward.
  - 早期 Beta 中已经记为 0 的用量不会回填，总量自新请求起开始累计。
- Atria exposes no balance or rate-limit endpoint, so the quota page still falls back to a fixed percentage; the usage column and history page now populate.
  - Atria 没有余额或限流接口，额度页仍回落到固定百分比；用量列与历史请求页会正常显示。
