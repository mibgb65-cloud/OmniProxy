# OmniProxy v2.0.0-beta.29

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版主要改动是**每个 Agent 使用固定入口地址**：Codex 恢复旧版 v1 的 `/codex/v1` 形态并保留官方登录，其余客户端各自一个前缀。同时一并包含工作区里已完成但未提交的 River 图片输入与客户端图片能力声明。数据库结构未变，无新迁移。

## 每个 Agent 一个固定入口

以前所有客户端共用 `http://127.0.0.1:端口/v1`，Codex 例外地使用带 Key 的长路径 `/agent/codex/<Key>/v1`。现在每个受管 Agent 都有自己的固定前缀：

| 客户端 | Base URL | 客户端自己追加的路径 |
| --- | --- | --- |
| Codex | `…/codex/v1` | `/responses` |
| Claude Code CLI、Claude Desktop | `…/claude` | `/v1/messages` |
| OpenCode | `…/opencode/v1` | `/chat/completions` |
| Kilo Code、MiMo Code、Qwen Code | `…/kilocode/v1`、`…/mimo-code/v1`、`…/qwen-code/v1` | `/chat/completions` |
| Harness Web／Desktop | `…/harness-web/v1`、`…/harness-desktop/v1` | `/chat/completions` |
| Kimi Code、Pi、Factory Droid | `…/kimi-code/v1`、`…/pi/v1`、`…/factory-droid/v1` | `/chat/completions` |
| Goose | `…/goose/v1/chat/completions` | 不追加，本身就是端点 |

- 前缀只做路由分组：进入网关后立即折叠回 `/v1/...`，协议解析、请求体上限（Responses／Messages 16 MiB、Chat 2 MiB）、查询参数白名单、并发与统计口径完全不变。
- 带接入 Key 的请求如果走错别的 Agent 的前缀，直接返回 `403 client_mismatch`，不会出现「用 Claude 的 Key 走 Codex 入口」的记账矛盾。
- 近似路径（例如 `/codexanything/v1/responses`）不会被当成前缀，仍然 404，网关不提供通用转发。

## Codex 恢复 `/codex/v1`，官方登录保留

新版 Codex 不允许重定义内置 `openai` 提供商表，因此旧做法只能把接入 Key 拼进路径。本版改为：

- `openai_base_url` 直接写 `http://127.0.0.1:端口/codex/v1`，配置里**不再出现接入 Key**。
- 官方 `auth.json`、登录方式、`model_provider`、会话目录一个字节都不改；Codex 仍以 ChatGPT 身份登录。
- 由于 Codex 在官方登录模式下发送的是 ChatGPT 令牌（超长 JWT），网关无法用它做接入 Key 校验，`/codex` 入口改为**在 Codex 接入启用时按前缀归属放行**；停用该接入后该入口随即关闭。其余入口仍强制要求接入 Key。
- 自定义提供商的 Codex 配置继续写入 `experimental_bearer_token`，那种形态下前缀校验照常按 Key 生效。

## River 图片输入

River 四款官方模型现在可以真正接受图片（此前目录只标文本、遇到图片本地就拒绝）：

- Claude Code／Desktop 的 Messages 与 Responses 图片历史、工具结果里的截图都按官方契约转换成 Chat `image_url` 块后转发。
- 支持 base64 data URL 与外部 URL；格式限官方公布的 JPEG／PNG／GIF／WebP，单图 base64 上限 16 MiB（组件有界值，低于官方 32 MiB），`detail` 只透传 `low`／`high`／`auto`／`original`。
- 仍然明确拒绝 `input_file`、`input_audio`、未知 `source.type`、非 base64 数据，不静默删除内容。

## 客户端目录的图片能力

受管客户端的模型目录按上游已确认能力声明图片输入：Harness／Pi 写 `input`、OpenCode／Kilo／MiMo／Qwen 写 `modalities.input`、Goose 写 `supports_vision`。未确认能力的模型在客户端里保持纯文本，不会被误允许附图。

## 兼容与已知边界

- 无新迁移，无数据格式变化；历史记录、设置与凭据保持原样。
- **已应用的客户端配置需要重新「预览 → 应用」才会换成新地址**。旧地址 `/v1/...` 与 `/agent/codex/<Key>/v1` 在本版继续可用，升级后不会立即失效；模型目录刷新会自动把已接管的聊天类客户端改写成新前缀，Codex 需手动重新应用。
- Claude Code CLI 与 Claude Desktop 共用 `…/claude`，两者只靠各自的接入 Key 区分归属与用量统计。
- 前缀不是配额边界：并发槽与请求期限仍是全局的。
- 安装器未签名、未自动安装、未打标签、未推送；真实覆盖安装与客户端重连由用户本地验收。
- Codex 在约 500k 用量时提前压缩、Google 上游 `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项，本版不宣称已修复。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在「设置与关于」核对版本为 2.0.0-beta.29，然后重新应用各 Agent 的一键配置。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布。
