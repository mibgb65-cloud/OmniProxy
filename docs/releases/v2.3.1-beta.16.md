# OmniProxy v2.3.1-beta.16

## Bug Fixes / 问题修复

- Signing in to WorkBuddy AI no longer ends with "the operation did not finish" while the account list stays empty. The browser sign-in itself worked: the token poll and the identity read both succeeded, but saving the new account failed locally. The `INSERT INTO accounts` statement listed 11 columns while supplying 12 values (the Google variant's `auth_email` column was dropped from the column list but its value was left in place), so SQLite rejected it at prepare time with `12 values for 11 columns`. / 登录 WorkBuddy AI 后不再出现「操作未完成」而账号列表仍为空。浏览器登录本身是成功的：令牌轮询与身份读取都通过了，失败发生在本地保存新账号这一步。`INSERT INTO accounts` 声明了 11 列却提供了 12 个值（从 Google 版改写时从列清单里删掉了 `auth_email`，却把对应的值留在原处），SQLite 在 prepare 阶段就以 `12 values for 11 columns` 拒绝。
- Failures now carry actionable codes instead of one generic message. A save failure reports `save_failed` (retry — the upstream token is still valid, no need to sign in again), a concurrent change reports `configuration_changed`, and a locally rejected request reports `invalid_input`. / 失败不再统一塌成一句通用文案：保存失败报 `save_failed`（直接重试即可，上游令牌仍然有效，不需要重新登录）、并发修改报 `configuration_changed`、本机拒绝的请求报 `invalid_input`。
- Sign-in failures are now written to the log with their stage (`token` / `identity` / `save`) and stable code. Previously the whole background sign-in failure path was silent, which is why a local SQL mistake looked like a network problem. / 登录失败现在会带阶段（`token`／`identity`／`save`）与稳定码写入日志。此前整条后台登录失败路径都是静默的，这也是一个本地 SQL 错误表现成「网络问题」的原因。
- The browser authorization card now says that the WorkBuddy page may offer to return to the WorkBuddy app after signing in — that is normal and OmniProxy receives the result automatically. / 浏览器授权卡片新增说明：WorkBuddy 登录页在登录后可能提示返回 WorkBuddy 客户端，这属正常现象，OmniProxy 会自动收到登录结果。

## Breaking Changes / 不兼容变更

None / 无。No new database migration (`050` / `051` shipped with `v2.3.1-beta.15` and were already applied), no public API change, and the WorkBuddy upstream protocol is untouched. / 无新增数据库迁移（`050`／`051` 已随 `v2.3.1-beta.15` 发布并执行过）、无公共 API 变更、未改动 WorkBuddy 上游协议。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.16`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.16`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved. The failed sign-in left no account behind, so just retry the WorkBuddy AI sign-in after installing. / 保留现有账号、路由、统计与客户端配置。上次失败的登录没有留下账号，安装后重新点一次 WorkBuddy AI 登录即可。

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests (157 files / 964 tests) and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试（157 文件／964 项）与 Windows 生产构建。
- New regression coverage: creating a WorkBuddy AI account persists it (the broken statement shape is reproduced as `12 values for 11 columns` with sqlite3), re-signing in with the same identity does not create a second account, tokens never appear in account metadata, rotation keeps the model catalog bound to the new version, and the save failure exposes a stable code. / 新增回归覆盖：新建 WorkBuddy AI 账号能落库（用 sqlite3 复现了坏语句形状 `12 values for 11 columns`）、同一身份重新登录不会建出第二个账号、令牌不出现在账号元数据里、续期后目录仍绑定新版本、保存失败给出稳定码。
- **Not verified**: the real end-to-end retry after installing — sign in, `/v3/config` catalog sync, a real chat completion and Credits readings. The catalog and chat paths still need your account; chat consumes real credits. / **未验证**：安装后的真实端到端重试——登录、`/v3/config` 目录同步、真实对话与 Credits 读数。目录与对话仍需要你的账号验证，对话会消耗真实积分。
