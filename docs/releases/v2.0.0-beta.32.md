# OmniProxy v2.0.0-beta.32

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版把 Codex 的转发流程整体换回 v1 形态：**透明转发**、**真 WebSocket**、**登录归网关**。新增迁移 042（给 `codex_settings` 增加 `upstream_base_url`，默认仍是官方订阅端点）。

## 1. 透明转发：前缀之后不再有端点白名单

`…/codex/v1/…` 与 `…/agent/codex/<接入Key>/v1/…` 前缀之后的任意子路径都会转发到上游：

- 路径按 v1 规则归一：剥离 `/backend-api/codex`、`/codex`、`/v1` 后拼到上游基址，`/v1/responses` → `…/backend-api/codex/responses`，`/v1/responses/compact` → `…/responses/compact`，`/v1/models` → `…/models`。
- 客户端请求头整体透传：`originator`、`session_id`、`conversation_id`、`OpenAI-Beta`（含压缩与 WS 协商）、`User-Agent` 都保留；只替换 `Authorization` 与 `ChatGPT-Account-ID`。
- 请求正文不再改写：不再强制 `store=false` / `stream=true`，不再删除 `max_output_tokens`、`temperature`、`top_p`，压缩编码原样转发。
- 上游基址可配置（默认 `https://chatgpt.com/backend-api/codex`），可用自建反代。
- 客户端 Base URL 仍是 `http://127.0.0.1:<端口>/codex/v1`，已应用的配置无需重写。

## 2. WebSocket 真正桥到上游

升级 Codex 的 WS 请求不再在本地翻译成 HTTP 调用，而是直接拨到上游 `wss` 并双向原样中继帧（单帧上限 16 MiB）。

- 客户端握手头随请求带到上游：`originator`、`session_id`、`User-Agent`、`OpenAI-Beta` 等都保留；握手自身管理的头（`Connection`／`Upgrade`／`Sec-WebSocket-*`）与 `Origin` 由网关重新生成。
- 握手被明确拒绝（401／429／5xx）时会换同池账号重拨，成功后才应答客户端。
- 网关「OpenAI 账号设置」里的 WebSocket 开关仍然生效：关闭时拒绝握手。
- 客户端配置里的 `features.responses_websockets` 仍保持 `false`：通道已就绪，但默认不强行打开未验证的协议版本。

## 3. 两种客户端基址都可用

`…/codex/v1/…`（当前一键配置写出的地址）与 `…/backend-api/codex/…`（v1 时代的基址）都进入同一套透明转发，旧配置不必改也能用。

## 4. 登录由网关拥有（v1 的池账号形态）

- 新增凭据类型：池账号的完整 `auth.json`（访问令牌＋续期令牌＋账号标识）存在本应用的受保护凭据存储里，SQLite 只留邮箱／套餐／官方账号 ID。
- 导入：把本机 `~/.codex/auth.json` 收进池；同一官方账号重复导入只更新凭据，不新增账号。
- 续期：访问令牌临近过期（30 分钟余量）时，网关用池里的 `refresh_token` 自己走 `auth.openai.com/oauth/token` 换新，并把新 `auth.json` 写回池记录；回写只换凭据，不改账号版本，不会打断进行中的请求。
- 下发：Codex 一键配置会把池账号写成客户端 `~/.codex/auth.json`（先留 `auth.json.omniproxy.bak`）；「恢复配置」会还原你原来的登录并删除备份。没有池账号时不接管登录。
- 原有的官方隔离登录账号仍然可用：两种登录来源共用同一套路由、冷却与换号逻辑。

## 5. 失败与切换

- 只有明确拒绝（401、429、5xx）才换同池账号；成功响应与已提交的响应不重放。
- 冷却窗口与协议路径共用同一份健康状态；并发上限、loopback Host 校验、接入 Key 归属校验都保留。
- 请求记账照旧：透传流也会统计状态、耗时、首字与 Token 用量（压缩响应正文时用量可能未知）。

## 兼容与已知边界

- 新增迁移 042；`codex_settings.upstream_base_url` 默认取官方订阅端点，旧数据库升级后行为不变。
- `chat/completions` 与 `messages` 仍走协议转换（订阅端点只接受 Responses）；`/v1/codex-models` 仍是本地目录。
- 「从本机 Codex 登录导入」目前只有后端绑定，界面还没有按钮。
- Codex 在约 500k 用量时提前压缩、Google 上游 `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项。
- 安装器未签名、未自动安装、未打标签、未推送。

## 安装与数据保留

先从托盘完全退出旧版，备份数据目录后覆盖安装。安装后在「设置与关于」核对版本为 2.0.0-beta.32，然后对 Codex 重新「预览 → 应用」：这次应用会把池账号写进客户端登录（若池里有账号）并重新写入网关地址。
