# OmniProxy v2.2.3-beta.8

## Features / 新功能

None / 无。

## Bug Fixes / 问题修复

- Saving the gateway port no longer moves it when the gateway is already listening on that port. With the app running on port 3000, saving `3000` used to bump the listener to `3001` and rewrite managed client addresses; it is now a no-op.
  - 网关正在使用某个端口时，再保存同一个端口不再被换成下一个端口。此前软件开着（生产 3000）点「保存端口」会被自动避让到 3001 并改写受管客户端地址；现在按无变化处理。
- The availability check now excludes the port this app holds itself. Other ports, and ports genuinely occupied by another program, are still detected and avoided exactly as before.
  - 端口检测排除本应用自己正在监听的端口；其它端口，以及确实被其它程序占用的端口，仍按原逻辑探测与避让。
- 「恢复默认端口」no longer restarts the listener when the default port is already the current one, so in-flight requests are not cancelled.
  - 「恢复默认端口」在默认端口就是当前端口时不再重启监听器，在途请求不会被取消。
- The settings card already showed “port available / gateway is listening” in this state; only the save path disagreed. The two now report the same thing.
  - 该状态下设置卡片本就显示「端口可用／网关正在监听」，只有保存路径的结论不一致；现在两者一致。

## Refactor & Performance / 重构与性能

- Added `AppService.listeningPort()`, which reports a port only while the gateway state is `running` (the port kept after `error` / `stopped` is not treated as owned), and used it for both the status and the save path. No new dependency.
  - 新增 `AppService.listeningPort()`，仅在网关状态为 `running` 时返回端口（`error`／`stopped` 保留的端口号不算持有），状态与保存两处共用同一判定。No new dependency / 无新增依赖。
