# OmniProxy v2.3.1-beta.29

## New Features / 新功能

- Google (Antigravity) subscription accounts now take their quota windows into account when the gateway picks an account. If the published quota snapshot says a window of the model's quota group is at 0% and its reset is still ahead, the account is skipped for that model: the request is not sent at all. Groups are matched by the official group names — `gemini-4-argon*` belongs to the `Gemini 4 Argon` pool, `claude*`／`gpt*` to `Claude and GPT models`, the remaining `gemini*` to `Gemini Models`. Models that cannot be classified, missing snapshots and untrusted snapshots are never pre-screened. / Google（Antigravity）订阅账号的额度窗口现在参与选号：已发布的额度快照里，该模型所属分组任一窗口为 0% 且重置时间未到时，路由直接跳过该账号、根本不发送请求。分组按官方分组名归类——`gemini-4-argon*` 属 `Gemini 4 Argon` 池，`claude*`／`gpt*` 属 `Claude and GPT models`，其余 `gemini*` 属 `Gemini Models`。无法归类的模型、缺少快照与不可信快照都不预筛。
- A 429 from a Google subscription account is now an account-level rejection instead of a plain client error: a 429 without the official "quota will reset after …" text used to be classified as `rate_limited`, while the failover policy deliberately ignored every Google 429 (that rule exists for API Key accounts, whose keys share one project quota). The account was therefore never cooled and never switched, so `balanced` rotation kept sending every ninth request into the exhausted account. The gateway now switches to the next account in the same pool within the same request and cools that (account, model) until the reset time known from the snapshot — 60 seconds when neither the upstream nor the snapshot says when. API Key accounts keep the old behaviour: no key switching, no account cooldown. / Google 订阅账号的 429 现在是账号级拒绝，而不是直接返回给客户端：没有官方「quota will reset after …」正文的 429 以前只归成 `rate_limited`，而故障切换策略刻意忽略所有 Google 429（这条规则是给共享同一项目额度的 API Key 账号用的），于是账号既不冷却也不换号，`balanced` 轮换每九个请求就往耗尽的账号送一次。现在同一请求内换到同池下一个账号，并把该（账号，模型）冷却到快照里已知的重置时间；上游与快照都没给时按 60 秒。API Key 账号保持原行为：不换 Key、不写账号冷却。
- After such a 429 the exhausted account's quota snapshot is refreshed once in the background (at most once per minute per account), so the other models of the same group are skipped as well and the account card shows the real remaining quota without waiting for a manual refresh. / 429 之后该账号的额度快照会在后台刷新一次（每账号每分钟至多一次），同组其它模型随后也会被跳过，账号卡不必等手动刷新就能显示真实剩余。

## Notes / 说明

- Everything else stays the same: the same request still fails over at most three accounts, all candidates skipped or cooling returns `429 account_pool_cooling` with the earliest recovery seconds, fixed accounts and explicit channels are not reordered, and no probe request is sent to an exhausted account. / 其余行为不变：同一请求最多尝试三个账号，全部候选被跳过或冷却时返回 `429 account_pool_cooling` 与最早恢复秒数，固定账号与显式通道不参与重排，也不向已耗尽账号发送探测请求。
- The pre-screen only reads the snapshot that is already stored (one indexed row lookup), so it does not add an official query per inference request. A stale 0% never blocks an account past its reset time. / 预筛只读已经落库的快照（单行索引查询），不会给每个推理请求增加一次官方查询；过期的 0% 也不会把账号屏蔽到重置时间之后。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no API, configuration or UI change: the behaviour change is limited to how Google subscription accounts are ordered and cooled. / 无数据库迁移、无 API／配置／界面变更：行为变化只限 Google 订阅账号的排序与冷却。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.29`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.29`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, re-enable any Google account you disabled while it was exhausted (it was disabled manually, not by the gateway). The routing change needs no re-login and no re-sync. / 升级后可以把之前因为额度耗尽而手动停用的 Google 账号重新启用（那是手动停用，不是网关改的）。本改动不需要重新登录或重新同步。
- The first request that reaches an account whose snapshot is still empty may still get one 429; it now fails over to another account within the same request instead of surfacing the error. / 如果某个账号还没有额度快照，第一个打到它的请求仍可能吃到一次 429；现在它会在同一请求内换号，而不是把错误抛给客户端。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 163 frontend files / 1000 tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 163 文件／1000 项测试与 Windows 生产构建。
- Covered by tests: model-to-group classification (including Argon staying out of the Gemini group), "wait for every spent window" reset calculation, ignored unknown／expired／reset-less states, the read-only gate (account version, login state, untrusted snapshots), 429 failover with cooldown, pre-screen skipping, pool cooling when every candidate is skipped, and the API-Key／Codex boundaries. / 测试覆盖：模型到分组归类（Argon 不并入 Gemini 组）、多个耗尽窗口取最晚重置、未知／过期／缺重置状态不预筛、只读额度门（账号版本、登录态、不可信快照）、429 换号与冷却、预筛跳过、全部候选被跳过时的池冷却，以及 API Key／Codex 的边界。
- **No real model request was sent while building this version**, and the routing change was not observed against a live exhausted account: the behaviour is locked by gateway tests driving two same-pool accounts through a real gateway port, but the real upstream responses are still unconfirmed. / **本版本打包时未发起任何真实模型请求**，也没有在真实耗尽的账号上观察这条链路：行为由网关测试锁定（两个同池账号走真实网关端口），真实上游返回仍待确认。
