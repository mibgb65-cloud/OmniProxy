# OmniProxy v2.3.1-beta.9

## Bug Fixes / 问题修复

- The Quota page marked every HowToFix account as “Not supported yet” / 「暂不支持」 and only showed a hint that balance queries were not wired up, even though the accounts page already displayed the prepaid USD balance. The quota resource classification only recognised DeepSeek, Kimi and StepFun balance accounts, so HowToFix fell through to the unsupported branch: no balance query, no refresh button, no contribution to the monitored-account counters. / 配额页把每个 HowToFix 账号都标成「暂不支持」，只提示「此账号的额度或余额查询尚未接入」，而账号页其实已经能显示预付美元余额。原因是配额页的资源归类只认 DeepSeek、Kimi 与阶跃星辰的余额账号，HowToFix 落到「未支持」分支：不查询余额、没有刷新按钮、也不计入可监控账号统计。
- HowToFix now uses the existing balance resource type, so the quota card shows the official prepaid USD remaining amount with the same refresh, batch refresh, retained-snapshot and status-counting behaviour as the other balance providers. / HowToFix 现在复用既有「余额」资源类型，配额卡显示官方的预付美元剩余额度，并与其它余额服务商共用刷新、批量刷新、快照保留与状态统计。
- The same card shows the locally recorded token usage (input / output / cached) under the balance, separated by a divider and labelled as local usage that is not the official bill. Balance and token usage are two different sources and are never merged into one number. / 同一张卡片在余额下方显示本机记录的 Token 用量（输入／输出／缓存），用分隔线分区并注明本机用量不是官方账单；余额与 Token 用量是两种来源，不合并成一个数字。
- A missing or unparsable remaining amount is reported as “Data unconfirmed” instead of “Exhausted”: the exhausted state still comes from the backend comparison, so absent data is never turned into a zero balance. / 上游没返回或无法解析金额时显示「数据待确认」而不是「余额耗尽」；耗尽判定仍由后端比较得出，缺数据不会被当成零余额。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no gateway or routing change. The HowToFix accounts keep the same stored credentials and catalogue. / 无数据库迁移、无公共 API 变更、不改网关与路由；HowToFix 账号的凭据与目录保持不变。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.9`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.9`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. After opening the Quota page the HowToFix cards query the balance directly; the token usage section reads the local request history. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。打开配额页后 HowToFix 卡片会直接查询余额，Token 用量取自本机请求历史。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- New coverage: HowToFix is classified as a balance resource with a queryable refresh, the three remaining-amount states (positive / zero / missing) map to available, exhausted and unconfirmed, and a page-level test asserts that the card renders the balance and the local token usage together without the “not supported” wording. / 新增覆盖：HowToFix 被归类为可查询的余额资源；剩余金额的三种状态（正数／零／缺失）分别映射到充足、耗尽与待确认；页面级测试断言卡片同时渲染余额与本机 Token 用量，且不再出现「暂不支持」。
- Not verified: a real desktop window against the four real HowToFix accounts (balance refresh timing and how the cards look next to the subscription ones). / 未验证：真实桌面窗口里 4 个真实 HowToFix 账号的余额刷新时序与卡片在订阅卡片旁的视觉效果。
