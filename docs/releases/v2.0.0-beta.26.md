# OmniProxy v2.0.0-beta.26

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版包含 Beta.25 之后的全部改动，是当前完整的构建。

## 思考强度：终于可以直接调了

之前三轮都没修好，原因在客户端而不在配置：Claude Desktop 只给**它自己认识的模型 ID** 渲染 effort 控件，内置能力表只有 8 个 Claude 型号（另有 fable／mythos 前缀），其余只认签名模型目录；OmniProxy 为了不伪造厂商身份使用 `claude-omniproxy-*` 不透明路由名，因此在客户端里永远没有滑杆，配置写什么都换不来入口。

本版把档位入口放回 OmniProxy：

- **本地 Agent → Claude Code／Claude Desktop → 配置模型**，每个上游公布过档位的模型卡片新增「思考强度」选择。
- 选项只来自该模型已确认的档位，例如 DeepSeek 系是「关闭思考(none)／高强度推理(high)／最高强度推理(max)」，GLM 系是 low／high／max；默认「跟随客户端」。没有公布档位的模型不显示该入口，也不显示伪造档位。
- 选定后由**网关**在该模型的 Messages 请求上覆盖 `output_config.effort`，并同步思考开关（`none` 关闭思考，其余保持自适应）。所以不依赖客户端滑杆：Claude Code、Claude Desktop 的 Code／Chat 会话都会按这个档位发出。
- 固定档位与「应用配置」在同一次提交里落库（迁移 041 新增 `model_effort_pins`），配置文件没写成功就不会留下只生效一半的档位；清回「跟随客户端」即删除该行。
- 只影响 Messages 协议；Codex 一类 Responses／Chat 客户端不参与，避免混用不同协议的档位语义。

## Claude 目录的档位声明

- Claude Desktop 的 3P 目录现在写入 `inferenceModels[].maxEffort`：客户端据此隐藏该模型并不支持的更高档位，并把上限同步给 Code 会话（跳过 `max`，因为 Claude Code 的 `maxEffortLevel` 不接受它）。
- 顶层 `defaultModelEffort` 按默认模型已确认的默认档位写入；模型没有确认档位时清除旧值，避免沿用上一个模型的档位。
- 两者都只在上游确实公布过档位时写入，未确认能力的模型保持未知。

## 兼容与已知边界

- 迁移 041 只新增一张表，不改动现有账号、凭据、路由、客户端配置、请求历史与安装身份。
- 客户端菜单里的档位显示仍由客户端自己判断，可能与网关实际发送的档位不同；以「配置模型」里选的档位为准。
- 档位说明来自上游公布的枚举，实际推理强度由上游执行；本版不宣称未经确认的档位。
- Codex 在约 500k 用量时提前压缩的现象**仍未定位根因**，本版不宣称已修复。
- Google 上游 `429 / RESOURCE_EXHAUSTED` 仍是独立调查项，本版不宣称解除限流。
- 构建与回归在本地执行，不以自动化测试替代真实上游调用、真实覆盖安装或客户端界面验收。

## 升级后需要做的两步

1. 在应用中重新应用需要更新目录的客户端配置（如 Claude、Claude Desktop、Codex、DeepSeek Harness 等），让客户端读取最新模型目录。
2. **完全退出**并重新启动对应客户端，避免继续使用缓存的旧菜单。

若只想改思考强度：在「配置模型」里选好档位并点「应用配置」即可，网关侧立即按新档位发送。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.26。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。
