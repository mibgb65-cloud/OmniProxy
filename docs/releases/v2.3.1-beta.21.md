# OmniProxy v2.3.1-beta.21

## New Features / 新功能

- WorkBuddy for the China mainland (`copilot.tencent.com`) is now a built-in subscription provider, separate from the international build. Sign in with the browser, and its models — including the Claude models that build serves — become routable through the local gateway. Accounts, tokens, catalogs and Credits stay isolated per build. / 新增内置订阅服务商「WorkBuddy（国内版）」（`copilot.tencent.com`），与国际版并列：浏览器登录后，其模型（含该构建提供的 Claude 模型）可经本地网关路由；账号、令牌、目录与 Credits 按构建隔离。
- The China build keeps its own client fingerprint and login platform (`platform=workbuddy`, `User-Agent: WorkBuddy/5.9.3 WorkBuddy/5.9.3 CLI/2.165.0`), so requests carry the shape its own desktop app sends. / 国内版使用自己的客户端指纹与登录平台标识（`platform=workbuddy`、UA `WorkBuddy/5.9.3 WorkBuddy/5.9.3 CLI/2.165.0`），请求形态与它的桌面端一致。
- Claude models on the China build are forwarded to the native Anthropic `POST /v1/messages` endpoint when the client speaks Messages, so reasoning levels work (the Chat endpoint ignores them there); the catalog adds `max` for those models. Chat and Responses clients keep working through the existing conversion path. / 国内版的 Claude 模型在客户端使用 Messages 协议时原样转发到原生 `POST /v1/messages`，推理档位因此生效（Chat 端点在该构建上忽略档位）；目录为这些模型追加 `max` 档位。Chat 与 Responses 客户端仍走既有转换链路。
- Models are discovered per account from the China build's own `GET /v3/config`; background and manual sync both cover the new kind, and token renewal does not invalidate the catalog. / 目录按账号从国内版自己的 `GET /v3/config` 同步；后台与手动同步都覆盖新服务商，令牌续期不会让目录失效。
- Credits use the same three-window reading (Credits / Extra credits / Total credits) with a China-specific card title. `glm-*` models keep image input there (the international build drops it). / Credits 沿用三窗口口径（计划内／额外／合计），卡片标题区分国内版；国内版 `glm-*` 保留图片输入（国际版会丢弃）。

## Breaking Changes / 不兼容变更

None / 无。One additive migration (`052_builtin_workbuddy.sql`) inserts a provider row; no existing account, route, credential or catalog is touched, and re-running migrations does not duplicate it. / 无破坏性变更。新增一条只追加的迁移（`052_builtin_workbuddy.sql`）插入服务商记录；既有账号、路由、凭据与目录不受影响，重复执行迁移不会重复插入。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.21`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.21`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, the new provider appears in 服务商; sign in from its card, let the catalog sync, then create a route for the models you want. / 升级后「服务商」页会出现新卡片：从该卡片登录、等待目录同步，再为需要的模型建路由即可。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Covered by contract tests: build fingerprints and login platform, China `/v3/config` catalog (including `glm-*` images and Claude `max`), native Messages forwarding (body untouched, no gzip, headers, business-code mapping), gateway dispatch between Chat and Messages, provider/account isolation and migration 052. / 契约测试覆盖：构建指纹与登录平台、国内版目录（含 `glm-*` 图片与 Claude `max`）、Messages 原生转发（正文不改写、不压缩、头集、业务码映射）、网关在 Chat 与 Messages 之间的分派、提供商／账号隔离与迁移 052。
- **Not verified with a real account yet**: the China build's login, catalog and one real conversation all need the user's account. The China build's fingerprint, `platform` value and Messages endpoint come from community-plugin research (0.2.36), not from an official contract. / **尚未用真实账号验证**：国内版的登录、目录与一次真实对话都需要用户账号执行。国内版指纹、`platform` 取值与 Messages 端点来自社区插件调研（0.2.36），不是官方契约。
- Not implemented in this version: the China build's daily check-in, cloud-hosted enterprise hosts (`<ent>.sso.copilot.tencent.com`), desktop sign-in file import and API Key auth. / 本版本未实现：国内版每日签到、云托管企业域名（`<ent>.sso.copilot.tencent.com` 等）、桌面登录文件导入与 API Key 认证。
