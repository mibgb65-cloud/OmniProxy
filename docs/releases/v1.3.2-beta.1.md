# v1.3.2-beta.1 - Featherless AI provider and multi-key routing / Featherless AI 接入与多 Key 调度

This beta adds Featherless AI as a first-class OpenAI-compatible provider. OmniProxy can now store multiple Featherless API keys, balance requests across them, retry another key after transient upstream failures, and synchronize the active model catalog available to the current plan.

本测试版将 Featherless AI 接入为一等公民的 OpenAI 兼容服务商。OmniProxy 现在可以保存多个 Featherless API Key，在 Key 之间平衡请求，在上游临时失败后切换其他 Key，并同步当前套餐可用的活跃模型目录。

## Features / 新特性

- **First-class Featherless provider**: Added account management, batch API-key import, credential validation, request statistics, outbound-proxy selection, and a configurable `https://api.featherless.ai/v1` upstream.
  - **Featherless 一等公民接入**：新增账号管理、API Key 批量导入、凭据验证、请求统计、出站代理选择，以及可配置的 `https://api.featherless.ai/v1` 上游地址。
- **Dedicated local endpoint**: OpenAI Chat Completions clients can connect to `http://127.0.0.1:3000/featherless/v1`, while the stable OpenAI-compatible gateway can select Featherless as its backend.
  - **独立本地入口**：OpenAI Chat Completions 客户端可连接 `http://127.0.0.1:3000/featherless/v1`；稳定 OpenAI 兼容网关也可以选择 Featherless 作为后端。
- **Multi-key scheduling**: Balanced scheduling distributes sequential requests across available Featherless keys. Retryable `429`, `500`, `502`, `503`, and `504` responses cool down the failed key and try another available key within the configured retry limit.
  - **多 Key 调度**：优先平衡模式会把连续请求分配到不同的可用 Featherless Key；遇到可重试的 `429`、`500`、`502`、`503`、`504` 时，会冷却失败 Key，并在配置的重试次数内尝试其他可用 Key。
- **Model catalog synchronization**: The gateway routing page can load up to 1,000 active Featherless models available on the current plan, ordered by popularity, while preserving full repository-style model IDs such as `Qwen/Qwen3-32B`.
  - **模型目录同步**：网关路由页可以加载当前套餐可用、按热度排序的最多 1,000 个活跃 Featherless 模型，并完整保留 `Qwen/Qwen3-32B` 这类仓库式模型 ID。
- **Integration attribution**: Featherless requests include OmniProxy attribution headers without overwriting caller-provided attribution.
  - **集成标识**：Featherless 请求会携带 OmniProxy 集成标识，同时不会覆盖调用方主动提供的标识。

## Compatibility And Upgrade Guidance / 兼容性与升级说明

- Existing account pools, routes, configuration, history, billing summaries, and theme state remain compatible. No local-data migration is required.
  - 现有账号池、路由、配置、历史、费用汇总和主题状态保持兼容，无需迁移本地数据。
- Add multiple Featherless keys under Account Management and select **Balanced** scheduling to rotate successful sequential requests. Queue mode keeps its existing fixed-priority behavior but still switches keys after retryable failures.
  - 在账号管理中添加多个 Featherless Key，并选择**优先平衡**调度，即可轮换成功的连续请求；队列模式继续保持固定优先级，但在可重试失败后仍会切换 Key。
- Featherless is exposed only for OpenAI Chat Completions routes in this beta. It is intentionally excluded from the Codex Responses route because the documented Featherless API does not currently advertise OpenAI Responses compatibility.
  - 本测试版只在 OpenAI Chat Completions 路由中开放 Featherless。由于 Featherless 公开文档目前没有声明兼容 OpenAI Responses，因此不会出现在 Codex Responses 路由中。
- Model availability, context length, tool use, and concurrency cost vary by model and subscription plan. Synchronize the catalog after adding a key to see models available to that plan.
  - 模型可用性、上下文长度、工具调用能力和并发成本因模型及套餐而异；添加 Key 后请同步目录，以查看该套餐当前可用的模型。
