# OmniProxy v2.3.1-beta.13

## Bug Fixes / 问题修复

- Codex showing an image to a River model no longer fails with `400 unsupported_content`. Codex returns the `view_image` result as an inline `data:image/png;base64,…` tool output of roughly 1 MB; the River adapter applied its 8 KiB remote-URL bound to every image address and rejected the legitimate screenshot locally (request `d91090a0…` failed in 161 ms without ever reaching the provider). Image addresses are now validated by form: inline `data:image` images are accepted up to the component-wide 16 MiB limit, while remote URLs keep the 8 KiB bound. / Codex 把图片交给 River 模型时不再报 `400 unsupported_content`。Codex 的 `view_image` 结果是一条约 1 MB 的内联 `data:image/png;base64,…` 工具输出，而 River 适配器把 8 KiB 的远程 URL 上限套到了所有图片地址上，在本地就把合法截图拒掉了（请求 `d91090a0…` 161 ms 内失败，从未到达上游）。现在按形式校验：内联 `data:image` 图片放宽到组件统一的 16 MiB 上限，远程地址保持 8 KiB 边界。
- Still rejected with `400 unsupported_content`, as before: empty or control-character image addresses, non-image `data:` URLs, inline images over 16 MiB, remote URLs over 8 KiB, unknown image block structures, `input_file` and `input_audio`. Nothing is silently dropped. / 仍然按原样明确拒绝：空地址或含控制字符的地址、非图片 `data:` URL、超过 16 MiB 的内联图片、超过 8 KiB 的远程 URL、未知图片结构、`input_file` 与 `input_audio`；不会静默删除内容。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no change to request-body limits (Responses stays bounded at 16 MiB, so the wider image bound cannot enlarge a request). Only River's Responses image validation changed; Chat／Messages conversion limits are untouched. / 无数据库迁移、无公共 API 变更、不改请求体上限（Responses 仍是 16 MiB，放宽图片上限不会放大请求）。只改了 River 的 Responses 图片校验，Chat／Messages 转换路径的上限不变。

## Local update / 本地更新

Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. Restart Codex after installing. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装；安装后重启 Codex。
- Application/frontend version: `2.3.1-beta.13`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.13`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。

## Verification boundary / 验证边界

- Reproduced on the installed build with a synthetic 600×600 noise PNG (1,080,993 bytes → a 1,441,346-character `data:image/png` URL) in a `view_image` tool result: `400 unsupported_content` in 352 ms, never reaching the provider. / 在已安装构建上用合成的 600×600 噪声 PNG（1,080,993 字节，对应 1,441,346 字符的 `data:image/png` 地址）放进 `view_image` 工具结果复现：352 ms 返回 `400 unsupported_content`，未到达上游。
- Same body against the new build on an isolated instance with the real River key: `200` + `response.completed` twice, and the model answered the colour of the image (`灰色`), so the pixels really reached the model. / 同一正文在新构建的隔离实例 + 真实 River Key 上：两次 `200` + `response.completed`，模型答出了图片颜色（`灰色`），说明像素确实到了模型。
- New coverage: inline 1 MiB tool-result image is accepted and forwarded unchanged; the inline/remote bounds table (1 MiB and at-limit inline pass, over-limit inline fails, non-image `data:` fails, at-limit remote passes, over-limit remote fails, empty and control-character addresses fail). / 新增覆盖：1 MiB 内联工具结果图片被接受并原样转发；内联／远程边界表（1 MiB 与正好到上限的内联通过、超限内联失败、非图片 `data:` 失败、正好到上限的远程通过、超限远程失败、空地址与控制字符失败）。
- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Not verified: a real Codex desktop screenshot conversation against the installed build — install, restart Codex and retry the same thread. / 未验证：安装构建后由真实 Codex 桌面端在同一截图会话重试；需要安装并重启 Codex 确认。
