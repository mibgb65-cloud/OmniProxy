# OmniProxy v2.5.0

本正式版汇总自 `v2.4.0` 以来的变更，包含仅在本机构建的 `v2.4.1-beta.1` 至 `beta.7`，无需逐个安装中间版本。

This stable release includes the changes since `v2.4.0`, including the seven local-only `v2.4.1-beta` builds. No intermediate installation is needed.

## Features / 新功能

- **Request records and optional body capture.** Enable body capture in Settings → Requests & Logs to browse and inspect recorded requests on the new Records page. Eligible client request bodies are stored locally with gzip compression, within the existing request size limits. Recording is off by default, and response bodies are not stored. / **新增「记录」页和可选的请求正文记录。** 在「设置 → 请求与日志」开启后，可在「记录」页浏览和查看已保存的请求正文。符合条件的客户端请求正文在原有请求大小限制内以 gzip 压缩保存在本机。默认不记录，不保存响应正文。
- **XLSX export.** Export request records matching the current search and result filters from the Requests page. The workbook includes request metadata, usage, timing and any captured body. Bodies that exceed Excel's cell limit are marked as truncated in the workbook; exporting does not alter stored data. / **导出 XLSX。** 在「请求」页按当前搜索与结果筛选导出请求记录，包含请求信息、用量、耗时和已记录的正文。超出 Excel 单元格上限的正文会在表格中标记为截断，导出不修改本地存储。
- **Usage by model family.** Usage totals combine confirmed reasoning-level variants of the same model family. Request details and XLSX exports still show the exact model ID. / **按模型家族汇总用量。** 用量统计将已确认属于同一模型家族的推理档位变体合并；请求明细与 XLSX 导出仍显示实际模型 ID。

## Bug Fixes / 修复

- **Reuse subscription accounts on sign-in.** Signing in again with the same ChatGPT/Codex or Google subscription identity reuses the existing account record. Existing duplicate records are not automatically deleted. / **重新登录时复用订阅账号。** 使用相同的 ChatGPT／Codex 或 Google 订阅身份重新登录时，复用原账号记录，不自动删除已有的重复记录。
- **Confirm the proxy protocol before first use.** OmniProxy confirms the endpoint's proxy protocol before using an explicitly configured scheme and recovers when it can verify the correct scheme. / **首次使用前确认代理协议。** 显式配置代理协议时，OmniProxy 会先握手确认；能够确定正确协议时自动恢复。
- **Keep Antigravity streams alive while waiting for upstream headers.** Streaming responses to Antigravity send headers and keep-alives before upstream headers arrive. / **Antigravity 流式请求等待上游时保活。** 在收到上游响应头前，先向 Antigravity 下发流式响应头并发送保活。
- **Apply provider proxy settings to resource calls.** Quota, balance, model catalog, login polling and token refresh now follow the provider's proxy policy. An explicitly required but unavailable proxy produces an error instead of silently connecting directly. / **提供商代理设置覆盖资源调用。** 额度、余额、模型目录、登录轮询和令牌续期遵循提供商的代理配置；明确要求走代理但代理不可用时会报错，不再静默直连。

## Breaking Changes / 不兼容变更

None / 无。

## Refactor & Performance / 重构与性能

Request list, usage and dashboard queries do not load captured bodies. The Records list uses stored previews; opening details loads the body on demand.

请求列表、用量和仪表盘查询不读取已保存的正文。「记录」页列表使用预览，打开详情时才按需读取正文。

## Upgrade Notes / 升级说明

- Upgrade directly from `v2.4.0` or any local `v2.4.1-beta` build. On first launch, migrations 053 and 054 run if not already applied; older Beta body records retain their original content and truncation flags. / **可从 `v2.4.0` 或任一该批本地 Beta 直接升级。** 首次启动按需执行迁移 053 和 054；旧 Beta 已保存的正文和截断标记会保留。
- Fully exit OmniProxy from the system tray and take a consistent backup of the data directory, including the SQLite WAL if present, before upgrading. Do not let an older build write to the migrated database. / 升级前从托盘彻底退出 OmniProxy，并一致性备份数据目录（包括存在的 SQLite WAL）；不要让旧版本写入迁移后的数据库。
- Captured bodies and XLSX exports can contain sensitive content. Review files before sharing them. The Windows installer uses the project's self-signed certificate; Windows may still show an untrusted publisher warning. / 已记录的正文和 XLSX 导出可能包含敏感内容，共享前请检查。Windows 安装器使用项目自签证书，Windows 仍可能提示发布者不受信任。
