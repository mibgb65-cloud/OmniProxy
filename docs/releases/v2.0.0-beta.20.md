# OmniProxy v2.0.0-beta.20

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

## 第三方模型推理档位

- 修复 Codex 目录在模型已声明推理档位、但缺少默认档位时 `default_reasoning_level` 为 `null`，导致客户端不展示思考强度选项的问题。缺省值由网关按「有 `high` 用 `high`，否则第一项」选择，并在目录中显式标注；不改变已有显式默认值。
- River 模型目录改用当前已确认的能力表：`DeepSeek-V4.1-Flash` 与 `DeepSeek-V4.1-Flash-1017` 提供关闭／高／最高三档，`GLM` 提供低／高／最高三档，均带中文说明与默认强度。已同步账号的旧快照不再继续输出过时或缺失的档位，更新后在路由页重新执行「同步官方模型」即可刷新。
- River 的 Messages→Chat 转换不再丢弃思考强度：仅当请求中的强度属于该模型实际确认的枚举时才透传为上游 `reasoning_effort`，非法值返回明确错误，不再静默降级。
- Claude Code／Desktop 菜单新增显式强度选项（如 `模型 · 高强度推理`），以网关生成的选项标识呈现，不伪装或改写真实厂商型号；选择后由网关还原真实型号与参数，并覆盖客户端沿用的旧「关闭思考」状态。只解析当前可用目录，停用或删除账号模型后选项立即失效；未知型号与未确认能力不生成选项，也不改变原模型默认标记。

## 上下文压缩与超时

- 识别明确的压缩请求（固定压缩端点，或经校验的 V2 压缩元数据），仅对这类请求使用独立的 10 分钟时限；普通推理仍保持原有 120 秒上限，不放宽其他请求。
- 压缩请求在留存记录中标记为 `responses/compact`，便于与实际请求超时分开排查。
- Codex 在约 500k 用量时提前压缩的现象本版**仍未定位根因**，本版不宣称已修复，也不修改或提高用户的 1.05M／900k 设置。

## 兼容与已知边界

- 继承 Beta.19 的 Codex Fast 服务档位、关于页正式入口及此前各版功能。
- 不新增数据库迁移，不改变安装身份、凭据格式、账号启用状态、路由选择或客户端登录。
- 推理档位只对已在能力目录中确认的模型提供；未验证的第三方型号保持未知，不做推测性枚举。
- Google 上游 `429 / RESOURCE_EXHAUSTED` 仍是独立调查项，本版不宣称解除限流。
- 构建与专项回归在隔离环境执行，不以本地测试替代真实上游调用、真实覆盖安装或客户端界面验收。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.20。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。
