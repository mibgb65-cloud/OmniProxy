# OmniProxy v2.3.1-beta.12

## Bug Fixes / 问题修复

- Codex (0.169 and later) selecting a River model such as `DeepSeek-V4.1-Flash-1017` no longer fails on every turn with `stream disconnected … error decoding response body`. The new Codex core asks for encrypted output by default (`include: ["reasoning.encrypted_content", "output.encrypted_content"]`); River answers with `200` plus an SSE preamble and then drops the connection. When a Codex request is routed to a non-OpenAI provider, the gateway now removes the `include` values that provider cannot express (`output.encrypted_content`), keeps the supported ones (`reasoning.encrypted_content`), and logs `codex unsupported includes dropped` with the count and the dropped values. / Codex（0.169 起）选择 River 的 `DeepSeek-V4.1-Flash-1017` 等模型时不再每轮报 `stream disconnected … error decoding response body`。新内核默认请求加密输出（`include: ["reasoning.encrypted_content", "output.encrypted_content"]`），River 会先返回 `200` 与 SSE 开头再断开连接。网关在 Codex 请求改走协议路径、目标是非 OpenAI 服务商时移除对方无法表达的 `include` 取值（`output.encrypted_content`），保留可用的 `reasoning.encrypted_content`，并记录 `codex unsupported includes dropped` 与数量、取值。
- The earlier beta.11 fixes stay in place and were confirmed active while debugging this round: orphan Companion Page tool results (`codex orphan tool outputs dropped`) and `type: "namespace"` tool groups (`codex namespace tools dropped`) are still removed before the request reaches a third-party provider. / beta.11 的修复保持有效，并在本轮定位中被日志确认生效：孤儿 Companion Page 工具结果（`codex orphan tool outputs dropped`）与 `type: "namespace"` 工具分组（`codex namespace tools dropped`）仍在请求送达第三方服务商前移除。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change. Only Codex requests routed to a non-OpenAI provider are adapted; the OpenAI transparent passthrough path keeps the request byte-identical, so encrypted-output requests still work there. On third-party models the client does not receive encrypted output — those providers cannot produce it. / 无数据库迁移、无公共 API 变更。适配只作用于改走协议路径、目标为非 OpenAI 服务商的 Codex 请求；OpenAI 透明转发保持正文逐字节不变，加密输出请求在 OpenAI 上照常可用。第三方模型上客户端拿不到加密输出——这些服务商本来就无法提供。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. Restart Codex after installing so it reconnects to the gateway. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装；安装后重启 Codex，让它重新连接网关。
- Application/frontend version: `2.3.1-beta.12`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.12`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。

## Verification boundary / 验证边界

- The failing request was captured byte-for-byte through a local relay in front of the gateway (102,957 bytes, four identical retries from the affected thread). Replaying it against the previous build reproduced the truncation after 185 bytes; the same bytes against this build return `200` with `response.completed`, twice. / 失败请求已通过网关前的本地中继逐字节抓到（102,957 字节，失败线程 4 次重试内容相同）。在旧构建上复放复现了 185 字节处中断；同一正文在本构建上两次都是 `200` + `response.completed`。
- `include` isolation on the real River key: with both values the stream truncates; with only `reasoning.encrypted_content`, or with no `include` at all, the response completes. / 真实 River Key 上单独比较 `include`：两个取值同时存在时流中断；只保留 `reasoning.encrypted_content`、或完全不带 `include` 时响应正常完成。
- New coverage: the `include` filter keeps supported and unknown values and drops only the unsupported one; the Codex entry adapter test asserts the upstream body carries `["reasoning.encrypted_content"]`; the real-key live test sends both values and expects a completed reply. / 新增覆盖：`include` 过滤保留可用与未知取值、只移除不支持的取值；Codex 入口整合测试断言上游正文只剩 `["reasoning.encrypted_content"]`；真实 Key live 用例同时发送两个取值并要求完整回复。
- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Not verified: the real Codex desktop window retrying the affected thread against the installed build — install and restart Codex to confirm. / 未验证：安装构建后由真实 Codex 桌面端在同一线程重试；需要你安装并重启 Codex 确认。
