# v1.2.8-beta.5 - Accurate Codex model reporting / Codex 模型显示修复

This beta fixes misleading Codex model labels in request history and the dashboard. Model-catalog polling is no longer reported as inference, and active WebSocket sessions now show the model selected by the client.

本次 beta 修复请求历史和仪表盘中误导性的 Codex 模型标签。模型列表轮询不再被当作推理请求，活动中的 WebSocket 会话现在会显示客户端实际选择的模型。

## Bug Fixes / 问题修复

- **Model-list polling no longer appears as GPT-5.6 Terra usage**: Successful `GET */models` responses no longer copy a nested catalog item into the request's model field. New model-list history entries remain unlabelled instead of being counted as Terra inference.
  - **模型列表轮询不再显示为 GPT-5.6 Terra 用量**：成功的 `GET */models` 响应不会再把模型目录中的嵌套条目写入请求模型字段。新的模型列表历史记录会保持未标记，不再被统计为 Terra 推理。
- **The dashboard shows the actual model for active Codex WebSocket sessions**: When the first WebSocket request message declares `gpt-5.6-sol`, the active-request record is updated immediately instead of retaining the Codex gateway fallback such as `gpt-5.5`.
  - **仪表盘显示 Codex WebSocket 活动会话的实际模型**：首条 WebSocket 请求消息声明 `gpt-5.6-sol` 后，活动请求会立即更新，不再保留 `gpt-5.5` 等 Codex 网关默认模型。
- **Regression coverage for both paths**: Backend tests now verify model-list responses stay unlabelled and live WebSocket activity changes to the requested model before the session closes.
  - **两个问题均增加回归覆盖**：后端测试会验证模型列表响应保持未标记，以及 WebSocket 会话关闭前活动记录已更新为请求模型。
