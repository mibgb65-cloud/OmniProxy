# OmniProxy v2.0.0-beta.28

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版相对 Beta.27 只改两处界面：仪表盘「调用趋势」重做，以及「设置与关于 → 数据存储」把占用分类拆细并支持清理安装残留。网关转发、账号、路由、客户端配置与数据库结构均未改动。

## 数据存储：不再有说不清的「其他」

之前数据存储只分数据库、运行日志、本地缓存和其他四类，安装相关文件全被算进「其他」。实测一台机器的 118 MB 占用里，「其他 102 MB 86%」几乎全是更新目录：每次点安装都会往 `updates/` 复制一份辅助程序副本（约 21 MB 一份），装完从不回收。

现在占用分六类：

- **更新缓存**：下载的安装包 + 每次安装留下的辅助程序副本。
- **登录凭据**：`credentials/` 下的登录凭据文件。
- **数据库**、**运行日志**、**本地缓存**、**其他**：口径不变，「其他」只剩真正的零散文件。

分布只显示实际占用非零的分类，并按大小从大到小排列，色块与列表顺序一致；全部为空时显示「暂无可统计的文件占用。」而不是一排 0 B。更新缓存存在时，卡片下方有一行说明它到底是什么。

### 清理更新残留

出现更新缓存时，数据存储页会多一个「清理更新残留」按钮：

- 只删除辅助程序副本 `runner-<32 位十六进制>.exe` 与残留的 `*.tmp`，实机上可释放约 84 MB。
- 保留已下载的安装包缓存 `package-<32 位十六进制>.exe`，避免下次升级强制重新下载。
- 保留 `status.json` 与 `install-result.json`，失败时仍可诊断。
- 只在你点击时执行，没有后台自动删除。正在运行的辅助程序对应的副本可能因文件占用而删除失败，此时会提示失败，其余已删除部分依然生效。

## 仪表盘：调用趋势

原来的趋势卡片把刻度画在图里，右侧最后一根柱子的日期会被裁掉，横向滚动用的是系统滚动条（带轨道和箭头，与产品其余部分不一致）。本版重做：

- 左侧独立刻度轴，`0` 与顶部整刻度对齐，中间为虚线参考线，基线为实线。
- 横轴标签单独一行，首尾不再被裁切；标签过多时按间隔抽样，最多 6 个。
- 柱子在图区内居中，宽度随列宽自适应（上限 22px），整列悬浮或键盘聚焦时高亮。
- 图例保留各分类合计值，悬浮提示给出单点明细与总量。
- 横向滚动改为 8px 细圆角自绘滑块：可拖动、可点击轨道跳转，内容放得下时自动收起，不再出现系统滚动条的轨道与箭头。

## 兼容与已知边界

- 无新迁移，无数据格式变化；升级后原有历史记录、设置与凭据保持原样。
- 本版不改客户端目录、Agent 配置与模型路由，升级后**不需要**重新应用客户端配置。
- 「登录凭据」只统计凭据文件的体积；系统凭据存储（DPAPI）不在该目录内，不会重复计算。
- 清理不会删除数据库、日志、账号或已下载的安装包；需要释放安装包缓存时暂无界面入口。
- `cache/` 分类保留但当前无写入方，实际显示为 0 并自动隐藏。
- Codex 在约 500k 用量时提前压缩、Google 上游 `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项，本版不宣称已修复。
- 构建与回归在本地执行，不以自动化测试替代真实上游调用、真实覆盖安装或客户端界面验收。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.28。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。

## 校验

- 安装器 `OmniProxy-Setup-v2.0.0-beta.28-windows-amd64.exe` 与同名 `.sha256` 位于 `release-assets/v2.0.0-beta.28/`。
- 完整质量门（格式 → lint → 类型 → Go 全部包 → 前端测试 → Windows production 构建）、Windows 版本资源与发布资产校验均通过。
