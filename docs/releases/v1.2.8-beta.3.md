# v1.2.8-beta.3 - Streaming, teardown and startup work / 流式转换、连接回收与启动优化

This beta makes the Codex compatibility path stream again, ends WebSocket sessions when the proxy stops, and takes several repeated costs off the request and startup paths.

本次 beta 让 Codex 兼容路径恢复流式输出，在停止代理时结束 WebSocket 会话，并移除请求路径与启动过程中的多项重复开销。

## Bug Fixes / 问题修复

- **Codex chat completions stream again**: The compatibility path read the entire upstream response before converting any of it, even when the client asked for a stream. Because the upstream request always sets `stream: true`, nothing reached the client until generation finished — a sixty second answer showed nothing for sixty seconds. Conversion now runs as events arrive.
  - **Codex 对话补全恢复流式输出**：兼容路径此前会读完整个上游响应才开始转换，即使客户端请求的是流式。由于上游请求恒为 `stream: true`，客户端在生成结束前看不到任何内容——一次 60 秒的回答会空白 60 秒。现在改为边接收边转换。
- **Stopping the proxy now stops WebSocket traffic**: WebSocket sessions are hijacked connections, which `http.Server.Shutdown` leaves alone by design. Nothing tracked them, so a stopped proxy kept relaying, recording usage and holding its account reservation, and changing the port stranded another pair of goroutines on every restart.
  - **停止代理时 WebSocket 流量随之停止**：WebSocket 会话是被劫持的连接，`http.Server.Shutdown` 按设计不会处理它们。此前没有任何地方追踪这些连接，因此"已停止"的代理仍在转发流量、记录用量并占用账号；变更端口时每次重启还会遗留一对协程。
- **Request history pagination stays put**: Reading page two or beyond threw you back to the first page within three seconds, because the polled entry list was replaced on every tick and that reset the page.
  - **请求历史分页不再跳回**：翻到第二页及以后时会在三秒内被弹回第一页，原因是轮询每次都替换整个条目列表并因此重置页码。
- **Concurrent reads of daily account stats**: The token list shared a backing array with the recorder and could observe a counter mid-update while a request finished.
  - **账号每日统计的并发读取**：账号列表与记录器共享同一底层数组，请求完成时可能读到正在更新中的计数。
- **Claude subscription quota reports why it is unavailable**: A failed lookup produced the same empty result whether the credential, the endpoint or the response shape was at fault. The status code now appears on the quota card. The request was also narrowed to the headers the endpoint expects.
  - **Claude 订阅额度会说明不可用的原因**：此前无论是凭据、端点还是响应结构的问题，失败都返回同样的空结果。现在额度卡片会显示状态码，请求头也收窄为该接口所需的部分。
- **Claude quota switch and row styling**: The switch showed as enabled while the risk dialog was still asking, and the row borrowed a fixed height meant for rows that carry buttons and lists.
  - **Claude 额度开关与行样式**：开关在风险提示仍在询问时就显示为已开启，且该行套用了为含按钮和列表的行准备的固定高度。

## Refactor & Performance / 重构与优化

- **Request history pruning moved off the insert path**: Every insert ran a full-table prune, measured at roughly 74ms once the table fills, plus a retention delete whose predicate could not use the time index. Pruning now runs periodically and at startup, and the retention predicate is index-friendly. Three indexes that no query could use were replaced with collation-matching ones, and `token_id` gained an index for both the filter and the startup relabel pass.
  - **请求历史清理移出插入路径**：此前每次插入都会执行一次全表清理，表写满后实测约 74 毫秒，并附带一次谓词无法使用时间索引的保留期删除。现在清理改为定期执行并在启动时执行一次，保留期谓词也可走索引。三个任何查询都用不上的索引被替换为排序规则匹配的版本，`token_id` 同时为过滤和启动重标记补上索引。
- **Polling pauses while the window is hidden**: Closing the window only hides it to the tray, and nothing watched for that, so the three second poll kept serializing logs, accounts, history and billing over the desktop bridge indefinitely. The default history page size also dropped from 10000 to 1000, which is five full pages at the table's page size.
  - **窗口隐藏时暂停轮询**：关闭窗口只是收进托盘，而此前没有任何地方监听该状态，因此三秒轮询会持续不断地序列化日志、账号、历史和账单数据。历史默认单次拉取量也从 10000 降至 1000，相当于表格分页的五整页。
- **Request bodies are no longer decoded to read one field**: Model normalization decoded the whole body into a map on every forward attempt, including retries, although most requests already carry the route's model and need no rewrite. The model is now probed on its own and the full decode only runs when the body has to change.
  - **不再为读取单个字段而解码整个请求体**：模型归一化此前在每次转发（含重试）时把整个请求体解码为映射，而多数请求本就携带路由模型、无需改写。现在先单独探测模型，只有确实需要改写时才执行完整解码。
- **OAuth expiry is checked before the refresh lock**: Every Codex and Claude attempt passed through one global mutex that was taken before anything decided a refresh was needed, and held across the refresh request. Expiry is decided by parsing alone, so it now runs first; concurrent attempts on the same account still collapse into a single refresh.
  - **OAuth 到期判断提前到加锁之前**：此前每次 Codex 和 Claude 请求都要经过一把全局互斥锁，而且是在尚未判断是否需要刷新之前就获取，并在刷新请求期间一直持有。到期判断只需解析即可完成，现在提前执行；同一账号的并发请求仍会合并为一次刷新。
- **The history table is no longer loaded twice at startup**: One load answered whether the table was empty and another found the highest id, each reading every row and its retry chain. Both now probe a single row, and the in-memory fallback list is no longer seeded from data that is normally never read.
  - **启动时不再两次加载历史表**：一次加载用于判断表是否为空，另一次用于查找最大 id，两次都会读取全部行及其重试链。现在均改为只探测一行，内存兜底列表也不再从通常永远不会读取的数据预加载。
