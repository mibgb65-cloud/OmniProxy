# OmniProxy v2.2.0 - 更新体验与界面交互升级 / Update experience and interface polish

Windows amd64 正式版，汇总自 v2.1.0 以来的更新完成提示、发布说明排版与弹窗交互改进，取代本地未公开的 2.1.1-beta.* 构建。

This Windows amd64 stable release brings together the post-update notice, release-note rendering and dialog improvements since v2.1.0. It supersedes the local, unpublished 2.1.1-beta.* builds.

## Features / 新特性

- **Post-update notice**: After a recorded update takes effect and the app reopens, a one-time dialog shows the running version and its bundled release notes. The previous version is shown only when it was recorded. Dismissing the dialog saves an acknowledgement so it does not reappear for the same version; a failed save remains retryable.
  - **更新完成提示**：已有更新记录对应的升级生效、应用重新打开后，弹出一次提示，展示当前版本和内置的本版更新说明。仅在有记录时展示升级前版本；关闭或确认后保存已读回执，同一版本不再重复提示，保存失败仍可重试。
- **Readable release notes**: The upgrade dialog, Settings changelog and post-update notice share Markdown rendering for headings, emphasis, lists, links, quotes and code blocks. Current-version notes are bundled with the application and remain available offline.
  - **发布说明排版**：升级浮窗、设置页更新日志和更新完成提示共用 Markdown 渲染，支持标题、强调、列表、链接、引用和代码块；当前版本说明随应用内置，离线可读。

## Bug Fixes / 问题修复

- **Dialog and popover dismissal**: Fix dialogs disappearing instantly when conditional rendering bypassed their exit state. Account management, subscription login, request details, Google projects, proxy settings, routing, provider priorities, Settings and update dialogs now retain their exit transitions.
  - **弹窗与浮层关闭**：修复条件挂载绕过关闭状态、导致弹窗瞬间消失的问题，覆盖账号管理、订阅登录、请求详情、Google 项目、代理设置、路由、提供商优先级、设置及更新相关窗口。
- **Fresh forms on reopen**: Preserve the closing content for its transition while creating a fresh form instance when reopened, preventing stale drafts or temporary state from leaking into a new operation.
  - **重新打开表单**：关闭时保留内容以完成过渡，重新打开时创建新表单实例，避免上次草稿或临时状态残留到新操作。
- **Raw Markdown in Settings**: The current-version changelog no longer displays heading markers, asterisks or backticks as unformatted release-note text.
  - **设置页原始标记**：当前版本更新日志不再直接显示未排版的标题标记、星号和反引号。

## Breaking Changes / 不兼容更新

None / 无。Relative to v2.1.0, this release adds no database migrations or dependencies and preserves installation identity, account data, routing and data locations.

相对 v2.1.0，本版无新增数据库迁移或依赖，沿用安装身份、账号数据、路由和数据位置。

## Refactor & Performance / 重构与优化

- **Upgrade dialog layout**: Keep the title and actions fixed while the version summary and release notes scroll, making long notes easier to read in smaller windows.
  - **升级浮窗布局**：标题栏和操作区固定，版本摘要与发布说明独立滚动，便于小窗口阅读长说明。
- **Consistent motion**: Dialogs and popovers use 150ms fade-and-scale transitions; status toasts also animate out. Reduced-motion preferences skip these effects. Closed dialogs do not start settings, subscription-session or request-detail reads merely to retain a closing animation.
  - **统一动效**：弹窗与浮层采用 150ms 淡入淡出和轻微缩放，全局提示补齐退出过渡；减少动画模式跳过这些效果。保留关闭动画不会让未打开的弹窗额外读取设置、订阅会话或请求详情。
- **Safe, dependency-free rendering**: Reuse the shared Markdown renderer without adding dependencies. HTML is displayed as text, remote images are not loaded, and only HTTP(S) or root-relative links become clickable.
  - **安全且无新增依赖的渲染**：复用共用 Markdown 渲染器，不新增依赖；HTML 只作文本显示，不加载远端图片，仅 HTTP(S) 与根相对路径生成可点击链接。

## Upgrade notes / 升级说明

- Exit the app normally and make a consistent data-directory backup, including SQLite WAL, before upgrading. Upgrading from v2.1.0 does not require account re-import or moving the data directory.
  - 升级前正常退出应用，并做包含 SQLite WAL 的一致性数据目录备份；从 v2.1.0 升级无需重新导入账号或搬迁数据目录。
- Application and installer version: `2.2.0`; Windows numeric resource version: `2.2.0.0`. This stable version is newer than all local `2.1.1-beta.*` builds.
  - 应用与安装器版本为 `2.2.0`，Windows 数字资源为 `2.2.0.0`；本正式版高于所有本地 `2.1.1-beta.*`。
- A fresh installation or an upgrade without a valid local update record does not force a post-update notice. Older versions may not have recorded the previous version, in which case that version is omitted rather than guessed.
  - 首次安装或没有有效本地更新记录的升级不会强制弹出更新完成提示；旧版本可能没有记录升级前版本，此时省略来源版本，不作推测。

## Release verification and limits / 发布校验与边界

- Public assets are built by GitHub Actions. Before publication, the installer is self-signed with the pinned project certificate and checked for signature validity, certificate pin, tamper rejection and final SHA256. Local unsigned validation packages are not public release assets.
  - 公开资产由 GitHub Actions 构建；发布前使用固定项目证书自签安装器，校验签名、证书 pin、篡改拒绝和最终 SHA256。本地未签名验证包不作为公开发布资产。
- Self-signing is not publicly trusted CA signing and may still trigger SmartScreen or unknown-publisher warnings. The application executable is not separately signed, and the installer does not import the certificate into the user's trust stores.
  - 自签不等同于公开受信任 CA 签名，仍可能触发 SmartScreen／未知发布者提示；应用本体暂不单独签名，安装器不向用户信任库导入证书。
- Automated tests and isolated browser checks do not replace real in-place upgrades, the actual post-update restart flow, native WebView2 transitions or visual checks at 140% font size. These require separate manual acceptance.
  - 自动测试和隔离浏览器检查不能替代真实覆盖安装、实际升级重启提示、原生 WebView2 动画及 140% 字号观感；这些仍需独立人工验收。
