# OmniProxy v2.4.1-beta.7

## Fixes / 修复

- **A provider's proxy now covers that provider's quota, balance, model catalog, login polling and token refresh — not just inference requests.** Previously those calls only carried a target host name, and the host fallback table was built from `providers.base_url`. Google subscription and Codex subscription use official hosts outside that table (`daily-cloudcode-pa.googleapis.com`, `cloudcode-pa.googleapis.com`, `oauth2.googleapis.com`, `www.googleapis.com`, `chatgpt.com`, `auth.openai.com`), so choosing "Use proxy" for that provider still let these calls go direct. The account page then showed the last quota snapshot while the model list failed with "temporarily unavailable" or a generic "operation not completed". Resource calls are now bound to the account's provider identity and use the same proxy decision as inference; this covers Google and Codex subscriptions, model catalog sync, DeepSeek/Kimi/StepFun/HowToFix balances, MiniMax quota, WorkBuddy credits and login polling, DuMate console queries, and the activation request. / **按提供商配置的代理现在覆盖该提供商的额度、余额、模型目录、登录轮询与令牌续期，而不只是推理请求。** 此前这些调用只带目标主机名，主机回退表来自 `providers.base_url`；Google 订阅与 Codex 订阅使用的官方主机不在表内（`daily-cloudcode-pa.googleapis.com`、`cloudcode-pa.googleapis.com`、`oauth2.googleapis.com`、`www.googleapis.com`、`chatgpt.com`、`auth.openai.com`），因此即使给该提供商选择「走代理」，这些调用仍会直连。账号卡于是显示旧的额度快照，而模型列表报「暂时不可读」或笼统的「操作未完成」。现在资源类调用会绑定账号所属提供商身份，与推理共用同一套代理判定；覆盖 Google／Codex 订阅、模型目录同步、DeepSeek／Kimi／StepFun／HowToFix 余额、MiniMax 额度、WorkBuddy 积分与登录轮询、DuMate 控制台查询以及激活请求。
- **Proxy failures are reported instead of silently falling back to direct.** If the provider is explicitly set to "Use proxy" and the proxy is unavailable or unconfigured, these calls now surface the existing `proxy_unavailable` / `proxy_protocol_mismatch` / `proxy_not_configured` codes. / **代理故障会明确报错，不再静默回退直连。** 提供商显式设为「走代理」而代理不可用或未配置端点时，这些调用返回既有的 `proxy_unavailable`／`proxy_protocol_mismatch`／`proxy_not_configured` 错误码。

## Notes / 说明

- Inference requests, Codex transparent forwarding (HTTP and WebSocket) and the connectivity probe keep their previous behavior and decision order. Host-name matching is still used only for calls that have neither an account nor a provider identity, such as application updates, Agent install downloads and the Antigravity client-version manifest (which falls back to a built-in version). / 推理请求、Codex 透明转发（HTTP 与 WebSocket）与连通性探针的行为和判定顺序不变。主机名匹配只保留给既无账号也无提供商身份的调用，例如应用更新、Agent 安装下载与 Antigravity 客户端版本清单（读取失败回退内置版本）。
- No database migration and no configuration rewrite. Existing `proxy_settings` and `providers.proxy_mode` stay as they are; simply refresh the account card after upgrading. / 无数据库迁移、不改写配置。既有 `proxy_settings` 与 `providers.proxy_mode` 保持不变；升级后在账号卡点一次刷新即可。
- Also included since beta.6: none (this build contains only the proxy coverage fix). / 相对 beta.6 仅包含本次代理覆盖修复。
