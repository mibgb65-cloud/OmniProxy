# OmniProxy v2.3.1-beta.3

## Bug Fixes / 问题修复

- Antigravity in Enterprise Gateway mode (`wireProtocol: openai`) silently stripped images out of tool results: `read_file` returned only `Showing binary file of type image/png`, so the model reported "cannot see image pixels" even though the gateway and the upstream Gemini both handle images. The client still produced the media and wrote it to disk — the bytes simply never entered the request (the follow-up request grew by 329 tokens, while the same PNG costs 1100+ tokens when sent directly through the gateway). / Antigravity 在 Enterprise Gateway 模式（`wireProtocol: openai`）下会把工具结果里的图片剥掉：`read_file` 只返回 `Showing binary file of type image/png`，模型因此声称「看不到图片像素」，而网关与上游 Gemini 都能处理图片。客户端其实产出了 media 并写到了磁盘，只是字节没进请求（同轮请求只多 329 Token，而同一张 PNG 直发网关占 1100+ Token）。
- The gateway now backfills those pixels: when a tool result carries only the binary placeholder and the same `tool_call_id` arguments contain an absolute path, it re-reads that file and, after sniffing it as PNG／JPEG／GIF／WebP and checking the 12 MiB limit, appends an `inlineData` part right after the `functionResponse` in the same turn. Only Gemini-family models (the ones that declare image input in the catalog) get the backfill; Claude and GPT-OSS stay text-only. Missing files, non-image content, oversized files and results without a path keep the previous behaviour without failing the request. / 网关现在把这些像素补回来：工具结果只剩二进制占位文本、且同一 `tool_call_id` 的参数里带绝对路径时，回读该文件，嗅探为 PNG／JPEG／GIF／WebP 且不超过 12 MiB 后，在同一回合 `functionResponse` 之后追加 `inlineData`。只对目录里声明了图片输入的 Gemini 族生效，Claude／GPT-OSS 保持纯文本；文件缺失、非图片、超限或没有路径时保持原样且不报错。

## Verification boundary / 验证边界

- Before packaging, `task --force verify` passed: Go packages, frontend tests (154 files / 935 tests), format, lint, typecheck and the Windows production build. / 打包前 `task --force verify` 通过：Go 全包、前端 154 文件／935 项测试、格式、lint、类型检查与 Windows 生产构建。
- Unit coverage: five new cases assert the backfill payload equals the file on disk, single-layer path arguments, non-image files, missing file / relative path / no path argument / text result / other binary placeholders, and that Claude／GPT-OSS models get no backfill. / 单元覆盖：新增五组用例断言回填内容与磁盘字节一致、单层路径参数、非图片文件、缺文件／相对路径／无路径参数／文本结果／其它二进制占位，以及 Claude／GPT-OSS 不回填。
- Real upstream check before the change: the same `blind_v4.png` sent directly to `gemini-4-hydrogen-xhigh` through the gateway returned 200 with `prompt_tokens` 1173 and the model describing the real colours and the `CODE:` string. / 改动前的真实上游对照：同一张 `blind_v4.png` 直发网关的 `gemini-4-hydrogen-xhigh` 返回 200，`prompt_tokens` 1173，模型描述出真实配色与 `CODE:` 字符串。
- Antigravity desktop retest with a real screenshot is still pending (it needs this installed build). Browser-screenshot tool results are outside the backfill scope because their arguments carry no re-readable file path. / Antigravity 桌面端真机复测仍待安装本构建后执行；浏览器截图形态不在回填范围内，因为其参数里没有可回读的文件路径。
