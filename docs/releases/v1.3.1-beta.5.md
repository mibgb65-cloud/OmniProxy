# v1.3.1-beta.5 - Show OmniProxy models in the ChatGPT app model picker / 让 ChatGPT 应用模型列表显示 OmniProxy 托管的模型

The ChatGPT desktop app builds its model picker from the catalog returned by `GET {openai_base_url}/v1/models`. Upstream only lists its own models, so models routed through OmniProxy (Atria Dawn Preview, DeepSeek, MiMo, ...) never appeared in the picker even though requests for them were proxied correctly. Codex CLI reads `model` from `config.toml` directly, which is why it worked there and the app did not.

ChatGPT 桌面应用的模型列表来自 `GET {openai_base_url}/v1/models` 返回的目录，而上游只列自己的模型，所以 OmniProxy 托管的模型（Atria Dawn Preview、DeepSeek、MiMo 等）不会出现在列表里，尽管这些模型的请求本身能正常代理。Codex CLI 直接读 `config.toml` 里的 `model`，所以它一直正常——这就是之前"CLI 能识别、应用不显示"的原因。

## Features And Fixes / 新增与修复

- The proxy now appends the models from the one-click Codex profiles (`~/.codex/omniproxy-*.config.toml`) into the catalog it returns to the app, so they show up in the picker with a readable name and context window.
  - 代理现在会把一键配置生成的 Codex profile（`~/.codex/omniproxy-*.config.toml`）里的模型追加进返回给应用的目录，模型即可带可读名称与上下文窗口显示在列表中。
- Injected entries use the minimal schema the client requires, including `base_instructions`, and are skipped when the model is already listed upstream, so official models are never duplicated or hidden.
  - 注入条目使用客户端要求的最小 schema（含 `base_instructions`），且上游已存在的模型会跳过，官方模型不会被重复或隐藏。
- Verified the generated catalog against the installed Codex binary; any unparseable response is passed through unchanged, so a catalog change upstream cannot break the picker.
  - 已用本机安装的 Codex 二进制校验生成目录；任何无法解析的响应原样透传，上游目录变更不会弄坏模型列表。
- Unit and integration coverage in `codex_models.go` / `codex_models_test.go` / `codex_models_service_test.go`, including a full `ServeHTTP` pass asserting the client receives a byte-consistent body and `Content-Length`.
  - `codex_models.go` / `codex_models_test.go` / `codex_models_service_test.go` 的单元与集成测试覆盖，包含一次完整 `ServeHTTP` 通路，断言客户端收到字节一致的正文与 `Content-Length`。

## Upgrade Guidance / 升级说明

- No configuration change. After upgrading, fully quit and reopen the ChatGPT app so it refetches the catalog; the injected models then appear in the model picker.
  - 无需改动配置。升级后请完全退出并重新打开 ChatGPT 应用，使其重新拉取目录，托管的模型即会出现在模型列表。
- Selecting an injected model sends requests to OmniProxy exactly as Codex CLI does; make sure the matching token (for example an Atria account) is added and not exhausted. The picker itself needs a working OpenAI token to load the catalog first.
  - 选中注入模型后，请求会像 Codex CLI 一样发给 OmniProxy；请确认已添加对应令牌（例如 Atria 账号）且未耗尽。模型列表本身需要先有一个可用的 OpenAI 令牌才能加载。
- Removing a model from the one-click selection rewrites the profiles, and the next catalog fetch stops listing it.
  - 在一键配置里移除某个模型会重写 profile，下一次目录拉取便不再列出该模型。
