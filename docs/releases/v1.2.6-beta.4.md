# v1.2.6-beta.4 - Quota windows and recovery safeguards / 额度窗口与恢复防护

This beta fixes Codex quota windows that were displayed using a fixed five-hour assumption and strengthens configuration recovery, refresh ordering, and upstream response handling.

本次 beta 修复 Codex 额度固定按 5 小时显示的问题，并加强配置保存恢复、前端刷新顺序和上游响应处理。

## Features / 新特性

- **Dynamic Codex quota windows**: The quota view now follows the window duration returned by the Codex API, showing five-hour or weekly quota only when that window is actually available.
  - **动态 Codex 额度窗口**：额度页面根据 Codex API 返回的窗口时长显示 5 小时或周额度，仅在对应窗口真实存在时展示。

## Bug Fixes / 问题修复

- **Configuration rollback**: Failed proxy or control-port restarts now restore the previous in-memory configuration, running proxy, and persisted configuration file.
  - **配置回滚**：代理或控制端口重启失败时，恢复旧的内存配置、运行中的代理和已持久化配置文件。
- **Stale refresh protection**: Overlapping realtime refreshes and billing-date requests can no longer overwrite newer data with an older response.
  - **过期刷新保护**：实时刷新和账单日期请求发生重叠时，旧响应不再覆盖最新数据。

## Breaking Changes / 不兼容更新

- None / 无

## Refactor & Performance / 重构与优化

- **Upstream response limit**: Codex and Zo non-streaming response conversion now stops safely at 32 MiB instead of reading an unbounded response body.
  - **上游响应上限**：Codex 和 Zo 的非流式响应转换现在限制为 32 MiB，避免无界读取异常响应。
- **Retention consistency**: Request-history retention is only updated in memory after database pruning succeeds.
  - **保留策略一致性**：请求历史仅在数据库清理成功后更新内存中的保留设置。
