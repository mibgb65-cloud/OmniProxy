# OmniProxy v2.3.1-beta.8

## Bug Fixes / 问题修复

- HowToFix accounts added in `v2.3.1-beta.7` could not reach a model catalogue: the provider was implemented in the backend, but the Routing page's “同步官方模型” account list did not include the `howtofix` kind, and the background catalogue sync only ran for OpenAI and Google. Users saw HowToFix accounts with a live balance but no models and no way to trigger a sync. / `v2.3.1-beta.7` 里的 HowToFix 账号拿不到模型目录：后端已经支持该服务商，但路由页「同步官方模型」的账号列表没有 `howtofix` 类型，后台目录同步也只覆盖 OpenAI 与 Google。结果是账号卡能显示余额，却没有模型，也没有任何入口触发同步。
- The catalogue is now synced automatically: the app starts a HowToFix background sync that runs at startup and after account create/update/delete, provider enable/disable and a successful manual sync. It only touches accounts whose current catalogue version has no models yet, de-duplicates per account and credential version inside a single run, keeps the last successful snapshot on failure, and never retries in a loop. / 目录现在自动同步：应用启动、账号增删改、服务商启停和手动同步成功后都会在后台补一次，只处理「当前目录版本还没有任何模型」的账号，同一运行内按账号与凭据版本去重，失败保留上次成功的快照，不循环重试。
- The Routing page “同步官方模型” selector now lists HowToFix API Key accounts for a forced refresh. / 路由页「同步官方模型」的下拉现在能选到 HowToFix API Key 账号，用于强制重新拉取。
- The HowToFix accounts page no longer shows “余额查询和密钥有效性检测尚未接入” — that notice is now hidden for providers whose balance is live. / HowToFix 的账号页不再显示「余额查询和密钥有效性检测尚未接入」；余额已接入的服务商都不再显示这条过期文案。
- The read-only catalogue sync status shown on the Routing page now merges the OpenAI and HowToFix background jobs: running if either is running, pending counts are summed, the first error code wins and the newest timestamp is kept. / 路由页显示的目录同步状态现在合并 OpenAI 与 HowToFix 两个后台任务：任一在运行即显示同步中，待同步数量求和，错误码取第一个，时间取最近一次。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no gateway change. The merged sync status can report a HowToFix failure code (`howtofix_auto_sync_failed`) in addition to the existing OpenAI one; the message text on the Routing page is unchanged. / 无数据库迁移、无公共 API 变更、不改网关。合并后的同步状态除了原有的 OpenAI 错误码外，还可能显示 `howtofix_auto_sync_failed`；路由页提示文案不变。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.8`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.8`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. After updating, HowToFix catalogues fill in on their own within a few seconds of startup. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。更新后 HowToFix 的目录会在启动后几秒内自动补齐。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- New coverage: background API-key sync only touches enabled stale accounts of its own provider (disabled accounts, other providers and subscription accounts are skipped), a second request in the same run does not hit the upstream again, a disabled provider never reaches the upstream, merged sync status semantics, the Routing page lists HowToFix accounts for manual sync, and the accounts page hides the stale balance notice for HowToFix while keeping it for providers without a balance query. / 新增覆盖：后台 API Key 同步只处理本服务商启用的过期账号（停用账号、其他服务商与订阅账号都跳过）、同一运行内再次请求不再访问上游、停用服务商不访问上游、合并状态语义、路由页能列出 HowToFix 账号手动同步、账号页对 HowToFix 隐藏过期余额提示而对没有余额查询的服务商继续显示。
- Not verified: a real desktop run against a real HowToFix account (startup sync timing and the model menu inside Claude Code／Codex), and how the newly added `ag/gemini-*` models behave if the account group changes. / 未验证：真实桌面窗口里用真实 HowToFix 账号的启动同步时序与 Claude Code／Codex 的模型菜单，以及账号分组变化后新增 `ag/gemini-*` 模型的实际表现。
