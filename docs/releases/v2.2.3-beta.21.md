# OmniProxy v2.2.3-beta.21

## Changes / 本版内容

- In-progress requests stay at the top of the request list. A long-running request no longer sinks below the requests that finish after it: the list sorts running requests first (across pages), and a “Finished” divider separates them from the completed ones. Grouping is also applied in the table itself, so the visual order holds, and pending rows keep their relative order. / 请求页里进行中的记录固定置顶。长请求不再被随后完成的请求挤到中间：列表先排进行中的记录（跨分页也成立），并用一条「已结束」分隔行把它们与已完成记录分开。表格内部也做一次分组，视觉顺序稳定，进行中的几条之间仍保持原有先后。
- The reasoning level of a variant model now really wins. beta.18's attempt relied on the catalog folding `-low`/`-medium`/`-high`/`-xhigh` variants into a base model; Google publishes only the variants, so nothing was folded and `gemini-4-hydrogen-xhigh` was still reported and executed as `low`. The gateway now recognises the level from sibling variants (two or more known levels sharing the prefix), so the record and the upstream thinking level are both `xhigh`. / 变体型号的推理等级这次真的生效了。beta.18 依赖目录把变体折叠成基础模型，而 Google 只发布变体，折叠不会发生，于是 `gemini-4-hydrogen-xhigh` 仍被记录并执行为 `low`。现在按同族兄弟档位识别（同一前缀下两个以上已知档位），记录与上游思考档位都是 `xhigh`。
- Also inherited from beta.19/beta.20: Google account card is compact again (no duplicated manual sync button), Antigravity inline images reach Gemini, Google accounts have their own settings panel with queue/balanced rotation (migration 047). / 同时沿用 beta.19／beta.20：Google 账号卡片恢复紧凑（去掉重复的手动同步按钮）、Antigravity 内联图片可以送到 Gemini、Google 订阅账号有独立的「Google 账号设置」可切换队列／平衡轮换（迁移 047）。

## Breaking Changes / 不兼容变更

- Migration 047 (`google_settings`, default `queue`) runs on first start if the installed build predates beta.17. / 如果当前安装的版本早于 beta.17，首次启动会执行迁移 047（`google_settings`，默认 `queue`）。
- Request list ordering changes: running requests now sort before finished ones regardless of start time. / 请求列表排序变化：进行中的请求不再按开始时间混排，而是固定排在已结束之前。
- No public API change. / 无公共 API 变更。

## Verification and limits / 校验与边界

- `task --force verify` passed: format check, lint, typecheck, Go test packages, frontend suite (149 files / 904 tests) and the Windows production build. / `task --force verify` 通过：格式检查、lint、类型检查、Go 测试包、前端测试（149 文件／904 项）与 Windows 生产构建。
- A Go test pins the ordering (a pending record inserted first stays first even after three later finished requests) and checks that the state filter is unaffected; three component tests cover the pinning, the divider position, and the two single-group cases. / Go 测试固定了排序（先插入的进行中记录在三条更晚完成的记录之后仍排第一），并验证状态筛选不受影响；三个组件测试覆盖置顶、分隔行位置与只有一组时的情况。
- Variant-level fix was verified end-to-end against the real catalog on an isolated instance in the previous build cycle and carries over unchanged. / 变体档位修复已在上一轮用真实目录在隔离实例上端到端验证，本版沿用未变。
- The desktop client's own 60-second cut-off for long-thinking models (`499 request_cancelled` on `gemini-4-argon-high`) is unchanged. / 桌面端对长思考模型自己的 60 秒上限（`gemini-4-argon-high` 的 `499 request_cancelled`）本版未变。
- The local installer is unsigned and may trigger an unknown-publisher or SmartScreen warning. Building does not install or launch the application. / 本地安装器未签名，可能触发未知发布者或 SmartScreen 提示；构建不安装、不启动应用。
