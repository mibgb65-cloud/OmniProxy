# OmniProxy v2.4.1-beta.4

## Fixes / 修复

- **Reasoning levels no longer split a model in usage statistics.** Upstream publishes a separate model ID per thinking level (`gemini-4-neon-high`, `-low`, `-medium`, `-xhigh`), and every statistics view grouped by the exact ID, so one model showed up as several rows and each variant took a spot in the top six. The model dimension now merges variants that differ only by reasoning level: “By provider and model”, model share, daily usage by model and the dashboard token share all count one model. Requests and tokens are summed, and hovering the merged row lists the model IDs that were merged. / 「推理档位不再把同一个模型拆开。」上游为每个思考程度发布独立模型 ID（`gemini-4-neon-high`／`-low`／`-medium`／`-xhigh`），而所有统计视图都按精确 ID 分组，于是同一个模型显示成多行，每个变体还各占前六名的一个名额。现在模型维度只按推理档位区分的变体合并为同一模型：「按提供商与模型」、模型用量占比、模型每日用量与仪表盘模型 Token 占比口径一致，请求数与 Token 相加，悬浮合并行还能看到被合并的具体型号。

## Notes / 说明

- Only confirmed families are merged, by evidence rather than by name: two or more known level suffixes on the same base name, or the base model itself being a known model. A lone `-high` with no base model stays as is, and `-thinking`, `-tiered`, `-lite`, `-free` are never treated as levels. / 只合并有证据的家族，不按名字猜：同一基础名出现两个及以上已确认档位后缀，或基础名本身也是已知模型。只有一个 `-high`、没有基础模型的型号保持原样；`-thinking`、`-tiered`、`-lite`、`-free` 不会被当成档位。
- Nothing is rewritten in the database: merging happens when statistics are read, so history, request details, records page and exports keep the exact model ID of every request. This version has no migration. / 不改写数据库：合并在读取统计时完成，历史数据、请求明细、记录页与导出仍保留每次请求实际使用的型号 ID。本版本无数据库迁移。
- The top six and “Other” are computed after merging, so the rows shown may differ from earlier screenshots. / 前六名与「其他」按合并后的家族计算，因此与之前的截图相比行数可能变化。
- Also included since beta.3: re-authorizing the same Google or ChatGPT account updates the existing account instead of adding a duplicate. / 同时包含 beta.3 的内容：重新授权同一 Google／ChatGPT 账号会更新原账号，不再新增重复卡片。
