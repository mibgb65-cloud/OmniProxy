# OmniProxy v2.3.1-beta.28

## New Features / 新功能

- The Google (Antigravity) accounts page now groups subscription accounts by the quota groups they actually report. Accounts returning the same set of group names sit next to each other, an account that reports an extra group such as `Gemini 4 Argon` gets its own section (listed first, because it has more groups), API Key accounts and accounts whose quota has not been read yet go last, and every section header states the group names plus the account count. With a single section the page keeps its previous flat layout and shows no headers. Cards and the list view both follow the grouping. / Google（Antigravity）账号页现在按账号实际返回的额度分组集合分区：分组集合相同的账号相邻，多出 `Gemini 4 Argon` 这类分组的账号单独成区并排在前面（分组更多者优先），API Key 账号与额度尚未读取的账号排在最后，每个分区标题写明分组名与账号数。只有一个分区时保持原来的平铺、不显示标题。卡片视图与列表视图都生效。
- Grouping is driven only by `groups[].name` in the official quota snapshot: it keeps the upstream group order for display, keys sections by the sorted name set (so a different upstream order never splits one set into two sections), and ignores the percentages, reset times and plan tier. Amounts used therefore never move an account between sections, and nothing is inferred beyond the returned names. / 分区只依据官方额度快照里的 `groups[].name`：展示保持上游顺序，分区键用排序后的名字集合（上游顺序不同不会被拆成两区），与百分比、重置时间和套餐档位都无关，因此额度用掉多少不会让账号换区，也不推断分组名之外的含义。

## Notes / 说明

- A section titled "quota groups unknown" is not the same as "this account lacks the group": it means the quota has not been read yet (signed out, not refreshed, or the read failed), and the section says so. Accounts move to their real section after a successful refresh. / 「额度分组未知」分区不等于「该账号没有这组额度」：它表示额度尚未读取（未登录、尚未刷新或读取失败），分区内直接写明这一点；刷新成功后账号会自动归入对应分区。
- This does not distinguish a self-paid Pro subscription from a student/promo Pro subscription. Both report the same Antigravity tier (`g1-pro-tier`) and the same badge, and nothing in `account_id` or the tier encodes the billing source; that difference only exists in Google's billing records. / 本版本不区分「自费 Pro」与「学生 Pro」：两者返回同一个 Antigravity 档位（`g1-pro-tier`）与同一个徽章，`account_id` 和档位里都不带付费来源，这一差异只存在于 Google 的账单记录里。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no API or configuration change: the accounts page reuses the quota query and local snapshot the cards already use, so grouping issues no extra upstream request. / 无数据库迁移、无 API／配置变更：账号页复用卡片已有的额度查询与本地快照，分区不会额外请求上游。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.28`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.28`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, open the Google (Antigravity) accounts page. Sections appear once at least two different group sets are known; with one known set the page stays flat. A brand-new install may show every account in the "quota groups unknown" section for a moment until the quota reads finish. / 升级后打开 Google（Antigravity）账号页即可看到。至少有两种不同的分组集合时才会出现分区；只有一种时页面保持平铺。刚启动时配额还没读回来，可能会短暂把账号都放在「额度分组未知」分区里。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 163 frontend files / 1000 tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 163 文件／1000 项测试与 Windows 生产构建。
- Covered by tests: group signature (trim, de-duplication, upstream order), sections split by an extra group and ordered with more groups first, one set in different upstream orders merging into one section, account order preserved inside a section, API Key and unknown sections placed last, card and list views rendering the sections, the flat layout when only one section exists, and the unknown section's explanation. / 测试覆盖：分组签名（去空白、去重、上游顺序）、多一组额度的账号单独成区且排在前面、同一集合因上游顺序不同仍合并成一区、分区内账号顺序保持、API Key 与未知分区排最后、卡片与列表视图的分区渲染、只有一个分区时的平铺、未知分区的说明文案。
- **No real model request was sent while building this version**, and the grouped layout was not eyeballed in the running desktop window: the geometry is locked by tests and existing grid rules, but the pixels in a real window are still unconfirmed. / **本版本打包时未发起任何真实模型请求**，分区布局也没有在运行中的桌面窗口里目视确认：排布由测试与既有网格规则锁定，但真实窗口里的像素表现仍待确认。
