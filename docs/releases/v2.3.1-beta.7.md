# OmniProxy v2.3.1-beta.7

## Features / 新功能

- HowToFix is now a built-in provider (`builtin_howtofix`, migration 049, enabled by default). Add an API Key account, run “同步官方模型”, and the gateway calls `GET https://api.howtofix.id/v1/models` for that account. The catalogue is issued per account group (for example `hy4` only exists in the `vip` group), so the provider ships no preset models and publishes nothing before the first sync. / HowToFix 成为内置服务商（`builtin_howtofix`，迁移 049，默认启用）。添加 API Key 账号后执行「同步官方模型」，网关用该账号调用 `GET https://api.howtofix.id/v1/models`；目录按账号所属分组发放（例如 `hy4` 只在 `vip` 分组），因此没有内置预设，未同步前不发布任何模型。
- Chat Completions is forwarded natively and usage is accounted from the upstream `usage` field. Responses／Messages requests are converted to Chat by the existing `agentprotocol` path and re-encoded into the caller's protocol; HowToFix's documentation claims native Anthropic and Gemini routes, which this adapter does not use and does not claim. / Chat Completions 原生透传并按上游 `usage` 记账；Responses／Messages 由既有 `agentprotocol` 转成 Chat 后按调用方协议回包。官方文档称 Anthropic 与 Gemini 路由为原生直出，本适配器不使用也不宣称它们。
- Accounts show the prepaid USD balance from `GET /v1/dashboard/billing/subscription` (`hard_limit_usd`). The deployment returns `soft_limit_usd`／`system_hard_limit_usd` with the same value and `total_usage` is always `0`, so only the remaining amount is displayed instead of a misleading “limit/used” pair. / 账号卡展示来自 `GET /v1/dashboard/billing/subscription`（`hard_limit_usd`）的预付美元余额。该部署的 `soft_limit_usd`／`system_hard_limit_usd` 与其同值、`total_usage` 恒为 `0`，因此只显示剩余额度，不显示会误导的「额度上限／已用」。
- Provider page gets the official HowToFix icon and bilingual labels; the provider also counts in “接入检查” and in the account balance panels. Managed clients (Claude Code, Codex, DSH, OpenCode, …) pick the models up automatically from configured routes — no per-client wiring. / 提供商页使用官方图标与中英文名称，HowToFix 也计入「接入检查」与账号余额面板。受管客户端（Claude Code、Codex、DSH、OpenCode 等）从已配置路由自动获得模型，不需要逐客户端接入。

## Breaking Changes / 不兼容变更

None / 无。No public API change. Migration 049 only appends the `builtin_howtofix` row: existing provider switches, accounts, credential references, routes and statistics are left untouched. Emitted for this provider only: Chat requests go to `POST /v1/chat/completions` with `Authorization: Bearer sk-…`; `reasoning_effort` and `stream_options` are not injected, and a `402` insufficient balance is returned to the client instead of failing over to another key. / 无公共 API 变更。迁移 049 只追加 `builtin_howtofix` 一行：已有服务商开关、账号、凭据引用、路由与统计均不改动。仅对该服务商生效：Chat 走 `POST /v1/chat/completions` + `Authorization: Bearer sk-…`；不注入 `reasoning_effort` 与 `stream_options`；`402` 余额不足原样回传，不切换到其他 Key。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.7`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.7`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- First launch runs migration 049 and appends the enabled-by-default `builtin_howtofix` preset; a HowToFix account is only created when you add one. / 首次启动执行迁移 049 并追加默认启用的 `builtin_howtofix` 预设；HowToFix 账号需要你自己添加。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 155 frontend test files (940 tests) and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 155 个文件（940 项测试）与 Windows 生产构建。
- New coverage: adapter contract tests (Bearer header, fixed path, non-Chat protocols and unsafe base URLs rejected, SSE/JSON passthrough), catalogue filtering and failure cases, migration 049 idempotency, routing eligibility before/after sync, gateway conversion round-trips for both protocols, and balance error mapping. / 新增覆盖：适配器契约测试（Bearer 头、固定路径、拒绝非 Chat 协议与不安全基址、SSE／JSON 透传）、目录过滤与失败分支、迁移 049 幂等、同步前后的路由资格、两种协议经网关的转换往返、余额错误码映射。
- Checked against a real account key on 2026-11-15: `GET /v1/models` returned 12 models (id/object/created/owned_by only, no capability metadata), one `POST /v1/chat/completions` with `max_tokens: 1` returned 200 with `usage` 31/1, and the balance moved from `50` to `49.999998` after that request. / 2026-11-15 用真实账号 Key 复核：`GET /v1/models` 返回 12 个模型（只有 id/object/created/owned_by，没有能力元数据）；一次 `max_tokens: 1` 的 `POST /v1/chat/completions` 返回 200、`usage` 为 31/1；该请求后余额从 `50` 变为 `49.999998`。
- Not verified: whether HowToFix's Anthropic／Gemini routes are truly native, long-context/tool/image behaviour on real models (the catalogue publishes no capabilities, so none are claimed), and the balance panel's appearance in a real desktop window. / 未验证：HowToFix 的 Anthropic／Gemini 路由是否真为原生直出；真实模型上的长上下文、工具与图片行为（目录不发布能力，因此一律不声明）；真实桌面窗口中的余额面板视觉。
