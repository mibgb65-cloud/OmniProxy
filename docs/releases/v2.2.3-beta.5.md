# OmniProxy v2.2.3-beta.5

## Features / 新功能

## Bug Fixes / 问题修复

- Codex forwarding for OpenAI API Key accounts now uses `https://api.openai.com/v1` when the built-in provider address is empty, rather than failing with an empty upstream address. Custom API addresses and the subscription endpoint remain unchanged.
  - OpenAI API Key 账号通过 Codex 转发时，内置提供商地址留空会正确使用 `https://api.openai.com/v1`，不再因空上游地址失败；保留自定义 API 地址和订阅端点原行为。
- Background OpenAI model discovery now includes enabled API Key accounts without requiring a subscription login state. Catalogs remain scoped to the credential version and refresh after a key replacement.
  - OpenAI 后台模型发现纳入已启用的 API Key 账号，不再要求订阅登录状态；目录仍按凭据版本隔离，更换 Key 后重新同步。
- Creating a single account or importing a batch now notifies background model discovery, avoiding the need to restart merely to discover a new API Key account.
  - 单个新增、批量新增账号后会通知后台模型同步，避免仅为识别新 API Key 账号而重启应用。

  - 保留现有账号和客户端配置。同一模型同时支持订阅与 API Key 账号时，如需明确使用 API 额度，请建立精确路由并固定 API Key 账号；不会自动跨计费池切换。
