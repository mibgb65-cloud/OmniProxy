# OmniProxy v2.3.1-beta.26

## Bug Fixes / 问题修复

- Account-level refusals keep their real error code and now switch accounts. WorkBuddy business refusals (`11158` model entitlement, `11128` channel, `11159` signature, `10085` fingerprint) reach the gateway as stable codes, not as boundary errors, so the request record fell back to `503 credential_unavailable`; the failover classifier could not see them either, which is why three `gemini-4-carbon` requests each tried the same account exactly once and never reached the second account in the pool. Stable codes are now translated at the gateway boundary, `model_not_entitled` and the 401 class count as account-level refusals (cooling the account/model pair for 30 and 5 minutes), and a request with no remaining candidate returns the real 403 instead of a fake 429 pool cooldown. Provider-level refusals (channel, signature, client fingerprint) and local credential failures still do not switch accounts. / 账号级拒绝保留真实错误码并换号：WorkBuddy 的业务码拒绝（`11158` 模型权益、`11128` 渠道、`11159` 签名、`10085` 指纹）到网关时只是稳定码而不是边界错误，请求记录因此被兜底成 `503 credential_unavailable`，失败分类也看不到它们——三条 `gemini-4-carbon` 请求各只尝试同一个账号一次，同池第二个账号从未被尝试。现在稳定码在网关边界完成翻译，`model_not_entitled` 与 401 类按账号级拒绝处理（分别冷却 30／5 分钟），没有剩余候选时返回真实 403 而不是伪造的 429 池冷却；服务商级拒绝（渠道、签名、客户端指纹）与本地凭据故障仍不换号。
- Family name plus effort resolves before provider selection, so a relay can no longer intercept Google's request. The Antigravity desktop sends `gemini-4-carbon` with `reasoning_effort=high`, while only the WorkBuddy relay publishes that bare id and the Google subscriptions publish `-high`／`-low`／`-medium`. Routing matched the bare id first, so the official subscription variants never entered the candidate list. The family name is now resolved to the real variant before any provider is chosen: it requires an explicit effort, at least two confirmed effort siblings, and an exact level match (no nearest-level substitution); requests without an effort or without a matching variant are left untouched. / 家族名 + 档位在选服务商前解析，中转站不再截获谷歌请求：Antigravity 桌面端发送 `gemini-4-carbon` 加 `reasoning_effort=high`，而裸型号只有 WorkBuddy 中转站发布、Google 订阅只发布 `-high`／`-low`／`-medium`，路由按精确 ID 先命中裸型号，官方订阅的变体永远进不了候选。现在选服务商之前就把家族名解析成真实变体：要求客户端明确给出档位、同族至少确认两个档位后缀、且档位精确匹配（不做就近替换）；没有档位或没有对应变体的请求完全不变。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no API or configuration change. Behavior changes only for requests that already carry an explicit reasoning effort on an effort-variant family, and for accounts that are refused at the account level. / 无数据库迁移、无 API／配置变更。行为变化仅限“带明确档位的档位变体家族”和“账号级拒绝”这两类请求。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.26`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.26`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- This build also contains the beta.25 cache-hit fix, so a Google request made after upgrading should show both the real cache hit and the official subscription as its target. / 本构建同时包含 beta.25 的缓存命中修复，升级后新的 Google 请求应同时显示真实缓存命中与官方订阅目标。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 159 frontend files / 977 tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 159 文件／977 项测试与 Windows 生产构建。
- Covered by tests: business-code translation and status mapping, account-level classification table, WorkBuddy two-account switch with cooling, single-candidate real 403, provider-level refusal without a switch, family-name routing for four effort cases and the single-sibling boundary. / 测试覆盖：业务码翻译与状态映射、账号级分类表、WorkBuddy 双账号换号与冷却、单候选真实 403、服务商级拒绝不换号、家族名路由的四种档位场景与单变体边界。
- **No real subscription or relay request was sent while building this version** (they would consume quota); the first requests after installing confirm both fixes end-to-end, and the request record now names the true refusal code. / **本版本打包时未发起真实订阅／中转请求**（会消耗额度）；两处修复的端到端结果由安装后的首批请求确认，请求记录会直接给出真实拒绝码。
