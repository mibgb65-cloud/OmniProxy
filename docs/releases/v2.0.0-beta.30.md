# OmniProxy v2.0.0-beta.30

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版修两个推理强度问题：**River 的 DeepSeek 型号在 Codex 里只能停在「高」无法切换**，以及**Google 系每个推理档位都变成一行模型**。数据库结构未变，无新迁移。

## River：档位在 Codex 里真正可选

Codex 的模型目录只认它自己的档位词汇（`minimal`／`low`／`medium`／`high`／`xhigh`）。River 用 `none`／`max` 表达两端，目录把这些值原样发出去后 Codex 不认识，于是选择器只剩「高」一个值——看起来就是「没法选推理强度」。

- 现在目录按就近语义发布：`none → minimal`、`max → xhigh`，默认档位同步映射。
- 网关收到请求后还原成上游取值：`minimal → none`、`xhigh → max`；未确认的档位仍然明确返回 `unsupported_reasoning_effort`，不会静默降级。
- 影响 `DeepSeek-V4.1-Flash`、`DeepSeek-V4.1-Flash-1017`、`GLM-5.3-Flash` 等有档位枚举的 River 型号；Messages、Responses、Chat 三条链路都按同一套映射。

需要重新应用一次 Codex 配置（或触发一次模型目录刷新）才会看到新的档位列表。

## Google：档位不再是一堆「模型」

Google 系上游用**独立型号**表达 thinking level：`gemini-3.8-flash-low`、`…-high`、`…-medium`，显示名分别是 `Gemini 3.8 Flash (Low/High/Medium)`。之前目录照搬，客户端菜单里就出现了一串「模型」，同一型号还会重复。

- 目录现在把这些变体折叠回同名基础模型：菜单只留 `Gemini 3.8 Flash` 一行，档位由客户端 effort 控件选择。
- 网关在请求时把档位换成实际存在的变体型号，并移除档位字段——订阅通道的生成参数是白名单校验，多余的 `reasoning_effort` 会被直接拒绝。
- 折叠只在同名基础模型同时存在时发生；只有变体的孤立型号保持原样，不会误合并不同型号。
- 已经保存的旧选择（例如 `gemini-3.8-flash-low`）在路由失败时按反向映射还原成「基础模型 + 档位」，不会变成 `unsupported_model`。
- 显示名相同但 ID 不同的型号（实测 `Gemini 3.5 Flash Lite` 有 4 个：`gemini-2.5-flash`、`gemini-2.5-flash-lite`、`gemini-2.5-flash-thinking`、`gemini-3.5-flash-lite`）**不会**合并——它们是不同的路由目标，合并会改变实际请求的模型。

折叠在下一次同步模型后生效。

## 兼容与已知边界

- 无新迁移，无数据格式变化；历史记录、设置与凭据保持原样。
- 档位就近映射不是语义等价：`none`（关闭思考）对 Codex 表达为 `minimal`，`max`（最高强度）表达为 `xhigh`。客户端没有同名选项时这是唯一能选到的表达方式，文案不夸大能力。
- 客户端是否真的渲染 effort 控件仍取决于客户端自己；Claude Desktop 对不透明路由名不显示控件是已知客户端限制，应用内的「思考强度」入口继续可用。
- Codex 在约 500k 用量时提前压缩、Google 上游 `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项，本版不宣称已修复。
- 安装器未签名、未自动安装、未打标签、未推送；真实覆盖安装与客户端菜单验收由用户本地完成。

## 顺带包含（Beta.29 之后未单独发版）

- 固定入口前缀已生效：Codex `…/codex/v1`（保留官方登录）、Claude 系 `…/claude`、其余 `…/<client>/v1`；旧 `/v1` 与 `/agent/codex/<Key>/v1` 继续可用。
- River 图片输入与受管客户端目录的图片能力声明。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录。安装后在「设置与关于」核对版本为 2.0.0-beta.30，然后对 Codex 重新「预览 → 应用」、在路由页同步一次 Google／River 模型目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用。
