# OmniProxy v2.4.1-beta.3

## Fixes / 修复

- **Re-login no longer duplicates an account.** The account page's “Add account” dialog never sends the local account ID, so authorizing the same Google or ChatGPT account again inserted a second row with the same identity. Two rows sharing one email and `account_id` got separate catalog and quota snapshots, and the gateway treated one upstream account as two rotation candidates. Saving an authorization now looks up the subscription identity (provider + normalized email + official `account_id`) first and updates that account — keeping its ID, name, creation time and enabled state — instead of creating a duplicate. Explicit re-login from a card keeps its existing “same identity only” rule. / 「重新登录不再产生重复账号。」账号页「添加账号」弹窗不携带本地账号 ID，因此对同一个 Google／ChatGPT 账号再次授权会插入一条身份相同的记录。两条记录各自持有目录与额度快照，网关还会把同一个上游账号当成两个轮换候选。现在保存授权前先按订阅身份（提供商 + 规范化邮箱 + 官方 `account_id`）查找已有账号并更新它，保留 ID、名称、创建时间与启停状态，不再新增重复卡片；卡片上的「重新登录」仍保持「只能替换同一身份」的既有约束。

## Notes / 说明

- Accounts that already contain duplicates are left untouched: delete the extra card from the account page. Lifetime usage totals are stored by identity, so removing a duplicate card does not reduce them. Accounts sharing a workspace but with different mailboxes stay separate. / 已经存在重复的账号不会自动清理：在账号页删除多余的那张卡片即可。终身用量累计按身份保存，删除重复卡片不会减少累计；同一工作区里邮箱不同的成员仍是各自独立的账号。
- This version has no database migration. Routing, request history, quotas and settings are unchanged. / 本版本无数据库迁移，路由、请求历史、额度与设置保持不变。
