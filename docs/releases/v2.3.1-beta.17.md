# OmniProxy v2.3.1-beta.17

## Bug Fixes / 问题修复

- WorkBuddy AI Credits now load and display. The billing API is not shaped like the chat API: it wants `POST /billing/meter/get-user-resource-summary` with an empty JSON object body, the short `WorkBuddy/<version>` user agent and only the account headers — no `X-Agent-*`, no `X-Stainless-*`. OmniProxy sent a `GET`, and the gateway answered `404`, so the account card showed `—` and an error. / WorkBuddy AI 的 Credits 现在能正常读取并显示。计费接口和对话接口形态不同：要 `POST /billing/meter/get-user-resource-summary` + 空 JSON 对象正文、短 `WorkBuddy/<版本>` UA，只带账号头，不带 `X-Agent-*`／`X-Stainless-*`。OmniProxy 之前发的是 `GET`，被网关 404，所以账号卡只显示 `—` 和报错。
- The plan name now comes from the billing API's `SubscriptionPackageName` and is shown next to the credits title. The sign-in identity has no plan field, which is why the account used to read "package unknown". / 套餐名改为取自计费接口的 `SubscriptionPackageName`，显示在额度标题旁。登录身份里没有套餐字段，这是之前一直显示「套餐未知」的原因。
- WorkBuddy failures no longer collapse into one generic message. Errors cross three layers with different prefixes (`workbuddy_ai:`, `subscription:`, `gateway:`); the UI now recognises the stable code wherever it appears instead of only after the first two prefixes. A `404`/`429`/network failure on the quota or catalog path now says what actually happened. / WorkBuddy 的失败不再统一塌成一句通用文案。错误来自三层、前缀各不相同（`workbuddy_ai:`／`subscription:`／`gateway:`），界面现在按稳定码切词识别，而不是只认前两种前缀。额度或目录路径上的 `404`／`429`／网络失败现在会说清实际发生了什么。
- The model-catalog sync warning now logs the real error code instead of always `workbuddy_auto_sync_failed`. / 目录同步的 WARN 现在记录真实错误码，不再永远是 `workbuddy_auto_sync_failed`。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no change to the WorkBuddy upstream protocol beyond using the billing endpoint the way the official client does. / 无数据库迁移、无公共 API 变更；除按官方客户端形态调用计费接口外，未改动 WorkBuddy 上游协议。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.17`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.17`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes and the already-synced WorkBuddy AI catalog are preserved: just open the account card after installing and the credits load without signing in again. / 保留现有账号、路由以及已同步的 WorkBuddy AI 目录：安装后直接打开账号卡即可加载额度，不需要重新登录。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Verified against the real account before writing the fix: `GET` on the billing path returns `404`, while `POST {}` with the official client's headers returns `200` with `CreditGroups[plan_base 100]`, `TotalCredits "100"`, `SubscriptionPackageName "Free"`, `IsPaidUser false`. The adapter's parsing is pinned to that exact payload as a unit test, and the request shape (method, body, headers, no chat headers) is asserted by a contract test. / 写修复前已在真实账号上核对：计费路径 `GET` 返回 `404`，而 `POST {}` + 官方客户端头返回 `200`，内容为 `CreditGroups[plan_base 100]`、`TotalCredits "100"`、`SubscriptionPackageName "Free"`、`IsPaidUser false`。适配器解析以这份真实正文固定为单元测试，请求形态（方法、正文、头集、不带对话头）由契约测试断言。
- **Not verified**: the in-app credits display and a real chat completion after installing. Chat consumes real credits; the free plan currently holds 100 credits. / **未验证**：安装后应用内的额度显示与真实对话。对话会消耗真实积分；当前 Free 计划为 100 credits。
