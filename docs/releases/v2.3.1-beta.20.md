# OmniProxy v2.3.1-beta.20

## Bug Fixes / 问题修复

- WorkBuddy AI models that declare `onlyReasoning` now expose reasoning levels. The upstream `/v3/config` gives four of them (`max-model`, `gemini-4-carbon`, `gemini-4-argon`, `kimi-k3`) only a `reasoning.effort` value instead of a `supportedEfforts` list, so OmniProxy stored them with no levels at all — and dropped their default (`high` for `max-model`, `medium` for the three others). Those models accept `low/high/max` plus their own level upstream, so the catalog now fills them in that way and keeps their own level as the default. / WorkBuddy AI 中只声明 `onlyReasoning` 的模型现在也有推理档位。上游 `/v3/config` 对 4 个模型（`max-model`、`gemini-4-carbon`、`gemini-4-argon`、`kimi-k3`）只给 `reasoning.effort`，不给 `supportedEfforts` 列表，因此 OmniProxy 之前把它们存成「没有档位」，连默认档位也丢了（`max-model` 是 `high`，其余三个是 `medium`）。这些模型在上游接受 `low/high/max` 加上自己的档位，目录现在按这个口径补齐，并保留它自己的档位作为默认。 / 目录刷新后，模型目录与网关的模型档位选择器会显示这些档位。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no frontend change. Only the synced model catalog metadata changes; existing routes and clients keep working. / 无数据库迁移、无公共 API 变更、无前端变更。仅同步得到的模型目录元数据变化；现有路由与客户端不受影响。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.20`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.20`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After the upgrade, click **Sync** in 路由 → 模型目录 (or let the next automatic sync run) so the stored catalog picks up the filled-in levels; existing snapshots keep their old metadata until they are refreshed. / 升级后请在「路由 → 模型目录」点一次**同步**（或等下一次自动同步），让已存目录拿到补齐后的档位；未刷新前旧快照仍是旧元数据。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Real account evidence (Free plan, `/v3/config`, 25 models): 21 models declare `supportedEfforts` (for example `glm-5.3` → `low/high/max`, `gpt-6.1-sol` → `low/medium/high/xhigh/max`, `hy4std` → `high` only); `max-model`, `gemini-4-carbon`, `gemini-4-argon` and `kimi-k3` declare `supportsReasoning: true` + `onlyReasoning: true` with just `effort`; `default-model`, `hy-image-3.5` and `kling-video-v3` declare no reasoning at all. / 真实账号证据（Free 计划，`/v3/config`，25 个模型）：21 个模型声明 `supportedEfforts`（例如 `glm-5.3` → `low/high/max`、`gpt-6.1-sol` → `low/medium/high/xhigh/max`、`hy4std` 只有 `high`）；`max-model`、`gemini-4-carbon`、`gemini-4-argon`、`kimi-k3` 是 `supportsReasoning: true` + `onlyReasoning: true` 且只有 `effort`；`default-model`、`hy-image-3.5`、`kling-video-v3` 完全没有推理声明。
- The fallback set (`low/high/max`) follows the community plugin `@magpie-community/opencode-workbuddy-auth` 0.2.36 (`effortsOf()`), which requests those levels on real accounts; the levels themselves were not re-measured per model in this version. `none` is never published as a level (the upstream `canDisableThinking` flag is unreliable). / 回退档位集合（`low/high/max`）沿用社区插件 `@magpie-community/opencode-workbuddy-auth` 0.2.36 的 `effortsOf()`，它在真实账号上请求过这些档位；本版本没有逐个模型重新实测档位。`none` 不作为档位发布（上游 `canDisableThinking` 不可靠）。
- **Not verified**: paid-plan credit deduction, and a real desktop client (Codex／Claude Code) conversation through the gateway. / **未验证**：付费套餐的积分扣减，以及真实桌面客户端（Codex／Claude Code）经网关的对话。
