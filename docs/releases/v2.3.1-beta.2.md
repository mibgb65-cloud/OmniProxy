# OmniProxy v2.3.1-beta.2

## Features / 新功能

- Google subscription Gemini models now declare `text` + `image` input in the model catalog, so Antigravity (and every managed client that reads the same catalog) publishes `supportsImages: true` and stops blocking attachments for these models. Claude and GPT-OSS on the subscription channel stay text-only because their image path has not been verified. / Google 订阅的 Gemini 模型在模型目录里声明 `text` + `image` 输入，Antigravity 以及所有读同一份目录的受管客户端随之发布 `supportsImages: true`，不再拦截这些模型的附图。订阅内的 Claude／GPT-OSS 通道未验证图片，继续按纯文本发布。
- Chat requests now accept inline images inside tool results: the text goes into `functionResponse` and the image becomes an `inlineData` part in the same user turn. This is the shape an agent uses when `read_file` or a screenshot tool brings a picture back, so the model finally sees pixels instead of a placeholder. / Chat 请求开始接受工具结果里的内联图片：文本进 `functionResponse`，图片作为同一 user 回合里的 `inlineData` part。agent 通过 `read_file` 或截图工具带回图片时正是这个形态，模型终于能看到像素而不是占位提示。
- Images that cannot be inlined (remote URLs, unsupported formats, oversized payloads) and images in `system` / `assistant` turns still fail explicitly; nothing is silently dropped or downgraded to text. / 无法内联的图片（远程 URL、非白名单格式、超限）以及 `system`／`assistant` 回合里的图片仍然明确失败，不会静默丢弃或降级成文本。

## Bug Fixes / 问题修复

- Antigravity agents reported "the current model does not support images" and only received placeholder text when reading PNG files, even though the underlying Gemini model and the gateway transport both support images. The blocker was the capability declaration plus the missing tool-result image conversion. / Antigravity 的 agent 读 PNG 时只拿到占位提示并声称「当前模型不支持图片」，而上游 Gemini 与网关通路其实都支持图片；阻断点是能力声明与缺失的工具结果图片转换。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change. / 无数据库迁移、无公共 API 变更。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray (the running instance is an older build), back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy（当前运行的是更早的构建），备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.2`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.2`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。
- After upgrading, click **Sync official models** once on the Google account so `account_models` picks up the image capability, then fully restart Antigravity so it re-reads the remote model list. Without these two steps the client keeps the old text-only catalog. / 升级后需要在 Google 账号卡片上点一次「同步官方模型」，让 `account_models` 拿到图片能力，然后完全重启 Antigravity 重新拉取远端目录。少了这两步，客户端读到的仍是旧的纯文本目录。

## Verification boundary / 验证边界

- Before packaging, `task --force verify` passed: Go packages, frontend tests (154 files / 935 tests), format, lint, typecheck and the Windows production build. / 打包前 `task --force verify` 通过：Go 全包、前端 154 文件／935 项测试、格式、lint、类型检查与 Windows 生产构建。
- Real upstream requests on an isolated instance (copy of the production data directory, separate port, running app untouched) returned 200: a user-message image was described as `Pink`; the same tool round with only text made the model say it could not see the image; with the tool-result image it answered `Pink` again. / 隔离实例（生产数据副本、独立端口、未触碰运行中的应用）真实上游请求返回 200：用户消息图片被描述为 `Pink`；同一工具轮只有文本时模型明确说看不到图片；带工具结果图片时再次回答 `Pink`。
- Antigravity desktop retest with a real screenshot is still pending; the operating system installation is not upgraded by this build automatically. / Antigravity 桌面端使用真实截图的复测仍未执行；本次构建不会自动升级系统安装。
