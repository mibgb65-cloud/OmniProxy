# OmniProxy v2.2.3-beta.17

## New Features / 新增功能

- Google accounts get their own settings panel. The Google provider now shows a “Google account settings” button with the same **account rotation** choice Codex and River already have: sequential (default) keeps the routing order, balanced spreads new requests across the available Google AI subscription accounts in the same pool. It only rotates subscription accounts — API key accounts are never reordered — and a pinned account never switches. The setting is stored in the new `google_settings` table and applies immediately, without restarting the gateway. / Google 账号页新增「Google 账号设置」，提供与 Codex／River 相同的**账号轮换方式**：队列轮换（默认）保持路由顺序，平衡切换在同池可用的 Google AI 订阅账号间轮流分配新请求。只对订阅账号生效——API Key 账号不参与重排——固定账号不切换。设置保存在新表 `google_settings`，保存后立即生效，无需重启网关。

## Bug Fixes / 问题修复

- The `xhigh` model's reasoning level is no longer downgraded by the client's own effort field. Antigravity sends variants such as `gemini-4-hydrogen-high` as the model while also attaching a reasoning effort field (measured: `low`). The request detail and the upstream `thinkingConfig.thinkingLevel` followed that field, so a High model was reported and executed as Low. The catalog-confirmed level inside the model ID now wins, and the conflicting field is removed from the body before forwarding. / 变体型号的推理等级不再被客户端自带的档位字段降级。Antigravity 会把 `gemini-4-hydrogen-high` 这类变体当模型发送，同时附加一个推理档位字段（实测为 `low`）；请求明细与上游 `thinkingConfig.thinkingLevel` 都跟着该字段走，于是 High 模型被记录并执行为 Low。现在以目录确认的型号档位为准，转发前移除矛盾的档位字段。

## Breaking Changes / 不兼容变更

- One new database migration (047) creates `google_settings` with the default `queue`; no existing table, setting or account is modified. / 新增一项数据库迁移 047，新建 `google_settings` 并写入默认 `queue`；不改动任何已有表、设置或账号。
- No public API change; family-name + level requests, the `xhigh` pass-through and other clients keep their previous behavior. / 无公共 API 变更；家族名 + 档位、`xhigh` 透传与其它客户端行为保持不变。

Fully exit OmniProxy from the system tray (the running instance is beta.16), back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布。请先从托盘完全退出 OmniProxy（当前运行的是 beta.16），备份数据目录，再运行安装器覆盖现有安装。

## Verification and limits / 校验与边界

- `task --force verify` passed: format check, lint, typecheck, Go test packages, frontend suite (148 files / 902 tests) and the Windows production build. / `task --force verify` 通过：格式检查、lint、类型检查、Go 测试包、前端测试（148 文件／902 项）与 Windows 生产构建。
- Rotation has unit coverage for queue order, balanced distribution, API-key exclusion, pinned accounts and settings validation; a real two-account distribution test needs more than one Google subscription account. / 轮换有单元测试覆盖队列顺序、均衡分配、API Key 排除、固定账号与设置校验；真实双账号分配验证需要多于一个 Google 订阅账号。
- Not fixed here: Antigravity sessions on a long-thinking model (`gemini-4-argon-high`) that produce no first token within 60 seconds still end as `499 request_cancelled`. The gateway keeps waiting (5-minute header wait, 10-minute request budget) and a curl client completes such a request in ~60 s, so the cutoff is the desktop client's own timeout, which this build cannot change. / 本版不修复：`gemini-4-argon-high` 这类长思考模型在 60 秒内没有首个 token 时仍会以 `499 request_cancelled` 结束。网关本身会继续等待（响应头 5 分钟、整请求 10 分钟），隔离实例用 curl 发同样请求约 60 秒能成功，所以 60 秒是桌面端自己的超时，本版无法改变。
- The local installer is unsigned and may trigger an unknown-publisher or SmartScreen warning. Building does not install or launch the application. / 本地安装器未签名，可能触发未知发布者或 SmartScreen 提示；构建不安装、不启动应用。
