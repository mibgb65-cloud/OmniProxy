# OmniProxy v2.3.0

本次正式版汇总自公开版本 v2.2.2 以来的新增功能与修复，包含此前仅本地构建的
v2.2.3-beta.1–beta.24，不需要逐个安装中间版本。

This stable release includes the features and fixes since the public v2.2.2 release,
including the previously local-only v2.2.3-beta.1–beta.24 builds. Intermediate installs are not required.

## Features / 新功能

- **Baidu DuMate personal edition.** Import the local desktop login read-only or paste a Cookie header,
  verify the remote identity, and keep credentials in Windows DPAPI-protected storage. The gateway
  forwards Chat Completions using short-lived tokens; Responses and Messages use existing conversion.
  View points and expiry, manually check in, and distinguish live data, snapshots and pending credit.
  Only the two exposed aliases are published; underlying models and context capacity remain unspecified.
- **新增百度搭子 DuMate 个人版。** 支持只读导入本机搭子桌面端登录态，或手动粘贴
  Cookie 请求头；远端身份核对通过后按百度账号绑定，凭据仅保存在 Windows DPAPI
  受保护存储。网关以短期 token 转发 Chat Completions，Responses／Messages 经既有
  协议转换；积分面板支持可用／已用积分、最近到期信息和手动每日签到，区分实时结果、
  历史快照及「已提交但尚未到账」。只发布上游暴露的 `model-text`、
  `dm-auto-model/text.L0` 两条别名，不推断底层模型或上下文容量。
- **OpenAI API Key forwarding accounts.** Add an official OpenAI API key and sync its model catalog
  to use it through the gateway. API keys and subscription accounts retain their respective upstreams,
  without changing Codex login, sessions or one-click configuration.
- **支持 OpenAI API Key 转发账号。** 在账号页添加 OpenAI 官方 API Key，随后同步模型目录，
  即可通过本地网关使用；API Key 账号使用官方 API 入口，订阅账号继续使用原订阅入口，
  不改变 Codex 既有登录、会话和一键配置方式。
- **Antigravity desktop integration.** Configure the official gateway, publish eligible Google
  subscription models including catalog-listed Claude/GPT-OSS models, restore managed fields on
  disconnect, and track gateway port changes. Inline images reach image-capable Gemini models,
  subject to existing size, format, protocol and target-model validation.
- **接入 Antigravity 桌面客户端。** 支持配置官方网关、发布账号有权使用的 Google 订阅
  模型（包括目录中的 Claude／GPT-OSS），断开时按受管字段恢复，网关端口改变时同步地址。
  Antigravity 用户消息中的内联图片可经网关传至支持图片的 Gemini 模型；图片大小、格式、
  协议与目标模型仍受现有边界校验。
- **Queue/balanced Google subscription account rotation.** Upgrades retain queue order until the
  user selects balanced mode. Codex fallback candidates also follow their existing rotation setting.
- **Google 订阅账号支持队列／均衡轮换。** 升级默认保留原队列顺序，均衡模式需要用户主动选择；
  Codex 兜底候选池也遵循其已有轮换设置，不再固定优先使用第一个账号。
- **Automatic model catalog synchronization.** OpenAI subscription catalogs are refreshed when needed
  after startup, authorization and account changes; legacy imports also trigger synchronization.
  The UI shows progress, and failures preserve the last successful catalog with a manual retry path.
- **模型目录自动同步。** OpenAI 订阅账号在启动、授权和账号变更后按需后台补齐目录，
  旧版账号导入后也会触发同步；页面展示同步状态，失败保留上次成功快照并支持手动重试。
- **Usage analytics.** Six KPIs, switchable daily trends, token composition, provider/model/account
  shares, top-six daily model stacks, hourly distribution and 30-day request quality, with a
  two-column wide-screen layout and stacked narrow-screen reading order. Unknown cache usage is not zero.
- **用量页新增完整分析视图。** 包括 6 项 KPI、可切换的每日趋势、Token 构成环形图、
  提供商／模型／账号占比、Top 6 模型每日堆叠趋势、24 小时时段分布及近 30 天请求质量。
  宽屏结构区采用两栏布局，窄屏按阅读顺序堆叠；未知缓存报告不会被伪装为零。
- **Actual reasoning effort in request history.** Unspecified and historical values remain unknown.
  In-progress requests stay at the top, separated from completed requests.
- **请求记录展示实际思考档位。** 记录网关实际携带／发送的档位；历史记录或未指定档位
  显示「—」。进行中的请求固定置顶，并与已结束请求分隔。

## Bug Fixes / 问题修复

- Fix Codex compatibility when forwarding through an OpenAI API Key account.
- 修复 OpenAI API Key 账号通过 Codex 使用网关的兼容性问题。
- Align Google subscription Agent request shaping and refusal handling; fix Antigravity catalog
  authentication headers, Chat protocol marking and model-family/variant parsing, and adjust timeouts.
- 对齐 Google 订阅 Agent 请求形态与拒绝处理；修复 Antigravity 目录鉴权头、
  Chat 协议标记、模型家族名和变体解析，并调整响应头等待与请求时限。
- Preserve model-encoded reasoning effort over client fields, including variant-only catalogs;
  stop downgrading Antigravity `xhigh` to `high`.
- 型号自带思考档位时不再被客户端字段降级；Antigravity 的 `xhigh` 不再降为 `high`，
  目录只有变体型号时也遵循型号档位。
- Use a single desktop instance and bring its existing window forward on repeated launches.
- 桌面应用采用单实例运行，重复启动会唤起已有窗口。
- Do not report the gateway's current listening port as occupied when saving it.
- 修复保存当前正在监听的网关端口时被误判为占用。
- Local proxy detection now fills only the hostname, not `auto://127.0.0.1`;
  reject schemes, ports and paths in the host field before saving.
- 修复「探测本机代理」把 `auto://127.0.0.1` 等带协议地址写进主机字段；
  保存前检查协议、端口与路径等非法主机输入。
- Remove River's blanket local 128-tool rejection; upstream limits may still apply.
- 移除 River 适配器统一按 128 个工具拒绝请求的本地限制；上游仍可能有自己的限制。
- Simplify redundant refresh controls, align the Antigravity client card and stabilize the log footer.
- 精简部分冗余刷新入口、统一 Antigravity 客户端卡片，并稳定日志页脚高度。

## Refactor & Performance / 重构与基础升级

- Upgrade Wails from `v3.0.0-beta.30` to stable `v3.1.0`, aligning the Go module, frontend runtime
  and build CLI without enabling experimental Wake.
- Wails 桌面框架由 `v3.0.0-beta.30` 升级为正式版 `v3.1.0`，Go 模块、前端运行时和构建
  CLI 保持一致，不启用实验性 Wake。
- Reuse shared background catalog sync and protocol conversion. Usage charts use existing SVG/DOM
  capabilities without adding a charting library.
- 复用共享模型目录后台同步与既有协议转换链路；用量图表使用现有 SVG／DOM，
  不额外引入图表库。

## Breaking Changes / 不兼容变更

- No intentional public API breaking change. Existing accounts, data locations, external client-file
  protections and update preferences are retained.
- 无主动改变公共 API 的不兼容变更；既有账号、数据位置、客户端外部修改保护和更新偏好保留。
- Database migrations **046–048** add request reasoning effort, Google rotation settings and the
  DuMate provider. Previously applied local-Beta migrations are not repeated.
- 相对 v2.2.2 新增数据库迁移 **046–048**：请求思考档位、Google 轮换设置、
  DuMate 内置提供商。启动时按需执行，已在本地 Beta 执行过的迁移不会重复执行。
- **Do not downgrade and let an older application write to the upgraded database.** Retain current
  data and restore a consistent pre-upgrade backup into a separate directory before handling rollback.
- **不要直接降级并让旧程序继续写入升级后的同一数据库。** 需要回退时，应保留当前数据，
  使用升级前的一致性备份恢复到独立目录后再处理。

## Upgrade notes / 升级说明

1. Fully quit from the system tray and take a consistent data-directory backup including SQLite WAL;
   copying only a running database file is insufficient.
2. Download `OmniProxy-Setup-v2.3.0-windows-amd64.exe`, verify its `.sha256`, and install over the
   existing installation. Existing installation identity and data location are retained.
3. Local `v2.2.3-beta.*` users can upgrade directly. Stable and Beta channels can discover this release.
   Externally modified client catalogs still require preview and explicit application.
4. GitHub Actions builds and project-self-signs the public installer, verifying its signature,
   certificate pin and SHA256. **Self-signing does not imply public CA trust or SmartScreen reputation.**

**中文升级步骤：**

1. 从托盘完全退出 OmniProxy，先备份当前数据目录；SQLite 备份须包含 WAL，
   不要仅复制运行中的主数据库文件。
2. 下载 `OmniProxy-Setup-v2.3.0-windows-amd64.exe`，核对同名 `.sha256` 后覆盖安装。
   安装身份与既有数据位置沿用原配置，无需重新导入已有账号。
3. 本地 `v2.2.3-beta.*` 用户可直接升级到本版；正式版和 Beta 更新渠道均可发现本版。
   客户端目录被外部修改时仍需先预览再应用，不会静默覆盖用户配置。
4. 公开安装器由 GitHub Actions 构建，使用项目证书自签并校验签名、证书 pin 与 SHA256。
   **项目自签不等于公开 CA 信任或 SmartScreen 信誉保证**，Windows 仍可能显示未知发布者提示。

## Known limitations / 已知边界

- DuMate has automated import, identity isolation, token refresh, three-protocol forwarding and model
  visibility coverage. **Real-account requests, tool calls, reasoning usage, point consumption,
  credited check-ins and live client integration remain unverified.** Responses/Messages are
  conversions, not native upstream protocols. Automatic check-in is not implemented.
- DuMate 已有自动化导入、身份隔离、token 并发刷新、三协议转发和模型可见性回归；
  **真实百度账号请求、工具调用、reasoning 用量、积分消耗、签到到账及真实客户端联调尚未验证**。
  Responses／Messages 是网关转换而非上游原生接口；自动签到未实现。
- Google subscriptions still use the Antigravity channel. A separate Gemini CLI Code Assist
  Standard/Enterprise channel and complete parity/live acceptance for other clients such as DSH
  remain planned.
- Google 订阅目前仍为 Antigravity 通道；Gemini CLI 独立 Code Assist
  Standard／Enterprise 订阅通道未实现，DSH 等其他客户端的完整对齐与真机验收仍在计划中。
- Automated tests, builds and signature verification do not replace real installation, first-run
  migration or native-window acceptance. Publication does not install/start the app or operate accounts.
- 自动化测试、构建和签名校验不等于真实覆盖安装、数据库首次实机迁移或原生窗口验收。
  发布过程不会自动安装、启动应用、修改本机账号或执行签到。
