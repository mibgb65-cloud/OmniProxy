# OmniProxy v2.0.1-beta.1

本地预发布版本（Windows amd64）。未签名、未公开推送，安装包仅供本机覆盖更新。

## 修复：Codex 透明转发的 Token 用量不再漏记

通过 `…/codex/v1` 透明转发的请求，此前会出现「上游已经返回 usage，但请求记录和用量页仍是
未知／0」的情况：尝试记录在响应被完全消费之前就被结束，持久化挂到已结束的尝试上，整笔用量
被数据库回滚。本版：

- 响应消费完成（含流式终结事件）后才结束这次尝试，成功、取消、上游中断按实际原因收尾。
- 父记录绑定失败时也补收尾，避免留下无法兑换的用量。
- 记账失败只写受控诊断码（`accounting_unavailable`），不改写已经交付给你的响应字节，
  也不重放请求。
- 历史被漏记的 Token **不会回填**，只是从本版起不再丢。

## 提供商：OpenAI 预设与 River 新模型

- OpenAI 卡片的预设模型换成官方当前主推的四款：`GPT-6 Astra`、`GPT-6.1 Sol`、
  `GPT-6.1 Terra`、`GPT-6 Luna`，不再显示 `GPT-5.4`／`GPT-5.4 Mini`／`GPT-4.1`／`o3`。
  这只是卡片预览，账号实际可用模型仍由同步结果决定。
- River 预设从四款扩到六款，新增：
  - `Qwen/Qwen3.8-27B-FP8`：262,144 上下文、262,143 输出，档位 `none`／`low`／`medium`／`xhigh`
    （官方用 `xhigh`，没有 `high`／`max`）。
  - `moonshotai/Kimi-K3`：1,048,576 上下文、32,768 输出，档位 `none`／`max`，默认 `max`。
    官方 `low`／`high`／`max` 分层需要 `chat_template_kwargs`，本版不发送该扩展，因此不公布分层。
- 公共模型名为 `Qwen3.8-27B-FP8`、`Kimi-K3`，实际请求仍发送 River 官方完整 ID；
  `Kimi-K3` 不与直连 Moonshot 的 `kimi-k3` 合并（两者是不同计费入口）。
- Qwen 上下文不足 1M，客户端不会出现它的 `[1m]` 选项。
- 之前已经同步过 River 官方模型的账号，需要在路由页对该账号再点一次「同步官方模型」才会看到
  新两款；未同步过的账号立即显示六款预设。

## 其他

- 订阅额度观测的测试改用完成屏障，消除并发跑测试时的偶发失败；产品行为不变。

## 升级说明

- 覆盖安装即可，无新增数据库迁移、无新增依赖。
- 版本号从 `2.0.0` 升到 `2.0.1-beta.1`：Windows 数字版本为 `2.0.1.0`，安装身份、安装目录与
  数据目录沿用原设置；已有的路由、别名、账号、客户端配置、用量与额度留存快照保持不变。

## 已知边界

- 安装器未签名，Windows SmartScreen 可能提示未知发布者。
- 新模型只按官方文档与公开计费接口接入，未使用真实 River Key 验证账号权限、计费或长窗口。
- 本版的原生窗口视觉与真实账号请求仍需安装后在本机验收。
- 历史被漏记的 Token 未回填，用量页的旧数据不会自行修复。
