# v1.3.0-beta.1 - Opt-in Codex quota-window activation / 可选 Codex 额度窗口自动激活

This beta adds an explicit setting that can automatically start inactive Codex five-hour and weekly quota windows with one minimal Codex request.

本次 Beta 新增显式设置开关，可在 Codex 五小时和周额度窗口尚未开始计时时，通过一次最小 Codex 请求自动启动窗口。

## Features / 新特性

- **Opt-in activation setting**: A new `自动激活 Codex 额度窗口` switch is available under Global Settings → Scheduling and Protection. It is disabled by default and takes effect only after the user enables and saves it.
  - **可选激活设置**：在「全局设置 → 调度与保护」中新增「自动激活 Codex 额度窗口」开关。该功能默认关闭，仅在用户主动开启并保存后生效。
- **Five-hour and weekly detection**: Paid Codex accounts are activated only when the five-hour or weekly reset window is missing. Free accounts follow their weekly-only quota shape.
  - **五小时与周窗口检测**：付费 Codex 账号仅在五小时或周重置窗口缺失时触发；Free 账号按照其仅有周窗口的额度结构处理。
- **Minimal activation request**: OmniProxy sends one low-reasoning `gpt-5.6-luna` Responses request with storage disabled, then immediately refreshes usage to verify that the expected windows appeared.
  - **最小激活请求**：OmniProxy 使用 `gpt-5.6-luna` 发送一次低推理、禁用存储的 Responses 请求，随后立即刷新额度，确认预期窗口已经出现。
- **No duplicate activation**: Accounts with active windows do not send an activation request. Concurrent Codex maintenance checks are serialized while the setting is enabled.
  - **避免重复激活**：已有有效窗口的账号不会发送激活请求；开关开启时，并发 Codex 维护检查会串行执行。
- **Safe retries**: A failed request or a failed post-activation quota check is not recorded as successful, so a later maintenance check can retry safely.
  - **安全重试**：请求失败或激活后额度复查失败时不会被记录为成功，后续维护检查可以安全重试。

## Upgrade Guidance / 升级说明

- The feature remains off after upgrading. Enable it explicitly in Global Settings and select `保存设置` if automatic activation is desired.
  - 升级后该功能保持关闭。如需自动激活，请在「全局设置」中主动开启并点击「保存设置」。
- Enabling the switch authorizes OmniProxy to consume a very small amount of Codex quota for accounts whose expected window has not started.
  - 开启开关表示允许 OmniProxy 为尚未启动预期窗口的账号消耗极少量 Codex 额度。
- Existing account pools and local configuration remain compatible. No data migration is required.
  - 现有账号池和本地配置保持兼容，无需数据迁移。
