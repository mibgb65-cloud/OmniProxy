# OmniProxy v2.0.0-beta.22

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

## River 图片输入（Claude Code / Desktop 视觉）

- 修正 Claude Code／Desktop 通过 River 模型发送图片时报 `400 / unsupported_content` 的问题。此前图片在到达 River 之前就被本地协议转换拒绝，与 River 官方声明的能力不一致；本版按官方契约把图片转发给上游。
- Messages 的 `image` 块（base64 或外部 URL，包括截图工具返回在 `tool_result` 里的图片）与 Responses 的 `input_image` 都会转成 River 的 Chat `image_url` 块，工具调用 ID 与结果关联保持不变。
- `detail` 档位（`low`／`high`／`auto`／`original`）原样透传；图片格式限官方公布的 JPEG／PNG／GIF／WebP。
- River 四款模型在模型目录中标记为「文本 + 图片」，Claude CLI／Desktop 菜单据此识别视觉能力。
- 仍然拒绝而非静默丢弃：未知图片源类型、Files API 文件引用、非 base64 数据、`input_file`／`input_audio`，以及超出容量的内容。DeepSeek 直连通道仍按文本处理，不因为 River 支持图片就放宽。
- Codex 的 `input_modalities` 策略不变，仍只公布原生订阅线路已确认的图片直通能力。

## 兼容与已知边界

- 继承 Beta.21 的 Claude 单模型 + 原生 effort 控件，以及此前各版功能。
- 不新增数据库迁移，不改变安装身份、凭据格式、账号启用状态、路由选择或客户端登录。
- 图片按官方限制只应出现在 `user` 消息中；`system`／`assistant` 消息里的图片由上游返回错误，属官方行为。
- 本版未使用真实 River Key 做图片计费与 Token 用量实测，也未在本机重启原生 Claude 客户端验收；相关结论由用户本地验收。
- 音频与文件（Files API）输入仍未接入。
- Codex 在约 500k 用量时提前压缩的现象**仍未定位根因**，不宣称已修复，也不修改用户的 1.05M／900k 设置。
- Google 上游 `429 / RESOURCE_EXHAUSTED` 仍是独立调查项，本版不宣称解除限流。

## 升级后需要做的两步

1. 在路由页对 River 账号点一次「同步官方模型」。已同步过的账号以最近一次成功的官方目录为准，不重新同步不会出现新的图片能力标记。
2. 在应用中对该 Claude 客户端**重新应用一次一键配置或刷新目录**，然后**完全退出并重启** Claude，菜单才会读到新的模型能力。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.22。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。
