# OmniProxy v2.3.1-beta.15

## New Provider / 新服务商

- WorkBuddy AI (Tencent CodeBuddy international, `www.workbuddy.ai`) is now the fifteenth built-in provider, with the same subscription shape as Codex and Google. Sign in from the accounts page with browser authorization; tokens live only in DPAPI, SQLite keeps a `credential_ref` and displayable identity. / WorkBuddy AI（腾讯 CodeBuddy 计划国际版，`www.workbuddy.ai`）成为第十五个内置服务商，形态与 Codex／Google 订阅同级。在账号页用浏览器授权登录即可，令牌只进 DPAPI，SQLite 只保存 `credential_ref` 与可展示身份。
- Model catalog comes from the account's own `/v3/config` and syncs in the background after login; per-model context window, output limit, image input and reasoning efforts follow what upstream declares, and a failed sync keeps the previous snapshot. Ordinary token renewal rebinds the catalog version inside the same transaction, so models no longer disappear after a refresh. / 模型目录来自账号自己的 `/v3/config`，登录后后台自动同步；上下文窗口、输出上限、图片输入与推理档位只按上游声明建模，同步失败保留旧快照。普通续期在同一事务内重绑目录版本，刷新令牌后模型不会再静默消失。
- Gateway routing: `workbuddy_ai/*` models are forwarded natively (streaming) over Chat Completions. Non-streaming Chat and Responses／Messages clients are served by aggregating the upstream stream inside the gateway and re-encoding the complete result; a half-built tool call is never handed to a client. A `401` first renews the token once, and only then fails over to another account. / 网关路由：`workbuddy_ai/*` 模型走 Chat Completions 原生流式转发。非流式 Chat 与 Responses／Messages 客户端由网关聚合上游流后按原协议重新编码，不会把半个工具调用交给客户端。`401` 先续期一次，仍失败才换号。
- Credits: the account card and the quota page show `Credits` (plan), `Extra credits`, `Total credits` and, when present, `Prepaid credits`. Missing fields display as unknown rather than `0`. Credits are display-only and do not influence scheduling. / 额度：账号卡与配额页展示 Credits（计划内）、Extra credits、Total credits 以及有则显示的 Prepaid credits。字段缺失显示未知而不是 `0`。额度只用于展示，不参与调度。

## Breaking Changes / 不兼容变更

No public API change and no change to existing providers, routes or account semantics. This release does add database migrations: `050_builtin_workbuddy_ai.sql` appends one built-in provider row and `051_workbuddy_quota_snapshots.sql` creates a new quota-snapshot table. Both run automatically at startup, only add data, and do not reset existing providers, accounts, routes or statistics. / 无公共 API 变更，不影响既有服务商、路由与账号语义。本版本**包含数据库迁移**：`050_builtin_workbuddy_ai.sql` 追加一条内置服务商记录，`051_workbuddy_quota_snapshots.sql` 新建额度快照表。两者在启动时自动执行，只追加数据，不重置既有服务商、账号、路由或统计。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. The new migrations apply on the first start after installing. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装；新增迁移会在安装后首次启动时自动执行。
- Application/frontend version: `2.3.1-beta.15`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.15`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved. WorkBuddy AI models only appear after an account is signed in and `/v3/config` has synced; nothing is routed to them before that. / 保留现有账号、路由、统计与客户端配置。WorkBuddy AI 的模型只在账号登录并完成 `/v3/config` 同步后出现，在此之前不会有任何请求被路由过去。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests (156 files / 961 tests) and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试（156 文件／961 项）与 Windows 生产构建。
- WorkBuddy AI coverage is contract-level only: a loopback fake upstream verifies the required headers and user-agent fingerprint, gzipped request bodies, Chat-only forwarding, `stream: true`, the single 401 retry, upstream error-code mapping (`10085`／`11128`／`11159`／`11158`／`11217`) and catalog/quota parsing boundaries (unknown stays unknown, never `0`). The login state machine, identity check, renewal-rebinds-catalog regression and the gateway's streaming/aggregation paths are unit-tested. / WorkBuddy AI 的覆盖只到契约层：回环假上游验证必需请求头与 UA 指纹、gzip 请求体、只发 Chat、`stream: true`、401 单次重试、上游错误码映射（`10085`／`11128`／`11159`／`11158`／`11217`）以及目录／额度解析边界（未知保持未知，不会写成 `0`）。登录状态机、身份核对、续期后目录仍可路由的回归、网关流式与聚合路径均有单元测试。
- **Not verified**: real-account browser sign-in, the real `/v3/config` catalog, a real Chat completion and real Credits readings. Those consume real credits and were not executed; the upstream protocol facts still come from the community plugin analysis and are marked as unverified in `docs/product/WORKBUDDY.md`. Verify them on your own account after installing. / **未验证**：真实账号浏览器登录、真实 `/v3/config` 目录、真实 Chat 调用与真实 Credits 读数。这些会消耗真实积分，本次未执行；上游协议事实仍来自社区插件分析，已在 `docs/product/WORKBUDDY.md` 标注未经验证。安装后请用自己的账号验证。
- Upstream client fingerprint is pinned to WorkBuddy AI `5.9.3` / CLI `2.165.0`; a vendor release that changes it may require updating `internal/provider/workbuddyai/workbuddyai.go`. / 上游客户端指纹固定为 WorkBuddy AI `5.9.3`／CLI `2.165.0`；厂商发版改变指纹时可能需要更新 `internal/provider/workbuddyai/workbuddyai.go`。
