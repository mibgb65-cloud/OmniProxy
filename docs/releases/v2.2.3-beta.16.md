# OmniProxy v2.2.3-beta.16

## Bug Fixes / 问题修复

- The `xhigh` thinking level is no longer downgraded. Google publishes Gemini 4 Hydrogen as four separate variants (`-low`, `-medium`, `-high`, `-xhigh`), and the gateway already routed the model ID to `gemini-4-hydrogen-xhigh` — but the `thinkingConfig.thinkingLevel` sent upstream was still mapped to `high`, because the effort mapping only knew `low` / `medium` / everything-else. Real requests confirm the upstream accepts `xhigh`, so the level is now passed through unchanged: model ID and thinking level finally agree. / `xhigh` 思考档位不再被降级。Google 把 Gemini 4 Hydrogen 发布为 `-low`／`-medium`／`-high`／`-xhigh` 四个变体，网关其实已经把模型 ID 换成 `gemini-4-hydrogen-xhigh`，但发给上游的 `thinkingConfig.thinkingLevel` 仍被映射成 `high`——档位映射只认识 `low`／`medium`／其余。真实请求确认上游接受 `xhigh`，现在原样透传：模型 ID 与思考档位终于一致。
- Importing a legacy installation now syncs the model catalog by itself. The import used to stop as soon as the accounts were written, so new accounts had no model rows and the managed clients had no catalog entry; every account needed a manual click on “Re-sync to AI Agent”. A successful import now requests the existing background sync (Google and OpenAI), which discovers each account's catalog, rewrites the managed client configuration and emits the usual update event. A failed import still changes nothing. / 导入旧版数据后会自动同步模型目录。此前导入只把账号写进数据库就结束，新账号没有模型行、受管客户端也没有对应目录，每个账号都要手动点一次「重新同步到 AI Agent」。现在导入成功后会请求既有的后台同步（Google 与 OpenAI），由它发现各账号目录、重写受管客户端配置并发出更新事件；导入失败仍然不触发任何同步。

## Breaking Changes / 不兼容变更

None / 无。No database migration or public API change; other clients, protocols, catalog shaping and timeouts are untouched. The manual “Re-sync to AI Agent” button stays for retrying a failed sync / 无新增数据库迁移或公共 API 变更；其它客户端、协议、目录形状与时限不变。手动「重新同步到 AI Agent」按钮保留，用于同步失败后重试。
