# OmniProxy v2.3.1-beta.14

## Bug Fixes / 问题修复

- Long Codex conversations no longer fail with `400 unsupported_content` when routed to River (or Atria／MiMo). The Responses validators still capped the `input` array at 512 items, an old arbitrary bound; the thread that failed on request `e862bb6d…` had grown past it (its rollout already held 514 items, and Codex injects a few more per turn). All three Responses adapters now use the same 100,000-item safety bound as Messages, so the real limit is the existing 16 MiB request body again. / 长会话的 Codex 请求发往 River（以及 Atria／MiMo）时不再报 `400 unsupported_content`。Responses 校验仍把输入数组限制在 512 条这一历史遗留数字上，而报错的请求 `e862bb6d…` 所在线程仅 rollout 就有 514 条输入项，Codex 每回合还会再注入几条。三个 Responses 适配器现在与 Messages 使用相同的 100,000 条安全上限，真正的边界仍是既有的 16 MiB 请求体。
- Conversation history containing `custom_tool_call` / `custom_tool_call_output` (Codex `apply_patch`) is accepted by River instead of being rejected locally. Already the case for Atria and MiMo; River now matches, and the real key was verified to accept these items unchanged. A custom tool output without a `call_id` is still rejected. / 包含 `custom_tool_call`／`custom_tool_call_output`（Codex 的 `apply_patch`）的历史现在会被 River 接受，不再本地拒绝。Atria 与 MiMo 原本就放行，River 现已对齐，并用真实 Key 验证上游原样接受；缺少 `call_id` 的自定义工具结果仍会拒绝。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change. Request-body limits, JSON depth checks and the 16 MiB Responses bound are unchanged; only the item-count safety bound moved from 512 to 100,000 (matching Messages). / 无数据库迁移、无公共 API 变更。请求体上限、JSON 深度校验与 Responses 的 16 MiB 边界都不变，只有条数安全上限从 512 调整为 100,000（与 Messages 一致）。

## Verification boundary / 验证边界

- Reproduced on the installed build with the failing thread's own items plus the three dynamic developer items Codex adds per turn: 512 items → `200`, 513 items → `400 unsupported_content` in 91 ms, and the real shape (517 items / 13,907,104 bytes) → `400` in 1571 ms, matching the reported 1479 ms. / 在已安装构建上用失败线程自身的输入项加 Codex 每回合注入的 3 条动态 developer 项复现：512 条 `200`、513 条 91 ms 返回 `400 unsupported_content`；真实形状（517 条／13,907,104 字节）1571 ms 返回 `400`，与线上 1479 ms 一致。
- The same 517-item body against the new build on an isolated instance with the real River key: `200` + `response.completed`, with the model answering the conversation. / 同一份 517 条正文在新构建隔离实例 + 真实 River Key 上：`200` + `response.completed`，模型正常作答。
- `custom_tool_call` history was verified on the real key: `200` + `response.completed`; the plain control also completes. / `custom_tool_call` 历史在真实 Key 上验证：`200` + `response.completed`，纯文本对照同样完成。
- New coverage: 513 items are accepted and the 100,000 bound still rejects above it (River／Atria／MiMo); custom tool history is accepted while an orphan custom tool output is rejected. / 新增覆盖：513 条放行、超过 100,000 条仍拒绝（River／Atria／MiMo）；自定义工具历史放行、缺 `call_id` 的自定义工具结果拒绝。
- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Not verified: the real Codex desktop window retrying the thread after installing. / 未验证：安装后由真实 Codex 桌面端在同一线程重试。
