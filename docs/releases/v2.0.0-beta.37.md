# OmniProxy v2.0.0-beta.37

本地预发布版本（Windows amd64）。未签名、未公开推送，安装包仅供本机覆盖更新。

## 修复

- **Codex 订阅额度用完后无法继续发消息**。客户端实际使用的 `/codex/v1` 入口是透明转发，
  过去只在 HTTP 状态码是 401／429／5xx 时才换号；官方把「执行前额度拒绝」
  （`usage_limit_reached`）包在 HTTP 200 首事件里时，既不换号也不记录，客户端会反复撞同一个
  已耗尽账号。
  - 现在透明转发在写给客户端之前有界预读首事件（最多 4 KiB，未命中时原字节接回，
    长首事件不受影响），命中执行前额度拒绝即丢弃该响应、跳过该账号并使用同池其他账号。
  - 被拒绝的账号按上游给出的真实重置时间写入额度阻断：下一条消息直接走可用账号，
    不再先失败一次。重置时间缺失时只短期跳过，不假装额度已恢复。
- **Codex 透明入口换号后会返回 503 `accounting_unavailable`**。之前父请求在发送前就绑定到
  首个账号，一旦换到不同身份的账号，记账拒绝改动导致整条请求失败。现在改为尝试级记账：
  每次账号尝试单独记录，父请求只归属最终成功的那次响应。请求记录里能看到
  「2 次尝试 / 第 1 次 200 + `upstream_quota_exhausted`」的明细。
- **冷却时间不再一律 30 秒**。协议入口与 `/codex/v1` 统一优先采用上游 `Retry-After`
  （最长一天）；额度耗尽的阻断按真实重置时间（最长 8 天）。

## 变更

- 额度拒绝的判定逻辑上提到 `core/proxy`，协议入口（`/v1/responses`、`/v1/messages`、
  `/v1/chat/completions`）与 `/codex/v1` 透明入口共用同一套证据，不再有两份实现。
- 请求结束后按需刷新该账号的额度观察（同一账号与凭据版本 5 分钟内只刷新一次），
  让网关在下一条消息前就知道账号是否仍可用。不新增定时器、不对闲置账号做后台探测。

## 升级说明

- 覆盖安装即可，无新增数据库迁移。
- 已在网关配置过的路由、别名、账号与客户端配置保持不变。
- 关闭「账号故障切换」或给模型显式固定账号时仍不换号：额度阻断会登记，但请求按固定账号返回
  受控 429，不泄露上游正文。

## 已知边界

- 安装器未签名，Windows SmartScreen 可能提示未知发布者。
- WebSocket 中继中途的额度错误不换号重拨，只让阻断在后续请求生效。
- 若客户端（Codex Desktop 工作区）在发送前自行拦截额度，请求不会到达网关，
  网关无法触发换号；需要看请求记录里是否存在该次请求来区分。
- 真实订阅账号的额度耗尽换号效果由用户在本机验收。
