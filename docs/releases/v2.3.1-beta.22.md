# OmniProxy v2.3.1-beta.22

## Bug Fixes / 问题修复

- Managed-client catalogs that stop updating now say why, in the app. When another tool changes a client's config file, OmniProxy deliberately stops rewriting that file — but the only trace was a `refresh_failed` line in the runtime log, and the client's card showed a disabled “Configure” button. Each affected client now reports the reason as a stable code on its card, and the clients list shows a summary: “N clients had their config files changed by other tools, so automatic catalog updates are paused: …”. / 受管客户端目录停止自动更新时，界面现在会说明原因：配置文件被其它工具改写后，OmniProxy 出于安全会停止改写该文件，但以前只在运行日志里留一条 `refresh_failed`，卡片上的「一键配置」还是禁用状态。现在每个受影响客户端会显示稳定失败码，客户端列表页也给出汇总提示（「N 个客户端的配置文件已被其他工具修改，模型目录暂停自动更新」）。
- The primary action is no longer a dead end for `config_changed`: it becomes “Re-read and apply”, which loads the current file, previews it and applies with `acceptCurrentConfig` — one click, and your edits are preserved instead of overwritten silently. Other refresh failures (write failure, locked file, empty catalog) surface on the card too. / `config_changed` 时主按钮不再是死路：改成「重新读取并应用」，读回当前文件、预览后带 `acceptCurrentConfig` 应用——一次点击完成恢复，外部改动不会被静默覆盖。其它刷新失败（写入失败、文件被占用、目录为空等）也会显示在卡片上。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no client-config format change. Only how refresh failures are reported and how the configure action behaves when a file changed externally. / 无数据库迁移、无公共 API 变更、无客户端配置格式变化。仅改变刷新失败的呈现方式与「文件被外部修改」时主按钮的行为。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.22`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.22`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, open 网关 → 客户端接入: the affected clients are listed and each detail page offers “重新读取并应用”. Doing that for DeepSeek Harness (Desktop/Web) is what makes the models synced from WorkBuddy (international and China builds) appear in Harness's OmniProxy provider. / 升级后打开「网关 → 客户端接入」：列表会列出受影响的客户端，详情页提供「重新读取并应用」。对 DeepSeek Harness（Desktop／Web）各做一次，Harness 的 OmniProxy 提供商里就会出现 WorkBuddy（国际版与国内版）已同步的模型。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Covered by tests: refresh failure codes reach the client item (and `config_changed` wins over a generic code), re-applying clears the recorded issue, `failureCode` extraction from joined errors, the “Re-read and apply” button and its `acceptCurrentConfig` payload, and the clients-list summary. / 测试覆盖：刷新失败码进入客户端项（`config_changed` 优先于泛化码）、重新应用后清除记录、从聚合错误提取稳定码、「重新读取并应用」按钮与 `acceptCurrentConfig` 载荷、客户端列表汇总提示。
- **Not verified on a real client in this version**: the actual re-apply for a client whose file was changed externally is exercised by unit tests with fixtures, not against the user's Codex／Claude／Harness files. / **本版本未在本机真实客户端上验证**：文件被外部改写的客户端重新应用由单元测试（夹具）覆盖，未对用户的 Codex／Claude／Harness 文件执行。
- WorkBuddy channels themselves are unchanged in this version; the China build's real-account chat was verified in `v2.3.1-beta.21`. / 本版本未改动 WorkBuddy 通道；国内版真实对话已在 `v2.3.1-beta.21` 验证。
