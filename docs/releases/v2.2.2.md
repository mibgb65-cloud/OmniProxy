# OmniProxy v2.2.2

## Features / 新功能

None / 无。

## Bug Fixes / 问题修复

- **Restore Codex automatic-compaction capacity metadata.** The App Server `model/list` response does not expose the context window. OmniProxy now obtains each model's default `context_window` from the fixed official native catalog using the same verified subscription account, then merges it by exact model ID before refreshing managed client catalogs.
  - **修复 Codex 自动压缩所需的容量元数据缺失。** App Server 的 `model/list` 响应不提供上下文窗口。现在通过同一已校验订阅账号读取固定官方原生目录的默认 `context_window`，按模型 ID 精确合并后刷新受管客户端目录，避免长聊天因缺少默认压缩触发依据而持续增长。
- **Keep unknown capacity explicit and preserve safe snapshots.** Missing or invalid capacity, network failure and account changes fail synchronization without overwriting the last successful snapshot. Catalog reads are bounded, authenticated headers are cleared after use, and raw upstream errors are not exposed.
  - **容量未知时明确失败并保留安全快照。** 缺失／非法容量、网络失败或账号变更会停止本次同步，不覆盖上次成功快照；目录响应有界读取，鉴权头使用后清除，不暴露原始上游错误。
- **Preserve model and user boundaries.** Default models, reasoning levels, account isolation, provider proxy settings and existing user configuration remain unchanged. `max_context_window` is not treated as the enabled default window; no universal 1M window or compaction threshold is written.
  - **保留模型和用户配置边界。** 默认模型、思考档位、账号隔离、提供商代理设置及已有用户配置保持不变；不把 `max_context_window` 当成已启用的默认窗口，也不统一写入 1M 窗口或压缩阈值。

## Breaking Changes / 不兼容变更

None. No new dependencies or database migrations.

无。不新增依赖或数据库迁移。

## Refactor & Performance / 重构与性能

- Native CLI/Desktop offline regression now covers automatic compaction derived from catalog capacity, in addition to explicit compaction.
  - 原生 CLI／Desktop 离线回归在显式压缩之外，新增由目录容量触发自动压缩的覆盖。

## Upgrade notes / 升级说明

- After upgrading from v2.2.1, synchronize the affected Codex subscription account's models once. Successful synchronization refreshes unchanged managed client catalogs. Reload Codex afterward so new turns load the updated model metadata. If the client configuration was edited externally, preview and reapply it through the existing configuration flow.
  - 从 v2.2.1 升级后，对受影响的 Codex 订阅账号执行一次「同步模型」。同步成功会刷新未被外部修改的受管客户端目录；随后重新加载 Codex，让新回合读取新元数据。客户端配置有外部改动时，按既有流程预览后重新应用。
- Explicit user `model_context_window` or `model_auto_compact_token_limit` overrides are preserved and can still supersede model defaults. Older failed chats are not automatically cleared or repaired. Request transport compression is unrelated to history compaction.
  - 用户显式配置的 `model_context_window`／`model_auto_compact_token_limit` 保留，仍可能优先于模型默认值；不会自动清空或修复已经失败的聊天。请求传输压缩与聊天历史压缩无关。
- Application and installer version: `2.2.2`; Windows numeric resource version: `2.2.2.0`.
  - 应用与安装器版本为 `2.2.2`，Windows 数字资源版本为 `2.2.2.0`。

## Release verification and limits / 发布校验与边界

- Public assets use the existing GitHub Actions build, project-certificate self-signing and SHA256 verification pipeline. Self-signing does not provide public CA trust and may still trigger SmartScreen or unknown-publisher warnings.
  - 公开资产沿用 GitHub Actions 构建、项目证书自签与 SHA256 校验流程；自签不提供公开 CA 信任，仍可能触发 SmartScreen／未知发布者提示。
- Offline native-core regression uses short synthetic messages and simulated usage against a fake upstream. It verifies automatic triggering and completed compaction items, not real large-context capacity or summary quality. Real client acceptance and in-place installation are deferred at the user's request.
  - 离线原生核心回归只用短合成消息、模拟用量和假上游，验证自动触发与压缩完成项，不证明真实大上下文容量或摘要质量；按用户要求暂不做真实客户端验收与覆盖安装。
