# OmniProxy v2.3.1-beta.19

## Bug Fixes / 问题修复

- Chat requests to WorkBuddy AI no longer fail with `400 code 11128 "first message is not system prompt"`. The upstream conversation shape requires the first message to be a `system` message; OmniProxy forwarded client bodies as-is, so any client that starts with a user turn (or a converted Responses／Messages request that does) was rejected before inference. Outbound bodies are now normalised: `developer` becomes `system`, `max_completion_tokens` becomes `max_tokens`, and a default `"You are a helpful assistant."` system message is prepended when the first message is not one. / 发给 WorkBuddy AI 的对话不再报 `400 code 11128 "first message is not system prompt"`。上游会话形态要求首条消息是 `system`，而 OmniProxy 之前原样转发客户端正文，任何以用户消息开头的请求（包括转换后的 Responses／Messages）都会在推理前被拒。现在出站正文会归一：`developer` 改 `system`、`max_completion_tokens` 改 `max_tokens`、首条不是 system 时补一条默认 `"You are a helpful assistant."`。
- If the upstream channel check still refuses the system prompt (`11128`), the request is retried once with the system prompt moved into the first user message (`<instructions>…</instructions>`), which is the shape the official client's tooling uses; only a second refusal surfaces as `channel_rejected`. / 如果上游渠道校验仍然拒绝系统提示词（`11128`），会用「系统提示词下移为首条用户消息（`<instructions>…</instructions>` 包裹）」的形态自动重试一次；只有第二次也被拒才以 `channel_rejected` 报错。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no frontend change. Only the outbound WorkBuddy chat body is normalised; unknown fields are left untouched and already-compliant bodies are forwarded byte-for-byte. / 无数据库迁移、无公共 API 变更、无前端变更。仅归一 WorkBuddy 出站对话正文；未知字段不动，本来就合规的正文按原字节转发。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.19`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.19`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes and the synced WorkBuddy catalog are preserved. To try a real conversation, create a route for a WorkBuddy model (or use a client you already route through OmniProxy) and send a message. / 保留现有账号、路由与已同步的 WorkBuddy 目录。要试真实对话，为某个 WorkBuddy 模型建一条路由（或用已经走 OmniProxy 的客户端）发一条消息即可。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Real account evidence (Free plan, `glm-5.3-flash`): a user-only body returns `400` + `code 11128`; the same request with a leading system message returns `200` + SSE, answer `OK`, `usage` 26/3/29. The fixed adapter was driven end to end against the real API by an opt-in integration test (`-tags workbuddyreal`): the request body had no system message and came back `200` with streamed content. / 真实账号证据（Free 计划，`glm-5.3-flash`）：只有 user 消息时返回 `400` + `code 11128`；同一请求加上首条 system 后返回 `200` + SSE，回答 `OK`，`usage` 26/3/29。修复后的适配器由可选的集成测试（`-tags workbuddyreal`）对真实 API 端到端跑通：入参没有 system，仍拿到 `200` 与流式内容。
- **Credits were not deducted** on this Free account: three calls (101 tokens) left `plan_base` and `benefit` at 0 used over ~15 minutes of observation; Free plans appear to use a daily free allowance instead of credits. Paid-plan deduction is still unverified. / **该 Free 账号上没有观测到积分扣减**：三次调用（101 tokens）后观察约 15 分钟，`plan_base` 与 `benefit` 仍为 0 使用；Free 计划应当是走每日免费额度而不是 credits。付费套餐的扣减仍未验证。
- **Not verified**: a real desktop client (Codex／Claude Code) conversation through the gateway, and whether such clients' system prompts hit the upstream line fingerprint (the retry path is covered by a contract test, but real hits need a real client). / **未验证**：真实桌面客户端（Codex／Claude Code）经网关的对话，以及这类客户端的系统提示词是否会命中上游整行指纹（重试路径有契约测试覆盖，真实命中需要客户端实测）。
