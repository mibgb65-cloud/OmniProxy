# OmniProxy v2.0.0-beta.25

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版包含 Beta.24 之后的全部改动，是当前完整的构建。

## 请求归属：Token 是被哪个 Agent 用掉的

- 请求列表新增 **Agent** 列，请求详情新增 Agent 一行：Codex CLI／Desktop、Claude Code、Claude Code Desktop、DeepSeek Harness Web／Desktop、OpenCode、Kilo／Qwen／MiMo Code、Kimi Code、Pi、Factory Droid、Goose。
- 归属来自每个 Agent 自己的接入 Key（请求鉴权时同时识别），不解析、不保存 User-Agent，也不保存 Key。
- 搜索框可按 Agent 名称筛选；无法归属的请求（旧记录、直接调用、自定义客户端）显示「—」，不做猜测。
- 迁移 040 为请求明细增加 `client_id`。旧版本的请求记录没有该信息，升级后**只有新请求**才会带上 Agent 归属。

## 配额：没有官方额度接口的账号显示已用 Token

- River、Atria、普通 OpenAI API Key、自定义提供商不再只显示「暂不支持／查询尚未接入」，卡片直接给出本机留存的已用 Token：输入、输出、缓存、请求数。
- 输入包含缓存，三项不能相加；上游未返回的明细显示「—」，只统计到部分用量时显示「≥」。
- 卡片同时标注「本机用量不表示官方剩余额度或账单」，不会被误读成余额。
- 账号详情与配额页共用同一份用量数据与身份隔离，切换账号或提供商不会串数据。

## 悬浮提示

- 账号详情 Token 用量三块数值改用产品统一的悬浮提示（圆角卡片、模糊背景、箭头），不再出现系统原生白底提示框；完整数字同时提供给键盘与读屏用户。

## 本地 Agent 接入与用量面板

- 用量页「按账号成员／按模型」卡片的滚动条改为细圆角滑块，去掉系统原生轨道与箭头。
- 本地 Agent 目录每张分组卡片新增「一键配置」：一次为该分组内全部客户端写入完整默认模型目录，无需逐项挑选；逐项反馈进度与失败原因。

## 兼容与已知边界

- 迁移 040 只追加一列，不改动现有账号、凭据、路由、客户端配置与安装身份。
- 请求 Agent 归属无法回溯历史记录；升级后旧行显示「—」属于预期。
- 本机 Token 用量不等于官方账单或剩余额度；官方额度页仍按原逻辑查询。
- Codex 在约 500k 用量时提前压缩的现象**仍未定位根因**，本版不宣称已修复。
- Google 上游 `429 / RESOURCE_EXHAUSTED` 仍是独立调查项，本版不宣称解除限流。
- 构建与回归在本地执行，不以自动化测试替代真实上游调用、真实覆盖安装或客户端界面验收。

## 升级后需要做的两步

1. 在应用中重新应用需要更新目录的客户端配置（如 Codex、Claude、DeepSeek Harness 等），让客户端读取最新模型目录。
2. **完全退出**并重新启动对应客户端，避免继续使用缓存的旧菜单。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.25。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。
