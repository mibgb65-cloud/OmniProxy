# OmniProxy v2.2.3-beta.13

## Bug Fixes / 问题修复

- Antigravity requests that name a model family now resolve to the upstream variant the subscription actually serves. The desktop app folds a catalog entry such as `gemini-4-argon-high` into the family `gemini-4-argon` plus a reasoning level and sends that; the gateway rejected the unknown family name with `400 unsupported_model`, which the app reported as "Agent terminated due to error". The family is now matched against same-provider catalog variants, preferring the client's level, then `high`, `medium`, `low`, and finally a single variant. / Antigravity 发送家族模型名时不再报错。桌面端会把目录里的 `gemini-4-argon-high` 折叠成家族 `gemini-4-argon` 加档位再发送，网关此前按 ID 精确匹配、把未知家族名判为 `400 unsupported_model`，桌面端显示 “Agent terminated due to error”。现在会按同提供商的目录变体解析，优先客户端档位，其次 `high`、`medium`、`low`，最后接受唯一变体。
- The reasoning level is no longer dropped before routing. It used to be stripped immediately, so even a catalog family could not be resolved to the right variant; it is now kept for selection and removed from the body only after routing, right before the request reaches the subscription adapter (whose generation parameters are whitelist-validated). / 推理档位不再在路由前被丢弃。此前请求一进来就被剥离，即使目录里有家族行也选不到正确变体；现在先保留用于选型，路由完成后、发往订阅适配器之前才移除（适配器的生成参数是白名单校验）。
- Single-variant families resolve too: `gpt-oss-120b` maps to `gpt-oss-120b-medium` and `claude-opus-4-6` to `claude-opus-4-6-thinking`. Exact catalog IDs are untouched, and unknown families still return `400 unsupported_model`. / 只有单一变体的家族同样可解析：`gpt-oss-120b` → `gpt-oss-120b-medium`、`claude-opus-4-6` → `claude-opus-4-6-thinking`；精确 ID 不被改写，未知家族仍返回 `400 unsupported_model`。

## Breaking Changes / 不兼容变更

None / 无。No database migration or public API change; the catalog shape is unchanged and other clients keep their existing request semantics / 无新增数据库迁移或公共 API 变更；目录形状不变，其它客户端请求语义不变。

Fully exit OmniProxy from the system tray (the running instance is beta.12), back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布。请先从托盘完全退出 OmniProxy（当前运行的是 beta.12），备份数据目录，再运行安装器覆盖现有安装。

## Verification and limits / 校验与边界

- `task --force verify` passed: format check, lint, typecheck, Go test packages, frontend suite (147 files / 898 tests) and the Windows production build. New tests cover family + level selection, the no-level default, single-variant families, exact IDs staying untouched, unknown families still failing, and the effort field being removed before forwarding while the rest of the body is preserved. / `task --force verify` 通过：格式检查、lint、类型检查、Go 测试包、前端测试（147 文件／898 项）与 Windows 生产构建。新增测试覆盖家族名 + 档位选型、缺档位时的默认、单变体家族、精确 ID 不改写、未知家族仍失败，以及转发前移除档位且保留正文其余字段。
- The gateway now records the reasoning level the desktop actually sends, so a mismatch between the app's picker and the upstream variant shows up in the request detail instead of being silently dropped. / 网关现在会记录桌面端实际发送的档位，应用选择与上游变体不一致时能在请求明细里看到，而不是被静默丢弃。
- The local installer is unsigned and may trigger an unknown-publisher or SmartScreen warning. Building does not install or launch the application. / 本地安装器未签名，可能触发未知发布者或 SmartScreen 提示；构建不安装、不启动应用。
