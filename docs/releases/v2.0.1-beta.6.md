# OmniProxy v2.0.1-beta.6

本地预发布版本（Windows amd64）。未签名、未公开推送，安装包仅供本机覆盖更新。

## 功能：本地网关端口可以自己改了，占用了会自动让路

以前网关端口写死在运行环境里（正式版 3000），如果 3000 被别的程序占了，只能看着「代理端口不可用」
手动去解决。现在可以在应用里改：

- 「设置与关于 → 通用设置 → 本地网关端口」：显示当前端口、该环境的默认端口、端口是否可用、网关是否在监听。
- 填一个端口点「保存端口」：网关立刻在新端口上重启（原本在运行就继续运行，在途请求按原逻辑取消），
  设置写入本机配置，重启应用后仍然生效。「恢复默认端口」回到 3000。
- **端口被占用时会自动避让**：在你要的端口之后最多试 20 个，第一个空着的就用上，并在卡片上说明
  「端口 3000 已被占用，已自动改用 3001」。
- 勾了「启动软件时自动启动网关」的话，开机启动遇到端口冲突同样自动避让，不再只是记一条日志、
  让你自己去处理。
- 如果你用环境变量 `OMNIPROXY_PROXY_PORT` 固定了端口，设置卡片是只读的——环境变量优先，
  避免界面和环境变量互相覆盖；这种情况下冲突仍按原样报错，由你决定改哪一个。

## 端口变了，已接入的客户端会跟着改

网关地址是写进本地客户端配置里的，端口一变这些地址就失效了。所以保存端口时会同时处理：

- 由本应用写入、且之后没被外部改过的客户端配置，`http://127.0.0.1:<端口>/<前缀>` 里的端口会被
  就地改写（保留注释、其他提供商、密钥引用；`3000` 不会误伤 `30000`）。
- 被外部改动过（版本已经对不上）的配置**保持原样不动**，卡片会列出这些客户端，
  提示你重新读取并一键配置，避免覆盖别的工具或你自己的修改。

## 其他

- 端口解析顺序：`OMNIPROXY_PROXY_PORT` > 配置文件 `proxyPort` > 运行环境默认（正式 3000／开发 3001／测试 3002）。
- 保存端口后应用信息、关于页、网关页、本地 Agent 列表会自动刷新显示新端口。
- 新增内部端口探测包与端口切换、地址改写、绑定层测试；文档（PRD／网关页／构建／架构总览）已同步。

## 升级说明

- 覆盖安装即可，无新增数据库迁移、无新增依赖。
- 数字版本仍是 `2.0.1.0`（同一 patch 的 beta 递增不改数字版本），安装身份、安装目录与数据目录
  沿用原设置；账号、路由、别名、用量、额度留存快照与重置操作记录保持不变。
- 已经接入的本地客户端：如果你之前用的是 3000 且保持默认端口，升级后不需要做任何事；
  只有当你改了端口，才会按上面的规则改写地址。

## 已知边界

- 安装器未签名，Windows SmartScreen 可能提示未知发布者。
- 自动避让只在你填入的端口之后 20 个候选内寻找；都没空时保存会失败并保持原端口继续服务。
- 端口设置卡片、改写后的客户端地址、自动避让提示的实际观感**尚未在真实窗口人工验收**，
  建议升级后先在设置页改一次端口再改回，确认客户端仍能正常请求。
- 不改控制接口端口（3890/3891/3892），也不支持非 loopback 监听。
