# OmniProxy v2.0.0-beta.38

本地预发布版本（Windows amd64）。未签名、未公开推送，安装包仅供本机覆盖更新。

## 修复

- **一周额度估算长期显示 `—`**。账号卡片下方的美元估算在窗口里只要有一条「HTTP 200 成功但
  没解析出 usage」的记录，就整窗判为「用量不完整」并显示 `—`。实测一周窗口 192 条记录中
  只有 4 条此类记录（约 2%），却让 98% 的有效样本一起失效。
  - 现在未知占比不超过两成时按已确认样本估算（金额本来就带 `≈`，只会偏低、不会凭空偏高），
    超过两成或完全没有已知样本时才显示 `—`。
  - 未知**价格**的模型仍整窗不估：它可能让整个窗口都无法定价，不属于「少量样本缺失」。
  - 「已用不足 5% 不估算」的门槛不变。

## 新增

- **透明转发的 WebSocket 现在按轮记录请求与 Token 用量**。此前 Codex 走 `/codex/v1` 的
  WebSocket 只做双向原样中继：请求列表里看不到这些流量，Token 用量不增长，换号也没有尝试明细。
  - 每个 `response.create` 帧在转发前建立一条 `transport=websocket` 记录，并登记本轮实际使用的
    账号尝试；上游终结事件到达时写入该轮输入／输出／缓存 Token 与首字耗时。
  - 客户端在终结事件前断开记为取消（`request_cancelled`／499），上游中途断开记为
    `upstream_disconnected`（502），`generate:false` 的预热轮不记账。
  - 帧字节始终原样中继，只有记账不可用时才不把该轮送往上游。
  - 这些记录同样进入额度估算的样本，因此估算不再只有 HTTP 一条来源。

## 升级说明

- 覆盖安装即可，无新增数据库迁移。
- 已在网关配置过的路由、别名、账号与客户端配置保持不变。
- 旧的 `—` 不会补算历史；升级后新的额度观察与请求记录会按新规则出数。

## 已知边界

- 安装器未签名，Windows SmartScreen 可能提示未知发布者。
- 估算仍是本机样本的 API 等值粗估，不是官方余额；其他客户端消费与历史清理会让它失真。
- 「成功但没有 usage」的记录根因未定位（透明转发下 usage 缺失的残余缺口），本次只让它不再
  否决整窗估算。
- 实机 Codex WebSocket 会话的记账效果由用户在本机验收。
