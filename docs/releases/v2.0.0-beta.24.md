# OmniProxy v2.0.0-beta.24

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

本版包含 Beta.22、Beta.23 与本次的全部改动，是当前完整的构建。

## 推理强度：Claude 与 DeepSeek Harness

- 修正 Claude 推理强度设置不生效的问题。此前把上游真实最高档位 `max` 写进了 `modelSettings.maxEffortLevel`，但该键只接受 `low`／`medium`／`high`／`xhigh`，非法值导致档位解析异常，且 `max` 会被客户端压回 `high`。现在只写客户端接受的取值，上游默认 `max` 时映射为 `xhigh`。
- Claude 模型菜单保持每个模型只占一行（普通 + 可选 `[1m]`），推理强度使用客户端原生选择，不再出现「模型 · 高强度推理」这类伪模型条目。
- DeepSeek Harness 与 Pi 的模型选择器现在出现 **Effort** 菜单。此前目录把 `reasoningEfforts` 写死为 `false`，Harness 因此从不显示该项。现按上游已确认档位声明：DeepSeek 系提供关闭／高／最高，GLM 提供低／高／最高。
- 「关闭思考」在 Harness 中真实生效：`off` 显式映射为 `none` 并配合 `thinkingFormat: deepseek`，而不是留空——留空等于不发送参数，上游仍会思考。GLM 本身无法关闭思考，因此不提供该选项。
- 未确认档位的模型继续保持不声明，不凭空显示档位菜单。

## 图片输入（Beta.22／Beta.23）

- River 与 Claude 通道支持图片输入转发，Claude 的图片块转换为上游格式。
- 本地 Agent 客户端目录按上游**已确认**能力声明图片：Harness／Pi 写 `input`，OpenCode 系写 `modalities.input`，Goose 写 `supports_vision`。此前这几处写死纯文本，客户端会在本地拦截附图；未确认图片能力的模型仍保持纯文本。

## 兼容与已知边界

- 不新增数据库迁移，不改变安装身份、凭据格式、账号启用状态、路由选择或客户端登录。
- Claude 的强度控件是否出现取决于客户端对模型的识别情况，不同版本可能不同；`behavesAs` 只声明能力继承。
- Codex 在约 500k 用量时提前压缩的现象**仍未定位根因**，本版不宣称已修复。
- Google 上游 `429 / RESOURCE_EXHAUSTED` 仍是独立调查项，本版不宣称解除限流。
- 构建与回归在本地执行，不以自动化测试替代真实上游调用、真实覆盖安装或客户端界面验收。

## 升级后需要做的两步

1. 在应用中重新应用 **Claude** 与 **DeepSeek Harness／OpenCode／Pi／Goose** 各自的配置，让客户端目录读到新的档位与图片能力。
2. **完全退出**并重新启动对应客户端（Harness 若启用 HMR 则在下一请求生效）。仅重启进程而不完全退出时，客户端可能继续使用缓存的旧菜单。

River 账号如需图片能力，请在路由页重新执行一次「同步官方模型」。

## 安装与数据保留

先从托盘完全退出旧版，再为整个数据目录保留一致性备份，随后运行本安装包覆盖原安装目录，无需先卸载旧版或删除账号数据。安装后在“设置与关于”核对版本为 2.0.0-beta.24。

本版沿用现有安装目录、账号、数据库、设置、请求历史与累计统计，不主动清空数据，不自动重启 Claude／Codex Desktop；不要同时启动新旧版本写入同一数据目录。

本地安装包未签名，Windows 可能提示未知发布者，机器级安装需要管理员确认。构建过程不自动安装、停止或替换生产应用，不上传公开发布；真实覆盖安装与数据保留由用户本地验收。
