# OmniProxy v2.3.1-beta.4

## Bug Fixes / 问题修复

- Codex (CLI / Desktop) failed on every non-OpenAI model: selecting a River or DeepSeek model such as `DeepSeek-V4.1-Flash-1017` produced `401 Unauthorized` on three attempts, then `502 upstream_unavailable`, and the account was shown as "未选择账号" in the request list. Two defects stacked up. First, the `…/codex/v1` transparent passthrough is only contract-compatible with the OpenAI upstream, yet an API-key provider with an empty provider base URL fell back to `https://api.openai.com/v1`, so a River key was sent to OpenAI and rejected. Second, the passthrough never rewrote the body, so River's public model ID (`DeepSeek-V4.1-Flash-1017`), the Codex reasoning vocabulary and the provider's own validation/conversion never reached the upstream. / Codex（CLI／桌面端）选择任何非 OpenAI 模型都会失败：选 River／DeepSeek 的 `DeepSeek-V4.1-Flash-1017` 时连续三次 `401 Unauthorized`，随后 `502 upstream_unavailable`，请求列表里显示「未选择账号」。两个缺陷叠加：一是 `…/codex/v1` 透明转发只与 OpenAI 上游契约兼容，而按量服务商基址为空时会回落到 `https://api.openai.com/v1`，把 River 的 Key 发给了 OpenAI；二是透明转发不改写正文，River 的公共模型 ID、Codex 的档位词汇以及该服务商自己的校验／转换都没到达上游。
- The Codex entry now decides per request: `/v1/responses` (including `/responses/compact`) reads the model and, when the route target is not an OpenAI provider, hands the already-read body back to the protocol entry — the public model ID becomes the account's official ID, the Codex effort level is restored to the upstream value, and the request goes through that provider's adapter (validation, conversion, usage accounting). OpenAI models keep byte-for-byte transparent forwarding, and paths without a routable model (model catalog, analytics events) plus WebSocket handshakes are unchanged. A third-party key can no longer be sent to `api.openai.com`: the API-key branch now refuses with `unsupported_provider` instead. / Codex 入口现在按请求判定：`/v1/responses`（含 `/responses/compact`）读出模型后，若路由目标不是 OpenAI 服务商，就把已读正文交回协议入口——公共模型 ID 换成账号对应的官方 ID、Codex 档位还原成上游取值，并走该服务商的适配器（校验、转换、用量记账）。OpenAI 模型仍然逐字节透明转发，没有可路由模型的路径（模型目录、分析事件）与 WebSocket 握手保持原样。第三方 Key 也不会再发往 `api.openai.com`：按量分支改为明确返回 `unsupported_provider`。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change. Behavior nuance: in the built-in OpenAI mode (`…/codex/v1`), models from other providers now go through the gateway protocol pipeline, so their errors become provider-specific (`400 unsupported_content` etc.) instead of a misleading `401`. / 无数据库迁移、无公共 API 变更。行为细节：在内置 OpenAI 模式（`…/codex/v1`）下，其它服务商的模型改由网关协议管线处理，因此报错变成该服务商的具体原因（如 `400 unsupported_content`），不再是误导性的 `401`。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray (the running instance is an older build), back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy（当前运行的是更早的构建），备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.4`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.4`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. Restart Codex after upgrading so it reloads the model catalog. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。升级后重启 Codex 以重新加载模型目录。

## Verification boundary / 验证边界

- `task verify` passed before packaging: all Go packages, frontend tests (154 files / 935 tests), format, lint, typecheck and the Windows production build. / 打包前 `task verify` 通过：Go 全包、前端 154 文件／935 项测试、格式、lint、类型检查与 Windows 生产构建。
- New coverage: Core cases assert that a request judged non-transparent continues through the protocol entry without touching the passthrough session, that a transparent request keeps its path and body verbatim, and that non-protocol paths never consult the policy; gateway cases assert the Codex entry rewrites the model and effort and reaches the River base URL with the official ID (streaming and non-streaming), and that API-key targets of other providers are refused instead of falling back to OpenAI. / 新增覆盖：Core 用例断言判定为不可透明时请求改走协议入口且透明会话不取号、可透明时路径与正文逐字节不变、非协议路径不参与判定；网关用例断言 Codex 入口改写模型与档位后以官方 ID 打到 River 基址（流式与非流式），以及其它服务商的按量目标被明确拒绝而不是回落 OpenAI。
- Real upstream check (read-only production database, real River key, isolated listener): `/codex/v1/responses` with `DeepSeek-V4.1-Flash-1017` returned 200 in 1907 ms non-streaming and 200 in 833 ms streaming, with a complete `response.completed` event. The same request was 401 ×3 → 502 before the fix. / 真实链路验证（只读生产库、真实 River Key、隔离实例）：`/codex/v1/responses` + `DeepSeek-V4.1-Flash-1017` 非流式 200／1907 ms、流式 200／833 ms，并收到完整 `response.completed`。修复前同一请求是 401×3 → 502。
- Known limitation: the transparent WebSocket handshake carries no body, so with "Codex WebSocket" enabled those models still rely on the client falling back to HTTP; forcing them over WebSocket now returns `unsupported_provider` instead of `401`. / 已知限制：透明 WebSocket 握手没有正文，开启「Codex WebSocket」后这些模型仍依赖客户端回退 HTTP；强行走 WebSocket 会得到 `unsupported_provider` 而不是 `401`。
