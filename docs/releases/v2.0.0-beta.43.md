# OmniProxy v2.0.0-beta.43

本地预发布版本（Windows amd64）。未签名、未公开推送，安装包仅供本机覆盖更新。

## 新增：提供商出站代理（v2rayN / Clash 端口）

部分海外提供商在本机网络下不可达。本版新增「网络代理」：OmniProxy 只把选定的提供商请求转发到
**已经运行**的代理客户端端口，不启动、不接管、不修改系统代理。

- 提供商页右上角新增「网络代理」按钮。里面只有一处连接参数：协议、地址、端口、可选账号密码、
  不走代理的地址列表。
- **不用选协议**。v2rayN 默认的 `本地:[mixed:10808]` 是同一端口同时支持 HTTP 与 SOCKS5，
  本版会自动识别（两者都通时走 SOCKS5），并把结果记住；哪天代理换回纯 SOCKS 或纯 HTTP，
  运行时会自动纠偏，不需要重新配置。
- **探测本机代理**：并行检查 10808／10809／7890／7891／7897／1080／2080／1087，
  命中后一键填入，例如 `127.0.0.1:10808 · SOCKS5`。
- **按提供商决定是否走代理**：每个提供商三态——跟随全局／直连／走代理，另有「全部走代理」
  与「全部直连」。走代理的提供商卡片上会显示「代理」徽标。
- **测试按钮会区分三种失败**：代理端口无响应、端口不是 HTTP/SOCKS 代理、已连通（附协议与延迟）。
- 额度查询、余额查询、Codex 透明转发（含 WebSocket）与令牌续期同样遵循该策略，不是只有对话请求生效。
- 应用自身的更新下载与 Agent 安装包下载**不**经过这个代理。

## 行为与安全

- 代理端口没开或有故障时返回独立错误码，**不会**被算成账号故障，也不会把账号打进冷却。
- 密码只保存到 Windows 凭据库（DPAPI），界面只显示「已保存」；日志与错误里的地址一律脱敏。
- 明确设为「走代理」但根本没配置端点时会直接报错，不会静默改成直连。

## 升级说明

- 覆盖安装即可。**本版新增一条数据库迁移（044）**：新增 `proxy_settings` 表与
  `providers.proxy_mode` 列，默认全部为「跟随全局且未启用」，即升级后行为与之前一致。
- 回退到 Beta.42 及更早版本时，新增的表会被忽略；但请避免在旧版本上继续修改代理相关设置
  （旧版本没有该功能）。
- 已有的账号、路由、别名、客户端配置、用量与额度快照保持不变。

## 已知边界

- 安装器未签名，Windows SmartScreen 可能提示未知发布者。
- 代理软件需自行保持运行；应用不管理它的进程与订阅。
- 只支持 HTTP / HTTPS / SOCKS5 代理端口，不解析 vmess／vless／trojan 链接。
- Codex CLI 子进程（登录组件）仍使用系统环境变量中的代理设置，不受本页配置影响。
- v1 的 `outboundProxy*` 配置不会自动导入，需要在提供商页重新设置一次。
- 实机代理端口（mixed／纯 SOCKS／纯 HTTP 三种）与浅色主题下的弹窗布局仍需安装后本机验收。
