# OmniProxy v2.3.1-beta.18

## Bug Fixes / 问题修复

- "Sync official models" now works for WorkBuddy AI accounts. The manual sync path built its catalog service in the Wails layer and only attached the Google subscription, so the WorkBuddy branch hit `unavailable` immediately and always reported "sync failed"; the background auto-sync used a separate, correctly wired service, which is why the models were actually stored while the button kept failing. Both paths now share one wiring helper (`wireModelCatalog`) that attaches every subscription-based catalog source. / WorkBuddy AI 账号的「同步官方模型」现在能用了。手动同步在 Wails 层组装目录服务时只接了 Google 订阅，WorkBuddy 分支直接返回 `unavailable`，所以按钮永远报「同步失败」；而后台自动同步用的是另一套已接线服务，于是出现「模型其实已写入、按钮却一直失败」。现在两条路径共用一个 `wireModelCatalog`，订阅类目录源统一接线。
- Sync failures keep their real reason for the log. The catalog layer must answer a single `unavailable` to the UI (no upstream detail in the interface), but it now records the underlying error and the Wails layer logs its stable code — a category of bug that only shows as "sync failed" is now diagnosable. / 同步失败的原因会留在日志里。目录层对界面仍只回答一句 `unavailable`（不把上游细节带进界面），但现在会记录底层错误，由 Wails 层把稳定码写进日志——之前只能看到「同步失败」的那类问题现在能定位了。
- The background auto-sync starters (Google, WorkBuddy) use the same wiring helper, so a future subscription provider cannot be attached to one path only. / 后台自动同步（Google、WorkBuddy）也改用同一个接线函数，以后新增订阅通道不会再出现只接一条路径的情况。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change, no change to the WorkBuddy upstream protocol. / 无数据库迁移、无公共 API 变更、未改动 WorkBuddy 上游协议。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.18`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.18`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes and the already-synced 25 WorkBuddy models are preserved: after installing, press "Sync official models" once to confirm it returns the same catalog without an error. / 保留现有账号、路由与已同步的 25 条 WorkBuddy 模型：安装后点一次「同步官方模型」，确认返回同一份目录且不再报错。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- New regression coverage: a Wails-level test syncs a WorkBuddy account end to end against a fake `/v3/config` and asserts the rows and catalog version bind correctly — it fails with `models: unavailable` when the wiring is removed, which is exactly the reported symptom; a catalog-level test asserts the UI-facing error stays `models: unavailable` while the underlying `unauthorized` code is retained for logs. / 新增回归覆盖：Wails 层用假 `/v3/config` 端到端同步一个 WorkBuddy 账号，断言模型行与目录版本正确绑定——去掉接线时它会以 `models: unavailable` 失败，正是用户看到的现象；目录层测试断言对界面的错误仍是 `models: unavailable`，同时底层 `unauthorized` 码被保留给日志。
- **Not verified**: pressing the button in the installed build against the real account (needs your install), and a real chat completion (consumes credits). / **未验证**：在已安装版本里对真实账号点这个按钮（需要你安装后确认），以及真实对话扣减（消耗积分）。
