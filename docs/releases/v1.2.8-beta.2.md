# v1.2.8-beta.2 - Claude subscription quota and local hardening / Claude 订阅额度与本机加固

This beta gives Claude OAuth accounts real subscription quota instead of a meaningless API number, and hardens the local listeners, the update channel, and the request history store.

本次 beta 让 Claude OAuth 账号显示真实的订阅限额，不再显示无意义的 API 数字，同时加固本机监听器、更新通道和请求历史存储。

## Features / 新特性

- **Claude subscription quota**: Claude OAuth accounts can show their five-hour and weekly plan windows with usage percentages and reset times, in the same layout Codex accounts use. The toggle lives in Settings under **OpenAI / Anthropic / Codex** and is off by default; enabling it first shows a dialog describing the risks, because the usage endpoint is undocumented and Anthropic restricts subscription credentials to its own clients.
  - **Claude 订阅额度**：Claude OAuth 账号可以显示 5 小时和每周的套餐窗口，包含使用百分比和重置时间，布局与 Codex 账号一致。开关位于设置的「OpenAI / Anthropic / Codex」区块，默认关闭；开启前会先弹出风险说明，因为该用量接口未公开，且 Anthropic 限制订阅版凭据在其自有客户端之外使用。
- **Quota fetch stays separate from the health check**: A failed or changed usage response reports no quota and leaves the account healthy, instead of marking a working account invalid.
  - **额度查询与健康检查相互独立**：用量请求失败或返回结构变化时只显示无额度数据，账号仍保持健康状态，不会把可用账号误判为失效。

## Bug Fixes / 问题修复

- **Claude accounts no longer show a bogus API balance**: These accounts previously displayed "API 剩余额度" built from the rate-limit header of a `/v1/models` liveness check, which describes that endpoint's API limit rather than the subscription plan.
  - **Claude 账号不再显示错误的 API 额度**：此前这些账号显示的「API 剩余额度」来自 `/v1/models` 存活检查的速率限制响应头，反映的是该接口的 API 限制，而不是订阅套餐用量。
- **Codex config backup failures are no longer silent**: A failed backup write let the original `config.toml` be overwritten anyway, which made "restore original config" impossible. The error is now reported and the original file is left alone.
  - **Codex 配置备份失败不再被忽略**：备份写入失败时原 `config.toml` 仍会被覆盖，导致「恢复原始配置」永久失效。现在会返回错误并保留原文件。

## Security / 安全

- **Loopback Host validation**: The proxy and control listeners reject requests whose `Host` header is not a loopback name. Both already bound `127.0.0.1`, but without this check a web page that rebinds its own hostname to loopback became same-origin and could drive the proxy with the account credentials attached. Clients configured by OmniProxy always use `127.0.0.1` and are unaffected.
  - **回环 Host 校验**：代理和控制监听器会拒绝 `Host` 不是回环名称的请求。二者本就只绑定 `127.0.0.1`，但缺少该校验时，将自身域名重绑到回环地址的网页会变成同源，从而可以携带账号凭据驱动代理。OmniProxy 写入的客户端始终使用 `127.0.0.1`，不受影响。
- **Update downloads restricted to release hosts**: Installer and checksum downloads must use `https` and a GitHub release host. The downloaded file is launched with elevation on Windows, and a checksum fetched from a caller-supplied URL never established provenance.
  - **更新下载限定发布主机**：安装包和校验和下载必须使用 `https` 且主机为 GitHub 发布域名。下载的文件在 Windows 上会提权执行，而由调用方指定地址取回的校验和无法证明来源可信。
- **Go toolchain pinned to 1.26.5**: CI and release builds previously used whatever Go the runner provided, and the macOS jobs resolved to 1.26.0. `govulncheck` reported five reachable standard-library vulnerabilities on the older toolchain.
  - **Go 工具链固定为 1.26.5**：CI 和发布构建此前使用运行器自带的 Go 版本，macOS 任务解析到的是 1.26.0。`govulncheck` 在旧工具链上报告了 5 个可达的标准库漏洞。

## Refactor & Performance / 重构与优化

- **WAL journal for request history**: The history database only set `busy_timeout`, leaving the default rollback journal with `synchronous=FULL` and a journal fsync on every request insert. WAL with `synchronous=NORMAL` measured roughly 140x faster per insert. Both pragmas are best-effort, so filesystems without shared-memory support fall back to the previous behavior instead of failing.
  - **请求历史启用 WAL 日志**：历史数据库此前只设置了 `busy_timeout`，使用默认回滚日志和 `synchronous=FULL`，每次写入都要做一次日志 fsync。WAL 配合 `synchronous=NORMAL` 实测单次写入快约 140 倍。两个 pragma 均为尽力而为，不支持共享内存的文件系统会回退到原有行为而不是报错。
- Added backend coverage for the Claude usage parser and its opt-in gate, the loopback Host guard, the update host allowlist, the WAL pragma, and the new configuration round-trip.
  - 补充 Claude 用量解析与开关门控、回环 Host 守卫、更新主机白名单、WAL pragma 和新增配置项往返的后端测试。
