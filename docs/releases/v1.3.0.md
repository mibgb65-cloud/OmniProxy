# v1.3.0 - Codex quota-window activation / Codex 额度窗口激活

This stable release consolidates the v1.3.0 beta line. It adds opt-in automatic Codex quota-window activation, accurate detection of unused rolling windows, persistent activation history, and a single manual action in the OpenAI quota summary.

本正式版整合 v1.3.0 beta 系列改动：新增可选的 Codex 额度窗口自动激活、准确识别未使用的滚动窗口、持久化激活历史，并在 OpenAI 额度摘要中提供统一的手动入口。

## Features / 新特性

- **Opt-in automatic activation**: Global Settings now provides an `自动激活 Codex 额度窗口` switch. After the user explicitly enables and saves it, OmniProxy scans enabled Codex accounts immediately and during later maintenance checks.
  - **可选自动激活**：「全局设置」新增「自动激活 Codex 额度窗口」开关。用户主动开启并保存后，OmniProxy 会立即扫描已启用的 Codex 账号，并在后续维护检查中继续检测。
- **Safe minimal activation request**: When an expected five-hour or weekly window has not started, OmniProxy sends one low-reasoning `gpt-5.6-luna` Responses request with storage disabled, then refreshes quota state to verify the result. Active windows do not send a duplicate request.
  - **安全的最小激活请求**：预期的五小时或周窗口尚未启动时，OmniProxy 会发送一次低推理、禁用存储的 `gpt-5.6-luna` Responses 请求，随后刷新额度验证结果；已启动窗口不会重复发送。
- **Unified manual action**: The OpenAI quota summary provides one `检测并激活` action that processes the currently displayed enabled Codex accounts sequentially and reports a consolidated result.
  - **统一手动入口**：OpenAI 额度摘要提供单一「检测并激活」入口，串行处理当前显示且已启用的 Codex 账号，并汇总执行结果。
- **Persistent activation history**: Activation start, success, skip, and failure states are written to Request History with before / after reset timestamps and without credential values.
  - **持久化激活历史**：激活开始、成功、跳过和失败状态会写入请求历史，包含激活前后的重置时间，但不包含凭据内容。

## Bug Fixes / 问题修复

- **Rolling-window detection**: Successive quota responses and expected window durations distinguish an unused rolling `0%` window from an active low-usage window. The quota page labels the former as `未启动` instead of showing a misleading moving reset time.
  - **滚动窗口识别**：结合连续额度响应和预期窗口时长，区分未使用的滚动 `0%` 窗口与已启动的低用量窗口；额度页会将前者标记为「未启动」，不再显示误导性的移动重置时间。
- **Expired-window handling**: Missing or expired five-hour / weekly resets are eligible for activation, while a displayed `0%` usage value alone never triggers a request.
  - **过期窗口处理**：五小时或周重置时间缺失、已经到期时可触发激活；仅显示 `0%` 使用率不会单独触发请求。
- **Activation request compatibility**: The dedicated ChatGPT Codex request no longer sends the unsupported `max_output_tokens` parameter while retaining the minimal prompt, low reasoning effort, streaming response, and disabled response storage.
  - **激活请求兼容性**：专用 ChatGPT Codex 请求不再发送上游不支持的 `max_output_tokens` 参数，同时保留最小提示、低推理强度、流式响应和禁用响应存储。
- **Compact quota cards**: Repeated activation controls were removed from individual account cards and moved to the provider summary without changing backend activation decisions or quota rechecks.
  - **紧凑额度卡片**：账号卡片中的重复激活按钮已移至厂商摘要，后端激活判定和额度复查逻辑保持不变。

## Upgrade Guidance / 升级说明

- Upgrading from v1.2.9 keeps automatic activation disabled. Enable it explicitly in Global Settings and select `保存设置` if desired. Existing v1.3.0 beta installations preserve their current switch value.
  - 从 v1.2.9 升级时，自动激活保持关闭；如需使用，请在「全局设置」中主动开启并点击「保存设置」。现有 v1.3.0 beta 安装会保留当前开关状态。
- Enabling automatic activation or using the manual action authorizes OmniProxy to consume a very small amount of Codex quota only when live quota data shows an expected window has not started, is missing, or has expired.
  - 开启自动激活或使用手动入口，表示允许 OmniProxy 仅在实时额度数据确认预期窗口未启动、缺失或已过期时消耗极少量 Codex 额度。
- Existing account pools, local configuration, request history, billing summaries, and theme state remain compatible. No local-data migration is required.
  - 现有账号池、本地配置、请求历史、费用汇总和主题状态保持兼容，无需迁移本地数据。
- Beta users can upgrade directly to v1.3.0. The stable version compares newer than every v1.3.0 beta tag.
  - Beta 用户可直接升级到 v1.3.0；正式版版本顺序高于所有 v1.3.0 beta 标签。
- The macOS universal DMG remains unsigned and not notarized. Quit OmniProxy before replacing the app in Applications.
  - macOS Universal DMG 仍未签名且未公证；替换 Applications 中的应用前请先退出 OmniProxy。
