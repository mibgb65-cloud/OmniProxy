# OmniProxy v2.0.0-beta.31

本版为 Windows amd64 production 本地 Beta 安装包，供用户手动覆盖更新，未公开发布。

承接 Beta.30 的档位修正，本版改三处：**关闭思考改为映射到 `low`**、**Google 同型号重复行去重**、**River 模型在 Codex 里可以收图**。数据库结构未变，无新迁移。

## 1. 关闭思考（`none`）在 Codex 里显示为「低」

Beta.30 把上游 `none` 映射成 `minimal`，有些客户端不把 `minimal` 当作可选档位。现在统一映射为最低档 `low`：

| 上游档位 | Codex 档位 |
| --- | --- |
| `none`（关闭思考） | `low` |
| `high` | `high` |
| `max`（最高强度） | `xhigh` |

网关收到请求后按同一套映射还原：`low → none`、`xhigh → max`。`DeepSeek-V4.1-Flash-1017`、`DeepSeek-V4.1-Flash` 现在有三个可选档位（低／高／xhigh），不再只能停在「高」。

## 2. Google 型号不再重复成多行

上一版只在「同步模型」时折叠档位变体，没同步就还是旧样子。现在折叠与去重直接放在目录构建时：

- 档位变体（`Gemini 3.8 Flash (High)` / `(Low)` / `(Medium)`）折叠回基础模型 `Gemini 3.8 Flash`，档位由客户端 effort 选择，网关请求时换成实际变体型号。
- **显示名相同但 ID 不同的型号改用 ID 显示**。你目录里四个都叫 `Gemini 3.5 Flash Lite` 的条目实际是不同型号（`gemini-2.5-flash`、`gemini-2.5-flash-lite`、`gemini-2.5-flash-thinking`、`gemini-3.5-flash-lite`），现在菜单会分别显示这些 ID，不再出现四行一模一样的选项。
- 不重名的条目继续显示上游给的名称。

不需要再等「同步模型」，安装后重新应用一次 Codex 配置（或触发目录刷新）即可。

## 3. River 模型在 Codex 里可以收图

Codex 的 `input_modalities` 之前只对原生订阅放行图片，River 条目一律写 `text`，所以客户端直接拦下并提示「此模型不支持图像输入」。River 适配器已经按官方契约转发 `image_url` / `input_image`，本版据此对 River 条目声明 `text + image`：

- 目录把 River 型号标注为可收图，Codex 不再拦截。
- 其他未验证跨协议图片转换的兼容适配器仍只声明文本，不因为元数据里有 image 就放宽。

`DeepSeek-V4.1-Flash`、`DeepSeek-V4.1-Flash-1017`、`NVIDIA-Nemotron-3.5`、`GLM-5.3-Flash` 四款都会带上图片能力；实际能否识别仍由上游决定（官方能力表声明支持，本项目未逐张实测）。

## 兼容与已知边界

- 无新迁移，无数据格式变化。
- 折叠只在同名基础模型同时存在时发生；只有变体的孤立型号保持原样。
- 已保存的旧变体 ID（例如 `gemini-3.8-flash-low`）仍按反向映射还原成「基础模型 + 档位」，不会变成 `unsupported_model`。
- `none → low` 是就近表达，不是语义等价：客户端把「低」发回来时，网关才译成上游的「关闭思考」。客户端菜单里不会出现 `none` 这个选项。
- Codex 在约 500k 用量时提前压缩、Google 上游 `429 / RESOURCE_EXHAUSTED` 两项仍是独立调查项。
- 安装器未签名、未自动安装、未打标签、未推送。

## 安装与数据保留

先从托盘完全退出旧版，备份数据目录后覆盖安装。安装后在「设置与关于」核对版本为 2.0.0-beta.31，然后对 Codex 重新「预览 → 应用」，让新的目录（档位、去重名称、图片能力）写进 `omniproxy-models.json`。
