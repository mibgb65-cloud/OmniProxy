# OmniProxy v2.2.3-beta.4

## Features / 新功能

- The request list now records and shows the reasoning effort each request carried, so you no longer see only the model. A new “Reasoning effort” column sits next to the model, and the request details panel shows the same value.
  - 请求列表现在会记录并展示每次请求携带的推理等级，不再只能看到模型。「模型」右侧新增「推理等级」列，请求详情面板显示同一取值。
- The level is read from the protocol field the client actually sends: `output_config.effort` for Messages, `reasoning.effort` for Responses and `reasoning_effort` for Chat. Codex transparent forwarding is covered too, including one record per WebSocket `response.create` turn.
  - 档位取自客户端实际发送的协议字段：Messages 读 `output_config.effort`，Responses 读 `reasoning.effort`，Chat 读 `reasoning_effort`。Codex 透明转发同样覆盖，WebSocket 每个 `response.create` 轮次单独记录。
- The recorded value is what the gateway actually carried: the client's choice, or the level pinned for the model in this app (a pin overrides the client). Google-style effort variant model IDs are reported as their level.
  - 记录的是网关实际携带的值：客户端选择的档位，或应用内为该模型固定的档位（固定档位会覆盖客户端选择）。Google 系的档位变体型号会显示为对应档位。
- When the client sends no level, the request is historical, or the body cannot be parsed (for example a compressed passthrough body), the UI shows `—` instead of guessing an upstream default.
  - 客户端未指定、历史记录或正文不可解析（例如压缩的透明转发正文）时显示 `—`，不推测上游默认值。
- The level is display-only: it does not enter token totals, cost estimates, quotas or any aggregate, and request bodies are still never stored.
  - 该档位只用于展示：不进入 Token 累计、成本估算、配额或任何聚合统计，请求正文仍然不入库。

## Bug Fixes / 问题修复

None / 无。

## Breaking Changes / 不兼容变更

- Migration 046 adds `request_records.reasoning_effort` (`TEXT NOT NULL DEFAULT ''`). It runs automatically on first start; existing rows keep the empty value and show `—`.
  - 迁移 046 新增 `request_records.reasoning_effort`（`TEXT NOT NULL DEFAULT ''`），首次启动自动执行；历史记录保持空值并显示 `—`。
- No business API change. `RequestItem` gains an optional `effort` field.
  - 不改变业务 API；`RequestItem` 仅新增可选的 `effort` 字段。

## Refactor & Performance / 重构与性能

- Protocol field parsing for reasoning levels moved into the proxy core so routing and request accounting share one implementation; no new dependency.
  - 推理档位的协议字段解析下沉到代理核心，路由与请求记账共用一份实现；不新增依赖。

## Upgrade notes / 升级说明

- This is a local Windows amd64 Beta production installer for manual in-place updates, not a public release. Fully quit OmniProxy from the system tray and back up the current data directory before running the installer over the existing installation.
  - 本版本为供手动覆盖更新的本地 Windows amd64 Beta 生产安装包，未公开发布。更新前请从托盘完全退出 OmniProxy，并备份当前数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.2.3-beta.4`; Windows numeric resources: `2.2.3.0`; NSIS installer base version: `2.2.3`.
  - 应用／前端版本为 `2.2.3-beta.4`，Windows 数字资源版本为 `2.2.3.0`，NSIS 安装器基础版本为 `2.2.3`。
- Existing accounts, data-location settings and update preferences remain unchanged. Migration 046 applies on the first start after the update; no data is backfilled and no history is rewritten.
  - 既有账号、数据位置与更新偏好保持不变。迁移 046 在更新后首次启动执行；不回填数据、不改写历史记录。
- Only requests made after the update carry a level. To see a value, pick an effort tier in the client (for example the Codex effort menu or Claude's Effort control) or pin one for the model in this app.
  - 只有更新之后产生的请求才带档位。要看到具体取值，请在客户端选择档位（例如 Codex 的档位菜单或 Claude 的 Effort 控件），或在应用内为该模型固定档位。
