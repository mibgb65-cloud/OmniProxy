# OmniProxy v2.3.1-beta.25

## Bug Fixes / 问题修复

- Google subscription (Antigravity) requests no longer lose prompt-cache usage. The Chat conversion read only the prompt, candidate, thinking and total token counts, so `usageMetadata.cachedContentTokenCount` never reached the request record; every Google subscription request showed `—` for the cache column and the usage page had no cache samples. The adapter now maps that field to `usage.prompt_tokens_details.cached_tokens`, so the request list, the cache-hit rate and the cost estimate use the real values. Missing fields stay unknown, a reported zero still shows `0%`, and a cache count larger than the prompt is treated as unknown instead of inventing a ratio. / Google 订阅（Antigravity）请求不再丢缓存用量：Chat 转换只读了提示词、候选、思考、合计四个计数，`usageMetadata.cachedContentTokenCount` 从未进入请求记录，Google 订阅请求的缓存列一直是「—」，用量页也没有缓存样本。适配器现在把它映射为 `usage.prompt_tokens_details.cached_tokens`，请求列表的命中率与成本估算改用真实值。字段缺失仍保持未知，真实零命中仍显示 `0%`，缓存量大于提示词总数时按未知处理，不编造比例。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no API or configuration change. Historical rows keep `—` because the count was discarded at write time and cannot be backfilled. / 无数据库迁移、无 API／配置变更。历史记录仍显示「—」，因为当时该值已在写入前丢弃，无法回填。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.25`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.25`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, send one new Google / Antigravity request through the gateway: its row now shows the real cache hit (for example `缓存 50,560 / 输入 53,300` and `94.9%`) instead of `—`. Older rows stay `—` by design. / 升级后让网关跑一条新的 Google／Antigravity 请求：该行会显示真实命中量（例如「缓存 50,560 / 输入 53,300」与 `94.9%`），不再显示「—」；更早的记录按设计仍是「—」。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 159 frontend files / 977 tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 159 文件／977 项测试与 Windows 生产构建。
- Covered by tests: non-stream mapping, missing field, reported zero, cache larger than prompt, negative count rejected, and a streaming terminal frame that omits the field while an earlier frame reported it. / 测试覆盖：非流式映射、字段缺失、真实零命中、缓存大于提示词、负数拒绝，以及流式终帧省略而前帧已报告的情况。
- **No real subscription request was sent while building this version** (it would consume subscription quota); the first request after installing confirms the end-to-end result. / **本版本打包时未发起真实订阅请求**（会消耗订阅额度），端到端结果由安装后的第一条请求确认。
- Upstream Gemini 4 is known to drop `cachedContentTokenCount` intermittently; those responses still surface as `—` or `0%` exactly as the upstream reported, not as a guessed value. / 上游 Gemini 4 存在间歇性缺少 `cachedContentTokenCount` 的情况；这类响应仍按上游实际报告显示「—」或 `0%`，不猜测数值。
