# v1.2.6-beta.5 - Transactional proxy restart / 事务式代理重启

This beta makes proxy-port configuration changes transactional and prevents stale history requests from reporting errors after a newer refresh succeeds.

本次 beta 将代理端口配置变更改为事务式切换，并阻止旧的历史查询在新请求成功后继续误报错误。

## Features / 新特性

- None / 无

## Bug Fixes / 问题修复

- **Transactional proxy-port switch**: OmniProxy now binds the new proxy listener before replacing the running server. If the new port is unavailable, the existing proxy remains untouched and continues serving requests.
  - **事务式代理端口切换**：OmniProxy 先成功绑定新的代理监听端口，再替换运行中的服务；新端口不可用时，旧代理保持运行并继续处理请求。
- **Scoped configuration rollback**: A failed control-port change no longer restarts the proxy when the proxy configuration was not changed.
  - **限定配置回滚范围**：仅控制端口变更失败时，不再重启未发生配置变化的代理服务。
- **Latest history error wins**: An older failed history request can no longer display an error after a newer request has completed successfully.
  - **仅保留最新历史错误**：较旧的历史查询失败后，不再覆盖较新请求已经成功完成的界面状态。

## Breaking Changes / 不兼容更新

- None / 无

## Refactor & Performance / 重构与优化

- **Proxy shutdown cleanup**: A timed-out proxy shutdown now force-closes the old server so it cannot remain bound as an orphan listener.
  - **代理关闭清理**：代理优雅关闭超时后会强制关闭旧服务，避免遗留仍占用端口的孤立监听。
