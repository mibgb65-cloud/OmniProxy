# v1.2.7-beta.2 - Codex usage statistics and quota estimates / Codex 用量统计与额度预估

This beta corrects Codex WebSocket token accounting and model attribution, preserves exact quota percentages, and makes weekly cost estimates more conservative and explicit about their scope.

本次 beta 修正 Codex WebSocket token 统计与模型归属，保留精确的额度百分比，并让周限额费用预估更保守、口径更清晰。

## Features / 新特性

- None / 无

## Bug Fixes / 问题修复

- **Real-time WebSocket usage accounting**: A WebSocket connection now counts as one proxy request, while each completed response carrying usage records its token consumption immediately. Long-lived connections no longer delay all token statistics until disconnect or merge several responses into one request.
  - **实时统计 WebSocket 用量**：每条 WebSocket 连接只计一次代理请求；每个带 usage 的完整响应会立即记录 token 消耗。长连接不再等断开后才更新统计，也不会把多个响应合并成一次请求。
- **Accurate WebSocket model attribution**: History and usage records capture the model reported by Codex messages, avoiding stale gateway-route defaults such as `gpt-5.5` when the actual request uses GPT-5.6.
  - **准确记录 WebSocket 模型**：历史与用量记录会采用 Codex 消息中报告的实际模型，避免请求实际使用 GPT-5.6 时仍显示网关路由中的旧默认值（如 `gpt-5.5`）。
- **Exact quota percentages**: Codex quota responses retain the provider's decimal `used_percent` for display and estimates, while rounded integer values remain available for scheduling decisions.
  - **保留精确额度百分比**：Codex 额度响应会保留上游返回的带小数 `used_percent`，用于展示和预估；调度逻辑仍使用原有整数值。
- **Safer weekly estimate**: Weekly USD estimates require at least 5% observed usage, use GPT-5.6 Sol base pricing, and no longer apply an unsupported long-context multiplier to aggregate weekly data. The UI now clearly labels the result as a rough estimate based only on local proxy observations.
  - **更稳妥的周限额预估**：至少观察到 5% 用量后才显示美元预估，按 GPT-5.6 Sol 基础价格计算，并移除对周聚合数据不可靠的长上下文倍率。界面会明确提示该结果仅基于本地代理观测，是参考粗估。
- **Clearer usage labels**: Request and token totals are identified as cumulative local-proxy values, and cached input tokens are labeled as cache reads.
  - **更清晰的统计标签**：请求数与 token 总量明确标注为本地代理累计值，缓存输入 token 明确标注为缓存读取。

## Refactor & Performance / 重构与优化

- Split proxy request counting from token-consumption recording so streaming transports can update each metric at the correct lifecycle point.
  - 将代理请求计数与 token 消耗记录拆分，使流式传输能在正确的生命周期节点更新对应指标。
- Added regression coverage for live WebSocket accounting, model capture, exact quota percentages, and weekly-estimate thresholds.
  - 补充实时 WebSocket 统计、模型捕获、精确额度百分比和周限额预估阈值的回归测试。
