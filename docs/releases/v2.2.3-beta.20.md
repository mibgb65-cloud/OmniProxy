# OmniProxy v2.2.3-beta.20

## Bug Fixes / 问题修复

- The reasoning level of a variant model finally wins. beta.18 tried to make a model such as `gemini-4-hydrogen-xhigh` authoritative over the effort field the desktop also sends, but the check relied on the catalog having folded those variants into a base model. Google publishes only the variants (`-low`, `-medium`, `-high`, `-xhigh`) with no base `gemini-4-hydrogen`, so nothing was folded, the check could never match, and the request detail still showed `low`. The gateway now also recognises the level from sibling variants: when two or more known levels share the model's prefix, the suffix is the level, so the record and the upstream `thinkingConfig.thinkingLevel` are both `xhigh`. / 变体型号的推理等级这次真的生效了。beta.18 想让 `gemini-4-hydrogen-xhigh` 这类型号压过桌面端同时带来的档位字段，但判定依赖目录把变体折叠成基础模型；Google 只发布 `-low`／`-medium`／`-high`／`-xhigh` 变体，没有基础型号 `gemini-4-hydrogen`，因此不会折叠，判定永远不成立，请求明细仍然显示 `low`。现在网关还会按同族兄弟变体识别档位：同一前缀下存在两个以上已知档位时，后缀就是档位，记录与上游 `thinkingConfig.thinkingLevel` 都是 `xhigh`。
- A model that only happens to end with `-high` is still left alone: a single suffix with no siblings keeps whatever the client asked for. / 只是恰好以 `-high` 结尾的普通型号不受影响：只有一个后缀、没有兄弟档位时保留客户端的选择。

## Verification and limits / 校验与边界

- `task --force verify` passed: format check, lint, typecheck, Go test packages, frontend suite (148 files / 901 tests) and the Windows production build. / `task --force verify` 通过：格式检查、lint、类型检查、Go 测试包、前端测试（148 文件／901 项）与 Windows 生产构建。
- Reproduced against the real catalog on an isolated instance (copy of the production data directory, separate port, running app untouched): `gemini-4-hydrogen-xhigh` with `reasoning_effort: "low"` returned 200 and the new request record stored `reasoning_effort=xhigh`, while the older rows in the same copy still read `low` — exactly the difference the user reported. / 在隔离实例上用真实目录复现验证（生产数据目录副本、独立端口，未触碰运行中的应用）：`gemini-4-hydrogen-xhigh` 配 `reasoning_effort: "low"` 返回 200，新的请求记录写入 `reasoning_effort=xhigh`；同一副本里更早的记录仍是 `low`，与用户看到的差异一致。
- Unit tests cover the variant-only catalog (four model/level combinations) and the lone-suffix case that must not be overridden. / 单元测试覆盖只有变体的目录（四种型号／档位组合）以及不应被覆盖的单后缀情况。
