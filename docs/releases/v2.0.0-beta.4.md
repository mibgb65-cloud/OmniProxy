# OmniProxy v2.0.0-beta.4

修复真实 Codex 订阅转发中，上游已返回正常流式响应，网关却误报 `502 / invalid_upstream_response` 的问题。

- 兼容官方订阅 Responses 端点缺失 `Content-Type` 的情况：只对 HTTP 200、类型头缺失的响应，有界验证首个完整 Responses SSE 事件后补全类型。JSON、HTML、无效／不完整事件，以及明确声明其他类型的响应仍会被拒绝。
- 预读字节原样交回后续转发，不等待整个流结束；保留 HTTP／WebSocket 的响应内容、首字计时及用量统计，不通过重放请求掩盖错误。
- 增加媒体类型固定分类与是否推断的诊断日志，不保存原始响应头、正文、提示词或凭据。
- 加强 Codex CLI／Desktop 双内核模型配置契约测试，明确推荐模型、用户默认值与会话覆盖的区别。

修复已通过真实上游验收：`gpt-5.6-luna` 和 `gpt-6.1-sol` 的 HTTP／WebSocket 请求，以及实际安装的 Codex CLI 0.163.0、Desktop 内核 0.163.0-alpha.10.2，共六次请求均完整结束并记录用量。测试使用独立网关、临时数据库和应用隔离账号；没有修改用户 Codex 配置或登录。Desktop 内核验收不等同于外壳 GUI 的逐项验收，也不保证所有账号、模型与网络条件。

Windows amd64 测试版。升级后请重启 OmniProxy，确认新版本运行、网关已启动及客户端接入地址正确；仅下载新版本不会使正在运行的 Beta.3 自动获得修复。发布本身不会修改客户端配置或自动升级本机软件。

请同时下载安装器和同名 `.sha256` 校验文件。沿用既有覆盖安装、应用内下载／校验／重启静默更新及卸载保留数据的流程，不新增数据库迁移。Beta 更新渠道可发现本版，正式版 Latest 保持不变，旧 Beta 资产保留。

安装包尚未代码签名。升级与历史数据兼容边界见 [升级说明](https://github.com/mibgb65-cloud/OmniProxy/blob/main/docs/product/UPGRADE.md)。
