# OmniProxy v2.3.1-beta.11

## Bug Fixes / 问题修复

- Codex (desktop and CLI) sending a River model such as `DeepSeek-V4.1-Flash-1017` no longer fails with `stream disconnected ... error decoding response body`. The Codex desktop app injects its Companion Page snapshot as a `function_call_output` input item that has no `call_id`; such an item has no matching tool call, and River answered with `200` plus an SSE preamble and then dropped the connection. The gateway now removes these orphan tool results before forwarding, logs `codex orphan tool outputs dropped` with the count, and keeps every legitimate tool call and tool result untouched. / Codex（桌面端与 CLI）使用 River 的 `DeepSeek-V4.1-Flash-1017` 等模型时不再出现 `stream disconnected … error decoding response body`。Codex 桌面端会把 Companion Page 快照注入成没有 `call_id` 的 `function_call_output` 输入项，这类条目没有对应的工具调用，River 会先返回 `200` 与 SSE 开头再断开连接。网关现在在转发前移除这些孤儿工具结果，记录 `codex orphan tool outputs dropped` 与数量，带 `call_id` 的合法工具调用与工具结果原样保留。
- Requests outside the Codex entry that contain the same orphan tool result are now rejected by the River adapter with `400 unsupported_content` instead of failing halfway through a stream. / 非 Codex 入口出现同样的孤儿工具结果时，River 适配器返回 `400 unsupported_content`，不再出现「已开始流式再中断」。
- A response that ends because it hit `max_output_tokens` (or a content filter) is delivered as the terminal `response.incomplete` event. The gateway only treated `response.completed` as terminal, so it aborted a fully delivered stream and the client again reported `error decoding response body`. `response.incomplete` is now relayed as a normal terminal event. / 命中 `max_output_tokens`（或内容过滤）时，Responses 以终结事件 `response.incomplete` 正常收尾。网关此前只认 `response.completed`，会在完整交付之后仍中断连接，客户端同样看到 `error decoding response body`。现在 `response.incomplete` 按正常收尾转发。
- A streaming response that ends before a terminal event is now recorded as `upstream_stream_kind=incomplete_stream`, so it can be told apart from malformed data lines (`invalid_json`／`unexpected_shape`) and upstream error events (`upstream_error`). / 在终结事件之前结束的流式响应现在记录为 `upstream_stream_kind=incomplete_stream`，可与数据行不合语法（`invalid_json`／`unexpected_shape`）和上游主动报错（`upstream_error`）区分。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no public API change. Only Codex requests that are routed to a non-OpenAI provider are adapted; the OpenAI transparent passthrough path and other clients keep their existing behaviour. On third-party models the Companion Page snapshot is not forwarded — the MCP/agent tool groups behind it were already dropped for those providers. / 无数据库迁移、无公共 API 变更。适配只作用于改走协议路径、目标为非 OpenAI 服务商的 Codex 请求；OpenAI 透明转发与其它客户端行为不变。第三方模型上不再转发 Companion Page 快照——它背后的 MCP／多智能体工具分组本来就已对这些服务商移除。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. Restart Codex after installing. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装；安装后重启 Codex。
- Application/frontend version: `2.3.1-beta.11`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.11`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- Existing accounts, routes, statistics and client configuration are preserved; this release has no database migration. / 保留现有账号、路由、统计与客户端配置；本版本没有数据库迁移。

## Verification boundary / 验证边界

- Root cause reproduced against the real River key with seven request variants: the captured Codex body succeeds, the same body with a `call_id`-less `function_call_output` truncates after 185 bytes, and restoring a string `call_id` makes it complete again. / 用真实 River Key 做了七组正文对照复现根因：抓包正文成功；同一正文加入无 `call_id` 的 `function_call_output` 后在 185 字节处中断；把 `call_id` 换回字符串后恢复完成。
- The exact failing thread body (13 rollout input items, four orphan Companion Page results) was replayed against an isolated instance of the new build with the real key: `200` with `response.completed` twice, no truncated read. / 用真实 Key 把失败线程的原始正文（13 个 rollout 输入项、4 条孤儿 Companion Page 结果）复放到新构建的隔离实例：两次都是 `200` + `response.completed`，没有中断读取。
- New coverage: the Codex entry adapter drops only orphan tool results and keeps the matched call/output pair; the River adapter rejects orphan results with `400`; `response.incomplete` is relayed as a terminal event; a stream ending without a terminal event is classified as `incomplete_stream`. / 新增覆盖：Codex 入口适配只移除孤儿工具结果并保留成对的调用／结果；River 适配器以 `400` 拒绝孤儿结果；`response.incomplete` 按终结事件转发；终结事件前结束的流分类为 `incomplete_stream`。
- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, frontend tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端测试与 Windows 生产构建。
- Not verified: the real Codex desktop window replaying the affected thread against the rebuilt app — the user needs to restart Codex after installing and retry the conversation. / 未验证：安装新构建后由真实 Codex 桌面端复现原会话；需要用户安装并重启 Codex 后重试该会话。
