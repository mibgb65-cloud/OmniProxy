# OmniProxy v2.4.1-beta.2

## New Features / 新功能

- **Records page.** The sidebar now has a “Records” item between Requests and Logs. It lists only requests whose body was saved, newest first, with time, outcome, actual model, client, account, original and compressed size, a legacy-truncation badge and a readable preview of the recent conversation text. Search by request ID, model, account or agent, page through 20 at a time, and click a card to open the full request detail. / 侧边栏在「请求」与「日志」之间新增「记录」，只列出已保存正文的请求：按保存时间倒序显示时间、结果、实际模型、客户端、账号、原始／压缩后大小、历史截断标记与最近对话文本预览；支持按请求 ID、模型、账号或 Agent 搜索、每页 20 条分页，点击卡片进入完整请求详情。
- **Full request bodies.** Request content is no longer cut at 256 KiB. The gateway stores the complete client body (the request size limits of 16 MiB for protocol entries and 32 MiB for Codex transparent forwarding are unchanged), gzip-compressed, with a readable preview computed at capture time. / 请求正文不再按 256 KiB 截断：网关完整保存客户端正文（协议入口 16 MiB、Codex 透明转发 32 MiB 的请求上限不变），以 gzip 压缩入库，并在采集时生成可读预览。

## Notes / 说明

- Storage is bounded by a 512 MiB budget measured on compressed bytes. When it is exceeded, the oldest bodies are deleted first; request details and lifetime token totals are untouched. The Settings → Requests and logs card shows the current content usage and budget. / 存储以压缩后 512 MiB 为总预算，超出时先删除最旧正文；请求明细与终身 Token 累计不受影响。设置 → 请求与日志会显示当前正文占用与预算。
- Long Base64 inline data (images/audio) is still folded into a placeholder, and compressed or non-UTF-8 transparent bodies are skipped; response bodies, raw headers, User-Agent, access keys and credentials are never stored, and content never enters the runtime logs. / 长 Base64 内联数据（图片／音频）仍折叠为占位文本；压缩或非 UTF-8 的透明转发正文不保存；响应正文、原始头部、User-Agent、接入 Key 与凭据始终不保存，正文也不会进入运行日志。
- Rows saved by earlier versions may still be truncated at 256 KiB; they keep the “Truncated” badge and cannot be restored. New requests are complete. / 旧版本保存的行仍可能在 256 KiB 处截断，会继续显示「已截断」且无法恢复；新请求为完整正文。
- XLSX export still truncates a content cell at Excel's 32,767-character limit and marks it in the “Content truncated” column; that is an Excel limit, not storage truncation. The Records page and request detail show the full body. / XLSX 导出仍按 Excel 的 32767 字符单元格上限截断并在「正文截断」列标记；这是 Excel 的限制，不是存储截断。记录页与请求详情展示完整正文。

## Breaking Changes / 不兼容变更

None / 无。Migration 054 rebuilds `request_contents` and migrates existing rows in place; the switch remains off by default, and accounts, routing, request history and totals are preserved. / 无。迁移 054 重建 `request_contents` 并原地迁移旧行；开关仍默认关闭，账号、路由、请求历史与累计保持不变。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.4.1-beta.2`; Windows numeric resources: `2.4.1.0`; NSIS installer base version: `2.4.1`. / 应用／前端版本为 `2.4.1-beta.2`，Windows 数字资源版本为 `2.4.1.0`，NSIS 安装器基础版本为 `2.4.1`。
- First start runs migration 054 automatically. Old bodies are migrated as plain text and stay readable; new requests are compressed. The content switch stays off until you enable it. / 首次启动自动执行迁移 054。旧正文以明文行迁移并继续可读；新请求使用压缩存储。正文开关保持关闭，直到你主动开启。
