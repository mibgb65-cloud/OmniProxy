# OmniProxy v2.3.1-beta.27

## New Features / 新功能

- The dashboard gains a "Token share by model" card that follows the selected range (today by default). It lists the leading models with their share of the reported tokens, their totals and request counts, and merges the remaining models into an exact "other" row: the backend returns every model in the range, so the remainder is summed from real rows instead of being derived by subtraction. Time ranges are folded to local dates because `dashboard_buckets` has no model dimension; the read happens in the same read-only transaction as the metric cards, so a range switch never mixes two periods. The card sits next to "Client connections", which is re-laid out for the narrower column. / 仪表盘新增「模型 Token 占比」卡片，跟随所选时段（默认今日）：逐条列出领先模型的 Token 占比、合计与请求数，其余模型合并成精确的「其他」——后端返回该时段全部模型，余量由真实行相加而不是相减得出。`dashboard_buckets` 没有模型维度，因此时段按本地日期折算，并与指标卡在同一次只读事务里读取，切换时段不会混入上一时段的数字。卡片与「客户端接入」同排，后者改为适配窄列的竖排。
- The usage page gains a "Yearly activity" heatmap covering the last 365 local dates: 53 Monday-first columns, one cell per day, hover detail for a single day (input／output／total tokens and requests), a Token／requests metric toggle, a four-step scale taken from the quartiles of non-zero days, and a "Less → More" legend. Days after today only occupy space, and the leading padding days of the first week count as real zeroes and stay out of the "past year" total. It reads one extra 365-day daily aggregate of `usage_buckets` in the existing `UsageRead`, so it updates with the page's 5-second refresh. / 用量页新增「年度活跃度」热图，覆盖近 365 个本地日期：53 列、周一起始，每天一格，悬浮查看单日输入／输出／合计 Token 与请求数，可切换 Token／请求数，色阶按非零日子的四分位分四档，并给出「少 → 多」图例。今天之后的格子只占位，首周补齐的日期按真实的 0 计并不进入「过去一年」合计。它只是在既有 `UsageRead` 中多读一次 365 天的日汇总，因此随用量页 5 秒轮询一起更新。

## Breaking Changes / 不兼容变更

None / 无。No database migration, no API or configuration change: both additions are read-only fields on existing read methods, and no accounting rule changed. The dashboard and usage page simply show more of what is already stored. / 无数据库迁移、无 API／配置变更：两处都只是既有读取方法上的只读字段，未改变任何记账口径，仪表盘与用量页只是多展示已保存的数据。

## Local update / 本地更新

- Local Windows amd64 Beta installer, not a public release and not signed. Fully exit OmniProxy from the system tray, back up the data directory, then run the installer over the existing installation. / 本版本为本地 Windows amd64 Beta 生产安装包，未公开发布、未签名。请先从托盘完全退出 OmniProxy，备份数据目录，再运行安装器覆盖现有安装。
- Application/frontend version: `2.3.1-beta.27`; Windows numeric resources: `2.3.1.0`; NSIS installer base version: `2.3.1`. / 应用／前端版本为 `2.3.1-beta.27`，Windows 数字资源版本为 `2.3.1.0`，NSIS 安装器基础版本为 `2.3.1`。
- After upgrading, open Dashboard and Usage. The dashboard's new card needs requests already recorded in the selected range; an empty range shows an honest empty state rather than 0%. The heatmap fills from whatever daily totals this machine has collected so far. / 升级后打开仪表盘与用量页即可看到。仪表盘的新卡片需要该时段已有已记录的请求，没有任何已报告 Token 时显示空状态而不是 0%；热图按本机已经累计到的日汇总填充。

## Verification boundary / 验证边界

- `task verify` passed before packaging: format, lint (`go vet`／`staticcheck`／ESLint), `tsc --noEmit`, all Go packages, 162 frontend files / 990 tests and the Windows production build. / 打包前 `task verify` 通过：格式、lint（`go vet`／`staticcheck`／ESLint）、`tsc --noEmit`、Go 全包、前端 162 文件／990 项测试与 Windows 生产构建。
- Covered by tests: per-range model shares (a previous day's usage never leaks in), exact "other" merging and its empty／all-zero states, the 365-day calendar window and its local-date boundary, Monday-first grid alignment, month-label spacing, quartile levels and per-metric totals. / 测试覆盖：模型占比随时段收窄（前一日的用量不会混入）、「其他」的精确合并与空／全零状态、365 天窗口与本地日期边界、周一对齐、月份标签间距、四分位色阶与按指标取合计。
- **No real model request was sent while building this version**, and the two additions were not eyeballed in the running desktop window: their geometry is fixed by the grid and `aspect-ratio` rules and locked by tests, but the pixels in a real window are still unconfirmed. / **本版本打包时未发起任何真实模型请求**，两处改动也没有在运行中的桌面窗口里目视确认：排布由固定网格与 `aspect-ratio` 决定并被测试锁定，但真实窗口里的像素表现仍待确认。
