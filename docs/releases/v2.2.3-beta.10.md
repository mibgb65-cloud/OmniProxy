# OmniProxy v2.2.3-beta.10

## Bug Fixes / 问题修复

- River requests are no longer rejected locally just because they carry more than 128 tools. DeepSeek Harness merges its built-in tools with several MCP servers; with OpenPencil enabled the request carried 176 tools and every message failed with a bare `400 {"code":"invalid_request",...}` before anything was sent upstream. / River 请求不再因为工具数量超过 128 个就在本地被拒。DeepSeek Harness 会把内置工具与多个 MCP 合并发送；启用 OpenPencil 时该请求带 176 个工具，每条消息都在发往上游之前就得到笼统的 `400 {"code":"invalid_request",...}`。
- The tool-count limit was never part of River's published contract: the official limits page documents only the 50 MiB request body, image formats and timeouts. A direct request with 176 function tools against the same River model returns `200`. / 该计数上限从来不是 River 公布的契约：官方 Limits 只列出 50 MiB 请求体、图片格式与超时。对同一 River 模型直接发送 176 个函数工具的请求返回 `200`。
- Tool shape validation is unchanged: only `type=function` tools are accepted, the function name must be non-empty and at most 128 characters, and no tool is truncated or dropped. / 工具形状校验保持不变：只接受 `type=function`，函数名必须非空且不超过 128 字符，且不截断、不丢弃任何工具。

## Breaking Changes / 不兼容变更

None / 无。No new database migration or public API change / 无新增数据库迁移或公共 API 变更。Requests that previously failed locally with `400 invalid_request` because of the tool count are now forwarded upstream and answered by River; clients that relied on that local rejection will see the upstream result instead / 此前因工具数量在本地失败为 `400 invalid_request` 的请求现在会发往上游并由 River 作答；依赖该本地拒绝行为的一侧将看到上游结果。

Other providers keep their existing 128-tool check, since none of them has an equivalent upstream verification / 其他提供商适配器保留既有 128 工具检查，它们都没有等价的上游核对结论。

## Refactor & Performance / 重构与性能

- `internal/provider/river/tools.go` drops the count branch only; the per-tool loop and its error codes are untouched. New tests cover 1／128／129／176／200／512 tools and a `Client.Forward` contract test that asserts all 176 tools reach the upstream intact. / `internal/provider/river/tools.go` 只移除计数分支，逐条校验与错误码不变；新增测试覆盖 1／128／129／176／200／512 个工具，并有一条 `Client.Forward` 契约测试断言 176 个工具原样到达上游。No new dependency / 无新增依赖。
